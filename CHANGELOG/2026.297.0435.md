**The gate's own token.** The org's PR-body linter used to fail ANY fenced block containing
the ellipsis character, so a gate whose own output carries that character could not have
that output pasted into a PR body at all. The umbrella's `scripts/check-task-command-vars.mjs`
therefore rendered the reference it forbids as three ASCII dots. The linter's rule now has a
**form**: it fires on the AUTHOR's elision — an elided `$ ` command line, an elided `head`
command's output, a dropped line of the paste — and ALLOWS a program's own token
(opencharly/marketplace#537). The ASCII rendering is therefore deleted: the gate prints the
character the product prints, and a pasted transcript of this gate is the product's, not the
body's.

| file | what it carries |
|---|---|
| `scripts/check-task-command-vars.mjs` | the printed reference: the product's own token, not an ASCII rendering of it |
| `hooks/pre-commit` | the banner comment: the new rule, and why the banner itself stays ASCII |
| `layer-charly-internals` | the gitlink: `13e28d3` → `ecf9eee` |
| `marketplace` | the gitlink: `c77077b` → `42b8789` |

**Why the banner stays ASCII.** The banner opens the transcript a PR pastes as its gate
evidence, and the comment names the codepoint instead of embedding it, so a grep for it over
that file stays meaningful. The linter no longer requires the ASCII-ness (a program's own
token is allowed), so it is kept for the greppable property, not for the linter — and the
comment now says exactly that. The ASCII rendering that is deleted is the GATE's: the
reference it forbids, printed to tell the operator what the rule forbids.
