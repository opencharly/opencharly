# 2026.234.1251 — refactor: drop CHANGELOG placeholder, simplify workflows, add dotgithub submodule

## Summary

Redesigns the CI workflow architecture from first principles — eliminating the CHANGELOG placeholder/rename mechanism entirely and simplifying both dispatchers.

### What was wrong

The old flow required a placeholder `CHANGELOG/<calver>.md` in every PR diff, then the org-wide pr-validator renamed it via bot-token Contents-API pushes, exiting and relying on a `synchronize` re-trigger. That dance created a cyclic loop, left stale red checks, required bot tokens, and ran validation twice per PR.

### New flow

1. **pr-validator** (`charly/pr-validator`): AI review → on PASS, enable GitHub native auto-merge (squash). No CHANGELOG manipulation, no bot tokens, no wait-ci job. Branch protection waits for ALL required checks before auto-merge fires.
2. **tag-on-merge**: triggers on `pull_request: closed` (merged) + a 15-min `schedule` sweep backstop. Creates the CalVer tag AND writes `CHANGELOG/<calver>.md` from the merged PR's title + body (the body IS the changelog).
3. **PR authors**: write the normal PR body — no CHANGELOG file in the diff, no `## CHANGELOG` section.
