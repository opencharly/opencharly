**What the observation was, and what this change does.** The mutation harness carries two mechanisms, because the code lives in two places: a **"gate"** mutation (in the gate's executed path — the fixture copy runs it and the parent judges the copy's behaviour) and a **"self"** mutation (in the harness's own assertion logic, which the fixture copy never executes — so the mutated source is run *as a self-test*, and the mutation is caught when that nested self-test fails on the assertion under test).

In a nested self-test, the `mutate()` call ran **before** the recursion guard. The nested run's own source is already mutated, so the mutation's application there was a thing the nested run could not assume — and where the mutation did not apply, the nested run reported a failure ("mutation ... did not apply") that belongs to the parent's proof, not to the nested run's own verdict. The guard now decides **first**: a nested run skips the "self" mutation before it touches the source, so the skip is unconditional, and the nested run's output carries only what it is there to say — that the assertion under test fails, which is what the parent reads.

The proof that this is load-bearing is measured, not asserted: the same nested source, given to the pre-fix code and to this code, is RED on the first and GREEN on the second (the control below).
