# 2026.268.1528 — fix(map): print via the canonical status verb; bump charly for the renderer

## Summary

`charly task map` printed no map. Two root causes, both fixed here, and the
charly gitlink is advanced to deliver the dependency.

### Root cause 1 — `map` duplicated the canonical table and discarded its stdout

The umbrella `map` step used an inline `command:` that **re-implemented** the
`verb:git-submodules status` table (an R3 duplication), and the `command` verb's
pass path returns only `exit=N` — its stdout is asserted via matchers, never
echoed. So the table was built and discarded. `map` now composes
`verb:git-submodules status` directly, so the table becomes the step's
`Result.Message`.

A `task:` verb wrapper is deliberately **not** used: `verb:task` returns only a
one-line summary, which would discard the table again.

### Root cause 2 — the task reporter dropped `Result.Message`

Even a verb-backed step's table was invisible because the `charly task` text
reporter rendered only the authored step `Text`. That is fixed in
**opencharly/plugin-task#5** (merged), which charly now pins at
`candy/plugin-task/v0.2026268.1402` (**opencharly/charly#662**, merged). This PR
advances the umbrella's charly gitlink `4f9c868 → 5d0b66e` to deliver it.

### What changed

- `charly.yml` — `map`'s step becomes `git-submodules: {mode: status}` (the ONE
  status implementation, shared with `pins MODE=status`).
- `charly` — gitlink `4f9c868` → `5d0b66e` (charly `origin/main`, which carries
  the merged plugin-task 1402). Every other pin is left at HEAD: routine sync
  noise belongs to the sync workflow, not this PR.
