# 2026.312.2224 — feat(check): a gate over the schema patterns in every plugin module

## Summary

`DESIGN.md` §25 lists "schema patterns on every plugin CUE module (D-PAT-1..3)" as a gate, and `TODO.md` 2.16 recorded that no such control existed — only D-PAT-1 on `DESIGN.cue`, by Appendix A.4 check 6. This lands the first of the three as the fifth control of the design check, so it actually runs. **A gate with no caller does not count**, which is why the caller is part of this change rather than a follow-up.

`scripts/design-dpat.sh` judges **D-PAT-1 in every pinned plugin CUE module**: no `close(` call, no field written `f?: _|_`, no open struct that is not the `#Opaque` definition, and every use of `#Opaque` marks itself `// S10` (§10.1). `bash scripts/design-check.sh` runs it as control 5/5, and `DESIGN.md` Appendix A documents it in the same shape as its siblings.

Three properties make it a gate rather than a linter that always says yes.

- **It judges the schema that ships.** The pin set comes from this tree's own index (`git ls-files --stage`), so `spec` and every `plugin-*` gitlink are judged at the commit the tree records. Each module is read out of its own object store (`<git-common-dir>/modules/<path>`) at that commit — never from a checkout, which can be stale, dirty or absent (a session worktree materializes no gitlink). A repository or a pinned commit it cannot read is a FAILURE that names the path and the remedy, and a run that judges nothing also fails: a gate that silently judges fewer modules than it claims is the failure mode this change exists to remove.
- **It cannot be red on the tree it lands on, and cannot be green on a new violation.** The tree carries 224 violations today (close 70, absence 86, open 68) across 44 files in 9 modules, and rewriting them is TODO.md 2.16's §10.1 work. `design/dpat-baseline.tsv` records them as a census, so the gate is green here and red on anything new. The census is a ratchet: it is keyed by the construct rather than by the line, so an edit that shifts a known violation cannot redden the gate and a new violation cannot hide behind a tolerated line; and an occurrence BELOW its count fails too, so every fix lowers its row in the same change and the census must reach zero. opencharly/opencharly#945 tracks it.
- **It can fail, and the failure is proven.** `--self-test` mutates an isolated fixture through every rule and both census directions, and the run's own `--emit-census` prints the file it compares against.

Scope boundary, stated rather than silent: a `vendor/` tree inside a plugin repository mirrors another system's published schema (the egress vendoring pipeline), so it is out of scope — and the run reports how many files that boundary left out.

Not in this change: D-PAT-2 and D-PAT-3 have no control yet (§25's gate is not complete until they do), and no existing violation is fixed — the census is the record of what remains.

The same row's count raised to 2, so the census overstates the debt by one:

