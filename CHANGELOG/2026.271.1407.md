# 2026.271.1407 — fix(opencode): native watcher delivery via SDK (toast + noReply context), not a CLI subprocess

## Summary

Fixes every finding of the validator BLOCK on this PR, and catches the branch up to
`origin/main` (clears the BEHIND state). Head `f2bb3e0`.

The title/body claim — native, in-process delivery via opencode's own SDK, never an
`opencode run` subprocess — is now true of the shipped code, and the unproven runtime is
stated plainly as the landed, inert-by-default behaviour.

**Block 1 — the `noReply` context injection is implemented, not commented out.**
`client.tui.showToast(...)` remains the visible signal. The second, previously
commented-out call now runs: the plugin resolves the target session id from
`client.session.list()` (the most recently updated root session whose `directory`
matches the project directory, excluding child sessions) and calls
`client.session.prompt({ path: { id }, body: { noReply: true, parts: [{ type: "text",
text: line }] } })`. `noReply: true` is the documented context-only injection (SDK
docs: *"Inject context without triggering AI response (useful for plugins)"*), so an
in-flight turn is not interrupted. If no session resolves, the wake is toast-only.

**Block 2 — RDD: the binding is stated plainly as UNPROVEN / INERT, not deferred.**
There is no "confirm on the next restart" wording anymore. The plugin docstring and the
instructions both state, as the landed behaviour, that the binding has **not** been
exercised under opencode's Bun runtime (no opencode V2 / disposable target was available;
only the module and its pure helpers were unit-tested under Node), that it **watches
nothing** until `.opencode/pr-watch.items` carries at least one item, and that it warns
and no-ops if the `setup(ctx)` context does not expose `ctx.client` / `Bun`. Nothing in
the repo relies on it.

**Block 3 — `.opencode/instructions.md` and the docstring match the code exactly.**
The rewritten section states the binding is `.opencode/plugins/pr-watch.ts`, runs the
generic watcher with **`Bun.spawn`** (not Bun's `$`), delivers with the two real SDK calls,
resolves the id via `client.session.list()`, reads `.opencode/pr-watch.items`, and is
inert/experimental. The docstring is truthful: the plugin checks `Bun`, the SDK client,
and the watcher script, and logs a warning (`client.app.log`, else `console.warn`) before
no-opping.

**The round-1 gate hole — fixed.** `scripts/check-pr-watch.mjs` no longer strips only
whole-line `//` comments: `stripComments()` removes `/* … */` block comments (including
the ` *`-prefixed docstring) **and** whole-line `//` comments, so the primitive assertions
can only pass on real code. A **negative control** proves it: needles embedded in a
synthetic docstring/comment are asserted ABSENT after stripping. This is exactly the
"load-bearing call left as a comment" regression, and the gate now fails for it.

**Notes.** `scripts/check-pr-watch.mjs` ships real unit tests for the pure helpers
(`parseItems`, `pickSessionID`, `lastWakeLine`) and the comment hole above; it is wired
into `charly task verify` (`charly.yml`) and `hooks/pre-commit`. `.opencode/pr-watch.items`
is added as a comment-only template, so the config file is documented in-repo and the
plugin is inert by default. The watcher it drives, `marketplace/scripts/gh_watch.sh`,
exists on `opencharly/marketplace` `origin/main`; the umbrella's `marketplace` gitlink
currently predates it, so the plugin warns and no-ops until the pin is synced.
