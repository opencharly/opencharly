# 2026.300.1647 — fix(pre-push): git's real push contract — the published branch from stdin, the pushed remote from $2, a PATH-built tool farm, and a machine-checked skip count (#743)

## Summary

Head `7cba2b90587ace1763b3b53170fef15e8605a1d9` — 3 files changed, 434 insertions(+), 128 deletions(-).

The predecessor PR (#742) gave this umbrella's pre-push hook a LIVE-body check: it compares the body the push validates, at `$(git rev-parse --absolute-git-dir)/PR_BODY.md`, with the body's LIVE copy on the PR — because the validator reads the PR's copy, and a body file that was correct while the PR's copy was stale passed the gate perfectly. It shipped with a contract git does not have. Git hands a pre-push hook TWO arguments — the remote NAME and the remote URL — and writes the refs it publishes on **stdin**; there is no third argument. The merged hook read `local_ref="${3:-}"`, so the published branch was always empty and the check fell back to `git rev-parse --abbrev-ref HEAD` — the CHECKED-OUT branch, not the PUBLISHED one. The same hook took the pushed remote from a function that was called with no arguments at all, so the remote was always `origin` whatever the push named. Both were invisible in the merged arms, because the arms ran the hook with no arguments and no stdin, against a fixture with one branch and one remote — where a wrong branch and a wrong remote are indistinguishable from the right ones. A push of another branch was compared against the WRONG PR: a false PASS on one push, a false BLOCK on another.

The merged gate's no-`gh` tool farm was built from three hard-coded directories (`/usr/local/bin`, `/usr/bin`, `/bin`), so on a host whose node lives in nvm, homebrew or mise the farm held no node, the reconciliation was silently skipped, and the arm exited 0 having exercised none of what it was written to exercise. The merged record also stated four skip cases where the code has six.
