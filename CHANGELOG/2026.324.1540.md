# 2026.324.1540 — docs(design): add the XDG data root and containment requirements

## Summary

Adds the normative XDG contract to `DESIGN.md` and folds the mandate into R11. No runtime code.

- **D-STORE-1** resolves configuration, data, state, cache and runtime through the one contract
  resolver (`spec/storeroot`), with the XDG search paths (`XDG_CONFIG_DIRS`, `XDG_DATA_DIRS`),
  `CHARLY_CACHE_DIR` used verbatim as the single override, and the documented runtime→state
  fallback.
- **D-STORE-7**: `charly clean` never touches the data root.
- **D-STORE-8**: tests inject roots through the `Resolver` type; one non-parallel/subprocess test
  covers the process-environment default.
- **D-STORE-11**: outside `spec/storeroot`, no code reads `HOME`/`XDG_*` or builds a
  base-directory path.
- **D-STORE-12**: `$XDG_DATA_HOME/charly` is durable user data (SSH keys, VM disks and per-VM
  state, encrypted-volume plaintext, bind-mounted volumes), never a cached item; the cache store
  stays under the cache root.
- **R11** gains one sentence citing D-STORE-1/11/12 and pointing at `/charly-internals:xdg`; the
  acceptance checklist gains the host-path pointer. AGENTS.md enumerates neither roots nor env
  vars.

This supersedes the disposition in opencharly/opencharly#1098 / opencharly/spec#375 **by operator
direction**: that data root served the built-image store; this one serves durable user data, and
D-STORE-3's single cache store is unchanged. The cache/data split is semantic: cache is
re-derivable; data is durable and `charly clean` never evicts it.
