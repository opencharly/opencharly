# 2026.280.2135 — fix(harness): charly_worktree_remove must not report a removal it never performed (#410)

## Summary

Cluster C8's `opencharly/opencharly#410`. `scripts/check-pi-gates.mjs` asserted the pi gate
extension by matching its **text**, so the surface was "asserted by nothing" that could see
behaviour. This change fixes the defect the text could not see and gives the surface the gate
that can.

**The defect (root cause, proven from the shipped pi runtime, not inferred).** `charly-gates.ts`
wrapped its `git worktree remove` in `try { … } catch { … --force … }`. `pi.exec` never rejects:
pi 1.0.4's `exec` delegates to `execCommand`, whose promise **resolves** `{stdout, stderr, code,
killed}` in every branch, its own internal catch included. So the `--force` retry was unreachable
dead code and a removal git had refused printed success.

**The fix.** Every recovery step is driven by the observed **result** (`code`/`stderr`), never a
rejection; a refused removal returns `isError: true` instead of a success string; the report
carries the **observed** effect (`removed`). The branch arm replaces the retired ancestry test
`git branch --merged origin/main` — blind to the org's squash landing, so every landed `feat/`
branch leaked — with a squash-true **patch-id** proof (`git cherry` -> `- <sha>`) and `-D`, and an
unlanded branch is **kept** and named as kept. The legacy ancestry path is deleted, not left
beside the new one.

**The gate.** `scripts/check-pi-gates.mjs` now also **loads the shipped module** (Node's native
type-stripping, a stand-in for its only runtime bare import `typebox`, and an `ExtensionAPI`
stub whose `exec` mirrors the proven real contract) and **fires** the gate and the tool against
real git repositories. No assertion was weakened: the aggregated static reading is unchanged and
all 12 pre-existing mutations still go red.
