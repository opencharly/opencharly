# 2026.241.1947 — chore: pin the two punktfunk repos (layer-punktfunk, plugin-punktfunk)

## Summary

Registers the two new punktfunk repos in the org view, taking the umbrella from 344 to
**346** submodules:

| path | repo | role |
|---|---|---|
| `layer-punktfunk/` | [opencharly/layer-punktfunk](https://github.com/opencharly/layer-punktfunk) | installs the punktfunk streaming host (host daemon + web console + plugin runner) from unom's signed pacman repo on Arch/CachyOS |
| `plugin-punktfunk/` | [opencharly/plugin-punktfunk](https://github.com/opencharly/plugin-punktfunk) | serves the `punktfunk:` check verb — probes and manages a running host over its management REST API |

[punktfunk](https://git.unom.io/unom/punktfunk) is a Rust game/desktop-streaming **host
daemon** (native `punktfunk/1` QUIC protocol plus Moonlight/GameStream compatibility). The
org had no punktfunk surface and no game-streaming host of any kind: the existing
`selkies-*` / `wayvnc` / `sway-*` corpus streams a *desktop out of a container* over
WebRTC/VNC, which is a different axis from a host daemon with its own protocol and
management plane.

**Policy B:** both are bucket 3 ("everything else → its own default-branch HEAD"), so
`scripts/lib/policy-b.sh` needs no change — `CHARLY_PINNED` stays the five distro families.
Each `.gitmodules` entry carries a plain-HTTPS URL and `branch = main`, verified against the
remote default via `git ls-remote --symref`.

**On the pin being ahead of the tag** — deliberate, and worth stating because it looks like
drift at a glance. `tag-on-merge` mints the CalVer tag and *then* writes
`CHANGELOG/<calver>.md` to main, so the default-branch HEAD is one commit ahead of the tag:

```
layer-punktfunk   gitlink 4310759 = origin/main  ("docs: add CHANGELOG 2026.241.1915 for PR #1")
                  tag v2026.241.1915 = 0a914ad
plugin-punktfunk  gitlink 1b55e4e = origin/main  ("docs: add CHANGELOG 2026.241.1930 for PR #1")
                  tag v2026.241.1930 = f6d5c18
```

Policy B pins default-branch HEAD, not the tag; the CalVer tags are what `@github` candy
refs consume. Both pins are merged refs on `main`, never a PR branch.
