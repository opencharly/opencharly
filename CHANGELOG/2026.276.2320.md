# 2026.276.2320 — fix(umbrella)!: verify — an uninitialized submodule is a NOTICE, never a walk-up comparison (#337)

## Summary

`charly task verify`'s submodule-cleanliness step could not pass on a tree that rule 4 requires. Its guard
read `[ -d "$path" ] || fail "$path: not checked out"` — and an UNINITIALIZED submodule **is** a directory,
so the guard passed, and every later `git -C "$path" …` resolved the ENCLOSING superproject through git's
directory walk-up. The step then compared the SUPERPROJECT's HEAD against the SUBMODULE's gitlink and
failed on a state that cannot exist: `FAIL: sdk: HEAD <enclosing-head> != gitlink <sdk-pin>`, on EVERY path a
root has **not** materialized — and that count is a property of WHICH root it is measured at, because the
checkout audit sees only what that root materialized. The same metric, measured on this clone at two roots:
**405 of 424 paths at the umbrella ROOT** (`f96e776`, 19 of 424 materialized) and **423 of 424 in a session
WORKTREE** (`fad91f1`, 1 of 424 materialized — `charly`, which this session initialized to read its source
for the RCA below). Finding 6 reconciles the two numbers in full, and finding 5 pastes the sweep.

This PR makes an uninitialized `.gitmodules` path (declared, gitlinked, no checkout) a printed NOTICE
instead of a FAIL, and prints the counts it audited so that a pass can never read as a silent one. Every
tooth is kept: a dirty tree, `HEAD != gitlink`, a wrong `branch`, a `.gitmodules` path with no gitlink in
the index, and a nested `box/*` off charly's gitlink all still FAIL — each proven by a mutation that
reintroduces it.

### The findings on heads `01b2f04` and `56775ee`, and how each is closed

**1 — the WARNING (R1 / R10): the gate run pasted below is hermetic and emits none.**

Mechanism, read from the charly source at the ref the binary was built from (`charly` @ `fe4b00b4`, the
umbrella's own recorded gitlink) — `charly/charly/plugin_loader.go`:

- `:435` `packagedInstall()` — true only when the running binary's own directory is `/usr/bin` or
  `/usr/local/bin` (`:429`).
- `:447` `devPluginDirWarned sync.Once` gates the notice to one emission per process.
- `:454` `warnSkippedFHSPlugins()` prints it when `:461` finds a `*.providers` in the FHS plugin dir.
- `:484` `bakedPluginDirs()`: the dev-binary branch at `:492-494` calls it and returns `dirs`; the

So the notice is a property of **the host and the binary**, never of this change (which touches no Go
file), and it is about exactly one thing: the FHS plugin search path, which a dev/worktree binary
deliberately drops. The same binary prints it for maintenance verbs this PR does not touch at all

run is pasted beside it so nothing is hidden.** Paste 3 is `CHARLY_PLUGIN_ONLY=1 … task verify` — the gate's

announcement lines) is run-to-run nondeterminism that occurs in BOTH modes: two runs of the same mode on

measure() {
  R="$1"; H=$(git -C "$R" rev-parse HEAD)
  mapfile -t P < <(git -C "$R" config -f "$R/.gitmodules" --get-regexp '^submodule\..*\.path$' | awk '{print $2}')
  declare -A GL
  while read -r m s t p; do GL[$p]="$s"; done < <(git -C "$R" ls-files -s | awk '$1=="160000"')
  n=0; g=0; d=0
  for p in "${P[@]}"; do
    if [ -e "$R/$p/.git" ]; then g=$((g+1)); else n=$((n+1)); [ "${GL[$p]:-x}" = "$H" ] || d=$((d+1)); fi
  done
  echo "$R  HEAD=$H  paths=${#P[@]}  .git-present=$g  no-.git=$n  of-those_gitlink!=head=$d"
}
