# fix(tasks): compose the pin verb ONCE in `verify`, so it cannot report `0 policy pins`

Head `22a8cc8fbeb665df86a74e1c1d93f652c771e2c1` (branch `fix/one-pin-composition`, base `origin/main` at `fa733f3`), one file,
`charly.yml`, 19 insertions and 22 deletions.

## Summary

`charly task verify` composed `verb:git-submodules` twice, and the two compositions could not agree:

1. a `task: pins` step (`param: [MODE=verify]`) — the pin contract's EDGE half, whose Message
   `verb:task` discards (it returns a one-line summary);
2. a bare `git-submodules` step with `pin_map: {}` — the checkout audit, which is HALF 2 of the same
   verb, and which therefore could only ever report **`0 policy pin(s)`**, because the map it was
   handed was empty.

So the task's own paste said zero pins while the tree held six, and the coverage that proves the
audit ran lived in a Message that no step printed. Measured on the untouched umbrella tree:

```
$ ./charly/bin/charly task verify ; echo rc=$?
task verify: 21 step(s), 0 failed
  [pass] check — the pin contract's edge — every distro-* gitlink equals charly's own box/* gitlink
      ran 1 task(s), 0 step(s) failed
  [pass] check — every submodule is clean and checked out at its recorded gitlink — the ONE verb that owns the clause (its coverage rides its Message, the channel that renders on the pass path; a command step's does not)
      verify: 0 policy pin(s) hold across 431 submodule(s); 431 checkout(s) clean at their gitlink
rc=0
```

`mode: verify` runs BOTH halves in ONE call — half 1 the edge over `pin_map`, half 2 the checkout
audit over every `.gitmodules` path — so the second composition bought nothing but a contradictory
count. It is deleted. The task now composes the verb once, through `pins`, which is the ONE canonical
holder of the 6-entry map (the map literal exists exactly once in the file, as `pins`'s own comment
requires).

### What the one composition reports

```
$ ./charly/bin/charly task pins --param MODE=verify ; echo rc=$?
task pins: 1 step(s), 0 failed
  [pass] run — run git-submodules in the selected mode
      verify: 6 policy pin(s) hold across 431 submodule(s); 431 checkout(s) clean at their gitlink
rc=0
```

Six pins, all holding, plus the checkout coverage — the answer the second composition was printing
as zero.

### The residual loss, filed rather than paid for twice

The wrapper's Message is discarded by `verb:task`, so this task no longer reprints that
`N policy pin(s) … K checkout(s) clean` line at all. Paying for it by re-composing the verb is
exactly the defect this change removes, so the loss is filed instead:
`opencharly/plugin-task#33` carries the measurement (the direct `pins` run above versus
`task pin-check`, which prints `ran 1 task(s), 0 step(s) failed` and no counts) and the root fix
(propagate the wrapped run's step Messages through the `task:` verb).
