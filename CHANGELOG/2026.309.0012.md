## Summary

Batch 24 of the DESIGN amendments the capability ledger records (tracked in #838). `#AndroidFields` was
`{device, api_level}`, so an emulator could be **named but not composed**: the `box` its image is built
from, the `serial` of a device that already exists, and the `google_account` sign-in had no field — and
today's `android:` carries all three.

| file | what changed |
|---|---|
| `DESIGN.cue` | `#AndroidFields` gains `box`, `serial`, `google_account`; `#GoogleAccount` is the sign-in shape |
| `DESIGN.md` | the android example gains a **created** emulator node; §17.1's kind row says what one takes |
| `design/dulling.tsv` | `kind:android` becomes sharp |
| `design/dulling-disposition.md` | regenerated |

Two details that are the point of the batch rather than decoration:

- **the token is a secret reference.** `google_account.token` names the `secret:` **need entry** that
  carries it, so a credential never appears in the document itself.
- **the example had to be a CREATED node.** The existing android example connects to an adb endpoint, and
  a *connected* node does not spread its kind's create fields (the `connect_create` mechanism from #865).
  A connected example would have proved nothing about the fields this batch adds.
