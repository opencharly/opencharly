## Summary

The pi watch binding made two claims about state it had already recorded. Both were measured, both are
now honest, and both ship with a gate that can go RED.

Head `8321c9cfe056855dab07791a5c123588ca8c5472` — 2 files, +42 −1.

**1. `watch_arm status` explained an EMPTY retired set as if the arm were gone.**

```
  retired: - (a state event fired — not re-armed; restart to re-watch)
  armed:  yes (this session's arm is tracked)
```

`retired: -` is the EMPTY set — nothing was retired — but the parenthetical explaining a *non-empty*
set is concatenated unconditionally. Read as a pair, it says "the arm is gone" three lines above
`armed: yes`. It was read that way: the operator asked why no watcher was set, the session accepted a
process failure that had not happened, published a wrong RCA on it, and killed and re-armed a
perfectly healthy watcher. The empty case now says `- (nothing retired)` and the explanation appears
only when there is something to explain.

**2. The delivery path — and why there is NO guard there now.**

My first round ADDED a `gh.retired` guard in `handleGhLine` and the review blocked it: an arm the body
itself admitted unreachable. That is correct, and it is fixed by deleting it rather than by arguing.
The measurement, recorded at the site: the engine's continuous loop already drops a retired item
(`open = open.filter(...)` in `watchStream`), and this binding's child is the ONE-SHOT `watch` —
`runWatch` returns a single fire, so a child prints at most one line and is gone before its item could
be retired behind its back. A guard there is an unreachable arm; CONC(a) blocks it and R5 removes it.

The three late wakes that made me think otherwise were QUEUED FOLLOW-UPS (`deliver()` uses
`deliverAs: "followUp"` while a turn runs), and the third settled it: the engine cannot emit CONFLICT
for a closed PR (`cur.state === "open"` is in the classifier), so that line was valid when produced.

**And a correction this PR carries from the issue.** I first attributed three late wakes to defect 2.
That was wrong: `deliver()` uses `deliverAs: "followUp"` when the session is not idle, so every wake
arriving mid-turn is QUEUED and surfaces when the turn ends — which is what those three were. The
third one settled it: the engine cannot emit CONFLICT for a closed PR (`cur.state === "open"` is in
the classifier), so that line was valid when produced and only delivered late. Defect 2 is therefore
recorded as an unreachable arm and REMOVED — not carried as a defect and not papered over with a test.

### Spike

**RCA claim (defect 1):** the retired-set explanation was concatenated unconditionally, so the empty
set carried the sentence that explains a non-empty one.

**Candidates:**

- **C1 — build the line from a conditional on `retired.length`.** Works: the empty set renders
  `- (nothing retired)` and the populated set keeps its explanation. What the diff implements.
- **C2 — always print the explanation and drop the `-` sentinel** (so an empty set reads
  `retired:  (a state event…))`. Rejected: it makes the empty set LESS legible and still explains a
  state that is not there.
- **C3 — print only `retired: <list>` with no explanation at all.** Rejected: it loses the one thing
  an operator needs from the line when the set IS populated — that a retired item will not re-arm
  until a restart.

**Winner: C1**, and the assertion pins both directions (the unconditional form must not return, and
the empty case must be named).

**RCA claim (defect 2):** the delivery path consults no retirement state.

**Candidates, and the winner is the ABSENCE of a guard — which is what the diff implements:**

- **C1 — add a `gh.retired` guard in `handleGhLine`.** Written in round 1 and BLOCKED: reachability is
  the test, and this arm cannot be reached. The engine's continuous loop drops a retired item itself
  (`open = open.filter(...)` in `watchStream`), and this binding's child is the ONE-SHOT `watch` —
  `runWatch` returns a single fire, so a child prints at most one line and is gone before its item
  could be retired behind its back. An unreachable arm in a modified file is CONC(a), and R5 removes it.
  **Rejected, and removed.**
- **C2 — no guard at all, with the reason recorded at the site. WORKS (winner).** The invariant is held
  by the ENGINE (continuous loop drops the item) and by the BINDING's shape (one-shot child), so the
  binding needs no second copy of the rule. This is what the diff ships: a comment stating the
  measurement, and no branch.
- **C3 — a guard in `deliver` instead.** Rejected: `deliver` also carries BED lines, which have no item,
  so the guard would need a fourth piece of state to tell the two apart.
