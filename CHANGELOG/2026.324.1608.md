# 2026.324.1608 — docs(design): a candy declares var:, and a step substitutes from it

## Summary

**DESIGN now says a candy declares `var:`, and a step's `${NAME}` substitutes from it.**

**The divergence this closes.** `spec/schema/candy.cue:115` has declared `#CandyFields.var` for as long as the field has existed, and `#Op`'s own `config:` comment states the rule those variables follow — *"substitutes ${VAR} refs in content: at generate time (**candy var: ∪ auto-exports**)"*. **DESIGN said neither.** `grep -c '`var`' DESIGN.md` → `0`.

**spec's own `AGENTS.md` names this exact situation as a defect:**

> *"A field that exists in `schema/*.cue` and not in `DESIGN.md` is **either** a projection that has not been documented **or** a field that should be deleted — and **which one it is must be decided in `DESIGN.md`**, not in the PR that needs the field. Add the `DESIGN.md` row for a new field before (or in the same cutover as) the CUE that projects it, never after."*

**This is that row**, and it is decided here rather than inside `opencharly/spec#403` — which is the PR that needs the field and therefore, by that rule, must not be the one deciding it.

**Where it lands:** §16's candy field table, beside `path_append` — the other field that feeds substitution — and projected onto `#Content` and the closed `_candyField` list so the schema that implements it is a projection rather than the only copy.

**The consequence it records:** a bed's runner builds a `check:` step's substitution from the candy's metadata, so this row is what makes `opencharly/plugin-pipeline#70`'s fix a wiring change against a stated rule instead of a field nobody documented.
