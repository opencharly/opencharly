# 2026.308.0457 — feat(design): name the pixi and mise build managers (batch 8)

## Summary

Batch 8 of the DESIGN amendments the capability ledger records (tracked in #838). Five builder
check-words were dulled because a builder plugin was its own node; the design routes a build
environment through `builder: {manager: …}` instead (D-IR-7's manager set, D-LAW-8's "adds a row,
never a plugin").

**Three of the five already had their manager** — `npm`, `cargo`, `aur` — and were dulled only by the
reading. **`pixi` and `mise` genuinely were not there**, so `_manager` gains both at `time: "build"`,
and all five rows become `sharp` against `#BuilderAlt`, citing D-IR-5.

`kind:builder` itself **stays dulled**: its 19-field template vocabulary (cache mounts, detect rules,
privileged, manylinux) has no field on the manager payload. That is a separate amendment and is not
claimed here.

| file | what changed |
|---|---|
| `DESIGN.cue` | `pixi` and `mise` join `_manager` at build time |
| `DESIGN.md` | the os-repository example declares a pixi and a mise manager build in a box of their own |
| `design/dulling.tsv` | the five builder rows become `sharp`, citing `#BuilderAlt` and D-IR-5 |
