**Git reads a path argument as a PATHSEC, not as a path.** A name carrying a glob character matches SEVERAL paths; a name BEGINNING with `:` is pathspec MAGIC that matches NOTHING. Both misreads are SILENT — the command exits 0 — so a reader that is wrong cannot be told apart from a reader that is right. Measured (git 2.56.0) on a fixture whose submodule path is `a*b`, beside a sibling `a!b`:

```
$ git ls-files -s -- 'a*b'
160000 4e2bf410ed595c9d7f7f4ccf22dd4686c99444cf 0	a!b
160000 a5c31bd9bcb56525be13217fd376b229aafb50d4 0	a*b
$ git ls-files -s -- ':(literal)a*b'
160000 a5c31bd9bcb56525be13217fd376b229aafb50d4 0	a*b
$ git ls-files -s -- ':colonpath'
exit=0
$ git submodule status -- 'a*b'
-4e2bf410ed595c9d7f7f4ccf22dd4686c99444cf a!b
-a5c31bd9bcb56525be13217fd376b229aafb50d4 a*b
$ git submodule status -- ':(literal)a*b'
-a5c31bd9bcb56525be13217fd376b229aafb50d4 a*b
```

The two halves belong to DIFFERENT commands: the index readers (`ls-files`, `ls-tree`) are exposed to the colon half, the submodule readers (`status`, `update`) to the glob half — so a reader that fixes only one of them is still wrong.

**The fix: ONE definition, and every path argument goes out through it.** The read form and the exclude form are the same magic with and without the exclusion, so the two cannot drift:

```
$ grep -n "pathspec_for" scripts/init-submodules.sh
445:pathspec_for() {
457:  git -C "$ROOT" ls-files -s -- "$(pathspec_for literal "$1")" | awk '$1 == "160000" {print $2; exit}'
468:  git -C "$ROOT" submodule status -- "$(pathspec_for literal "$1")" 2>/dev/null | head -1 | cut -c1
609:    specs+=("$(pathspec_for literal "$path")")
659:    exclude+=("$(pathspec_for exclude,literal "$p")")
707:    git -C "$ROOT" -c protocol.version=2 submodule update --init --filter=blob:none -- "$(pathspec_for literal "$path")"
```

**`:(literal)` is measured safe for this tree.** It PRESERVES directory descent — `:(literal)box` still reaches `box/cachyos` — so the umbrella's directory-shaped pin paths are unaffected; and a path that does not exist still fails loud (rc=1), because the magic is PARSED, not literalized.

**Reachability, stated honestly: the defect was LATENT, not live.** The umbrella's declared submodule set carries neither form, and `git submodule add` refuses a colon-prefixed path, so no live path was misread today. The readers are generic over any path, and the path set is a file the repo's own maintainers edit; `git submodule add` DOES accept a glob-named path, so the glob half is reachable through git's own command.

**The arms.** Two new self-test claims drive the readers with the two misread forms. Their oracle is the fixture's KNOWN sha, not a read through the helper under test, so an arm stays discriminating even when the helper itself is wrong. The glob fixture's checkout is put BEHIND its recorded gitlink on purpose: a checkout that materializes lands AT its pin, and an advance of a checkout that is already there returns early — so without that, the fourth site the fix touches would never be reached.

*Corrected after the merge — the first version of this fence pasted one regex whose two clauses were both defective, and the pasted output could not be reproduced by the pasted command.* *Mechanism* — the regex was written in a double-quoted shell string, so `\$` reached the pattern as a BARE `$`; under git's regex (`REG_NEWLINE`) a bare `$` is an end-of-line anchor, so the whole alternation could never match, and the pasted positive control — run at the time against a pattern whose `\$` had been escaped by hand — matched on a different pattern than the one shown. Its first clause also required a variable name starting with a LETTER, so the two `-- "$1"` sites never matched, and its second clause spelled the name INSIDE the parentheses (`\(specs|exclude\)\+=`), which no line in the file has, so it was dead in both directions. *Missed control* — nothing ran a pasted command against a pasted output, and the sweep's own "no hits" result was indistinguishable from a pattern that cannot match; the positive control was the only thing that could have caught it, and it was pasted rather than re-run. *Blast radius* — this body's evidence only; the script, the arms and the gate depend on no regex. *Root fix* — the two clauses are now separate, POSIX-ERE-clean patterns that are re-run and pasted from their real output, each with a positive control that must hit (four bare sites on the pre-change commit; the mutated array site), and the array clause — which the dead clause was meant to cover — is now real and controlled. The RCA is in the successor PR's body and on this PR's thread.*
