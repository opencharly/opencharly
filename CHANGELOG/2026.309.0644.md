# 2026.309.0644 — feat(design): give a used secret its source, its destination and its choice (batch 33)

## Summary

Batch 33 of the DESIGN amendments the capability ledger records (tracked in #838). `credential:` names a
host credential file, where it lands in the venue, and whether it is optional. The design bound a secret to
the deployment and **stopped there** — the file a value comes from had no home.

A `use:` entry on the `secret` capability is **keyed by the secret's name**, and `#SecretUse` now carries:

| field | meaning |
|---|---|
| `src` | the host file the value is read from |
| `dst` | where the value lands in the venue |
| `optional` | a missing source does not fail the deployment |

`verb:credential` becomes `sharp`.

**The capability model was the blocker, not the fields.** An earlier attempt at this batch attached them to
the `use:` shape without the name key, and the examples gate rejected it twice — `#CapabilityRow.use` is
*"its need entry's fields, and a `default`"*, and a `use:` entry is `{[name]: shape}`. The correct authored
form is `use: {secret: {<name>: {src, dst, optional}}}`.

| file | what changed |
|---|---|
| `DESIGN.cue` | the `secret` capability's `use` shape is `#SecretUse`; `#SecretUse` is new |
| `DESIGN.md` | the host-need example gains a `lab-signing` node using a host key |
| `design/dulling.tsv` | `verb:credential` becomes sharp |
| `design/dulling-disposition.md` | regenerated |
