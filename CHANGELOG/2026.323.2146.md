One watcher start and one wake in 20 s are correct; a binding that re-arms a state-event item starts the watcher every few seconds. Starts are counted by one line after the shebang of the scratch copy of `cli.ts`. The local server is deleted. Skips visibly without a GitHub credential.
2. **`check-gh-tools.mjs` layer E (`LIVE_OPENCODE`).** `coord_watch` reads the same real merged PR; `coord_comment` runs as a DRY RUN — a gate never posts a real comment, and a dry run is a real call that does not write, not a fake. Two defects meant this layer had **never** proved the tool path — every run skipped "the model did not invoke …", on #1160 and since:
   - a custom "test runner" agent made the model call no tool at all; the layer now uses the default agent with a plain request;
   - `opencode` takes its project directory from `PWD`, not from the process cwd, so with the gate's own `PWD` inherited the binding read the umbrella's `.opencode/` and never saw the throwaway project's `coord.conf` (the tool refused for missing identity). The spawn now passes `PWD`.
   An invoked tool with a wrong result now FAILS, kept apart from a model that never called it (SKIP), by the model's own `execute` trace.
3. **A watch deadline holds at the poll floor** (`scripts/gh/lib/watch.ts`). The watch slept a full poll interval before it checked its deadline, so at the 300 s floor `--timeout 60` waited 300 s — which is why layer E could not see a broken engine (its `opencode` call was killed at 240 s, before printing anything). It never sleeps past the deadline now. The gate's timeout tests run at a 1 s interval and could not see this; a new assertion runs at the real floor.

4. **Round 2 — `check-pin-verb-scope.mjs` reads a list item past its blank lines.** While this PR waited, opencharly/opencharly#1189 rewrote the repo-setup checklist; its pin-advance step became step 6, with a code fence and a second paragraph that carries the scope sentence ("advances every pin the umbrella declares"). The gate anchored on the old step 5, and its extractor ended every surface at the first blank line, so `charly task verify` on `main` failed two steps ("the surface is GONE"). The prose is right; the gate was not. The surface is re-anchored on step 6, and a list item now continues past a blank line when the next line is indented into the item (Markdown), ending at an unindented line — with a self-test arm for both directions. #1189's session is told on its PR.

**Left deterministic, and why.** `check-gh-tools.mjs` layers B and C still drive the CLI and the OpenCode binding against a local server. They do not claim to be live: they assert the exit-code and wake-line contract for states real GitHub cannot be made to produce on demand — a 429, a 500, a lock takeover, a conflict that appears after arm. The live proof of the same code is layer E above, and the CLI's own live use on real PRs (opencharly/opencharly#1145, #1160; the #628 re-run proof on opencharly/marketplace#630).
