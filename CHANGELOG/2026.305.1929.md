# 2026.305.1929 — docs(agents): a disarmed-but-active goal is a broken REARM, not a consent question

## Summary

`AGENTS.md` Part II #10 sized a goal's round budget and told an agent to stop and ask
the operator at ~80%, naming the hard `round-limit` disarm — but said nothing about the
state that actually misleads: a goal that still READS `active` while its continuation
has already been disarmed.

This adds that missing sentence: **a disarmed-but-active goal means the REARM is broken —
say so; do not ask the operator for a word.** It carries the mechanism, so a future reader
can check it rather than take it on faith: activation is process-local and never persisted
(`@deepseek-ai/dsh-goal/README.md:99`), and positive rounds advance only on goal-sourced
`user/message` events (`:100`) — the same event the org plugin's re-arm seam keys on. An
`active` goal whose continuation was armed but which reads `disarmed` is therefore a defect
in the re-arm, not a request for consent.

**This prose was recovered, not authored fresh.** It existed only as a staged change in the
`retention` session worktree (`docs/agents-rule10-rearm-counterline`, a branch already landed
as an ancestor of `main`) — on no branch and not on `main`. This session's branch/worktree
cleanup would otherwise have discarded it. The pre-edit patch is preserved at
`.dsh/preserved/retention-AGENTS.patch`.
