# 2026.251.0744 — fix(pr-status watch): wait for the merge after PASS; umbrella dispatcher: concurrency dedupe per PR

## Summary

Real fixes, not guidance notes:

1. **`.pi/extensions/github-pr-status.ts` — `watch` mode now waits for the merge.** The old `concluded` gate returned the snapshot the moment a run concluded, so a PASS on an open PR returned immediately instead of polling until the armed auto-merge completed (the #38 pain: PASS != merged). New `watchDone` semantics: terminal on a FAILED run (BLOCK) or on the PR leaving `open` — a PASS keeps polling until merge/close or timeout.
2. **The umbrella's own `pr-validator` dispatcher gains the per-PR `concurrency` dedupe** (`cancel-in-progress: true`, group keyed by repo + pr-number) — a re-dispatch or push cancels the in-flight run, so the head can never carry duplicate same-name `validate / validate` check runs again (a duplicate FAILED run kept `mergeable_state: blocked` despite PASS — measured). The same dedupe lands in the reusable org workflow + install-source dispatcher (opencharly/.github, T4-clean: no escalation) and was applied to eval-omarchy's + pi-omarchy-eval's copies.
