## Summary

The rulebook never said **when** a requested maintainer sign-off, or a PR-body fix a verdict asks for, must be in place, nor **how** a sign-off is made. So a PR could be pushed or re-run while the sign-off was still missing, and the run could only BLOCK again. That happened on opencharly/opencharly#448 and opencharly/layer-charly-internals-extra#16 (opencharly/opencharly#451).

`AGENTS.md` changes:
- **"Before every update push"** now covers validator re-runs as well as pushes. New step 6: everything the verdict asks for is in place BEFORE the next push or re-run, meaning a requested T4 sign-off comment and every PR-body change. Then push or re-run exactly once. One BLOCK that requests a sign-off is expected; a second run with it still missing is a violation.
- **Part II #7.** A sign-off is a PR comment from a maintainer-set account. Either the operator writes it, or an agent writes it at the operator's explicit direction and says so. An agent never posts one on its own initiative, and the comment is posted before the next push or re-run.

The validator's T4 gate is unchanged. The same guidance lands in `/charly-internals:git-workflow` in the sibling leg opencharly/layer-charly-internals#106.
