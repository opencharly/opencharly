# 2026.268.1355 — fix(sync): restore honest sync evidence + ignore root local state

## Summary

Two umbrella-owned defects, both surfaced while catching up with upstream and
both root-caused (R1) rather than worked around.

### 1. The sync PR body's per-pin evidence was structurally dead

The Taskfile→task cutover (#247) deleted `scripts/sync-gitlinks.sh`, whose log
carried the per-pin `  <path> -> <sha>` lines that `scripts/sync-pr-body.sh`
grepped. The replacement composer `verb:git-submodules bump` returns only a
one-line summary (`bumped N submodule pin(s): …`), **and** `charly task`'s text
reporter drops a passing step's own `Result.Message` — so the log carries no
per-pin line at all. The body builder's `grep -F "  ${p} -> "` therefore matched
nothing and emitted `MISSING from producer log — investigate` for **every** moved
pin.

Measured with the real post-cutover producer shape:

```
$ printf 'dotgithub\ncharly\n' > /tmp/moved.txt
$ cat /tmp/producer.log
task sync: 1 step(s), 0 failed
  [pass] run — bump the pins (charly rolls first, then distro-* from its new gitlinks)
$ SYNC_EVIDENCE_OUT=/tmp/ev.txt bash scripts/sync-pr-body.sh "$PWD" \
    /tmp/moved.txt /tmp/producer.log /tmp/pblog.txt /tmp/body.md /tmp/ev.txt
$ sed -n '/What produced this diff/,/^```$/p' /tmp/body.md
  dotgithub -> (MISSING from producer log — investigate)
  charly -> (MISSING from producer log — investigate)
```

The `--self-test` could not catch this: it fed only the retired `->` form, so it
passed against an input reality no longer produces (a test that cannot fail).

**Root fix:** stop coupling the body builder to any incidental producer-log
format. The authoritative per-pin proof is already the index-derived
`staged-gitlink` vs remote default-branch `HEAD` table
(`scripts/sync-pin-evidence.sh`); the producer log is now pasted **verbatim** as
context, bounded inside the function. The bound is applied with `sed -n` rather
than a caller-side `head`, because this harness ignores SIGPIPE (AGENTS.md
"Command hygiene") and a `head` reader would let the producer flood the log with
broken-pipe write errors.

The self-test now exercises **both** historical producer shapes and asserts the
excerpt is verbatim (no injected `MISSING`).

```
$ bash scripts/sync-pr-body.sh --self-test
sync-pr-body: self-test OK (393-pin body under the 65536 cap with the true total + hint;
artifact carries all rows; small input no hint; the producer excerpt is verbatim for BOTH
the retired per-pin and current summary shapes; over-cap trips the hard guard)
```

### 2. The root `.gitignore` omitted the local-state classes the umbrella produces

`charly task verify` does **not** check the root tree (it asserts each
*submodule's* cleanliness), so this is about an honest root `git status`, not a
gate — no false claim.

## Surfaced product defect — routed to its named owning PR

The investigation also proved a product defect in `opencharly/plugin-task`: its
`command:task` text reporter prints only each step's authored `Text`, never
`Result.Message`, so a passing `run:` step's output is discarded and a failing
step's diagnostic is invisible. That is why `charly task map` prints no map and a
real `sync` failure printed no reason (the swallowed `index.lock` cause this
session hit).

This defect is fixed by PR **opencharly/plugin-task#5**
(`fix(cli): render a step's Result.Message in text mode`), already open with its
own R10 (proved RED on the pre-fix reporter, green with the fix). It is not a
submodule of this umbrella (rule 1 forbids editing it here), and this umbrella
change has an explicit exit that does not depend on it: the body's per-pin proof
is the index-derived table, and the producer log is pasted regardless of content.
This is a routed, named cutover — not a deferred follow-up.
