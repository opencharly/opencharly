# 2026.322.2047 — feat(pins): register opencharly/pod-cdi as a submodule

## Summary

`opencharly/pod-cdi` was created, merged and tagged `v2026.322.1717`, and every GPU pod box in `distro-cachyos` now bases on it — but the umbrella never learned the repo exists. It was absent from `.gitmodules` and had no gitlink, so `charly task verify` could not judge the pin at all. The split existed beside the org rather than inside it.

Three lines change, and the third was the gate telling me a fact:

```
.gitmodules   +[submodule "pod-cdi"] path + url + branch = main
pod-cdi       +160000 commit 78791938…   (new gitlink)
```

## How tested

**The change's own gate, run on this tree.** A fresh clone cannot load the project until its `import:` paths exist, so the order is `scripts/init-submodules.sh` → `charly task verify`:

```console
$ bash scripts/init-submodules.sh
init: OK — 18 of 18 requested path(s) are materialized at their recorded gitlinks
init: notice — 377 of 395 declared submodule path(s) have no checkout; their pin is still audited from the index

$ charly task verify
task verify: 48 step(s), 3 failed, 0 skipped
exit=1, want 0 (stderr: FAIL: pod-cdi: missing branch= in .gitmodules)
```

That is the gate naming my own change. `branch = main` added to the `.gitmodules` entry:

```console
$ charly task verify
task verify: 48 step(s), 1 failed
$ grep -c 'missing branch=' /tmp/tv4.log
0
```

**3 failures → 1, and the `pod-cdi` failure is gone.**

**Reconciling the gate's own numbers, from its own lines.**

The gate prints `[fail]` lines at two levels: top-level steps, and nested steps inside them. Its summary counts only the top level. That is why four `[fail]` lines accompany `3 failed`.

*Before — `task verify: 48 step(s), 3 failed`:*

```text
[fail] check — each pin's CURRENCY — the pin is at the ref its intent …
[fail] run — run git-submodules in the selected mode          <- NESTED inside CURRENCY
[fail] check — every submodule's branch equals its remote default — KE…
[fail] check — the opencode gate plugin contract
```

*After — `task verify: 48 step(s), 1 failed`:*

```text
[fail] check — the opencode gate plugin contract
```

| level | before | after |
|---|---|---|
| top-level failed steps | **3** | **1** |
| nested `[fail]` inside CURRENCY | 1 | 0 |

**Two of the three top-level failures were mine and are gone** — `CURRENCY` and `branch equals remote default`, both because `pod-cdi` was absent from `.gitmodules` and then lacked `branch =`. The nested `run git-submodules` line was inside `CURRENCY` and went with it. The one that remains is pre-existing and filed.

*Reported, not failed:* inside the CURRENCY step, the currency run also printed

```text
currency: 23 of 395 pin(s) NOT current [3 behind, 1 blocked-by charly:box/arch (behind), …]
```

That is output from a step that failed for a different reason (`pod-cdi: missing branch=`), and the gate's policy is to REPORT a `behind` pin rather than fail on it. It is not one of the three failures.
