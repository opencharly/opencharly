# 2026.296.1445 — docs(agents): the umbrella's rulebook states a wave's index-lock rule

## Summary

Head `7bf489b903621e1dd1caed1d1f40158e402f909b` — 1 file, +11 −1.

A pin wave holds the umbrella worktree's **index** for the minutes it rolls the submodules. The wave stages each advanced path with a `git add` in the superproject, and that `git add` takes the worktree's index lock; a concurrent `git status` in the SAME worktree takes that lock for an instant, so the wave's own `git add` can lose the race. A wave that loses the race names every path it could not STAGE, and whether that cost a PIN VALUE is a second question — the path may have been at the ref it already serves. So **while a wave runs, run no other git command in that worktree**; and after it, ask the currency question, which names every pin that is not at the ref its intent names.

That race is measured, not hypothetical: on 2026-10-23 an umbrella wave's staging lost the index lock to a concurrent `git status` in its own worktree, and three pins were named unstaged. The RCA and its evidence are the filed issue's own body (opencharly/layer-charly-internals#137).

The producer's half of this rule is already merged and carries the mechanism: opencharly/layer-charly-internals#138 landed the paragraph in `.agents/skills/git-workflow/references/umbrella-mechanics.md`, merged as `61f67965b70f6fb9b4a02ae92a5cce5bafdce8eb` and tagged `v2026.296.0940`. This PR carries the **umbrella's** half — the rule in the umbrella's own rulebook, in Part II #3, where the pin wave is described. The umbrella's rulebook is where an agent working in the umbrella reads what a wave is; the producer's file is the detail the rule points at.
