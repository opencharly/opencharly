## Summary

Head `0726ea5e3112ebbe3157f5552b61093a049b1486` — the commit this PR pushes: **3 files changed, 252 insertions(+), 7 deletions(-)**.

**The umbrella's own gate now runs the governance reconcile in its STRONG form.** The reconcile checker lives in the pinned `dotgithub` checkout, and the `.github` repo's CI runs it in the CI form — against its OWN checkout, where every sibling-repo row SKIPS. The strong form (`--root <the umbrella>`) is the only form that asserts the cross-repo rows, and the umbrella is the one checkout that carries the sibling repos. The umbrella's gate never ran it, so a surface that moved out of a sibling repo was invisible: by hand, in CI, and in every automated run (opencharly/opencharly#674).

**The gate is a script, not an inline step, and that is the load-bearing part.** `scripts/init-submodules.sh` derives the light tree's working set from four committed sources, and source 4 is *"a path in a string literal that is CODE (not a comment) under `scripts/`"*. A path named only in `charly.yml`'s step text is invisible to that derivation — so `dotgithub` would never join the derived working set, the step would SKIP on every light tree, and the control would be exactly as invisible as it is today under a name that promises otherwise. The gate names the path in exactly one code string literal, and the derived working set now carries the repo the gate reads.

**What the gate does, and what it does not do.** It INVOKES the pinned checker — the checker, the claims manifest and the stale-pointer control stay in the repo that owns them, and this script copies none of that logic (R2), so the control's own fixes land in their own repo and arrive here with the pin. It resolves the checkout root from its own location, propagates the checker's exit status, and reports a **visible** SKIP when the checkout does not carry the reconcile at all.

**The finding this change raises.** The strong form now runs, and it says plainly what it can and cannot see: `checked=62 skipped=19 fail=0`. The 19 skips are the manifest's *skill-source* rows, and they skip because the repos they name are not in the umbrella's tree at all — 17 of them name `layer-charly-internals`, which the org **archived** when the skills moved into the umbrella's own `.agents/skills/…` trees. A row whose owner repo is not carried is a shape #246's stale-pointer control cannot see: that control fires when the owner IS materialized and the FILE is absent. Filed as opencharly/.github#257, with the measured root fix.
