## Summary

#616 made each *concept* in DESIGN.cue generic. This PR makes its *shapes* generic. Every definition is now one shape of a closed grammar (§3.1, **S1–S11**), named by one scheme (**D-NAME-2/3/4**), with exactly one Go mapping (§6, **C1–C7**, **D-GEN-7/8**). A new design-check control (check 8, "grammar") enforces all three. Scope is DESIGN.md, DESIGN.cue, `design/` and the design scripts; no product code changes.

### Shapes (§3.1)

| Shape | Form | What it replaced |
|---|---|---|
| S3 vocabulary table | `_x: {word: {row}} @vocab(owner)`; `_xWord` always derived | every hand-written word list, `_managerPhase`, every inline enum of 3+ words (55 tables now) |
| S4 key-tagged union | `#XAlt` → `#X: or([for _, a in #XAlt {a}])`, one spelling | — |
| S6 fragment | `#XFields`, composed by spread (`{#XFields..., f: …}`) | duplicated retry, presence, secret and check fields |
| S11 typed row table | `#XRow` + `_x: [#Word]: #XRow` + derived shapes; a row's shape slot holds a named definition, scalar, word union or `{}` | `#NeedType`/`#ProvideType`, `_driverWord`, `#ResourceAlt`, `#MethodIO`/`#HostMethodIO`, the store method pairs, five admission tables |

Tables that now carry data the prose used to hold:
- **`_driver`.** One typed driver table for every pluggable subsystem (`pod`, `vm`, `kubernetes`, `agent`, `secret`): `form`, `access`, `capture`, `grant`, `tool`, `default`. Exactly one default per subsystem is enforced in CUE (`_subsystemDefaultDriver`). An empty `#UserConfig` resolves to every subsystem's default. Agent runtimes and secret backends are driver rows; `secret_backend` is gone.
- **`_capability`.** One capability table. `#Need`, `#Provide` and `#Resource` are derived from it. `exclusive` exists only on leasable rows, and `any` is a row of `_gpu`, so D-VAL-14 moved from prose into the schema and its §5.4 row is deleted. Sizing is a need: `cpu: core`, `memory: ram|shm`, `storage`.
- **`_deploymentKind`.** One row per kind (`create`, `connect`, `top`, `admit`, `beside`, `content`). Every body, inner table, beside table and `#KindAlt` member is derived from these rows. `#TopLocal`, `#InnerLocal`, `#CreatedKubernetesNode`, `#AgentBody` and `#MachineOnly` are deleted. D-NEST-7 merges into D-NEST-6 (an inner node admits only `create`). A kind with no top placement or no admitted inner node has no such entry (no `or([])`), so the `agent` kind cannot stand at the top level or hold a node.
- **`#VenueAlt`.** One venue table for authored `connect:` and the resolved `#VenueOutput` (`access`, `via`). `#Hostname` no longer takes a port; `#Address` is `host:port`.
- **`_method` / `_hostMethod`.** Each method is a row `{role, input, output, stream}`. `start`/`stop`/`destroy` are one `transition: {to}` over the `target` rows of `_state`, and `stream` moved from prose into the row. D-PROTO-10 names no method itself; the streaming methods are listed in a table marked `_streamMethodWord _streamHostMethodWord` (D2 derivations of the rows), so check 1 compares the prose with the rows: `realize`, `capture`, `restore`, `log`, `run` and the host's `venue_exec`.
- **`_store`.** One store table: each row (`content`, `state`, `secret`, `config`) gives its `key`, its `value`, whether it is `addressed` by its digest, and whether a plugin may `put` it. `#StoreKey`, `#StoreValue` (the `get` output, keyed by store, so a `state` record and the `config` section come back structured) and `#PutInput` are derived from it. `config` is read-only, and `content` takes no key. An atomic `state_commit` record carries the `state` row's value (`#StateRecord.value: _store.state.value`, S10 `#Opaque`), so `put` and the commit cannot drift apart.
- **Verbs and steps.** Fact and protocol verbs are tag tables. Steps are keyed by intent (`run`, `check`, `harness_check`, `harness_run`), and a check composes `#CheckFields` with exactly one verb. Matchers gain `not` and `json`; `not_contains` and `not_matches` are deleted. Fact verbs share `#PresenceFields`, and the http `header` is keyed by `#HeaderName`. There is one `retry` model, one `concurrency` field, and `on:` says where a check runs.
- **Parameters.** One `#Parameter` for candies and pipelines; `#CandyParameter` requires `choice`.
- **Binary data.** `#Base64` is used for binary data on the JSON wire.

### Naming (D-NAME-2/3/4, the operator's decision)

- **Who chose the name decides its case.** Schema words are snake_case (`#Word`), user names are kebab-case (`#Name`), and the two cannot collide.
- **An external identifier is a row value, never a word.** Examples: `native`, a driver's `tool`, a device's `/dev` path.
- **Definition suffixes form a closed set:** `Alt`, `Fields`, `Row`, `Set`, `Check`, `Input`/`Output`, plus `_x`/`_xWord`/`_#X`. The retired suffixes are `Body`, `Only`, `Type`, `IO`, `Entry`, `Attr`, `Reply`, `Info` and `Spec`.
- **Eleven collisions resolved:**

| Word | Meaning | New name |
|---|---|---|
| `command` | plugin role | `subcommand` |
| `input` | candy input | `parameter` |
| `spec`, `answer`, `argument` | S10 payloads | `config` |
| `operation` | venue capability | `access` |
| `operation` | audit field | `action` |
| `kind` | audit class | `event` |
| `detail` | status text | `message` |
| `engine_api` | any driver's API | `driver_api` |
| `scope` | capture scope | `capture` |
| `namespace` | external (kube/container) field | typed `#Label` |

### Generation (§6, D-GEN-7/8)

Every shape has exactly one Go mapping:
- a vocabulary table → a typed word with `Valid()` (constants when `core`-owned);
- a tag table → a one-of struct (homogeneous) or `X<Tag>` arm structs (heterogeneous), with an exactly-one decoder;
- a method table → per-role interfaces and typed clients and servers, with stream types;
- a derived shape → generated from its rows (C7);
- `#Opaque` → `json.RawMessage`, `#Base64` → `[]byte`.

Every list comprehension is one of six derivation forms (**D-GEN-8**):
- **D1** the word list of a table;
- **D2** a named subset of its rows;
- **D3** a named grouping of its rows by another table (`_subsystemDriver`, `_roleMethod`);
- **D4** a tag-table union;
- **D5** a union over a named word list, whose default must be a row;
- **D6** inside a row-derived definition, the union one row selects (`_#Placed[k][p]`).

A filter is always named, never written inline. Defaults live only in CUE. DESIGN.cue carries **no `@go(` attribute**. The generator is charly's own, built on the CUE Go API. `cue exp gengotypes` cannot express key-tagged unions, enums or keyed collections. A throw-away spike on `cuelang.org/go v0.18.0-rc.1` emitted C3/C4/C5 Go from DESIGN.cue-shaped CUE that passes `go vet` and `go build` (below). Building the real generator is filed as opencharly/spec#271.

### Toolchain: CUE v0.18.0-rc.1, language v0.18.0

- **The pin.** `scripts/design-cue.sh` pins `v0.18.0-rc.1` with the four published release digests, and uses no other version. The generated check module declares language `v0.18.0`. Strict embedding means a fragment composed with fields is spelled `{#F..., f: …}`.
- **A defect, worked around openly.** Under structure sharing, CUE v0.18.0-alpha.3 and rc.1 keep a closed union arm viable in the example loader ("incomplete value A | B"). It happens only when the same data is referenced from several loader fields. The loader's four `cue` calls, and only those, run with `CUE_DEBUG=sharing=false` (`loader_cue` in `scripts/design-examples.sh`, with the measured rationale in a comment and in Appendix A.5). Scoping it to the loader keeps the consistency check at 6–9 s instead of 123 s. This is the operator's decision. The operator also chose not to file it upstream.
- **Functions not adopted.** The CUE functions experiment did not finish evaluating this schema in over 5 minutes, against 0.02 s for the equivalent comprehensions. The schema uses the canonical comprehension spellings, and check 8 enforces them.

### Design calls flagged for review

- Sizing as needs: `cpu`, `memory`, `storage` are leased capacity, not machine fields.
- One host store API (`get`/`put`).
- `transition` replaces `start`/`stop`/`destroy`.
- Drivers are keyed by subsystem, with secret backends and agent runtimes among them.
- The plugin role `command` → `subcommand`.
- User-visible snake_case renames: `kernel_param`, `harness_check`, `on_failure`, `secret_service`, ….
- The project-owned generator.
- `#Base64` for binary data on the JSON wire.
- The builder payloads `#BuilderBootstrap{command!, box?}` and `#BuilderManager{name!, box!}`.

### Checks and coverage

- **Check 8, "grammar"** (`scripts/design-consistency.sh`) enforces:
  - no hand-written word list;
  - every list comprehension is one of D1–D6: the check strips each form where it may stand and fails on whatever is left;
  - no word written beside a word union, and every default word is a row of its table;
  - no inline enum of 3+ words;
  - no `@go(`;
  - no retired suffix;
  - every table carries `@vocab` with a §7.1 owner;
  - snake_case schema words;
  - no inline struct with named fields besides its S4 tag, at any depth (C1);
  - no row writes an inline struct into a shape slot (S11).

  It has fifteen self-test rows.
- **Loader and rules.** The loader (`design/example/load.cue`) and `rules.cue` read every placement table from the `_deploymentKind` rows. The design scripts use no piped `head`. A check is unified only with the verb arm it names.
- **Negatives.** 18 negatives were re-targeted, and `venue-no-operation` is renamed to `venue-no-access`. 16 new cases cover `exclusive` on a non-leasable need, the removed fields, a venue the kind does not admit, a candy parameter without `choice`, an unknown transition state, a kebab-case schema word, a snake_case node name, a `put` to the read-only `config` store, a base64 field in a `state_commit` record, and an `agent` at the top level or holding a node. There are 102 in total, up from 86.
- **Parity.** `design/parity.tsv` has 17 home cells remapped; `verb:kernel-param` is now `renamed`. 208/208 provider words are still mapped.
