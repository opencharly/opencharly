# 2026.242.1021 — feat(pi): autodetect and break behavioral-rut loops in loop-guard

## Summary

The pi loop-guard extension (`.pi/extensions/loop-guard.ts`) only blocked **exact re-issues of calls from truncated responses** (assistant `stopReason: "length"`). The 2026-08-30 second loop incident was a different class: a **behavioral rut** — the same *successful* tool call (`sed -n "752,788p"` / `sed -n "1044,1091p"` on the same file) re-issued 8+ times because each truncated response made the model re-run the same diagnostic to "recover" context instead of producing the deliverable. Those calls succeeded, so the truncation detector never fired.

This change:
1. **Adds a behavioral-rut detector** to `loop-guard.ts`: a per-call (tool, serialized-args) repeat counter; the Nth identical call (N>=3) is blocked with a directive to change approach and delegate to a subagent. The block is not reset, so the model must change approach to proceed.
2. **Documents the autodetect protocol** in `.pi/APPEND_SYSTEM.md`: the three loop signals (repeated output-token-limit rejections, repeated identical tool calls, re-reading the same data) and the mandatory break response (never re-issue; delegate to a subagent; produce the deliverable).
