One design cutover of `DESIGN.md` / `DESIGN.cue`, decided with the operator item by item on #675:

- **Plugin-first.** Part I is now the plugin architecture: §3 core/sdk/spec/plugins, §4 the contract, a new §5 *How plugins interact* (the four channels; apis; D-API-1/2), a new §6 *Building a plugin*, §7 declaring plugins, §8 capabilities, §9 host capabilities. Part II is the schema foundation, Part III what authors write, Part IV the runtime. Every `§` reference is remapped through one old→new table: in `DESIGN.md`, `DESIGN.cue`, `design/`, the design scripts, `design/parity.tsv`, and, per the operator, `TODO.md` (references only, no content change). `design-consistency.sh` now finds its sections by title, not by number.
- **One capability interface.** A node relates to a capability by one of three keys, with one entry shape per type: `provide:` sets it, `need:` says it MUST be set, `use:` says it CAN be set, with `default:` where the type has a value.
  - The generic `optional` attribute is removed, and §1.1's generic-attribute paragraph is amended to match.
  - Each capability row now carries a `use:` slot; `#Use` is derived like `#Need`.
  - `gpu: {}` is any GPU (D-HW-9), and the `any` vendor word is removed.
  - `parameter:`/`with:` become the `parameter` capability type: for a candy it's a bounded choice that must carry `one_of` (D-SCH-7), for a pipeline any text.
  - A candy's content `env:` and a deployment's former `with:` become `provide:`.
  - New: D-CAP-6 (need wins over use in a union), D-VAL-14 (a name under `need:` and `use:` at once is an error).
- **Three check phases, named by what is observed.**
  - `artifact`: the built artifact, in an instance that runs nothing.
  - `ready`: the deployment's readiness condition.
  - `deployment`: once the deployment is ready.

  Each verb arm in the verb tables declares the phases it observes (`#ArtifactPhase`, `#DeploymentPhase`, D-VERB-7). A `run` step has no phase. A deployment's and a pipeline stage's checks are deployment checks. `any`, `build` and `runtime` are removed. A new §16.5 specifies all three.
- **No check beds in DESIGN.md.** Removed: the `bed` term, the per-kind cycle table and the pipeline `bed` stage (now a `deployment` stage). `disposable`/`preemptible` are stated generically. AGENTS.md R10 now names the check bed and its real cycle, the one `/charly-check:check` already documents in `references/beds-and-r10.md`. The planned producer leg, opencharly/layer-charly-check#51, was closed: the skill already documents the real cycle, and the DESIGN table was an unimplemented target, which the operator decided to drop.
- **Terms.** The package manager's "phase" is renamed its "time" (`_managerTime`), so "phase" means only the check phase. API names in examples are snake_case words (`image_load`), per D-NAME-2.
- **Examples.** They use Arch (a new `arch-image` source) and CachyOS. Omarchy is removed. The §19 version example stays Fedora 43, as the operator excepted.
- **Design scripts.** They run in the repository root and write nothing. The planted-defect self-test is deleted (`scripts/design-selftest.sh`, both `selftest.tsv` tables), so the per-row umbrella copy #668 measured is gone. The committed negative cases prove each check can fail; six are new or rewritten for this model.
