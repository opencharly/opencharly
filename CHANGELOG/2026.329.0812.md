# 2026.329.0812 — docs(strict-policy): a diagnostic is an instrument, prove it observes

## Summary

Adds a section to `/charly-internals:strict-policy` capturing the most expensive discipline failure of a long session: **an instrument that measures nothing reports the same output as a system that does nothing.**

Two shapes, both measured:

- **A silent instrument reads as a silent system.** A trace file carried zero events and was read as "the element received nothing" — the image actually carried no instrumentation at all, because the branch was the fix branch and the trace belonged to a diagnostic one.
- **The probe never ran.** A step the runner drops (an unsupported field on a `run:` step), a binary absent from the in-container PATH (`/usr/sbin` is not on it), a verb used in a stage where the endpoint does not resolve (`cdp:` needs the `browser` stage), or — the one that cost six runs — **a step whose venue is its TREE POSITION**, placed in the wrong member of a multi-member bed and measuring the other container.

The procedure it prescribes: copy a working instrument rather than compose one from schema (`stdout:` is a sibling of `cdp:`, never a child; `run:` steps carry no assertions); check the tool exists in the target image first (`podman run … command -v`, ten seconds against a fifteen-minute bed run); make the value impossible to miss by failing on a sentinel so it lands in the summary's `reason` (and respect the ~200-character truncation); add an A/B control; and report the instrument's failure **as the instrument's failure**, because dressing a malformed probe up as a product finding poisons every conclusion after it.
