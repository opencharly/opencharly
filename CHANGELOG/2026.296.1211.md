# 2026.296.1211 — feat(gates)!: a count of a collection that grows must be derived or dated

## Summary

Head `95e91f5e5f05930578a72d8593f9068211f83169`, **9 files, +506 −59** — the umbrella's prose no longer states the size of a
collection that GROWS as a bare number, and a new "C" family in the EXISTING measurement gate
makes that a standing rule instead of a one-time edit.

**The branch carries a merge of `origin/main`.** The ruleset's strict status check requires the
branch to be up to date with `main` before it merges, and `main` advanced by two commits after
this branch's round-1 push — the retirement of seventeen skills-only carriers, which also drops
the umbrella's submodule count. The branch is brought forward with a **merge**, not a rebase: the
published history is not rewritten, and the diff this PR publishes is the same nine files either
way.

**The finding.** The umbrella's own prose stated the size of the org's shape over and over:
`425 submodules`, `430 remotes`, `1 of 424 paths`, `423 of 425 modules`, `402 pins`, `424 paths`,
`393 pins`, `200 path rows`. Each was a figure recorded once, on a tree that has since grown.
Two are already wrong — the umbrella has 412 submodules today, so `425` is stale in three
places — and nothing in the tree said so.

**The mechanism.** The count was recorded to make a claim concrete, and afterwards nobody could
remove it without losing the claim. But a count of a growing collection is not a measurement: it
is a claim about a moving target, and it decays silently — the org gains a repo, the corpus
grows, the refresh advances a pin, and the sentence is simply wrong. The tell is that the two
figures in the same file did not agree with each other: a real measurement is reproducible, a
remembered one is not.

**The rule.** A count of a collection that grows is only allowed to be **DERIVED** (read from
the collection itself at run time) or **DATED** (a point figure of one measurement, carrying the
day it was taken). A new "C" family in `scripts/check-readme-measurements.mjs` enforces it: a
count of at least ten of a fleet noun — submodules, pins, paths, modules, remotes, worktrees,
calls — is a **finding** unless the block that states it carries an ISO date, is rounded (`~N`),
is a cap ("at most N"), or is a floor ("N+").

**What the family reads.** The surfaces are **DERIVED**, never hand-listed: a list of files is
itself a claim about a collection that grows. The set is the **tracked FILE SET** (`git ls-files`
minus gitlinks — another repo's tree — minus `CHANGELOG/`, which is history and may name the
legacy form, minus symlinks, which are projections of another repo). A file with no extension is
a surface; a file that quotes a string is a surface, and a line that states a count is a
sentence whether or not it is a comment. Markdown emphasis and code spans are stripped before
the match, because a count wrapped in them is the same count. In a YAML file a count is dated by
the date in its **own** scope — the innermost indentation scope that holds it — and not by a date
somewhere else in a top-level key's subtree.
