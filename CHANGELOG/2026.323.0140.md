## Summary

**Successor to `#1144`**, itself the successor to `#1138`,, which auto-closed at the five-verdict threshold with its content unlanded
(`scripts/check-live-boundaries.mjs` does not exist at `origin/main`). **This PR carries the same
tree**; nothing was re-derived. **The maintainer sign-off given at the operator's explicit direction
on `#1138` applies to this identical tree**, and is re-requested below for the record.

A test that **skips and mocks the same live boundary** does neither of the two things **D-CODE-5**
(`DESIGN.md:2650` — *"Live boundaries are tested against the real service or skipped visibly"*)
permits: it does not run against the real service, and it does not skip visibly, because the mock
answers instead. **That pair is the defect this gate measures**, and it is what TODO 14.4 asks for.

**The control comes FIRST.** The first self-test arm is a test file that skips visibly and mocks
nothing — it must be GREEN, and the skip line must be PRINTED. Only once that passes do the RED arms
run. Written the other way round, the first draft fired RED on a `t.Skip` sitting inside a comment,
and the second stored one pair per file so a second skip in an already-mocking file was invisible.
**Both defects were caught by arms written before the disposition was decided** — which is the whole
argument for control-first.

**A census, not an allowlist.** `design/live-boundary-census.tsv` freezes today's population per file
with an exact count, and the gate fails three ways:

1. a pair with no census row (a NEW one, including a new file);
2. a file carrying MORE pairs than its row records;
3. **a census row whose site is GONE.**

Direction 3 is what makes a stale baseline fail loudly instead of silently freezing debt, and it is
the direction the D-CODE-2 census gate beside it also carries.

**And the gate refuses to pass blind.** An unmaterialized submodule is an **empty directory, not an
absent one**, so `git -C charly ls-tree origin/main` walks up to the umbrella, succeeds, and answers
with the umbrella's tree — which carries no test file. A naive reader gets a clean empty list and
reports OK **over zero files**. `listFiles` now checks three things and SKIPs by name on each failure
(the path exists, its git toplevel **is** that path, `origin/main` resolves in it), and **a run where
every repo skipped exits non-zero**. A green over nothing is the one result a gate must never
produce.

## How tested

### The skip path, after the review

Two defects in it were found by review and fixed in `c99a594`, and both are named here because together
they were the opposite of the PR's own claim.

**A skipped repo has no opinion about its own census rows.** `seen` is populated only from repos that
were *scanned*, so a repo where `listFiles` returned `{skip}` contributed nothing — and the STALE sweep
then flagged **every census row of that repo** as "delete the row". On a light or partial tree the gate
went RED with bogus findings, which is precisely the failure "SKIP visibly" exists to prevent. The sweep
now excludes the rows of every skipped repo.

**The all-skip guard was unreachable.** On a fully skipped tree the STALE findings fired first and
`process.exit(1)` happened at the findings check, so the message explaining *why* never printed — a
reader saw eleven "delete the row" lines and no reason. The guard now runs ahead of the findings exit.



```console
$ node scripts/check-live-boundaries.mjs --self-test
PASS arm 0 (control): a visible skip alone is GREEN and printed
PASS arm 1: a NEW pair with no census row is flagged
PASS arm 2: a second pair in a census file is RED (WIDENED)
PASS arm 3: a census row whose site is GONE is RED (STALE)
PASS arm 4: a comment-only file stays green
PASS arm 5: a missing checkout SKIPs visibly
PASS arm 6: every repo skipped reports all three and invents no STALE finding
PASS arm 7: the CLI exits non-zero over an all-skipped tree
self-test: OK (8 checks — control first, every one fails when it should)
```

What each arm proves, in order — **the control first**:

| arm | it fires when |
|---|---|
| **0 (control)** | a test file skips visibly and mocks nothing — it must stay green **and print its skip line** |
| 1 | a pair appears in a file with no census row |
| 2 | a file carries more pairs than its row records |
| 3 | a census row's site has gone |
| 4 | a file mentions a skip only in a comment |
| 5 | a pinned repo is not checked out |
| 6 | **all three repos are skipped, with a census row seeded** — it asserts no bogus STALE finding is invented, and it fails when the exclusion is removed |
| 7 | **the CLI is spawned as a subprocess** over an all-skipped tree — it asserts a non-zero exit, which no in-process arm can reach |

**`arm 6` was vacuous on its first attempt and the review caught it**: `arm 4` leaves the census
empty, and with no rows the STALE sweep cannot fire — so the arm asserted a property its fixture could
not violate. It now seeds a row for a repo about to be skipped, and **removing the exclusion makes it
report exactly the bogus `STALE … delete the row` finding**, which is the proof that it discriminates.

**`arm 7` exists because `arm 6` could not reach the guard**: the all-skip exit lives in the top-level
`else`, and `selfTest()` calls `run()` in-process — so removing the guard left the self-test green
while the real gate printed `OK` over zero files. **The arm spawns the script in a scratch git repo
with no checkouts and asserts a non-zero exit**; removing the guard makes it report
`status=0 stderr=""`.

`arm 4` is the one that caught raw-line matching firing on prose; `arm 2` is the one that caught a
count of one per file; **`arm 6` is the one that caught the skip path judging repos it had not read.**

### It costs 3.4 s, so it is NOT in `hooks/pre-commit`

The census gate beside it is 129 ms because it greps. **This one reads every test file at the pinned
ref and strips comments, which is the price of `arm 4` being correct.** A pre-commit that adds 3.4 s
to every commit is one people bypass, so **the gate lives in `scripts/self-test.sh` and the
`charly.yml` task**, and `hooks/pre-commit` keeps only the fast structural checks.

**An earlier figure of 54 ms was measured over zero files while the gate was skipping everything,
and it said nothing about the cost of a real population** — which is the same defect the gate itself
exists to catch, turned on its own timing.
