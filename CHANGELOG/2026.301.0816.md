# 2026.301.0816 — fix(gate): the report is checked AT the publish path, and an empty category is a well-formed report (#771)

Closes #771

## Summary

Head `7cddedbc6113c7932442cfc100ed2d51a6ee62c0` — the commit this PR pushes: **1 file changed, 91 insertions(+), 19 deletions(-)**.

**The check and the publication are now ONE call.** The gate's report is a measurement a body pastes, so a count that disagrees with the list beside it must never reach a reader — but the check and the publication were two pieces of code that merely happened to be called in order, and nothing in the repo asserted that the check happens before the print. `publishClassification(lines, emit)` takes the report and a sink, checks it, and publishes only a clean report; the run path and the self-test both drive that one function, so there is no wiring left for a future edit to break with the tree still green.

**An empty category is now a well-formed report.** The report's shape had a tail of at least one character, so a category with no members could not be reported at all — and each of the three counts counts a thing that can go away: the day every file that names the pin-advance verb becomes a claim-maker surface, the non-claim list empties, and the gate that exists to catch a false claim becomes the false red. The shape admits an empty list, the report prints a count of zero with no trailing space, and the self-test covers the case in both directions: published at count 0, refused at count 1.

**The printed form on a populated tree is byte-identical to what it printed before**, so the shipped record's pasted measurement stays literally true (§3).
