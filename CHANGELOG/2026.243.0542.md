# 2026.243.0542 — feat(pi): restore gh_pr_status — per-PR charly/pr-validator status checking

## Summary

Restores the pi agent's PR-validation status tool and its system-prompt instruction, both accidentally deleted by the `#61` config cleanup ("slim project config to bare system prompt + plugins").

**Git-history archaeology:** `ab2448f` (#31) added `.pi/extensions/github-pr-status.ts` — the `gh_pr_status` extension tool (`check` = one-shot PR + org-wide `charly/pr-validator` status; `watch` = poll-until-conclusion, the "completion IS the wake" primitive for background subagents). `c291b96` (#61) slim-deleted it together with the `.pi/APPEND_SYSTEM.md` instruction telling agents to use it, leaving pi agents unable to learn validator verdicts without manually polling `gh` (the GitHub Actions validator has no path into a pi session — it does not wake the agent).

**This change:**
1. `.pi/extensions/github-pr-status.ts` — restored verbatim from its last pre-deletion state (`c291b96^`, 216 lines).
2. `.pi/settings.json` — re-registers the extension (`"extensions": ["./extensions/github-pr-status.ts"]`); packages unchanged (11).
3. `.pi/APPEND_SYSTEM.md` — system-prompt instruction restored and made unconditional: **check EVERY PR** with `gh_pr_status check` after opening/fixing it, run `gh_pr_status watch` in a background subagent while awaiting a verdict, with the failing-step semantics (Gate (BLOCK) vs wait-for-go-gate) and stale-comment head-SHA guard; plus the RCA'd tool-usage discipline (verify a child can execute before delegating — a tool-less child burns its turn probing names; long waits belong to a child, never the parent loop).
