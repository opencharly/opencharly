# 2026.242.0900 — feat: register distro-omarchy, and sync gitlinks to match (policy B)

## Summary

`charly` gained `box/omarchy` in [charly#476](https://github.com/opencharly/charly/pull/476).
**Policy B** says the umbrella's `distro-*` pins must **equal charly's own gitlinks**, so
the umbrella has to record the same submodule at the same commit — or the pinning gate
fails outright:

```
FAIL: charly has no gitlink at box/omarchy
```

That is this PR: register `distro-omarchy` and bring every pin back into line.

### Every file in the diff

| File | What changed |
|---|---|
| `.gitmodules` | `[submodule "distro-omarchy"]` — path, url, `branch = main` |
| `scripts/lib/policy-b.sh` | `[box/omarchy]=distro-omarchy` in `CHARLY_PINNED` |
| `distro-omarchy` | **new gitlink** at `2a1f530` — the exact commit charly records |
| `charly`, `sdk`, `spec`, `distro-cachyos`, `marketplace`, `plugin-generate-packages`, `pod-charly-hooks` | gitlinks advanced by `task sync` |

### Why seven other submodules moved

`task sync` bumps **all** pins per policy B, and `verify-pins.sh` compares **all** of them
across 347 submodules. The umbrella was simply behind on these seven, and a partial sync
would leave `verify` red — so this is the every-other-repo rule doing its job rather than
scope creep. The alternative (hand-pinning only `charly` + `distro-omarchy`) is exactly the
hand-pin R4 forbids: *"If charly's pinning changed, the fix is a sync, not a hand-pin."*

### One step that is easy to miss

`git -C charly submodule update --init --recursive` is required after the sync. Without it
charly reports a dirty working tree — its own `box/cachyos` gitlink moved — and `verify`
fails at

```
FAIL: charly: dirty working tree
```

before it ever reaches the pin comparison. The failure names charly, not the real cause,
which is why it is called out here.

## How tested

`task verify` — the full pinning gate — on the **final tree**:

```
$ task verify
check-policy-b: OK — 6 distro pins equal charly's gitlinks
verify-pins: OK — 347 submodules, policy B holds
OK: /home/atrawog/.cache/omarchy-work/umbrella2/.pi/extensions/umbrella-gates.ts parses (node type-strip pass)
EXIT=0
```

`6 distro pins equal charly's gitlinks` is the Policy B assertion this PR exists to satisfy;
it read 5 before `distro-omarchy` was registered. `347 submodules, policy B holds` is the
whole-tree check.

The gate was **not** green on the way here, and both failures were real rather than
environmental:

1. `FAIL: charly has no gitlink at box/omarchy` — the umbrella's `charly` pin predated
   #476. Fixed by `task sync`, not by hand-pinning.
2. `FAIL: charly: dirty working tree` — charly's inner submodules were stale after that
   bump. Fixed by the recursive update above.

The gitlink equality was also confirmed directly before running the gate:

```
$ git -C charly ls-tree origin/main box/omarchy
160000 commit 2a1f53055cbc3d7d0dbc94f25ffbb7cf944cba96	box/omarchy
$ git ls-files -s distro-omarchy
160000 2a1f53055cbc3d7d0dbc94f25ffbb7cf944cba96 0	distro-omarchy
```

Same commit on both sides, which is what Policy B means.

### Where this was run

In a **fresh recursive clone**, not in an existing working tree. The developer checkout on
this machine is on someone else's feature branch with modified submodules, and switching it
would have destroyed in-flight work (R6). `verify-pins.sh` requires all 347 submodules
checked out, so a shallow clone cannot run it — the first attempt failed with a misleading
`charly: dirty working tree` because the uninitialised submodule made the script's `cd`
fall through to the umbrella root.
