# 2026.327.1334 — feat(guidance): add the org-wide issue-label taxonomy to the rulebook, skills and CLI

## Summary

The org now labels every issue with exactly one `category:` and exactly one `type:` from a closed, generic set. The canonical labels, the generic rules, the org issue form, the sync/audit workflows and their tests live in `opencharly/.github` (#310, #312). This PR carries the umbrella half — the rulebook gist, the full skill guidance, and the one creation wrapper.

- **`AGENTS.md`** — a new "Issue categories and types" section (two closed single-choice axes, no fallback, no session/ownership/severity label, the repository name is never a signal, an undecidable issue is improved or split), the git-workflow dispatcher trigger, and a **Labels** acceptance item.
- **`.agents/skills/git-workflow/references/issue-labels.md`** (new) — the full detail: every value's test, the precedence order, the boundaries (loader vs capability, docs-site build vs content, pin proof vs wave, gate subject vs location), filing through the org form or the wrapper, the under-specified/split protocol, the audit and close-time verifier, the held-out cold-reader protocol, retired labels, and the DESIGN/rulebook/skill violation table.
- **`.agents/skills/git-workflow/SKILL.md`** — a short section, a reference-index row and a "when to use" line; the two ownership sentences that said "status label" now say the assignee plus the latest `CLAIM`/`OWNING` comment (`SKILL.md` and `references/multi-repo-coordination.md`).
- **`.agents/skills/repo-setup/SKILL.md`** — the full new-repository label contract as checklist step 7: `opencharly/.github` owns the taxonomy/rules/form/sync/audit; the bootstrap runs `labels.sh sync`; verify the 12 labels; a repo that ships its own issue template overrides the org default and must carry the same four required fields; no repository-specific labels; file through the form or the wrapper; the org audit reports drift.
- **`scripts/gh/cli.ts`** — the `issue` command: `--repo`, `--title`, `--category`, `--type`, `--remedy` and `--cited` (default `none`) are required; the body is the org form's four-field shape so the audit parses it like a form-filed issue; the session footer is appended. It does not carry a second copy of the taxonomy: the two labels go straight to the API, so an unknown value is refused at the boundary that owns it.
- **`scripts/check-gh-tools.mjs`** — new arms: the dry run emits the four fields + footer and writes nothing; the POST carries both labels and the four-field body; a missing `--remedy`, a prefixless `--category`, and an API label rejection each exit 5.
- **`scripts/sync-pin-evidence.sh` and `scripts/pin-contract-inputs.sh`** — the pin checks tested a long path list with `printf … | grep -q`; `grep -q` exits at its first match, the writer takes SIGPIPE, and the commit gate printed `printf: Broken pipe` twice. Both sites now use a here-string and the self-tests print no warning.
- **`charly.yml`** — the git-workflow and repo-setup triggers.
