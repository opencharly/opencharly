### The verdict: `dulled`, `amend D-FLOW-1`

**The schedule half — the field survives, the firing does not.** The old cell read "the target is one `cron:` field", which reads as though the target had dropped the whole thing. It has not: `#Pipeline` carries `schedule?: #Schedule`, and `#Schedule` is `{cron!: #Cron}`, so an author can declare a schedule today and still can in the target. What has no home is the firing. §15.1 says "`charly pipeline run <name>` runs one; there is no second runner", and the `cron`/`schedule` sweep of `DESIGN.md` returns only a Kubernetes toleration (`NoSchedule`) and a check description ("the workload is scheduled"), both pasted under *How tested* — so no rule in this document fires the `cron:` an author writes, and `apply`/`list`/`remove`/`run-now`, which install, read, delete and fire a trigger descriptor, have nothing to operate on.

**The gate half — understated, not wrong.** `resume --token/--approve/--cancel` answers a paused gate. In the target, `#StageAlt`'s `ask` arm carries `#StageAsk: {prompt}` — a question with no answer channel — and `_state` is a deployment's four words with no `paused` among them. The design keeps the ask (D-FLOW-1: "a gate over deployments, an agent loop over a run and an approval are stages, never fields of their own") and forms neither the answer nor the state that holds between question and answer.

**Why not `accept retirement`, and so why no §A.9 row.** A §A.9 row states a trade the document makes on purpose, and A.9 requires every retirement it records to cite it. Neither half is such a trade. The schedule half would have to be recorded as "a pipeline's schedule is declared and never fired", which contradicts the document keeping `#Schedule` on `#Pipeline`; the gate half as "the design asks and never answers", which contradicts D-FLOW-1's approval-as-a-stage rule. An A.9 row here would convert a hole in the design into a decision — the opposite of what A.9 is for. A.9's existing "an umbrella maintenance verb in the authored model" row does not apply either: that row is about the umbrella's OWN verbs, which run "where no project exists yet", while `charly pipeline schedule apply` acts on a pipeline that IS in a loaded project.

**What is deliberately not done.** An answer channel on `#StageAsk`, a paused run state and a schedule runner are contract changes. Inventing them to turn the row green is the fake fix A.8 exists to prevent, so the row records the debt and names the requirement that owns it — `D-FLOW-1`, which carries both the one-runner rule and the approval-as-a-stage rule.
