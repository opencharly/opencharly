# 2026.272.1930 — docs(agents)!: the orchestrator owns the entire PR surface; subagents research/write/merge code only

## Summary

Corrects the orchestrator/subagent contract in `AGENTS.md`. The prior text was internally
inconsistent (it still said a subagent opens its own PR, runs a pre-push self-audit, and reports
"a merged PR + its CalVer tag") and, worse, it licensed the **hands-off** behaviour that just
failed: on `charly#717` an orchestrator let subagents **create and push** PRs and "watch" their
own verdicts, and **nine PRs sat BLOCKED and unchanged with inflated attribution tiers.**

**New contract:**

### The main session (the orchestrator) owns, and does HIMSELF
- **Creating every PR and running the push — the SINGLE push after full validation.** A subagent
  MAY make **many commits** in its worktree; the orchestrator is the only one who pushes.
- **Fully validating every code change AND every PR body BEFORE the push** — reading the diff,
  running the gates, proving the body. A subagent's claim is never the validation.
- **Reading every `charly/pr-validator` verdict IN FULL** — every block, every comment
  disposition.
- **Ensuring EVERY finding is fixed before the next push** — all findings in **ONE** commit;
  never a partial fix; never a push at the block limit.
- Driving to a PASS (native auto-merge arms on PASS; no `gh pr merge`, no `--admin`).

### A subagent does exactly THREE things
**RESEARCH**, **WRITE CODE** (commit freely — many commits fine), **MERGE CODE**. It **NEVER**
creates a PR, pushes, writes a PR body, reads/dispositions a verdict, decides a merge, or
coordinates. It hands the worktree back with a precise report; the orchestrator does the rest.

### The PR lifecycle — the orchestrator owns ALL of it
1. creates the PR + runs the single push · 2. validates the change AND the body · 3. reads every
verdict in full · 4. ensures every finding is fixed before the next push · 5. merges (native
auto-merge on PASS).

The `## Subagent lifecycle` Instruct/Use template is aligned (`Deliverable` = the code change in
the worktree + evidence, **not** a merged PR; a **Scope boundary** field states the three-verb
limit), so the two sections no longer contradict.
