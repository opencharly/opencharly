### DESIGN amendments (R11)

**D-REF-3, one repository form.** A repository is written `owner/name` on GitHub and `host/owner/name` on any other host. That one form applies everywhere a repository is named: `repo:`, `import:`, `plugin:`, `checkout:` and the CLI.
- `github.com/owner/name` is rejected, so a GitHub repository has one spelling and D-LAW-1 holds.
- D-REF-7 now cites D-REF-3 instead of stating its own GitHub rule. The rule is stated once.
- `#Repo` becomes `=~"^([a-z0-9-]+\\.[a-z0-9.-]+/)?[A-Za-z0-9-]+/[A-Za-z0-9_.-]+$" & !~"^github\\.com/"`.
- Every DESIGN example moves to the short form; the CLI block shows one GitHub and one non-GitHub reference.
- Go `module:` paths are module paths, not repository references, so they stay as they are.

**D-CAP-8 (new), an endpoint's address.** An endpoint's address is its port, transport, protocol, host and path. Several endpoints may share a port and are told apart by `path` or `host`.

**D-VAL-15 (new), no duplicate address.** Two endpoints of one stack with the same whole address are an error naming both. The design check runs it in `rules.cue`, within one candy.

**D-VAL-13 (amended), one publication per shared port.** Endpoints that share a guest port and transport share one publication. Published to two different host ports, they are an error.

**D-VERB-8 (new), an http check by endpoint name.** `#HttpCheck` becomes the S4 choice `#HttpCheckAlt {url, endpoint}`, with the shared S6 fragment `#HttpRequestFields`. The endpoint form takes the scheme, host, port and path from the provided endpoint, where the check runs.

**Updated examples:**
- `check-phases` gains two endpoints on port 8080 and an `http: {endpoint: page}` check.
- The §16.6 `labels` example uses `endpoint: web`.
- Appendix A states that GRIEVANCES examples are complete documents, each validated alone.
