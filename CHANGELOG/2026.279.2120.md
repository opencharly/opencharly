### The `context:` value on the composed step — stated, not left implicit

The composed step declares `context: [runtime]`. The first revision of this branch declared
`[deploy]`, copied from the `map`/`sync`/`pins` tasks, whose own `git-submodules` steps carry it. That
was wrong, and wrong invisibly, so it is corrected and accounted for rather than left unexplained.

`Runner.ContextSkipReason` (`sdk/kit/runner.go`) activates exactly two contexts — `box`→`build`,
`live`→`runtime` — and `PlanGrammar.InContext` (`sdk/checkkit/checkkit.go:37`) is a plain membership
test over `effectiveContexts(op)`. `deploy` is active in **neither** mode, so a step declaring it is
skipped in both: the checkout audit would have become a silently-skipped step the moment this task
was composed into a bed — the same defect class this composition exists to close, reintroduced by a
context keyword. `[runtime]` is the value the combined step it replaces declared (`origin/main`'s
`verify` is 15 steps, every one `[runtime]`) and the value all 16 other steps of this 17-step task
declare. It was invisible here because `charly task` does not apply the context filter at all — the
step ran and rendered its Message while declaring `[deploy]`. The step's own comment now carries
this reasoning and both named call sites, so the next reader re-derives nothing.

**The five sibling sites are deliberately left alone, and why.** The umbrella's *maintenance* tasks
— `map`, `pins`, `self-test`, `hooks`, `sync` — also declare `[deploy]` on their steps. I did not
change them, and the reason is that `[deploy]`→`[runtime]` is **not** a neutral correction. Under a
bed it moves those steps from *skipped* to *executed*, so `hooks` would
set `core.hooksPath` inside a bed and `sync` would bump pins inside a bed. The correct value depends
on an intent that the source does not record — the value dates from the task surface's own authoring
(`f230518`, #247) with no rationale in `README.md` or `AGENTS.md` — and `git-submodules` is an
extracted verb with no `VerbCatalog` entry, so nothing defaults it. Guessing it in either direction
would be a behaviour change with no proof. It is filed as **#413** and claimed, with the sharp case
named there (`policy-b` composes `pins`, whose inner op declares `[deploy]` while the outer step
declares `[runtime]`).

### Scope item 2, decided here because the issue requires the decision, not a silence

`#403` says the `branch == remote default` audit must be decided explicitly in this PR. **It stays
inline.** No verb owns the clause — the tagged verb's `status` mode prints a branch but does not
assert the remote's default — and it is the expensive half (one `git ls-remote` per submodule, 425
of them, hence that step's `timeout: 20m`). Scope item 3 stands too: charly's nested-submodule check
stays inline, because the verb has no recursive-nested clause. Both facts are written into the
steps' own comments, so the next reader re-derives nothing.

### Why the verb is composed *directly* here and not through the `pins` task

`task:` (`verb:task`) returns only a one-line summary and **discards the inner verb's Message**.
The coverage that proves this audit ran lives only in that Message. The umbrella already composes
`git-submodules` directly in its `map` task for exactly this reason; `verify` now does too.

### The defect this closes — measured in one transcript, not argued

A passing `command:` step renders only `exit=0`; its stdout is discarded. The deleted loop's final
act was to `echo` its coverage, so the step claimed coverage in the one place a reviewer looks and
could never show it. That is visible in this run's own transcript, where the composed verb step and
the `command:` steps beside it are demonstrably treated differently:

```
  [pass] check — every submodule is clean and checked out at its recorded gitlink — the ONE verb that owns the clause (its coverage rides its Message, the channel that renders on the pass path; a command step's does not)
      verify: 0 policy pin(s) hold across 425 submodule(s); 425 checkout(s) clean at their gitlink
  [pass] check — every submodule's branch equals its remote default — KEPT INLINE, deliberately, because no verb owns this clause, and it is the expensive half (one git ls-remote per submodule, hence the timeout below)
      exit=0
```

Both lines are from the run transcribed under **How tested** below, not abridged.

### The load-bearing pin — why composing the verb alone would have been a regression

Composing the verb is only honest if the binary carries the verb arm that audits checkouts. It did
not. The umbrella's `plugin-task` gitlink was the walk snapshot `4be0a5e`, whose `verify` arm
iterates `pin_map` only — and this step passes `pin_map: {}`, so against that pin the composed step
asserts **nothing at all**. Shipping the composition on the old pin would have deleted the checkout
audit and put an auditing-nothing verb in its place: a silent hole in the pinning gate, the exact
defect class `#403` exists to close.

`charly task sync` closes it by advancing the gitlink. `plugin-task` now sits at default-branch HEAD
`50a8234d`, the commit carrying the `v0.2026279.1656` code that `charly/go.mod` requires and that is
compiled **into** the binary the gate runs:


The two commits ship together because neither is honest alone: the refactor needs the pin, and the
pin's only purpose here is to make the refactor true.
