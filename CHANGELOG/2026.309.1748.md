# 2026.309.1748 — feat(design): give a manager package its revision and its values digest (batch 44)

## Summary

Batch 44 of the DESIGN amendments (tracked in #838). A helm release is checked as a **manager package** —
`package: {name: "helm:<release>", ...}` — and the design carried only `name`, `present` and one `version`
matcher. So `revision` and `values-hash` had no home, and `release-exists` collapsed into `present`.

`#PackageCheck` gains **`revision`** and **`hash`**, both matchers: a manager package's own identity, which
an OS package does not name. **`verb:helm` becomes sharp** — all four of its operation keys now have a field:

| helm key | the field |
|---|---|
| `release-exists` | `present` |
| `status` | `version` |
| `revision` | `revision` |
| `values-hash` | `hash` |

| file | what changed |
|---|---|
| `DESIGN.cue` | `#PackageCheck` gains `revision` and `hash`, with a comment naming why an OS package uses neither |
| `DESIGN.md` | a `helm:lab` package check exercising both |
| `design/dulling.tsv` | `verb:helm` becomes sharp |
| `design/dulling-disposition.md` | regenerated |
