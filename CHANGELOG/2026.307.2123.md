gid/home/shell/not_group/linger, group gid, interface mtu, dns server, mount source/opt, file
filetype/link_target/sha256/group_of, service scope/none_failed/ignore) and the web-server example
asserts the four `#HttpCheck` fields — so deleting any restored field now fails validation. This was
the second review finding on this thread, and it was right.

**Citations are names, never positions.** Editing the examples shifted `DESIGN.md` by 15 lines and
made every `DESIGN.md:<line>` citation stale (150 findings) — the same failure that cost two rounds
on `DESIGN.cue` lines. So the ledger now cites `DESIGN.md` by **requirement or section**
(`DESIGN.md:D-VERB-3`, `DESIGN.md:§16.5`) and `DESIGN.cue` by **definition** (`DESIGN.cue:#FileCheck`).
A line citation in **any column** of either ledger is itself a failure; a cited requirement or
section must be one the document defines; a named definition must exist exactly once and appear in
that row's `evidence`.

**A mechanical sweep is not a read.** Round 3 found that the sweep removing `(DESIGN.md:NNNN, NNNN)`
citations deleted the first number and left the second: 38 `target_form` cells ended in a bare
`, 1929)` and one unbalanced `)`. The gate was green because `cite_check` read only the guideline and
evidence columns. Every `target_form` cell is now read and repaired, and the control fails on a line
citation in any column — so the column that hid this can hide nothing.

**The ledger records the result without overclaiming.** `verb:file`, `verb:mount`, `verb:user`,
`verb:unix_group`, `verb:http` flip to `sharp`. `dns`, `interface` and `service` stay `dulled` on
what this batch does not close — the plural address set and the artifact-phase question — and they
are named.
