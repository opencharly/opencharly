# 2026.281.0819 — feat(hooks): run the org's PR-body linter before the push, not after the verdict (#404)

## Summary

Closes `opencharly/marketplace#404`. The org judges PR bodies with its own linter,
`marketplace/scripts/pr_body_lint.py`, and the validator reads the body **live** — so every defect
that linter can catch mechanically was paid for in review rounds instead of seconds. The linter
existed; **nothing ran it before the push.** This lands the hook that does, plus the assertion that
proves it.

**What the hook is, and what class it is in.** `hooks/pre-push` runs the linter on the body about to
be published. Hooks guard **deterministic mechanics only** — this checks the body's FORM (a missing
required section, a trailer that is not the last line, a bare `N/A`, an ellipsized fence, a pasted
head SHA that is not HEAD) and judges nothing about the change, the attribution tier, or the
evidence. It is distinct from `.claude/hooks/pre-push-gate.sh`, which is a harness gate over the
command TEXT; this one runs on the actual push, from git.

**The body path convention** (decided by the Lead, implemented here): the body defaults to the **git
dir** — `git rev-parse --absolute-git-dir` + `/PR_BODY.md`, overridable with `PR_BODY_FILE`. It is
per-**worktree** (`…/.git/worktrees/<name>`), so two session worktrees can never fight over one
body; absolute, so it survives a change of cwd; and it never dirties the tracked tree.

**Three skips, all VISIBLE, none fail-closed** — in the shape `pre-commit-gate.sh` already uses for a
missing `golangci-lint`:

1. **No body** → skip and print how to create it. A body's absence at push time is the *discipline*
   failing, not a defect in the diff; a hook that blocked there would be inventing a rule.
2. **No linter** (an unmaterialized `marketplace` submodule, which every fresh session worktree has)
   → skip and name the one command that fixes it, so a fresh worktree stays landable.
3. **A linter that cannot RUN** → skip. This case was found by firing the hook, not by reading it:
   `pr_body_lint.py` imports a **sibling module** (`squash_body.py`), so a partial materialization
   dies with a Python traceback that **also exits 1** — indistinguishable from "findings" by exit
   code alone. Without the `--help` pre-flight, one broken submodule would block every legitimate
   push in the clone, which is the fail-closed-infrastructure class the doctrine exists to prevent.

**The assertion** is `scripts/check-pr-body-gate.mjs`, wired into `hooks/pre-commit` so it is **run**,
not merely asserted: **one static reading** (the executable bit, the git-dir path, the override, both
skip branches, and the linter it invokes) plus **five assertions that FIRE the real hook** against
real git repositories and the real linter — because a regex cannot see whether a skip exits 0, or
whether a finding actually reaches the push.

**Two defects in my own first version, both recorded rather than quietly fixed.**

- The checker copied only `pr_body_lint.py` into its scratch repo and asserted merely `exit 1` for a
  defective body. It **passed — for the wrong reason**: the linter was crashing on the missing
  sibling, and a crash also exits 1. It now copies the whole `scripts/` directory and asserts the
  linter's own `FAIL  sections:` finding line.
- The reviewer caught the second: the checker **failed closed when `marketplace/` was absent**, so —
  because `hooks/pre-commit` runs it — the commit gate went red on a *default fresh session
  worktree*. That is the exact class the hook it asserts exists to avoid, and it contradicted this
  change's own stated goal. `fire()` now guards the linter source and skips **visibly**, naming the
  materialization command, and `--self-test` reports `N/5 arms live; M skipped` instead of throwing or
  passing silently (`check-harness-config.mjs`'s precedent for a surface missing from a checkout). A
  skipped arm is never counted as caught.

  hook's own documented contract applied to the checker, not a suppression.
- **R4a — fix the product first:** the hook runs the org's canonical linter rather than a new bespoke

  hook bypass; `git status --short` is empty and the hook file is mode `100755`.
- **R7 — prove behaviour, not compilation:** six assertions (one static + five fired), five mutations,
  and the fired cases run real git and the real linter — one of them caught a defect in the hook (the
  third skip) that no static reading had, and the submodule-absent case is proven in both directions.
- **R7a — live or skip:** the hook runs against real repositories with the real linter; where the

- **R9 — binary equals source:** the clone-level gate ran through the worktree-local charly build

- **R10 — fresh disposable proof:** no disposable target is affected — a clone-level git hook, its

**What this does NOT do, so nothing is implied that the diff does not perform.** It does not lint a
body that is never written to the convention's path — an author who keeps their body elsewhere must
pass `PR_BODY_FILE` or the hook skips. It does not wire the linter into any harness's `PreToolUse`
gate, and it does not make the linter part of the required status check. It fires only where
`core.hooksPath=hooks` is installed, which is per clone via `charly task hooks`. And where the
`marketplace` submodule is unmaterialized, both the hook AND its checker skip visibly — the fired
assertions are not run in that checkout, which the self-test reports as `0/5 arms live` rather than as
a pass.
