# 2026.330.2148 — feat(opencode): make permissions deny-capable and derive the session slug

## Summary

opencode V2 gives every agent an ordered base policy whose first rule is a catch-all `allow`, so the project's V1 `permission` map — 26 `allow` entries — granted nothing the default did not already grant, and one entry granted `gh pr merge *`, the action `AGENTS.md` forbids outright. This PR replaces that map with the V2 `permissions` array carrying the denies the rulebook requires, and rewrites gate check 5 so it can actually fail.

Six opencode-only gaps close with it:

1. **Permissions are real.** `gh pr merge*`, `git push *--force*` and `git commit *--no-verify*` are `deny`. Under the allow base policy only `deny`/`ask` constrain, so the inert V1 map and its 19-skill allowlist are deleted (R5).
2. **Check 5 asserts effect, not text.** It requires the V2 array, the three denies, and the absence of a forbidden `allow`. Its three old mutations (which measured an `allow` key's absence) are replaced by three that can fail for the right reason.
3. **All seven corpus agents are bound.** Six new thin `.opencode/agent/` pointers delegate to the corpus definition and the owning skills. Check 12 now resolves refs inside the pointers AND asserts each pointer's `marketplace/**/agents/<name>.md` target exists.
4. **The `Agent:` slug is unique per session.** When no arg/env/conf names one, `coord.ts` derives `<session_v2.slug>-<full session id>` through the same read-only store handle `agent-progress` owns. The slug alone is not unique across sessions; the id makes it so.
5. **The version claims are true.** Host `v2.0.18` → measured `v2.4.2`; pin `1.18.33` → `1.19.6` (both ship `./v2/promise`). Each V2 primitive is marked re-verified or explicitly not re-measured.
6. **The `docs` shadowing is recorded.** The corpus `docs` skill wins the bare name over the user-level document connector.

Closes #1303.

### Spike

**Permission posture — three candidates, spiked on the real binary.** (a) deny-only: explicit denies, default allow kept; (b) ask-based: base `shell *` → `ask` plus an allowlist; (c) document-only: leave the config, fix the prose. (a) was spiked first because it is the only one that changes behaviour without adding prompts: `gh pr merge --help` → `Permission denied: shell` (`executed:false`), while a compound `bash -c 'echo one && (echo two | tr a-z A-Z)'` ran to `exit 0`. (b) rejected — it prompts on every command, including the autonomous R10 bed runs the rulebook requires. (c) rejected — it leaves the merge permitted, i.e. it does not fix the defect. Implemented: (a).

**Agent slug — three candidates.** (a) `ses-<8hex>`; (b) `<title slug>-<full session id>`; (c) per-call only with a live-collision check. (b) was chosen and spiked end to end: a fresh `opencode run --standalone` produced `eager-rocket-ses_de64c6dacffel0OqRxPlLM2P87` from the store row, not from an argument. (c) still fails when the arg is omitted, which is the defect being fixed.

**Glob scoping — two rejections measured.** `git *push*--force*` false-positives on a commit message containing that text (the scanner's resource is the whole command string); `*push*-f*` false-positives on any branch name containing `-f`, including this PR's own `feat/opencode-permissions-fix` shape. The deny set is therefore scoped to `git push *--force*`, and precise flag/refspec parsing stays with the pre-push gate, which already covers `-f`, `--force-with-lease`, `+refspec` and `core.hooksPath`. This is friction, not a sandbox, and the body says so.
