### 2. `scripts/check-harness-config.mjs` — the self-test no longer aborts on an unmaterialized submodule surface

**Mechanism (RCA, run before any remediation).** The first `task verify` on this worktree FAILED:

```
  [fail] check — the harness-config gate discriminates — each mutation turns it RED (fixtures)
      exit=1, want 0 (stderr: node:internal/fs/cp/cp-sync:56 ...)

$ node scripts/check-harness-config.mjs --self-test
Error: ENOENT: no such file or directory, lstat '<worktree>/marketplace/DISPATCHER.md'
    at cpSyncFn (node:internal/fs/cp/cp-sync:56:13)
    at stage (file:///<worktree>/scripts/check-harness-config.mjs:156:7)
```

`marketplace` is a SUBMODULE; `stage()` copied every surface unconditionally, so a checkout that does not materialize its submodules — the session-worktree layout **Part II rule 2 requires** — threw ENOENT out of the self-test and aborted every remaining arm, masking the gate's real verdict.

**Missed control.** The gate ITSELF already guards this exact case three times (checks 8/12/13: `"marketplace ... not checked out — ... check skipped"`). Only the self-test's fixture stager lacked the same guard, so the one command a worktree diff MUST run was the one command a worktree could not run.

**Fix (in this diff, not parked).** `stage()` skips an unmaterialized surface with a NOTICE — the same precondition and the same voice as the gate's own three guards — and the four corpus-measured arms (check 12's two, check 13's coverage and collision) are skipped identically, with the report naming how many arms were live.
