# 2026.301.2236 — fix(gate): the narrowing arm has two tiers — a weak preposition that names a subset narrows too (#789)

Refs #789.

## Summary

Head `0f4810360c81fd95dba2a524d2be64ac9fcdbd45` — 1 file changed, 163 insertions(+), 19 deletions(-).

**The defect.** Arm D of `scripts/check-pin-verb-scope.mjs` recognised only SCOPE
prepositions — "over", "across", "within", "among" — so a narrowing phrased with any
other preposition escaped it. The sentence *"the pin operation for the `distro-*` paths
— advances EVERY pin this repo declares"* states the scope and contradicts it in the
same breath, and the gate stayed GREEN. #788 fixed the three surfaces that carried the
narrowing; this change closes the class, so the next narrowing is caught whatever
preposition carries it — provided the subset it names is MARKED (a glob, a quoted
token, a hyphenated proper name, or an ALL-CAPS name).

**The RCA.**

- **Mechanism** — arm D matched a clause by its PREPOSITION, and a preposition is not
  the operation's scope object. "over" governs the verb's own object ("the pin
  operation over the `distro-*` set" — a subset), but "for", "on", "at" and "to"
  govern durations ("for the minutes it rolls the submodules"), destinations ("to the
  owning repo") and generic singulars ("at those pins"). The arm read all four as scope
  objects, so it had to either miss the narrowings it was written for or fire on prose
  that narrows nothing.
- **Missed control** — the gate asserted the POSITIVE claim (every claim-maker surface
  states the scope) and one SHAPE of the negative one. Nothing asserted that the
  narrowing clause is found whatever preposition carries it, so a shape the author did
  not anticipate was green by construction. The GREEN line compounded it: it claimed
  the arm proved *"none narrows it to a subset"* — a claim about every clause, backed by
  a match on four prepositions.
- **Blast radius** — every reader of this repo's claim-maker surfaces: the README's
  maintenance table, the manifest's task descriptions (printed by `charly task list`),
  and the `git-workflow` family's references, which the guidance corpus projects for
  every harness that loads it. No consumer ran the wrong verb; a consumer was told the
  wrong scope and no gate would have said so.
- **Root fix** — the arm reads the clause in TWO TIERS. Tier 1 is a scope preposition:
  the verb's own object follows it, so any subset named there narrows the operation.
  Tier 2 is a weak preposition or a restrictive adverb: it fires only when the
  qualifier NAMES a subset (a glob, a quoted token, a hyphenated proper name, an
  ALL-CAPS name), because a tier-2 phrase that names nothing narrows nothing. The
  GREEN line states what the arm proves, and the self-test carries a red arm for every
  surface and a negative control over the benign shapes.

**Finding 2 — the tier-2 negative control could pass vacuously when the mutation could
not be applied.**

- **Mechanism** — `const fs = mutated === null ? [] : findings(...)` collapsed *"the

  empty array. `fs.length === 0` therefore incremented `noisy` never and `ok(...)` ran,
  so a control whose setup had broken reported PASS. The universal-scope control carried
  the same mechanism.
- **Missed control** — the control asserted only that a benign clause stays GREEN; it
  never asserted that it actually EXERCISED a clause. A control that cannot fail when
  its setup breaks is not a control, and this one could not fail at all in that case.
- **Blast radius** — both negative controls in this file. A broken surface lookup, or
  an anchor that stopped matching, would have turned the whole tier-2 discrimination
  into a silent vacuous PASS — the gate would have kept publishing its GREEN line while
  testing nothing.
- **Root fix** — both negative controls now FAIL when the surface cannot be located or
  the mutation cannot be applied, and the tier-2 control counts the clauses it applied,
  so it reports OK only when every clause was applied AND evaluated.

### Why the clause is read in two tiers, and not by one wider regex

A single regex carrying the weak prepositions fires on the umbrella's own prose. The
measurement below runs that naive form over the CLEAN tree — a tree with no narrowing in
it — and every finding it reports is a false positive:

Six distinct clauses, twenty findings — and among them only FIVE distinct shapes,
because one is the same generic singular in a second case: a generic singular ("at
those pins" / "AT those pins"), a restrictive adverb over one repo ("only the new
repo"), and three destination phrases ("to move one pin", "to the owning repo", "to
the umbrella as a submodule"). None of them is a scope object. A gate
that fires on those teaches its reader to ignore it. The two-tier form keeps the tier-1
rule exactly as it was and adds tier 2 only where the qualifier NAMES a subset, and it
stays GREEN over the same clean tree:
