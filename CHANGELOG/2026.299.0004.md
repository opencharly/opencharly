**This is #690's review round, continued after it merged.** The fresh `charly/pr-validator` on #690 passed the change and raised two minor observations against the gate that #690 introduced. R1 is unambiguous about a finding raised on your own PR: it is never filed away — it is **fixed**, or rebutted on the thread with evidence. Both observations are in code this change owns, and both are fixable without touching a claim, so both are **fixed here**, in the same repo, in the same control, in one commit.

**Observation 1 — the buffer that scales with the repo was Node's 1 MiB default.** `trackedFiles` read the tracked set with `git ls-files -s -z` and inherited `execFileSync`'s default `maxBuffer` of 1 MiB. That output grows with the repo: MEASURED on this tree, 1458 entries cost 108,140 bytes — 74.2 per entry — so a tree of ~14,137 files crosses the default, and past it the gate **died** with `ENOBUFS` instead of judging. A control that stops judging on the large trees is failing at the job it exists for. Every git call now goes through ONE helper, `gitOut`, that raises the ceiling to 64 MiB, so the ceiling is set in a single place and every call inherits it — including the two that scale with a repo (`ls-files -s -z`, `ls-tree -r --name-only`) and the one that scales with a file (`cat-file blob`), which carried a ceiling of its own before.

**Observation 2 — the `--self-test` failed closed where it cannot run.** The plain gate SKIPS VISIBLY when the pinned charly has no checkout; the `--self-test` **failed** there. Its mutations are built FROM the pinned version, so a tree that cannot derive the version cannot run them — and failing anyway turned every such tree's verify red over a check that never ran. That is the fail-closed-infrastructure class this repo's sibling gates refuse on purpose: `scripts/check-pr-body-gate.mjs` skips a corpus-dependent check rather than fail it, and `scripts/check-harness-config.mjs` asserts that a tree whose corpus is absent leaves every corpus-dependent check SKIPPING. The self-test now SKIPS VISIBLY, prints the one command that materializes the checkout, and exits 0.

**Both fixes are proven able to fail, against the tree #690 actually shipped** — `origin/main`'s own copy of the file — not against a hand-made mutation:
