# 2026.243.0933 — feat(pi): charly_status tool for bed/image/vm status + don't-pile-up guidance

## Summary

Add `charly_status` — the gh_pr_status analogue for charly validation — plus the don't-pile-up system-prompt rule.

**Dependency change (disclosed):** `.pi/settings.json` REMOVES `npm:pi-web-ui@0.54.0`. Reason: the package's own manifest declares `pi.extensions: ["./extensions"]`, a DIRECTORY the extension loader cannot import as a module (`Cannot find module .../pi-web-ui/extensions`) — it broke every subagent child startup and nothing in the umbrella uses web-ui tools. Removing a broken, unused package, not a feature change.

**Tool:** `.pi/extensions/charly-status.ts` with `check`/`watch` modes for `bed` / `image` / `vm`: bed status from charly's OWN .check artifacts + bed lock (auto-locating the tree under the box project roots), image presence (read-only podman), VM domain state (read-only virsh); `watch` polls until a bed concludes (completion-is-the-wake, for background subagents).

**Guidance:** `.pi/APPEND_SYSTEM.md` — (1) the binding Don't-Pile-Up-Unfinished-Work rule (close every loop; always catch up with upstream main before finalizing a PR), (2) Charly validation status: use charly_status VIA A SUBAGENT; never ad-hoc ps/tail/podman/virsh shell.

**Follow-ups (named, in this PR's theme):** (a) apply the same settings.json extension entry to charly's copy so the 5-file harness-parity check stays green — charly repo, batch: pi-harness-parity-mirror; (b) fix the pi-claude-marketplace agent generator, which emits agent frontmatter with EMPTY descriptions + no extensions wiring (the reason .pi/agents/ wiring is local-only here) — batch: pi-claude-marketplace-agent-generator.
