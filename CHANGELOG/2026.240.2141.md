# 2026.240.2141 — fix: load the umbrella's R0 dispatcher skills (enabled but never installed for this project)

## Summary

The umbrella declared `charly-internals`, `charly-automation` and
`claude-md-management` in `.claude/settings.json` — and **loaded none of their
skills**. Every skill the `CLAUDE.md` R0 dispatcher points at was unreachable, so
R0 "load every skill the dispatcher selects" could not be satisfied in this repo
at all.

**Root cause (R1).** `enabledPlugins` is only the *enablement* half of the
contract. Skills load only when `~/.claude/plugins/installed_plugins.json` also
holds an install record whose `projectPath` is this repo. Every record was bound
to a different project, with `installPath`s (`…/charly-internals/1.1.0`) that no
longer exist — the plugin cache is commit-keyed (`…/7072e53a9d92`), not keyed by
those version numbers. The umbrella had a valid marketplace, a valid manifest,
valid skill frontmatter, and zero loaded skills.

**Why it went unnoticed.** `claude plugin list` reads enablement from
`settings.json` and prints `Status: ✔ enabled` regardless of whether the install
record resolves, so the CLI actively masked the breakage. The only reliable probe
is asking a fresh session what it can actually see.

**Fix.** Reinstalled at `--scope project` (which writes *both* halves) exactly the
plugins the umbrella needs, and no more:

| Plugin | Why it belongs here |
|---|---|
| `charly-internals` | R0 dispatcher: `git-workflow`, `strict-policy`, `root-cause-analyzer`, `agents` |
| `charly-automation` | R0 dispatcher: `agent`, `alias` |
| `claude-md-management` | already enabled; maintains this rulebook |
| `gopls-lsp` | 0 skills, 1 LSP server, ~0 always-on tokens; matches `charly/.claude/settings.json` |

The umbrella is a *view* of the org — it never builds images, runs pods, or probes
live containers — so the 22 image/pod plugins are deliberately **not** enabled.

**Consequence, not a separate edit:** four MCP servers leave this project along
with the image plugins that own them — `charly-coder:charly` (:18765),
`charly-jupyter:jupyter` (:8888), `charly-selkies:chrome-devtools` (:9224),
`charly-versa:marimo` (:22718). These were never broken: they are pod-provided
HTTP endpoints, and `ConnectionRefused` is the correct state when no box is
running. They simply have no role in the umbrella.

**Known remaining defect, not fixable in this repo.** `charly-internals` still
declares a `github` **stdio** MCP server (`command: github-mcp-server`) — a
third-party binary that is not installed, and that duplicates the `gh` CLI the
`git-workflow` skill already mandates. Unlike the four above it is not
pod-provided, so it has no legitimate consumer. Its authoritative source is
`charly.yml` in the **`charly-hooks` candy** (`opencharly/pod-charly-hooks`,
under the `internals` plugin's `mcp_servers:` block), vendored into
`opencharly/marketplace` as `internals/.mcp.json`. Both are **submodules** of this
umbrella, so rulebook rule 1 ("never edit inside a submodule") forbids fixing it
here; it needs a PR to `pod-charly-hooks`, a `charly marketplace generate`, and a
`task sync`. Filed as follow-up work in the owning repo rather than patched
around here (R4).

`.claude/settings.json` is **not** in `scripts/check-harness-parity.sh`'s `SHARED`
table, so it is an umbrella-specific fork by design (rule 8); this change creates
no parity drift. Hooks and `permissions.allow` are byte-identical throughout.

## Rulebook compliance

- **R1 — RCA before remediation.** Root-caused to stale project-scoped install
  records before touching config. The five failing MCP servers were then
  diagnosed individually rather than lumped together: four are correct
  pod-provided endpoints, one is a genuine defect — no "pre-existing" or
  "out of scope" classification for the latter, it is filed against its owning repo.
- **R3 — No duplication.** `claude plugin install/uninstall` remains the single
  writer of both halves; no hand-edited JSON.
- **R4 — No workarounds.** No hand-patched `installed_plugins.json`, no symlink
  from the missing version path to the commit-keyed cache dir, and the
  `github-mcp-server` gap is not papered over locally.
- **R5 — Delete legacy completely.** Stale version-keyed `installPath`s replaced,
  not shadowed; the over-broad 26-plugin set removed in this PR, not left behind.
- **R6 — Git safety.** `git status` + `git stash list` + `gh pr list` +
  `git worktree list` preflight before branching; `feat/` branch, fast-forward
  pushes only, no force-push, no `--no-verify`, no direct push to `main`. The PR
  was **updated with a follow-up commit, never closed and recreated**.
- **R7 / R10 — Prove the gate on the final tree.** `task verify`,
  `check-harness-parity.sh` and `gate_test.py` pasted above, run after the final
  commit on a clean tree; the 29-skill count measured from a fresh session.
- **Rule 1 — Never edit inside a submodule.** Umbrella-only change; 344 gitlinks
  untouched. The `github` MCP defect is explicitly *not* fixed here because its
  source lives in two submodules.
- **Rule 8 — Harness config parity.** `.claude/settings.json` sits outside the
  `SHARED` parity table by design; the shared hook scripts are unchanged.
