# 2026.263.2206 — fix(opencode): activate the compaction reserve and raise it to the model max

## Summary

Fix the umbrella root `opencode.json` so opencode auto-compaction fires with headroom instead of at the context wall.

**Root cause.** At the branch base (`origin/main`), `opencode.json` had **no `provider` block at all** — only `compaction.reserved: 100000`. opencode's `usable()` honors `reserved` **only** on the `model.limit.input` branch (`packages/opencode/src/session/overflow.ts`, v1.18.31):

```
const reserved = cfg.compaction?.reserved ??
  Math.min(COMPACTION_BUFFER, ProviderTransform.maxOutputTokens(model, outputTokenMax))
return model.limit.input
  ? Math.max(0, model.limit.input - reserved)          // honors reserved
  : Math.max(0, context - ProviderTransform.maxOutputTokens(model, outputTokenMax))  // ignores reserved
```

With `limit.input` unset, the effective trigger was `context - maxOutputTokens`. `maxOutputTokens` defaults to `OUTPUT_TOKEN_MAX = 32000` (`provider/transform.ts:18`) when `limit.output` is absent, so the wall was `1048576 - 32000 = 1016576` — the configured 100000 reserve was **dead**.

**Measured consequence.** Session `ses_f44b4fc7bffevBEN9oxbV3IX3C` accumulated **1016714** prompt tokens — **138 tokens *above* that wall**. Compaction therefore fired slightly late, and the serialized history (1,351,418 tokens; a measured 1.329× expansion) exceeded the 1,048,576 window:

```
level=ERROR agent=compaction error="AI_APICallError: The prompt is too long:
  1351418, model maximum context length: 1048576"
```

The compaction failed and the session was permanently wedged (the pending `compaction` part and the `finish=error` summary re-enter and re-fail on every resume).

**Change (`opencode.json`, harness-config only — +21/−1):**

| Key | Before (at `origin/main`) | After | Effect |
|---|---|---|---|
| model `limit.context` | *(absent — no provider block)* | `1048576` | declares the window |
| model `limit.input` | *(absent)* | `1048576` | **activates `reserved`**; trigger becomes `1048576-384000 = 664576` |
| model `limit.output` | *(absent → default 32000)* | `384000` | `models.dev` reports 384000 for `ollama-cloud/deepseek-v4.1-flash` |
| `options.max_tokens` | *(absent)* | `384000` | output/thinking budget (the model's max) |
| `options.reasoningEffort` | *(absent)* | `high` | keep reasoning quality high |
| `compaction.auto` | *(absent → default true)* | `true` | explicit |
| `compaction.prune` | *(absent → default false)* | `true` | clears old tool outputs so long sessions shrink rather than grow to the wall |
| `compaction.reserved` | `100000` | `384000` | **equals `limit.output`** — the one coherent value (see below) |
| `lsp` | *(absent → default false)* | `true` | enable built-in gopls (`.go`) and yaml-ls (`.yaml`/`.yml`) |

**Why `reserved` and `limit.output` are the same number (384000).** `reserved` is the headroom opencode keeps free below `limit.input` so the *generation* has room in the window: `usable = limit.input - reserved`. It must therefore be at least the output budget the request may use; `limit.output`/`options.max_tokens` is exactly that budget. Setting them equal (`384000`) means the trigger fires with precisely the generation budget reserved — no contradiction, one quantity with two names. (The earlier `393216` was wrong: 384×1024, not `models.dev`'s 384000.)

**Fits the window:** at the new trigger (`664576` input tokens) the measured 1.329× serialized summary is `≈883355` tokens < `1048576`. The old trigger left only 32000 of headroom, which the 1.329× expansion blew through.

The `provider` block is **new**; every key inside it was absent before (the diff is `+` lines only there). No submodule, pin, permission, or code change.
