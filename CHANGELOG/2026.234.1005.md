# 2026.234.1005 — ci: adopt org-wide validation chain — pr-validator + tag-on-merge, drop custom auto-merge

## Summary

Adopts the org-wide validation chain for the umbrella, after an audit found
the merge/landing configuration was broken and divergent. Every file in the
diff:

- `.github/workflows/auto-merge.yml` (deleted) — the custom auto-merge was
  broken (no `actions/checkout`; `gh pr merge --auto` and the inline tag
  computation failed with "not a git repository", run 32564343846) and
  diverged from the org pattern: it merged on the `verify` gate alone, with
  no AI validation, and tagged inline. Removed in favor of the org chain
  (R5 hard cutover — no legacy path survives).
- `.github/workflows/pr-validator.yml` (new) — `charly/pr-validator`
  dispatcher, charly's exact pattern: `wait-for-ci` waits for the umbrella's
  `verify` pinning-gate check-run (charly waits for its `go` gate), then the
  `validate` job calls `opencharly/.github/.github/workflows/pr-validator.yml@main`,
  which runs the fresh AI review (`pi-review-action`) and enables native
  auto-merge on PASS. PR number resolved via
  `inputs.pr-number || github.event.pull_request.number` so the
  `workflow_dispatch` re-run path works.
- `.github/workflows/tag-on-merge.yml` (new) — org sweep dispatcher:
  runs the org tag-on-merge reusable after every validator completion (plus
  a 15-minute schedule backstop) and tags every merged PR with its CalVer
  snapshot metaver.
- `README.md` — the landing description now names the validator-gated chain
  (pr-validator → native auto-merge → tag-on-merge) instead of the old
  verify-only auto-merge.
- `CHANGELOG/README.md` + `CHANGELOG/2026.234.0000.md` (new) — the
  repo-scoped CHANGELOG convention (one file per CalVer release), matching
  the org rule B19; the validator's rename step finalizes the placeholder to
  the merge-time CalVer.
- `AGENTS.md` / `CLAUDE.md` (edited) — PR body requirements now mandate the
  CHANGELOG entry and the exact `*Assisted-by: <Harness> <Provider Full
  Model Name> (<confidence>)*` footer (rules A1/B19), and reference the
  validator-gated landing.
- `.pi/prompts/pr-body.md` (edited) — template gains the CHANGELOG section,
  the exact attribution footer, and the `validate` AI gate as the
  verification gate.
- `.pi/extensions/umbrella-gates.ts` (edited) — the per-turn rules
  injection's PR-body block updated to the same A1/B19 requirements.

Repo settings (via API, not part of the diff): `allow_auto_merge=true`,
squash-only merge, `delete_branch_on_merge=true` — matching charly.

Branch protection on `main` (required checks `verify` + `validate /
validate`, enforce_admins, no force-push, no deletions) is enabled as an
immediate post-landing repo-setting step (it cannot exist in a diff;
self-gating bootstrap).
