## Two gotchas worth recording

Neither is visible in `task sync`'s output, and both bit this sync.

**1. `charly` comes out DIRTY.** The sync advances charly's nested `box/omarchy` submodule,
leaving charly's working tree modified — which fails `verify` and is a review blocker under
rule 1 ("a dirty submodule fails CI and is a review blocker"). Restored before committing:

```
$ git -C charly submodule update --init box/omarchy
Submodule path 'box/omarchy': checked out 'e2ae55764e174735c333e3f8582501e213cf069a'
```

**2. A partial sync reports success.** An earlier attempt died partway with

```
Another git process seems to be running in this repository, or the lock file may be stale
task: Failed to run task "sync": exit status 128
```

after concurrent submodule fetches — and left a **partial result: 18 of 26 gitlinks moved**,
silently. The surrounding wrapper still reported exit 0, so the failure is invisible unless
`task`'s own exit code is read. A later `task verify` would then pass on a tree whose
gitlinks are not actually current. This commit is from a run that recorded `TASK_EXIT=0`
across all 349 modules.
