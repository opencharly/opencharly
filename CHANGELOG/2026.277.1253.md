# 2026.277.1253 — docs(design): add normative DESIGN.md + DESIGN.cue, TODO.md and the executable design check

## Summary

This PR adds the umbrella's normative design and the executable control that keeps it consistent (closes #346; supersedes #347). It adds the plan's deliverables only, and changes no existing file.

- **`DESIGN.md`** is the target architecture of charly, `spec`, `sdk`, every plugin and every candy repository. Its sections:
  - laws and a closed term registry (§1–§2);
  - the CUE schema patterns S1–S9 (§3.1);
  - parsing, linking and validation, with tag dispatch D-LOAD-5 (§4–§5);
  - the complete core↔plugin protocol: method table, handshake, calls, host service, conformance (§8);
  - the authoring model for candies, boxes, sources, `os` and deployments, with intention-based nesting (Part III);
  - one ownership table (§7.1);
  - Appendix A, which explains every script of the design check.
- **`DESIGN.cue`** is the single schema copy, in CUE v0.17.1: the authoring part and the protocol part. Every rule the schema enforces on a document or a protocol message is tagged `// D-…` at its enforcing line. The rules about the schema itself (D-PAT-1) are enforced by the pattern gate, A.4 check 6.
- **`TODO.md`** gives every migration step from today's code. Each step has its current state (evidence re-verified at `origin/main` on 2026-10-03), its DESIGN target, its config migration before → after, and its code work. Adopting the design in the umbrella rulebook is item 10.1.
- **`scripts/design-*.sh` + `design/`** form the design check, which needs CUE v0.17.1 only:
  - `design-cue.sh`: the pinned toolchain, sha256-verified;
  - `design-consistency.sh`: `.md`↔`.cue` tables (marked, and unmarked tables that mirror a source), word lists, `@ref`↔rule lists, rule tags, IDs, `§` and `S<n>` references, vocabulary, and the schema-pattern gate;
  - `design-examples.sh`: automatic validation of every example, through the loader's dispatch and through `#Document`, plus 64 negative cases that each assert their rule and their error text;
  - `design-selftest.sh`: planted defects, each of which must be caught;
  - `design-check.sh`: runs all of the above.

No code changes. Each TODO.md item becomes its own issue and PR.

## The verdict on `c0add9a` (BLOCK, 1 finding): does not reproduce

```
$ cue eval DESIGN.cue -e '[for t, _ in #InnerOfMachineAlt {t}]'
["pod", "vm", "local", "kubernetes", "android"]
$ cue eval DESIGN.cue -e '[for t, _ in #AlongsideAlt {t}]'
["pod", "vm", "local"]
$ cue export DESIGN.cue design/example/load.cue -l '"doc"' design/negative/candy-in-pod.yaml -e dispatch
    "x.extra: a pod admits inside it exactly one of: pod, vm, local, kubernetes, android"
$ cue export DESIGN.cue design/example/load.cue -l '"doc"' design/negative/alongside-candy.yaml -e dispatch
    "x.extra: beside a pod stands exactly one of: pod, vm, local"
```

These are exactly the texts that `candy-in-pod.yaml`, `alongside-candy.yaml` and the `alongside-dispatch` self-test row assert. `design-check.sh` passes on `c0add9a` (output in How tested: 64 negatives, and the `alongside-dispatch` row reported `caught`).
