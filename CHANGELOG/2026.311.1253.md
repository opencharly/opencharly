# 2026.311.1253 — feat(design): a render may start from a skeleton, and an assertion may be negated (batch 59)

## Summary

Batch 59 of the DESIGN amendments (tracked in #838). `verb:generate` filled a **template** with vars and
asserted things about the result. After batch 57 a `render` existed — but it could only start from a **schema**,
because `schema!` was required, so a template had nowhere to be named.

`#Render` is now **two arms** (`#RenderAlt`): a `schema` (a document checked against one) or a **`skeleton`** (a
file the render fills in), each spreading the shared `#RenderFields`. That is the same two-arms shape that made
the run step's choice enforceable in batch 57, used for the same reason — a spread distributes over a plain
struct, never over a disjunction.

The other keys map without inventing anything:

| authored key | home |
|---|---|
| `template` | `skeleton` (`template` is a §2 **Not** term for `box`) |
| `vars` | `var` |
| `validate` | `strict` |
| `report` | `report` |
| `negate_checks` | a following **`check` step** whose `file.content` uses a **negated matcher** — the design already has it (D-VERB-3: `not` negates one) |

**`verb:generate` becomes sharp.**

| file | what changed |
|---|---|
| `DESIGN.cue` | `#RenderFields`, `#RenderAlt` (schema \| skeleton), `#Render` |
| `DESIGN.md` | the example renders a changelog entry into its skeleton and asserts the absence of an internal host |
| `design/dulling.tsv` | `verb:generate` becomes sharp |
| `design/dulling-disposition.md` | regenerated |
