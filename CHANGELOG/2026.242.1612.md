# 2026.242.1612 — feat(pi): replace loop-guard with loop-protection plugin

## Summary

Replace the loop-guard extension with **loop-protection.ts**, a proper pi plugin that fixes the agent repetition loop at the tool layer.

**RCA (2026-08-30, from live session evidence):** the loop is driven by the model degenerating into emitting the SAME tool call hundreds of times in one response (observed: 317 identical `fabric_exec` calls, 43K tokens) plus degenerate text repetition ("torso" x 2000+). The response hits the provider's TOTAL output cap (`max_tokens` is thinking + answer), the harness fails every call with a context-less "Re-issue the tool call" error, and the model repeats more — a self-amplifying loop (1133 truncation errors, 600M+ tokens burned).

The old loop-guard (exact-match retry blocking) never fired because looping calls differ slightly each time (timestamped paths), and it did not address the truncation handling. The new plugin has four protections:

1. **`tool_call`** — blocks the Nth consecutive identical call (dedup) and blocks re-issues of calls from truncated responses with a corrective directive (replaces the harness's "re-issue" instruction).
2. **`message_end`** — detects truncated responses (`stopReason: "length"`), identical-call repetition, and degenerate text repetition; tracks consecutive truncations.
3. **`context`** — injects a corrective message when >= 2 consecutive truncations or degeneration is detected, so the model changes behavior instead of repeating.
4. **`tool_result`** — auto-compaction: bounds tool results > 20K chars to 8K + a note, so the context cannot flood (the flood drives the degeneration).
