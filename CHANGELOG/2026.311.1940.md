# 2026.311.1940 — fix(design): bound the shape walk so a truncated definition reports instead of crashing

## Summary

The shape control in `scripts/design-shape-check.py` walks a definition's body to its closing brace. When the last definition's brace never closes, the walk ends at `cursor == len(lines)` and the resume condition read `lines[cursor]`, raising `IndexError: list index out of range` instead of letting the control compare the quoted shape. A row that quoted that definition went unchecked, and the self-test reported a false green while its machinery crashed (opencharly/opencharly#921, first seen in opencharly/opencharly#920).

The fix is one bound: `cursor < len(lines)` in the resume condition. The `else` stays `cursor + 1`; the literal `else cursor` form in the issue never advances a one-line definition and runs until it is killed (the `rc=124` run is pasted below).

`scripts/design-ledger.sh` now sends the shape checker's stderr into the finding file, so a crash fails the control instead of printing a traceback beside a green summary. `--self-test` gains an eighteenth mutation, `a truncated definition walk`: a synthetic definition is appended to the schema with its brace left open, a ledger row quotes it stale (`#SelfTestTruncated: {beta}`), and the run must print the control's own `is quoted as` finding and no `Traceback`.
