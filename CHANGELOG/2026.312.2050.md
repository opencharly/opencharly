# 2026.312.2050 — docs(design): the CUE-module spike's answer becomes design

## Summary

TODO.md item 0.2 commissioned an RDD spike to prove the CUE-module foundation, and every item in
sections 2–6 of TODO.md depends on it. The spike ran on 2026-11-08 against the pinned CUE
v0.18.0-rc.1 and answered. **The operator's decisions are the authority for this change, and
TODO.md 0.2 is the commissioning item.** This PR records those decisions where the rules they
govern live, so the design documents are the whole deliverable: no code, schema, pin, script or
candy changes.

**The three decisions as taken.**

- **Closure wins.** Definitions stay closed and complete. Shared fields are inlined into each arm
  at generation time; nothing is extended. S6's "shared fragment" stops being an authored
  mechanism and becomes a generator concern.
- **Core generates the one-of struct itself.** `cue exp gengotypes` is used for leaf shapes only.
  Core emits the §13 C4 one-of struct and an exactly-one decoder from the registry, and it
  normalizes the `@v0` import suffix. The derived-union requirement (S4) is kept, and it is core's
  generator that keeps it.
- **Digest pinning is core's job.** CUE requirements are semver-only, so core fetches the module
  artifact by digest and composes offline.

**Why closure, in the design's own terms.** A closed definition cannot be extended: on the pinned
CUE a bare embedding beside further fields, a unification with a literal, and a unification with
another definition each report `field not allowed`; a spread of a closed definition is the one legal
composition, and the result still refuses an undeclared field; and only an open definition admits a
field nobody declared, which is the acceptance closure exists to refuse. So S1 and S6 could not both
hold as written. The measurement decided which one yields, and the document now names which form is
legal, which fails, and where the sharing lands instead — the generator's inlining onto the one-of
struct.

**DESIGN.cue is deliberately untouched, and A.6's order still holds.** The schema copy already

## Evidence

The measurement Block 1 asked for, executed in this session with the CUE this repository pins
(`bash scripts/design-cue.sh` -> v0.18.0-rc.1). Each case is its own module with the same
`cue.mod/module.cue`; only `main.cue` differs. The tree's own `DESIGN.cue` performs the first case —
`#StepFields` is a closed definition and the schema spreads it beside further fields — and its first
answer below is that schema's own `gengotypes` run:

```text
$ cue version | sed -n 1p
cue version v0.18.0-rc.1

# the design schema in this tree spreads a CLOSED definition beside further fields, and types:
$ cue exp gengotypes .   # in a module holding this tree DESIGN.cue
gengotypes rc=0

$ cat spread/main.cue
#Base: {a!: string, b?: int}
#Spread: {#Base..., c!: bool}
ok: #Spread & {a: "x", c: true}

$ (cd spread && cue vet .); echo "rc=$?"
rc=0

$ cat spreadjunk/main.cue
#Base: {a!: string, b?: int}
#Spread: {#Base..., c!: bool}
bad: #Spread & {a: "x", c: true, junk: 1}

$ (cd spreadjunk && cue vet .); echo "rc=$?"
bad.junk: field not allowed:
    ./main.cue:5:34
rc=1

$ cat embed/main.cue
#Base: {a!: string, b?: int}
#Embed: {#Base, c!: bool}
ok: #Embed & {a: "x", c: true}

$ (cd embed && cue vet .); echo "rc=$?"
ok.c: field not allowed:
    ./main.cue:4:17
    ./main.cue:5:23
rc=1

$ cat unifylit/main.cue
#Base: {a!: string, b?: int}
ok: #Base & {a: "x", c: true}

$ (cd unifylit && cue vet .); echo "rc=$?"
ok.c: field not allowed:
    ./main.cue:4:22
rc=1

$ cat unifydef/main.cue
#Base: {a!: string}
#Other: {c!: bool}
ok: #Base & #Other & {a: "x", c: true}

$ (cd unifydef && cue vet .); echo "rc=$?"
ok.a: field not allowed:
    ./main.cue:3:9
    ./main.cue:5:23
ok.c: field not allowed:
    ./main.cue:4:10
    ./main.cue:5:31
rc=1

$ cat open/main.cue
#Open: {...}
#Spread: {#Open..., c!: bool}

$ (cd open && cue vet .); echo "rc=$?"
rc=0
```

Three answers. A spread of a closed definition is legal and the enclosing definition closes the
result: the first case vets, and the second still refuses a junk field. The forms that fail with
`field not allowed` are the bare embedding, the unification with a literal and the unification with
another definition. And only an open definition admits a field nobody declared. That is what
DESIGN.md:§10.1 S1 and S6 now say, and what DESIGN.md:§13 D-GEN-8's spread sentence agrees with.

  retained spread wording contradicts this PR's measurement, on the premise that CUE closedness is
  module-independent, so a spread inside one module must fail as an embedding does. That premise is
  disproved by executed measurement on the pinned CUE (under `## Evidence`): a spread of a closed
