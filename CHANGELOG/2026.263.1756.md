# 2026.263.1756 — fix(sync): the generated body proves each moved pin's default-branch HEAD

## Summary

Fixes the validator findings on the generated sync PR `opencharly/opencharly#229` by correcting the **body generator** in `.github/workflows/sync.yml` (the sync PR is bot-authored; its body is emitted by this committed block and cannot be hand-edited into truthfulness without fixing the generator).

Findings fixed:

1. **The coverage gate could not fail on the diff** — the body offered `scripts/check-policy-b.sh` as "the one pinning assertion this PR's diff can violate", but it asserts only **`distro-*`** gitlinks, while #229 moved `dotgithub`/`eval-omarchy`/`marketplace`/`sdk` (zero `distro-*`).
2. **The default-branch claim had no per-pin evidence** — only four short SHAs, no ref.
3. **The emitted "staged submodule SHA" read the wrong object** — the working-tree HEAD (then `HEAD:<path>`), not the staged index gitlink.
4. **The self-test had no coverage of the staged-gitlink read**, and it **corrupted the calling repo** (R1): git exports `GIT_DIR`/`GIT_INDEX_FILE` to hook processes, and `git -C <dir>` does not override them, so the fixture's `git config`/`update-index` wrote into the umbrella (measured: `core.bare=true`, `user.name=t`, a stray `sub` gitlink).

**Fix.** The pin-evidence logic is extracted into a committed, self-testing script, `scripts/sync-pin-evidence.sh`:

- `staged_gitlink` reads the **STAGED INDEX gitlink** with `git rev-parse --verify --quiet :<path>` (the index entry), falling back to `git ls-tree HEAD -- <path>` **only** when the path is not in the index (already committed, so HEAD *is* the recorded pin). It never reads the submodule working tree (finding 3) — and it **scrubs `GIT_DIR`/`GIT_INDEX_FILE`/`GIT_WORK_TREE`/…** so it always targets the repo it names (finding 4).
- `--verify --quiet` + `|| true` are the load-bearing fix for the fallback: bare `git rev-parse ":$p"` **echoes the literal `:<path>` token** on failure and exits non-zero, so the old `[ -n "$sha" ]` guard passed and the `ls-tree HEAD` fallback was **dead code** (the validator's block on the previous head). `--verify --quiet` prints nothing and exits 1; `|| true` keeps that from aborting under `set -e`.
- The body prints, per moved pin, `staged-gitlink=<sha> remote-HEAD=<sha> [kind, EQUAL|not-equal]` (finding 2).
- Policy B is offered as coverage **only when a `distro-*` pin moved**; otherwise the body says so plainly and names the per-pin evidence as the real coverage (finding 1).
- `--self-test` covers the classification (both ways), the equality, the coverage branch (both directions), a **real fixture repo** where the staged pin differs from HEAD, and the **unstaged-path fallback** (an absent path → empty; a path in HEAD but removed from the index → HEAD's pin) — each arm fails without its logic. It is wired into the **pre-commit gate**.
