**The umbrella's body/diff reconciler had no arm that asked whether a pasted commit id EXISTS.** Every SHA-bearing arm it has judges a sha the tree NAMES (`git rev-parse HEAD`), a file path the diff changes, or a number the diff carries — so a well-formed 40-hex string that no repository has ever heard of passed every gate that runs on a body: the reconciler, the org linter, the pre-push hook. **The control** — arm I in `scripts/check-pr-body-diff.mjs`: every 40-character id a body pastes must RESOLVE — in this repo's own object store, in the object store of every declared submodule whose checkout is here (a submodule's commits live in ITS store, not in this one), and among the pin values the tree records. An id that resolves NOWHERE and that the body attributes to exactly ONE repository the tree can see is a finding that names it, the way the other arms name what they found. An id the tree cannot attribute — no repository named near it, several named, one whose checkout is not here, or one whose object store could not ANSWER — is REPORTED and not judged, because a false finding is worse than no report.

**The discipline** — the rulebook's PR-body section, and the umbrella's own `git-workflow` skill (the SOURCE the corpus projects) beside the evidence bullets it belongs with: a pasted commit id is quoted as the 40-character output of the command that produced it; a prefix is quoted as a prefix and never inside a fence that claims to be a command's output; a 40-character id that resolves in no store this tree can see is never a citation.
