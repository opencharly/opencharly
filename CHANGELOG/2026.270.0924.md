# 2026.270.0924 — docs(agents): issue-first coordination + broaden the pre-push read to issues

## Summary

Extends the umbrella rulebook (`AGENTS.md`) with the **issue-first** coordination model
and broadens the mandatory pre-push read to issues:

1. **Rule 9 — search first; file and own an issue.** Before any non-trivial work (and
   before filing anything), search the org for an existing issue/PR (`gh search issues` /
   `gh search prs`) and ADD to that thread rather than duplicating; if none exists, file ONE
   proper issue (title/problem/evidence/scope) and reference it from the PR. The issue is
   the coordination point: check its owner and CLAIM it (comment + assign) BEFORE branching;
   if another session owns it, coordinate on the thread instead of opening a competing PR.
2. **Rule 9 — replacing a PR or an issue?** Comment on the OLD one referencing the new one,
   so other agents can follow where the work continued.
3. **Rule 10 broadened.** Before ANY update push, read the PR's latest comments +
   validation AND the latest comments/state of every ISSUE it closes or relates to
   (`gh issue view <N> --comments`), and act on each — alongside writing the body.

Mirrors the `git-workflow` skill changes (opencharly/layer-charly-internals#32, B2b + the
"Replacing a PR or an ISSUE" reference).
