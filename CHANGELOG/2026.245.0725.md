# 2026.245.0725 — chore: enable autoupdate for the charly-plugins marketplace

## Summary

Enable `autoupdate: true` on the `charly-plugins` marketplace in the pi harness desired-state config (`.pi/claude-plugins.json`), so the opencharly skills vendored into the pi agent are updated **automatically** from the marketplace.

Why: the `pi-claude-marketplace` extension (v0.18.1) reads the per-marketplace `autoupdate` flag from `claude-plugins.json` and, when true, cascades every marketplace refresh into updating (re-extracting) the installed plugins' skills. Without the flag the effective default is `false` (`record.autoupdate ?? false`), so the marketplace→plugin (skill) update cascade is NOT guaranteed — it currently relies on the startup reconcile/install path alone. This change makes the cascade explicit.

Source-verified mechanism (pi-claude-marketplace 0.18.1, shipped under `.pi/npm/node_modules/pi-claude-marketplace`):

- `persistence/locations.ts` — project-scope desired state = `<cwd>/.pi/claude-plugins.json`
- `persistence/config-io.ts` — `MARKETPLACE_CONFIG_ENTRY_SCHEMA = { source: string; autoupdate?: boolean }`
- `orchestrators/marketplace/update.ts` — `snapshotAfterRefresh`: `autoupdate = merged.marketplaces[name]?.entry.autoupdate ?? false` (SPLIT-01: the flag lives in the config, not state); `cascadeAutoupdates`: `if (!snapshot.autoupdate || pluginUpdate === undefined) return []` → per-plugin update (skill re-extraction, content-hash detection via `domain/version.ts::shaVersion`) when the flag is on
- `orchestrators/marketplace/autoupdate.ts` — the `/claude:plugin marketplace autoupdate` toggle persists the flag to this exact config ("state.json is NEVER written by a flip; the config write-back is the real flip (SPLIT-01)")
- Automatic trigger: pi `resources_discover` → `applyReconcile` (`bridges/hooks/event-router.ts`, `orchestrators/plugin/reinstall.ts`)
