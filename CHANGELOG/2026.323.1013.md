# 2026.323.1013 — feat(gh)!: one TypeScript watcher and coordination toolset for every harness

## Summary

ONE TypeScript implementation of the GitHub watcher, the validator-verdict classifier, the coordination comment and the session footer, used by every harness (opencharly/opencharly#1140). Head: `6ae08cba044da313eb97bcff94439d936e26f2fc` — 48 files, +2553 −3114 (round 2 adds one commit, `docs(gh): count the watcher on its node process, and decide T4 from the diff`).

**Why.** The org had three shell watchers (`gh_watch.sh`, `pr_watch_many.sh`, `pr_state_watch.sh` over `_watch_common.sh`), a shell coordination CLI (`coord.sh`), an OpenCode-only TypeScript engine and a fourth classifier in pi's `gh_pr_status`. They disagreed on what a verdict is. The one that every non-OpenCode session armed, `gh_watch.sh --events verdict`, keyed on the workflow run id, so it never saw a REST re-run (a new attempt under the same id) — opencharly/marketplace#628. The operator directed one set of TypeScript scripts for everything.

**What lands (umbrella leg; the marketplace deletion is a later leg, see Change classification):**

1. **`scripts/gh/` — the one implementation.** `node` runs it directly (type stripping; no build).
   - `lib/github.ts` — token resolution, REST and GraphQL, ONE rate-limit policy: back off ×2 (cap 600 s) below 200 remaining; any rate-limit signal is FATAL.
   - `lib/watch.ts` — the engine. **A verdict is the newest `validate / validate` check run of the `charly/pr-validator` suite on the PR's head**; it fires when that run is FINAL and NEW (a different check run than at arm, or not yet completed at arm), so a REST re-run fires. Classes PASS / BLOCK / INCONCLUSIVE (the validator's comment for that head) / PENDING. Events `verdict`, `merged`, `closed`, `conflict`, `comment`, `stall`. One batched GraphQL request per poll for N items; a 300 s poll floor that is REFUSED, not clamped.
   - **`conflict`** (new, default): a PR that conflicts with its base gets no test merge, so GitHub runs no validator at all and a verdict watch would wait forever. Measured on opencharly/opencharly#1145, which sat with no run for hours; the watch now wakes `CONFLICT` on that state.
   - `lib/coord.ts` — the closed verb set, the comment builder, the session footer and the identity rules (Claude Code / DSH session env, `COORD_*`, an in-process id).
   - `lib/lock.ts` — one watcher per item set; a second arm takes over the first.
   - `cli.ts` — `watch`, `status`, `footer`, `comment`; exit `0` event · `4` timeout · `5` usage/API · `6` lock · `7` rate limit · `8` initial poll · `143` taken over.
2. **Every harness binds it.** OpenCode's `coord.ts`, `pr-watch.ts`, `tracker.ts` and `lib/watcher-loop.ts` import the shared lib; pi's `watch.ts` spawns the CLI (with `--no-arm-wake` on re-arms), `github-pr-status.ts` is a one-shot read through the engine and `footer.ts` uses the shared builder; reasonix's hook prints the CLI command; Claude Code, Codex and DSH run the CLI as a background command.
3. **Deleted (R2, R5):** `.opencode/lib/watch.ts` (the OpenCode-only engine, 750 lines), `.opencode/lib/wake-line.ts`, pi's second classifier and watch loop, and `scripts/check-opencode-coord.mjs` (folded into the new gate).
4. **`scripts/check-gh-tools.mjs`** — the gate, wired into `charly task verify` and `hooks/pre-commit`: the pure contract (A), the CLI end to end against a local GitHub (B), the OpenCode binding in process (C), the footer against `pr_body_lint.py`'s `SESSION_LINE` (D), and the REAL `opencode` binary (E, `LIVE_OPENCODE=1`). `--self-test` runs ten mutations of the toolset in parallel and each must turn the gate RED.
5. **`scripts/check-body-removed-identifiers.mjs` judges removal against the head.** Deleting the three TypeScript files removed block-scoped locals (`s`, `it`, `session`, `verdict`, `footer`, …) that are alive in the new code, and the pre-push leg refused this body 27 times for naming them. A name now counts as removed only if the head tree no longer contains it as a whole word, read from git objects; a renamed test or a deleted helper is still caught. Its self-test gains one GREEN and one RED case for this, and all 15 of its arms discriminate.
6. **Stale docs swept in the same change:** the old rule range R0–R10 where the linter now requires R0–R11 (the self-audit, the Claude commit gate's header, a `sync-pr-body.sh` comment), the `hooks` task's description of what the hooks run, and `coord_watch`'s mechanism in `.opencode/instructions.md`.
7. **The guidance names one tool.** AGENTS.md's watcher gist and footer writer, the git-workflow skill (the decision table in `references/watch-and-wake.md`, the self-audit step, the footer table), the agents skill, and every harness's README, prompt and items file.
