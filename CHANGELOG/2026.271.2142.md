# 2026.271.2142 — fix(opencode): async + abortable coord executors (spawnSync froze the server)

## Summary

**R1 RCA fix (closes #299): `.opencode/plugins/coord.ts` used `spawnSync`, which
froze and restarted the opencode server.**

`spawnSync` blocks the server's event loop for the child's whole lifetime and
ignores the tool executor's abort signal. `coord_watch` runs the **long-lived**
`gh_watch.sh` watcher, so a single call froze the server for the whole watch window
and the supervisor restarted it. Measured: `grep -c spawnSync .opencode/plugins/coord.ts`
was **4**; `grep -c signal` was **0**.

Both executors now run their script through the SAME async, abortable primitive
`pr-watch.ts` already uses (`Bun.spawn`); never a synchronous spawn helper. The tool
executor's `context.signal` is wired to a `kill()` on abort (via the signal's
`abort` event — **not** a spawn option), and `coord_watch`'s `timeout` is
additionally enforced tool-side as a deadline that triggers the same kill.
Behaviour is unchanged (argv building, TIMEOUT-vs-error, footer). A Node fallback
keeps the executor unit-testable under plain `node`.

### Why SIGKILL, and the deadlock-safe await

- The watcher installs `trap '…' TERM`; bash **defers** a SIGTERM until its
  foreground child (`sleep`) finishes, so a SIGTERM abort overran to the full 30s
  stub (MEASURED). **SIGKILL is untrappable** (measured 1502ms with the trap
  installed).
- After a process-group SIGKILL the runtime's exit event is not guaranteed, so the
  await **races the natural exit against our own kill decision** — `spawnCapture`
  always returns promptly and can never hang the executor.

### Tests (`scripts/check-opencode-coord.mjs`)

- **static guards**: `coord.ts` contains NO `spawnSync`; wires the abort (an `abort`
  listener **and** `toolCtx?.signal`); spawns via the Bun runtime at the **CALL SITE**
  (`bun.spawn(` + the `globalThis.Bun` lookup, not a doc-comment mention); kills with
  `SIGKILL`.
- **deterministic unit test** (plain `node`): `coord_watch` with `timeout=1` kills a
  30s watcher (which installs a TERM trap) in ~1s; an aborted signal returns
  promptly. (A/B/B2 run in-process under `node`; only the live C layer runs against
  the REAL binary.)
- **`LIVE_OPENCODE=1`** (the REAL binary, the **Bun** path): a staged 30s watcher
  records START at once and FULL only after its sleep; the check asserts START fired
  and **FULL did NOT** (a blocking spawn would reach FULL), and that the plugin
  loaded at most once (no reload).

`.opencode/instructions.md` documents the async/abortable requirement.

**Run-duration RCA (why the live run is ~37s, not ~2s).** The measured wall time is
dominated by opencode's own boot + ONE model turn (~15-40s; the model must emit a
tool call), NOT by the watch. The watch itself is bounded by the START/not-FULL
discriminator: the 30s stub was killed at its 2s deadline. The assertion is
therefore bound to the START/FULL evidence, not to wall-clock, so it fails on the
blocking path.

**`coord_comment`'s `toolCtx` pre-existed on `main`** (no signature change needed):


The round-3 commit adds a one-line comment above that signature so the context (and
`toolCtx`'s use of `signal`) is visible in the diff; both executors thus call
`spawnCapture(argv, { signal: toolCtx?.signal })` with `toolCtx` in scope.

The RCA reproduced the defect first (a `timeout: 3` `coord_watch` ran a 20s stub to
completion) and the fix removes it.
