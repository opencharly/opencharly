# 2026.267.0926 — fix(opencode): port the umbrella gate plugin to the V2 plugin contract

## Summary

The umbrella's opencode gate plugin (`.opencode/plugin/umbrella-gates.ts`) was
written to the **V1** opencode plugin contract: a default-exported function that
receives `{ directory }` and returns a keyed hook map
(`{ "tool.execute.before": … }`).

opencode ≥ 2.0 (this was measured on **2.0.16**) no longer loads that shape. The
loader logs a **WARN** and keeps starting:

```
msg="failed to load plugin" target=.../.opencode/plugin/umbrella-gates.ts
cause="Cause([Fail(PluginModule.LoadError: Plugin must export a default definition
  with an id and an effect or setup function. (cause: SchemaError(Expected object
  at [\"default\"])))])"
```

Because it is a WARN, startup succeeds and the failure is silent: the
pre-commit / pre-push gates simply **stopped running** in the opencode harness,
so `git commit --no-verify`, force-push and direct-to-`main` push were no longer
blocked there. Nothing in the repo loaded the plugin under a real opencode, so
nothing caught it.

This PR ports the plugin to the V2 contract, adds a regression gate that fails on
the old V1 form, and wires that gate into the umbrella's commit and pinning gates.

### What changed

- **`.opencode/plugin/umbrella-gates.ts` → `.opencode/plugins/umbrella-gates.ts`** —
  moved to the documented V2 discovery location and rewritten as a V2 definition:
  ```ts
  export default {
    id: "umbrella-gates",
    async setup(ctx) {
      const hooksDir = join(ctx.location.directory, ".claude", "hooks");
      await ctx.tool.hook("execute.before", async (event) => { … });
    },
  };
  ```
  The V2 shell tool is named **`shell`** (V1's `"bash"`), so the hook matches
  `event.tool === "shell"` and reads `event.input.command`; a gate that exits 2
  makes the hook throw, which denies the tool call. The gate-script invocation
  (stdin payload, timeout, stderr surfacing) is unchanged, so gate behaviour is
  byte-identical.
- **`scripts/check-opencode-plugin.mjs`** (new) — **no stubs or mocks**: every
  layer runs the real artifact.
  - **A** — the plugin is a real ES module whose default export is a V2
    definition (object, string `id`, `setup` function). The V1 default-exported
    function fails here; that is the regression this gate exists for.
  - **B** — the **real** `.claude/hooks/pre-commit-gate.sh`, invoked with the same
    stdin payload the plugin sends, must BLOCK a hook-bypassing commit (exit 2)
    and ALLOW a benign one (exit 0).
  - **C** (opt-in, `LIVE_OPENCODE=1`) — the **real** `opencode` binary is driven
    end to end in a throwaway project: the loader resolves the plugin id, a gated
    `shell` call is **denied**, and a benign `shell` call succeeds. Skipped
    visibly when unset (live-or-skip; never a silent pass).
- **`hooks/pre-commit`** and **`scripts/verify-pins.sh`** — run the check, so a
  V1-contract plugin fails a commit locally and fails `task verify`.
- **`.opencode/instructions.md`** and **`HARNESS-PARITY.md`** — updated to the new
  path and the V2 contract.

### Relation to `opencharly/charly`

The umbrella plugin is a fork of charly's `.opencode/plugins/charly-gates.ts`,
which has the same defect. charly's copy was fixed in `opencharly/charly#645`
(merged, tag `v2026.267.0802`); its regression check is updated to this same
no-stub version in a companion charly PR, so the two copies stay byte-identical
(shared, not forked). Advancing the umbrella's `charly` gitlink to that merge is a
policy-B pin bump (a different change class and a whole-diff `task sync`) and
lands as its own sync PR; the `SHARED[]` parity entry for this script is added
there, since it compares against charly's pinned file.

The DENY uses a staged `charly/*_aliases.go` (a state-based block), not a
recognizable bypass flag, because the model self-censors on flags like
`--no-verify` and would never call the tool — which would prove nothing about the
gate. An innocent command is reliably run, and only the gate refuses it.
