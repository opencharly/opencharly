## Summary

**The two findings the `charly/pr-validator` raised on #726, fixed here.** Both were raised on this session's own pull request, so neither is filed away (R1): they are fixed, and the fix is measured below.

Head `83b2177b7e84aa4a1e37fc2c0880883e9e5f88b2` — the commit this PR pushes: **2 files changed, 74 insertions(+), 13 deletions(-)**.

**The first finding: the committed self-test could not discriminate the change #726 shipped.** The mechanism is exact. The harness's "self" mutation targeted a **plain string** that occurs TWICE in `scripts/check-governance-reconcile.mjs` — once in the D assertion it breaks, once in the mutation table's own copy of it. `String.replace` replaces the FIRST occurrence, so the parent's application consumed the D assertion and left the table's literal alone. The nested run's `mutate()` therefore still applied, the "mutation ... did not apply" case was **unreachable** in the committed harness, and the committed self-test read green in the guarded ordering and in the unguarded one alike.

**What this change does.** Every mutation target is now a **REGEX**, so a target's own source is not the text it matches and every target occurs EXACTLY ONCE in the file; the harness **counts** the occurrences and refuses an ambiguous target BY NAME. The "self" verdict must also be the parent's to read: the nested run must fail on EXACTLY the assertion under test, and must have taken the skip path. A nested run that reports a failure of its own is refused — and that refusal is what makes the guard's POSITION observable, so the committed coverage now fails without the change (the control below).

**The second finding: the record of #726 stated a claim no run makes.** `CHANGELOG/2026.300.0536.md` wrote that the pre-fix run was "RED on the first" and the shipped run "GREEN on the second". Both runs exit non-zero: the pre-fix run reports `FAIL (2)`, the shipped run `FAIL (1)` — the D failure, which is the assertion under test, is in BOTH. The record is corrected in this change, and the claim-keyed sweep is below. The published commit message of `36ab3b9` carries the same miswording and is **not** rewritten (R6): a published commit is not the tree's record, and the record is where a correction belongs.

| file | what it changes |
|---|---|
| `scripts/check-governance-reconcile.mjs` | every mutation target is a regex that occurs exactly once, the harness counts the occurrences and refuses an ambiguous target by name, and the "self" verdict must be exactly the assertion under test on a nested run that took the skip path |
| `CHANGELOG/2026.300.0536.md` | the record's "RED on the first and GREEN on the second" claim, which no run makes: both runs exit non-zero, and the pre-fix run reports one extra failure |

Closes #727
