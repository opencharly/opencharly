### What the chain changed: ONE resolver, on the surface both sides may import

`opencharly/charly#1119` recorded why core could not reach the ONE cache-root resolver: it lived in
`sdk/storekit`, a mechanism kit the plugin HOST may not import, so core hand-built
`$XDG_CACHE_HOME/charly` and `$XDG_RUNTIME_DIR/charly` and ignored `CHARLY_CACHE_DIR` — the idle
guard could not see the buildkitd it exists to follow and would kill a running install as WEDGED.
The three producer changes close that in one direction only:

- **spec#303** adds `spec/storeroot`, the contract module carrying the four roots (config, cache,
  state, runtime) and the single `CHARLY_CACHE_DIR` override.
- **sdk#499** deletes storekit's own computation and re-exports the contract module's:
  `type Root = storeroot.Root`, the four consts are re-exports, and `Dir`/`CacheDir` delegate — no
  second implementation, and the public API does not move.
- **charly#1121** resolves the idle guard's daemon discovery through it, so the import-purity gate
  passes AS WRITTEN — no exception, no residual-SDK row.
