# 2026.279.2217 — fix(tasks): make the seven maintenance tasks declare a context a runner activates (#413)

## Summary

Closes #413. The umbrella's seven maintenance tasks — `map`, `pins`, `self-test`, `hooks`,
`sync`, `skills`, `prune` — declared `context: [deploy]` on their only step. `deploy` is the
install-LOWERING axis; the plan runner activates exactly two contexts, box mode → `build` and
live mode → `runtime`. All seven now declare `[runtime]`, the value `verify`, `policy-b` and
`org-map` already carried, and a new gate keeps it that way.

| path | change |
|---|---|
| `charly.yml` | the seven `context:` values; a house-rule paragraph in the task-surface banner; `verify`'s composed-step comment, whose earlier reasoning was wrong |
| `scripts/check-task-contexts.mjs` | NEW — the gate; registered as `verify`'s 18th step and in `hooks/pre-commit`. Matches a step opener generically (any `- <word>:` in a `plan:`), and pins that breadth with a mutation of its own |
| `hooks/pre-commit` | the same gate, so a commit cannot introduce the defect |

### The RCA, and the two claims it corrected

#413 asked for the intent of `[deploy]` before anything was changed, on the ground that
flipping it was a behaviour change rather than a spelling fix. Establishing the mechanism
turned up two wrong answers — **both of which I had already written into the comments before
checking them against the source** — and both are corrected in this change rather than left
for the next reader to trust:

```
$ git diff --numstat origin/main...HEAD
46	15	charly.yml
4	0	hooks/pre-commit
305	0	scripts/check-task-contexts.mjs

$ git diff --shortstat origin/main...HEAD
 3 files changed, 355 insertions(+), 15 deletions(-)
```

(`46 + 4 + 305 = 355` insertions, `15` deletions, across the `3` files named two lines above — the arithmetic closes on the pasted numbers without needing a rendered bar chart.)

**1. "`charly task <name>` runs with a nil grammar."** It does not. The `task` verb supplies
its own grammar:

```
plugin-task/candy/plugin-task/grammar.go
  // InContext is always true: a task's steps run regardless of build/runtime mode.
  func (g taskGrammar) InContext(op *spec.Op, runtime bool) bool { return true }
```

wired in `newTaskRunner` (`plugin-task/candy/plugin-task/runner.go`) and reached by `runTask`
(line 145) before `kit.RunPlan`. That file documents the substitution as *"the grammar SEAM's
purpose … it is not a workaround"*: a task is host-native and has no image-build timeline to
separate. So **no task step, at any `task:`-composition depth, is ever context-gated** — which
is the real reason the seven tasks all worked, and the reason the value could sit there wrong.

**2. "An omitted `context:` falls back to nil — the same no-op as `[deploy]`."** It does not
either. Every step in this file is authored as `<word>: <input>` sugar, and the desugar rewrites
all of it to the generic `plugin` verb:

```
charly/charly/reserved_registry.go
  // the generic `plugin` dispatcher is the desugar's rewrite TARGET (every `<word>: <input>`
  // sugar key becomes plugin/plugin_input internally)
  var internalOnlyVerbs = map[string]bool{"plugin": true}
```

and `plugin`'s catalog entry is the **permissive** one:

```
spec/spec/verb_context.go
  "plugin": {ctxBuildDeployRuntime, DoAssert, false},
```

An omission therefore inherits "may run in any mode" and is harmless. That is exactly what
makes an explicit `[deploy]` *worse* than no key at all: it replaces a permissive default with
a dead set. The fallback chain itself, for completeness:

```
charly/charly/planrun_adapter.go
  // opEffectiveContexts returns the op's resolved execution contexts: an explicit
  // Context wins, else the verb's VerbCatalog default, else nil.
```

### Consequence, stated plainly rather than oversold

**The flip has no observable effect on today's behaviour.** Nothing walks a task's plan through
a grammar that consults the value, and nothing outside this repo composes any of the seven —
the only `task:` compositions of any of them are the three inside this file, all dispatched
through the task verb:

```
$ grep -rn --include=charly.yml -E '^[[:space:]]+task:[[:space:]]+(map|pins|self-test|hooks|sync|skills|prune|policy-b|org-map)$' .
charly.yml:129:          task: pins      # policy-b
charly.yml:178:          task: pins      # sync
charly.yml:198:          task: pins      # verify
```

Three hits in the whole tree, against **711** populated `charly.yml` files — so the search
was not vacuous (`find . -name charly.yml -size +0 | wc -l` → `711`, i.e. every submodule is
checked out and was actually scanned).

So the honest description of this PR is *not* "the maintenance tasks were broken and are now
fixed". They were never broken, and they were never not bed-runnable. What was wrong is that
the file **declared a mode that does not exist** — a declaration nothing could have honoured,
which is precisely the kind of thing that becomes a real skip the day the seam changes or the
step is copied into a check plan. The value now says what it means.

The `--self-test` mutates real regions of the shipped file — `map` back to `[deploy]` (assertion
A), the `skills` step's `context:` key deleted and the `org-map` step's set emptied to
`context: []` (assertion B, the Go `len(op.Context) > 0` zero-length-slice fall-through) — and
carries a **negative control**: a reachable set (`[build, deploy]`) must stay GREEN, because a
gate that fails on every change proves nothing.

And that last mutation is not decoration. The gate matches a step opener **generically** — every
`- <word>: …` item inside a `plan:`, which is the grammar's own shape — rather than enumerating
the four step verbs this file happens to use. An enumeration would make a step written with any
other sugar word invisible to the gate, and a completeness gate that cannot see a step is worse
than none: it reports *every step is reachable* over a set it silently truncated. But the
widening is **otherwise unpinned** — both the generic and the narrow regex count 27 steps on
today's file, so no check would fail if the breadth regressed. So the assertion is measured in
both directions:

```
$ sed 's#^const STEP_RE = .*#const STEP_RE = /^(\\s*)-\\s+(check|run|agent_check|agent_run):\\s*(.*)$/;#' \
      scripts/check-task-contexts.mjs > /tmp/gate-narrow.mjs   # the same gate, narrow opener
```
