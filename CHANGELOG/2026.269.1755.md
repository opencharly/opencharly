# 2026.269.1755 — chore(gitignore): ignore the root's generated VM-image + build-context files

## Summary

Add three missing generated-state classes to the umbrella root `.gitignore`:
`image/`, `.containerignore`, `.dockerignore`.

### RCA (8-step, R1)

**Unexpected.** After ordinary work at the umbrella root, `git status` reported
untracked files that are pure generated state:

```
?? .containerignore
?? .dockerignore
?? image/
```

**Mechanism.** The root produces the same generated-state classes charly's own
`.gitignore` already lists, but three were never added when #253 ("ignore root
local state") added `.check/`, `.build/`, `.opencharly/`:

- `image/` — built VM disk/seed artifacts (`charly vm build`; the configurable
  `vm.image_dir` root, default `image` — confirmed by `eval-omarchy/.gitignore`,
  which already ignores `image/` for exactly this reason).
- `.containerignore` / `.dockerignore` — `charly box generate` build-context
  ignore files (`defaults.context_ignore`); charly's own `.gitignore` lists both.

**Root cause.** An incomplete sweep in #253: it enumerated `.check/`, `.build/`,
`.opencharly/`, `scratchpad/`, `.worktrees/`, `bin/` but not the VM-image and
build-context classes the root also produces.

**Blast radius.** An honest root `git status` after any VM build / box generate.

### Fix

Add the three entries to the existing "Local-state classes" block (with the same
one-line rationale style), so the root tree stays clean.
