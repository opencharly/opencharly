## Summary

Head `5a50ca6604052e9e0a230198ba39e9d13b412375` — the commit this PR pushes. This PR's diffstat against `origin/main`: **2 files changed, 93 insertions(+), 11 deletions(-)**.

`scripts/init-submodules.sh` refuses to advance a path whose work tree is not clean — the right rule, read from the wrong view. git reports a NESTED path's divergence in the PARENT's porcelain view, so a descendant's state made the parent's view non-empty, and the guard refused a path whose OWN work tree was clean. The parent's own uncommitted work and a nested path's divergence were ONE condition in the view, and only the first is the parent's business.

**The advance is not recursive, so the two are not the same condition.** `git submodule update --init -- <path>` moves the parent's own checkout and nothing under it, so a descendant's state cannot hold the parent back. The nested level is the nested pass's business, at the nested level, under the same policy one level down — the policy the nested pass was written for.

**The guard now judges the path by its OWN work.** The porcelain view is taken with the path's DECLARED nested paths excluded by PATHSPEC — `git -C <path> status --porcelain -- . ':(exclude,literal)<nested>'`. The exclusion is a pathspec and not a filter on the output, so the parent's own uncommitted work — tracked, staged or untracked — is still reported, and only the declared nested paths leave the view. The declared set is read by the ONE reader the nested pass already uses (`declared_submodules`), so both levels read the same set, and a set that cannot be read FAILS LOUD rather than silently widening the view.

**The notice no longer names a cause that is no longer in the view.** It says the path's OWN work tree is not clean — its own uncommitted work — and names the reason it acts on.

**The coverage is DISCRIMINATING, and the mutation is live.** The self-test gains the fixture that makes git's view really see the divergence — the path's own config does NOT hide the nested path — and the claim that pins the shape: the parent advances to its record, the nested work survives, the nested divergence is still REPORTED (at the nested level), and the parent's own notice does not appear. With the guard reverted to the parent's whole view, the parent stays at its old commit, the claim FAILS, and the parent's own notice appears — the defect's own shape. Pasted below.

**The PRODUCT does the opposite, and that is filed, not hidden.** MEASURED against the product's own sequence (plugin-task v0.2026297.2108: `pinSubmodule` → `reconcileNestedCheckouts` → `git -C <path> submodule update --recursive`, the `--init`-less form), a nested checkout that carries a local commit is MOVED OFF that commit, with exit 0 and nothing reported: the local commit left HEAD, no branch carries it, and the parent's own view is clean afterwards. The umbrella's own initializer refuses that same checkout. Two implementations of the same act disagree, and the looser one is in the product — filed as opencharly/plugin-task#54 with the RCA and the measurement, and claimed. Pasted below.

**The two over-long comment lines in `.pi/extensions/charly-gates.ts` are re-wrapped** — the same 55 words, the file's own width — carrying #715's validator finding into this leg, because #715 is merged and a published commit cannot be amended (R6).
