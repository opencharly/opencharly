# 2026.314.0303 — chore(pins): advance plugin-cua to its §10.1 vocabulary tables

## Summary

`opencharly/plugin-cua#10` merged as `cfed3bf3b64400302d6d461a479213a8ae7e9cbd` and was tagged
`v2026.314.0145`. It converted the plugin's three inline `|` word unions — `_delivery`,
`_permissionMode`, and `_method` (a 29-word catalog written one alternative per line) — into
§10.1 S3 vocabulary tables, each with a derived `_…Word` list and an `or()` enum tagged
`@vocab(cua)`. The umbrella still pinned the pre-merge
`4b2c71be77f9a9031b5bc5371a067ec057e913e1`, so this PR advances that gitlink to
`09ced48ba8403ada9042d1dccde137abb2801c17` (the CHANGELOG tip the tag-on-merge workflow wrote
above the merge) **and lowers the §25 census in the same commit**, because
`scripts/design-dpat.sh` fails in both directions: a new violation AND an occurrence falling
below its recorded row. Pin and census cannot be split.

**Measured first, and it changed the report.** In a worktree with the working set materialized
and `plugin-cua` unmaterialized — the light tree's normal shape — `charly task pins --param
MODE=currency` reported the pin as `differs (no checkout to judge ancestry)` with
`producer-first legs: none reachable from this repo`:

```
currency: 1 of 409 pin(s) NOT current [408 cur, 1 differs (no checkout to judge ancestry)];
intents: 403 upstream leaf/leaves (403 implicit), 6 derived-from edge(s);
NOT CURRENT: plugin-cua: differs (no checkout to judge ancestry); intent upstream:main
(implicit: .gitmodules branch=); recorded 4b2c71be77; served 09ced48ba8 (branch);
producer-first legs: none reachable from this repo
```

After `CHARLY_INIT_PATHS=plugin-cua ./charly/bin/charly task init` materialized the checkout at
the recorded gitlink, the SAME pin against the SAME remotes read `1 behind` and named the leg:

```
currency: 1 of 409 pin(s) NOT current [1 behind, 408 cur]; intents: 403 upstream leaf/leaves
(403 implicit), 6 derived-from edge(s); NOT CURRENT: plugin-cua: behind; intent upstream:main
(implicit: .gitmodules branch=); recorded 4b2c71be77; served 09ced48ba8 (branch);
producer-first legs: plugin-cua (4b2c71be77 -> 09ced48ba8)
```

The advance existed the whole time; the first reading withheld it because the control could not
judge it, and its empty leg list read like "nothing to do". **One pin moved** — the wave reports
`pinned 6 pin_map entr(y|ies) (…; 0 moved) after rolling 8 leaf submodule(s) to their
default-branch HEAD (1 moved) and advancing 395 leaf pin(s) in the index (0 moved); 1 pin(s)
moved`.

**The census was regenerated, never hand-edited.** `bash scripts/design-dpat.sh --emit-census`
run at the OLD pin reproduces the committed `design/dpat-baseline.tsv` byte for byte — which
calibrates the instrument — and run at the NEW pin it removes exactly the 30 `plugin-cua` `union`
rows and adds nothing. `design/dpat-baseline.tsv` therefore goes from **583 lines to 553**, the
tree's known-violation count from **617 to 587** (union **382 → 352**), and the gate then agrees
with the tree in both directions.

**One more file, for the same reason.** The rewrite moved lines in the pinned `cua.cue`
(171 lines → 191), so the two `design/dulling.tsv` rows that cite it **by line** were
re-anchored to the constructs they name: `#CuaMethod` is now at `:167` (was `:113`) and
`#CuaDeviceInput` at `:173-191` (was `:137-171`). Neither the `29 Cua Driver operations` count
nor any of the words those rows name changed in the rewrite — verified against the new table,
which holds exactly 29 entries — so only the anchors moved.
