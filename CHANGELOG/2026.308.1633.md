# 2026.308.1633 — feat(design): give a cluster node its image and its reach-path port (batch 21)

## Summary

Batch 21 of the DESIGN amendments the capability ledger records (tracked in #838). **A cluster node gains
two fields, and the row stays `dulled` — now saying what actually remains.**

A `kind: kindcluster` template carried a **node image** and, per node, the **extra port mappings** that
make the ingress/NodePort path reachable. `#ClusterNode` was one field: `control_plane`.

| file | what changed |
|---|---|
| `DESIGN.cue` | `#ClusterNode` gains `image` and `port`; `#ClusterPort` (container port + the host port it publishes) |
| `DESIGN.md` | the kubernetes example sets a worker node with both |
| `design/dulling.tsv` | `kind:kindcluster` states what is now present and what still is not; `kind:kubernetes` no longer quotes the old one-field node shape |

`kind:kindcluster` stays **dulled**: `admission_policy` and the storage/ingress/image_default/pod_default/
defaults policy blocks still have no field. The row previously counted the node image among the missing;
it no longer does, which is the point of recording a partial restoration rather than claiming a verdict
the design does not support.
