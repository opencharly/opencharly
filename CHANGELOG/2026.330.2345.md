`#issuecomment-42` is not a corner case — it is the shape `gh pr comment` PRINTS, and the rulebook
coordinates through those comments. A dropped item is a watcher that never wakes while the session
believes it is armed, which is the failure this repo has already paid for once.

**The fix.** The engine gains `parseItemsFile` — the file reader that was *missing*, which is why
each binding invented one — beside `parseItem`, and the CLI gains `items <file>` so a binding that
cannot import TypeScript (the reasonix shell arm) uses the engine too. Every binding delegates and
owns no acceptance set. Validation stays in the ONE place that can act on it: `watch`, by name,
exit 5 — a binding that pre-filtered turned that refusal into silence.

### Spike

**RCA claim:** the items-file grammar lives per binding instead of once in the engine, so the
acceptance sets drift and a binding silently drops a valid scope.

**Candidates, each spiked against the shipped code and the engine's own observable behaviour:**

- **C1 — engine owns the whole grammar; bindings pass lines and validate nothing. WORKS.** The
  refusal already exists at the ONE place that can act on it: `cli.ts watch not-an-item` →
  `gh watch: malformed item 'not-an-item' — want owner/repo#123 or a GitHub PR/issue URL`,
  `exit=5`, while `github.com/o/r/pull/5` is accepted and watched. A binding that pre-filtered could
  only hide that.
- **C2 — engine exposes a reader returning `Item[]`, dropping malformed lines. REJECTED:** it
  reproduces the exact silence the issue is about, just inside the engine instead of outside it.
- **C3 — keep per-binding filters but derive them from `parseItem`. REJECTED:** it removes the
  DRIFT but keeps the SILENCE — pi still discards the `#issuecomment` form (its filter calls
  `parseItem`, gets `null`, and drops it), which is half the finding.

Winner: **C1**, and it is what the diff implements.
