# 2026.242.1024 — docs(pi): document output-cap config mismatch root cause

## Summary

The loop-guard (PR #52) blocks the retry but not the truncation. This change documents the ROOT CAUSE of the truncated responses in `.pi/APPEND_SYSTEM.md` so future sessions cannot re-introduce the mismatch.

**Root cause (RCA'd 2026-08-30):** the session's generation config requested more output than the model can produce:
- `deepseek-v4-flash:0731` (ollama-cloud) has a real output cap of `maxTokens: 32768` (models-store.json catalog, `reasoning: true`).
- `~/.pi/agent/models.json` overrode it to `65536` — the harness sent `max_tokens=65536`, the provider stopped at 32768 with `finish_reason="length"`, and the harness failed every tool call in the length-stopped message ("Re-issue the tool call with complete arguments").
- `defaultThinkingLevel: "high"` made truncation inevitable: high reasoning on a 32K output budget leaves too little for tool-call arguments.

**The config contract documented:** `maxTokens` must equal the model's real cap (never more); the thinking level must fit the output budget (`low`/`off` for a 32K-cap model); tool calls stay short; large-output needs use a model that has one (untagged `deepseek-v4-flash`, maxTokens 1048576).

The user-level config was fixed in the same session: `models.json` maxTokens 65536→32768, `settings.json` defaultThinkingLevel high→low.
