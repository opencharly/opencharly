# 2026.319.1102 — feat(tooling): the org map reconciles in BOTH directions, and it gets a caller

## Summary

Closes #1030. `charly task org-map` asked ONE direction of the two halves it joins: every
`.gitmodules` submodule had to have a row, and a row advertising a repo the umbrella does
**not** pin was never checked. A retirement is exactly the change that leaves that state —
the pins go, the prose stays — and that is how the Omarchy retirement's first draft left a
README advertising `distro-omarchy` while every count beside it had been fudged to match.

The RCA found **two** independent signatures under that one symptom, so both are fixed here:

| # | signature | what closes it |
|---|---|---|
| **S1** | the reconciliation is one-directional (row → submodule unchecked) | `A4 row→submodule`, proved RED on its own mutation |
| **S2** | the control has **no caller** — nothing in the tree runs it (the repo's "gate with no caller" class) | `hooks/pre-commit` runs it on every commit, and `A6` fails if that leg is removed |

The reconciliation moves out of the inline heredoc into `scripts/org-map.py` — ONE
The arms: the anchors, each section's own `N repos` claim, its row order, submodule→row,
row→submodule, and the header census. `charly task org-map` runs the control and its discriminator in the
shape `check-verify-branch-audit` already uses.

**One claim in my first version of the caller arm was wrong, and the mutation caught it:** a
bare `"scripts/org-map.py" in hook_text` test PASSED with the leg deleted, because the hook's
own header block names the script in prose. The arm is anchored to the CALL SITE now (a
stripped line that must START with the command), and the mutation below is the proof.
