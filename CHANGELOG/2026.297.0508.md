## Summary

This is the successor to opencharly/opencharly#654, which merged before its round-1 fix
could be pushed. It carries two things: the fix that validator's finding required, and the
wave's last consumer leg — the umbrella's `docs` gitlink, whose producer has landed and is
tagged.

**The fix.** #654's validator read the change as correct and raised two observations; one of
them is about the change itself: nothing asserted that the gate PRINTS the product's own
token. The self-test covered DETECTION, so the claim the change makes — the gate's output
carries the character the product prints — had no coverage that would fail without it (R7).
Three things land in one cutover:

- **Assertion T.** `--self-test` now asserts that the line the gate prints carries U+2026,
  and proves the assertion LIVE: a mutation of the gate's OWN text turns it RED. The printed
  text is that file's own text, so the assertion reads that file.
- **One owner for the printed line.** The clean-run message is now a function (`okLine`), so
  the self-test asserts the SAME string the main path prints (R2).
- **The ASCII rendering is gone from the file, not only from the constant.** #654's comment
  that introduced the constant still showed the three-dot form while the printed constant
  already carried the product's token — a claim the file itself contradicted, one level up
  from the assertion the validator asked for. That copy is deleted here.

**The pin.** The umbrella's currency report named `docs` as the one pin that was not current:
the docs repo's main advanced while the umbrella's pin still recorded the older commit,
because the docs leg of this wave had not landed yet. It has (opencharly/docs#182, merge
`bb4f006`, tag `v2026.297.0439`), and the pin moved through the pin contract's own verb —
`charly task sync`, never a hand-pin and never a branch checkout: `5e26799` → `a5bd2445`.
