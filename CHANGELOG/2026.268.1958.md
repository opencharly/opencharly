# 2026.268.1958 — docs: umbrella-centric, harness-independent development model

## Summary

Rewrite the umbrella rulebook around ONE development model and clean up the
documentation that contradicted it or had gone stale, and adopt the model's ignore
entry in this repo's own `.gitignore`.

### The development model (AGENTS.md)

- **Rule 4** states the model (it no longer bans worktrees). A session roots at the
  umbrella and edits every repository that exists here as a submodule through its own
  worktree under `<umbrella>/.worktrees/<slug>/<repo>/`, branched off fresh `origin/main`.
  The tracked submodule checkouts stay at their gitlinks and clean, so `verify` passes.
  `sdk`/`spec` are explicitly NOT submodules (they resolve from the Go proxy), so they
  are not listed — reconciled with rule 6.
- A new **"The development model"** section specifies: the root/worktree rule; the two
  ownership scopes (exclusive: worktree, branch/PR, worktree-local binary, generated
  state — safely-shared: umbrella root, plugin cache, repo cache, image store, each with
  its protection named); the concurrency rules (session-scoped `--tag` / `bed_domain`;
  `sync`/`verify` as the only gitlink writers); producer-first landing; and the precise
  invocation (`./charly/bin/charly task <name>`).
- **Rule 9** names the worktree as session-owned state.
- **Rule 8** separates *identical-by-design* (gate scripts + reasonix settings,
  diff-checked by `task harness`), *umbrella-only* (`hooks/pre-commit`), and
  *deliberately-forked* (per-harness settings/workflows). The Hooks doctrine is reworded
  harness-neutrally.
- Rule 6 no longer names `plugins` (not a submodule); invocation examples use the precise
  binary path.
