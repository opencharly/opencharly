# 2026.308.0936 — feat(design): let a harness carry the grader's own surface (batch 13)

## Summary

Batch 13 of the DESIGN amendments the capability ledger records (tracked in #838). The AI-CLI grader
catalog lost its working fields: today an `agent:` entry names the CLI's argv, how the prompt reaches
it, how it reports its version, its timeout, its environment, its working directory and the shape of
its output. The design kept only `argv`.

`#Harness` now carries `prompt_via` (argv or file), `version_command`, `timeout`, `env`,
`working_dir` and `output_format` beside `argv`, `model`, `need` and `use`.

One detail the gate forced: **`env` keys are `#EnvName`, not `#Name`** — an environment variable is
upper case, and the user-name rule is not its rule. The `.mcp.json` server row added in batch 11 is
corrected to match, so the design has one env-key rule rather than two.

**Round 1 of review found the verdict running ahead of the fields**: the row's own description named a
progress interval and a no-improvement window, and `#Harness` had no field for either — a `timeout` is a
deadline, not a liveness signal. `progress: {interval, no_improvement}` is now on `#Harness`
(`#HarnessProgress`), the example sets both, and the table is regenerated so the verdict rests on the
fields.

| file | what changed |

| `design/dulling.tsv` | `kind:agent` becomes sharp — the catalog's job is the harness node |
