Advances three submodule pins. This is the umbrella's own pin chore — `charly task sync` decided the
values, and this commit records them — and it carries the **consumer step for the `firecracker`
substrate contract** (umbrella ledger WI-1; `opencharly/spec#227`, merged `ada497a`, tag
`v0.2026287.1134`).


**Why the spec pin matters.** The contract module now carries the `firecracker` kind, its

Until the umbrella pins that merge, the umbrella's own view of the org is a contract that does not
know the substrate exists — and the plugin legs that follow build against the tag.

**A measured correction worth keeping, because it nearly produced a wrong PR.** `charly task sync`'s
first run reported **sixteen** pins. It had run in the checkout that *had* to run it — `bump` skips
uninitialized submodules and then fails loud, so it needs a fully-initialized checkout — and that
checkout (the clone root) is **behind `origin/main`**: `b730035` against `a29e91b`. Thirteen of the
sixteen advances were already on `main`. Recomputed against the branch this PR lands on, the decision
is the three pins above. *A pin decision is only meaningful against the branch it will land on, not
against whichever checkout happens to be initialized.*

all 428 submodules**, while the **checkout half covers the 18 that are initialized in this worktree**

fully-initialized checkout). The branch-vs-remote-default audit — the expensive `git ls-remote` half —
ran in full and passed.

**How the values were produced and transported, stated because it is unusual.** `bump` cannot run in
a session worktree (it fails when any submodule is uninitialized: `426 submodule(s) not an
initialized checkout`), so it ran in the fully-initialized clone root, against the SHA set that
checkout had. Its resulting gitlinks were then applied on a worktree branched off fresh
`origin/main`, and the clone root was **restored to exactly the SHAs it was found at** — all sixteen
checkouts were verified clean before being moved back, and the root's `git status` is again empty
apart from the pre-existing untracked `tmp_block.txt`. Only the three pins that differ from current
`main` are recorded here.
