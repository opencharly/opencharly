# 2026.278.1423 — chore(defaults): enable keep_images: 3 in the umbrella

## Summary

Enable `keep_images: 3` in the umbrella's `defaults:` block.

The umbrella set `keep_check_runs: 3` but left `keep_images` unset — which
DISABLES image retention (`0`/absent = no pruning). Every charly-labeled build
image was therefore retained indefinitely: 175 tagged images accumulated (27×
`arch`, 27× `cachyos`, 27× `arch-builder`, 24× `cachyos-layer-agent-forwarding`,
…), filling the host root disk to 82% (74 GiB free on 400 GiB).

Setting `keep_images: 3` makes both the post-build prune (`charly box build`) and
the on-demand `charly clean` enforce the same retention the `charly` submodule
already uses.

## How tested

**A/B on the CHANGED file's default.** The umbrella manifest was resolved with the
pinned engine (`v2026.278.0912`) and `charly clean --dry-run` read
`defaults.keep_images` directly. The ONLY difference between the two runs is this
PR's one-line change:

BEFORE (main umbrella, `keep_images` absent → retention disabled):

```
$ grep -n keep_images charly.yml          # no match
$ charly clean --dry-run
images: would remove 0 tag(s) (keep_images=0)
build: would remove 0 staging dir(s) under .build/_candy (keep_images=0)
```

AFTER (this PR's head, `keep_images: 3`):

```
$ grep -n keep_images charly.yml
27:    keep_images: 3
$ charly clean --dry-run
images: would remove 0 tag(s) (keep_images=3)
build: would remove 0 staging dir(s) under .build/_candy (keep_images=3)
```

The on-demand prune with that value reclaimed the disk the default now enforces:

```
$ charly clean --images --keep 3
images: removed 96 tag(s) (keep_images=3)
$ df -h /
/dev/sda1  400G  312G  89G  78%    # was 326G used / 74G free (82%)
```
