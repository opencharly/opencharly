# 2026.297.0817 — fix(pins): the wave body fails loud when the shared pin-contract definition is missing

## Summary

Three findings, one story: **a check must not report what it has not verified, and it must
not leave behind what it created.** The wave body published a coverage decision it never
made; this PR's own body published a sweep it had never run; and the guard that closes the
first defect leaked its own scratch every time it failed. All three are fixed here, and all
three are measured.

`set -euo pipefail` sat *after* `scripts/sync-pin-evidence.sh` sourced
`scripts/pin-contract-inputs.sh`, and — unlike the commit gate — the body carried no
existence guard, so a missing shared file would not fail loud. Measured on the merged

**The fix.** The body takes the commit gate's own shape — `hooks/pre-commit-gate.sh:77`
already guards the same shared file — and nothing else: `set -euo pipefail` first, then
an explicit existence guard that **names** the missing file, before the source. The two

**The coverage.** A new self-test arm runs a COPY of the body in a directory with no
shared file, in **body mode** with empty stdin — never `--self-test`, because the copy's
own self-test would re-enter the arm, and a self-referential arm is a hang, not a test.
The discriminator is the fail-open **signature**, not an exit code: the arm asserts that
`command not found` and the `NOT offered as this diff` claim are both **absent**, and that
the loud failure says the body cannot decide. The positive control re-runs the same copy
**with** the shared file and requires it to reach a coverage decision, so the arm cannot
pass by failing everything.

**Two — this PR's own body published a sweep it had never run.**

The validator's run on this PR came back `INCONCLUSIVE` — an engine class, filed as
**opencharly/plugin-review#47** (below). Its reasoning carried one real finding, and it
was against **this body**: the pasted `git grep` sweep was taken on another tree. The body
pasted `scripts/sync-pin-evidence.sh:290:` with that line's text, and on the head being
pushed line 290 read `guard_rc=0`; and the body claimed the phrase survived *"in exactly
one place"* when the tree carries it on three lines. The finding is mine, it is fixed, and
it is not filed away.

**The RCA.** *Mechanism:* the sweep in the body was written by hand from an earlier draft
of the arm, not pasted from a run against the head being pushed, so it described a tree
that no longer existed. *Missed control:* the umbrella's own body gate
(`scripts/check-pr-body-diff.mjs`) judges the body's **form** and the diff's arithmetic —
the file table (T), the pasted head (H), the counts (N) — and never whether a pasted
**output line** is the tree's own text. A stale paste is well-formed, so H, T and N all
accept it; the body's evidence was never checked against the tree it claims to describe.
*Blast radius:* the body is the changelog (R7) — the artifact the reader trusts, and the
one the validator reads. A body could state a fact about the tree that no run of any
command had established, and both gates would pass it. *Root fix:* a new arm (**E**) in
that gate — every fenced output line of the shape `path:NN:text` must resolve in the tree
being pushed: the file must exist there, the line must exist in it, and the pasted text
must be the text of that line. It is scoped to fenced blocks and never to prose (a prose
quote may name a line that has since moved, and that is a judgement, not a mechanical
fact), and a block that names another tree explicitly (`git show <blob>`, `git -C <dir>`)
is the documented escape.

**Three — the guard this PR adds leaked its own scratch every time it failed.**

The missing-shared-file guard's scratch was removed at the END of the arm, and `fail`
EXITS — so every failing run left the scratch behind. That is not cosmetic: one of the
ways that arm fails is a full filesystem, so a leaked scratch **amplifies the very
condition it reports**. Measured on 2026-10-24: the host's `/tmp` (a tmpfs with
`nr_inodes=1048576`) ran out of inodes while the arm was running; the arm's positive
control failed with `cp: cannot create regular file ...: No space left on device`; the arm
reported it, and the arm's own scratch was left behind.

**The fix.** One `scratch` helper now creates and registers every temporary path this
script makes — the guard's scratch, the fixture repository, the rows file — and ONE trap
removes every registered path on every exit path, so registering a second scratch can
never unregister the first. A new self-test arm registers a scratch in a subshell that
exits non-zero and asserts the scratch is gone afterwards: remove the helper's trap and
that arm goes RED, because the guard would then leak its scratch on every failure too.

The same class, in the same PR, in the same direction: the wave body reported a decision
it had not made, this body reported an observation it had not made, and the fix for the
first left a scratch behind every time it failed. One is fixed in the shipped builder, one
in the gate that guards the builder's evidence, and one in the builder's own temporary
state.

The third file closes the same gap in the umbrella's own description of that gate:
`charly.yml` enumerates the arms the reconciliation gate's self-test proves, and the
enumeration would otherwise leave the new arm — and the count arm that predates it —
unmentioned, so the step's own text would under-describe the product it runs.
