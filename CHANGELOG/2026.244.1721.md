# 2026.244.1721 — feat: first-party vision extension — image handoff + vision_ask tool for text-only models

## Summary

Adds a **first-party vision extension** to the umbrella's pi agent config — no third-party package, no user-level config.

The umbrella's coding model (`ollama-cloud/deepseek-v4-flash:0731`) is text-only and cannot see images. This change gives it vision two ways:

1. **Automatic handoff** — every image reaching the LLM-bound payload (pasted/attached images, `read`-tool results) is described by the configured vision model (`ollama-cloud/qwen3.5:397b`) and the description text is swapped in for the image block before the request leaves. Descriptions are batched (N images → ONE vision call) and cached per image hash.
2. **`vision_ask` tool** — the coding model can explicitly ask the vision model questions about a picture on demand.

Files:
- `.pi/extensions/vision.ts` — the extension (context/tool_result/before_agent_start hooks, DataLoader batching, per-hash LRU cache, graceful degradation, `/vision status` + `/vision model` commands, error log, `vision_ask` tool).
- `.pi/vision.json` — committed project-local config (`visionModel: "ollama-cloud/qwen3.5:397b"`).
- `.pi/settings.json` — registers `./extensions/vision.ts`.

The coding model is never changed by the extension; it only describes images for it. The ollama-cloud API key stays in `~/.pi/agent/auth.json` (already configured).
