# 2026.295.2251 — feat(design)!: one generic shape per concept — capability tables, generic leases, drivers, create/connect, display, one workflow kind

Closes #614

## Summary

A schema-first review of **every** shape in DESIGN.cue against D-LAW-8: a concept is modeled once, generically, and an instance is a row or a word of its table. Where DESIGN.md and the clean schema disagreed, DESIGN.md changed.

| Concept | Modeled for one case before | One generic shape now |
|---|---|---|
| exclusivity | a GPU-only lease field | `#NeedEntry {optional, exclusive}` on every need type. A grant that holds a host resource reports the lease its mechanism imposes (`#GrantItem.lease`), and core leases at the stricter of request and mechanism (**D-HW-8**). This one rule covers a GPU (CDI → shared, VFIO → exclusive), a device, a published port or a writable mount. Leasable host resources are rows of `#UserConfig.resource`. |
| needs and provides | hand-written fields per type | one table each, `#NeedType` and `#ProvideType`: a type states its key and its entry attributes. `#Need` and `#Provide` are derived from the tables. A new `memory` need replaces the `shm_size` field. `engine_api` names any driver. |
| drivers | per-kind fields; kubernetes' tool authored in documents | one table, `_driverWord`, with rows for pod engines, vm hypervisors and kubernetes cluster tools; `#Driver` derived (**D-DRV-1**) |
| create / connect | kubernetes `create: kind` and `connect: <text>`, android `emulator`/`adb`, local `host: local` | one shape (**D-DEP-6**): `create:` or `connect:`, where a connection is one venue alternative of `#ConnectAlt` (`shell`, `ssh`, `kvm`, `adb`, `kube`) |
| endpoints | `provide.port`, `provide.mcp`/`need.mcp`, the candy `route`, machine `port: {host, guest}` | one `endpoint` type (port, transport, protocol, path, host). Machines `publish` endpoints by name, and the guest port is derived (**D-VAL-13**). |
| screens | seven verbs and kinds: `wl`, `vnc`, `spice`, `record`, `cua`, `jetkvm`, `vision` | one `display` protocol verb (`screenshot`, `window`, `record`, `ask`) over whatever display transport the venue serves. `cua` becomes a harness; `jetkvm` becomes a `kvm` connection and a `power` venue operation. |
| verbs that were another verb | `helm` (release state), `adb` (`shell`, `install`, `device`) | `package` on a `helm:` or `android:` package, and `command` over the adb venue. A wait is the `eventually` modifier, not a `kube` operation. |
| workflows | `check-roster` kind; `iterate:` field; stage `approval`; free-text `when` | one `pipeline` kind (**D-FLOW-1**): a `bed` stage with `concurrency` replaces the roster, the agent loop is a pipeline, and approval is an `ask` stage. `when` is a matcher per argument, and `lane.over` names an argument. |
| readiness | candy `ready:` (a command only) | a `ready` step phase: any check step, with any verb |
| packages | `package` list plus a separate `package_input` keyed by its items, with D-VAL-13 to tie them together | `package` is a map; a manager entry carries its `input` (**D-IR-5/6**), and the cross-field rule is gone |
| content overrides | `os_override` covered packages and repositories only | `os_override` overrides the one `#Content` shape |
| image references | `source: {oci: <text>}` | `oci:` is an `#ImageRef` that names its registry (`quay.io/fedora/fedora:43`). An unqualified `fedora:43` is rejected, because charly never infers a default registry: the origin of a starting point is explicit (evidence below) |
| boot | `vm.firmware` | `#Os.boot.firmware`; `pod` and `vm` are now written identically with no exception (**D-DEP-1**) |
| machine content | `pod`/`vm` `env` and `volume` beside the box's own | content comes from the box (D-DEP-2): a guest's environment and its volumes are `#Content` of its candies, and a deployment-specific value is an `env` need it binds — one place for each, so `#MachineOnly` keeps only publishing, sizing and network (**D-DEP-7**) |
| an agent workload | `#AgentBody.provide` beside its box | an agent's provides come from its box's candies, like every machine's; `#AgentBody` keeps `from` and its runtime's own `spec` |
| doc projections | `projection: {word: bool}`, absent meaning "all" by convention | `projection:` the list of projections generated, with its default (all of them) declared in the schema (D-LAW-5: a default exists only where the schema declares it) |
| references in a type table | an `@ref` attribute on a hand-written field | a type-table row whose keys name nodes states its kinds as `ref: [...]` (`#NeedType.harness`); the linker and consistency check 2 read it as they read `@ref` (**S9**) |
| collections | S5 tied to "has attributes" | S5 stated once: what a node **defines** is a map keyed by name, even with an empty entry; what it **refers to** is a list |

**Design calls for review:**
1. **Roster and loops become pipelines.** `check-roster` and `iterate:` become `pipeline` stages, and `charly check run <roster>` becomes `charly pipeline run`.
2. **The cluster tool is configuration.** `kind` vs `k3s` is now a user-configuration driver choice, like engines and hypervisors.
3. **One package form.** `package: {ripgrep: {}}` replaces `[ripgrep]`; a little more to write buys one form that can gain an attribute.
4. **Retired verbs.** `helm` and `adb` fold into fact verbs.

Capability parity is preserved. `design/parity.tsv` is remapped (`kind:cua`, `kind:jetkvm`, `verb:helm`, `verb:adb`, the display verbs, `check-roster`, `iterate`, readiness, CDI-vs-VFIO), and all 208 provider words of `origin/main` map to their new homes (below). DESIGN.md, 11 examples, the negative cases, `rules.cue` (stage `bed` replaces the roster `bed`), the self-tests and the ledger follow the schema.
