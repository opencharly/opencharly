# 2026.327.2345 — fix(rulebook): say how an issue's two-axis classification is set at creation

## Summary

The "Issue categories and types" section claimed the labels are "set at creation through the org issue form or the `scripts/gh/cli.ts issue` wrapper". The wrapper does set them; the **form only records the answers** — the `label-audit` workflow applies them (immediately in this repository, and by the daily org audit elsewhere, because the org ruleset activates its required workflow on `pull_request` events only, so an `issues` trigger cannot run cross-repo). That gap was measured while implementing and resolving `opencharly/.github#318`.

The sentence now says what is true:

> Every issue carries exactly one `category:` and exactly one `type:` from the org-wide closed sets, whose two-axis classification is mandatory at creation — through the org issue form (whose answers the `label-audit` workflow applies) or the `scripts/gh/cli.ts issue` wrapper, which refuses to create without them.

No rule, value or example changes; only the claim about *when* the form path's labels appear.
