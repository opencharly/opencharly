# 2026.279.1527 — feat(harness): add the pi `question` tool

## Summary

pi ships the **primitive** (`ctx.ui.select` / `ctx.ui.input` / `ctx.ui.confirm`, `docs/tui.md`)
but no model-callable tool, and the `.pi/` restore deliberately dropped the `pi-subagents` /
question packages (a `typebox` manifest warning). An agent that needed a decision could
therefore only ask in prose and stop — which happened twice in this session.

Adds `.pi/extensions/question.ts`:

- a `question` tool: `question` (required), optional `options` (a pick-one list via
  `ctx.ui.select`), optional `header`. With no `options` it takes a free-text answer via
  `ctx.ui.input`.
- **dependency-free** — it uses the builtin UI methods, NOT the heavy
  `@earendil-works/pi-tui` custom-widget example.
- **headless-safe** — in a non-TUI session (`pi -p`, a child, CI) there is nobody to prompt, so
  it returns a clear "ask in prose and stop" result; it never throws and never fakes an answer.
- `executionMode: "sequential"` — a prompt is exclusive UI, so two concurrent prompts would race.

Plus `scripts/check-pi-question.mjs` (parse + static assertions + a 9-mutation self-test) wired
into `hooks/pre-commit` and `charly.yml`, with `.pi/settings.json` wiring asserted by the gate.

Neutral-first note: this is unavoidably pi-SPECIFIC — it binds pi's own UI primitive, and there
is no harness-neutral way to prompt a live session. It is the one case the directive allows.
