## Summary

**The umbrella could not be committed to locally.** `charly task verify` is the pre-commit hook, and it failed on `main`:


`action-review` is pinned at `a91036c` (late September) and defines **seven** check ids; this repo's `AGENTS.md` lists the **twenty-five** the **live** prompt already runs. The second failure names the cause in one line — **the committed rulebook is a month behind the live copy** — which makes this a pin lag, the same class of defect the campaign keeps finding in the landing chain, here on the rulebook itself.

**Blast radius, and it is not a red check.** CI runs no hooks and `tag-on-merge` writes `main` from a workflow, so merges kept landing and `main` kept moving. **The freeze was on authors** — every local commit in this repo failed — which is exactly why it read as quiet rather than broken.

## The fix

Advanced with **`charly task sync`**, which is what Policy B prescribes for pins — never a hand-pin, never a branch checkout:

```console
$ charly task sync
task sync: 1 step(s), 0 failed
  [pass] run — bump the pins (charly rolls first, then distro-* from its new gitlinks)

$ node scripts/check-validator-rule-map.mjs        # after — ALL FIVE, not a selection of them
  PASS  the AGENTS.md table lists 25 distinct check ids
  PASS  every rulebook check id (25) has an AGENTS.md row
  PASS  every AGENTS.md row names a check the rulebook defines
  PASS  every skill the table cites (10) resolves in the marketplace corpus
  PASS  the committed rulebook equals the live AI_REVIEW_PROMPT org variable
check-validator-rule-map: OK
rc=0
```

**The first version pasted only three of those five, and the reviewer caught the one that mattered:** the omitted line was `every skill the table cites (10) resolves in the marketplace corpus` — and the `marketplace` pin moves in this very PR (`a4089e4` → `ca0906d`). Omitting the check the change could actually perturb is the worst possible three-line subset, and it is pasted in full above.

23 gitlinks move, which is what a pin sync is. The commit carries `pre-commit: OK` — the gate this change unblocks, passing on the tree that fixes it.
