# 2026.293.0504 — chore(harness): re-derive reasonix.toml [skills] paths for the fireactions and strata families

## Summary

`reasonix.toml`'s `[skills] paths` is a **derived** enumeration — one entry per `marketplace/<family>/{skills,agents}` directory — produced by `scripts/sync-skill-bindings.mjs` (introduced in #502). The `marketplace` pin advances #518/#519 carried the `fireactions` and `strata` families, and the derivation was not re-run with them, so the harness-config gate's reasonix arm has been red on `main` since:

```
# on origin/main ad74dc5, clean tree, corpus materialised
$ node scripts/sync-skill-bindings.mjs --only reasonix --check
sync-skill-bindings: reasonix.toml [skills] paths  STALE (43 -> 45 entries)
FAIL: derived skill bindings are stale:
  reasonix.toml [skills] paths (43 -> 45 entries)
rc=1
```

This PR re-derives the binding with the owning generator. **Every changed path in the diff: `reasonix.toml` — two added lines** (`marketplace/fireactions/skills`, `marketplace/strata/skills`). Nothing is hand-edited, no pin is touched, no gitlink moves.

The two remaining `check-harness-config` failures on this tree are **corpus-level and pre-existing**: they are the same two that fail on `origin/main` without this change (baseline pasted below), they are filed, and their fix is producer-first in `opencharly/marketplace`.
