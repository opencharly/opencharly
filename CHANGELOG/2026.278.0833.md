# 2026.278.0833 — feat(harness): inject SOUL.md into the opencode + pi session context (#359)

## Summary

The identity surfaces all **said** "read `SOUL.md`", but none **fed it in** — a soul read only on request is not reliably part of who the agent is. This wires `SOUL.md` into the session-start context of the harnesses that have a documented **additive** injection mechanism, and gates each so it cannot silently unwire. Closes opencharly/opencharly#359.

- **opencode** — `opencode.json`'s `instructions` list (opencode's documented session-instruction list: each entry is a markdown file injected into the system prompt) now carries `SOUL.md` beside `.opencode/instructions.md`. No harness-specific file is needed — `SOUL.md` sits directly in the list.
- **pi** — `.pi/extensions/charly-gates.ts` reads the project-root `SOUL.md` inside its `before_agent_start` handler and injects the **content** every turn, so the injected text is the identity itself, not a pointer to it. When `SOUL.md` is **absent** it injects a visible `⚠` warning naming the #356 content-loss signature instead of the identity (warn-and-point, not fail-loud — the session still starts).

**Gated:**

- `scripts/check-harness-config.mjs` gains **check 7** — a `[surface, assertion, who]` table (one row per harness) asserting `opencode.json` injects `SOUL.md` and the pi extension reads+injects it — each with a `--self-test` mutation that turns it RED.
- `scripts/check-pi-gates.mjs` asserts the pi injection (`readSoul` + `SOUL.md` + `before_agent_start`) plus a mutation.

**Deferred (named, not silently dropped):** the harnesses with no wired injection are all routed to the companion issue **opencharly/opencharly#367**, which records a per-harness disposition:

- **Codex** and **reasonix** have no documented *additive* session-context mechanism at their config surfaces (Codex's `model_instructions_file` **replaces** the base system prompt; reasonix's documented hooks are Bash-only) — #367 tracks finding one or recording "no mechanism".
- **Claude Code** HAS a documented additive mechanism (a `SessionStart` hook → `additionalContext`), but the **operator ruled** (2026-10-05) to keep it on the `AGENTS.md` pointer and **not** add the hook; CLAUDE.md was retired in opencharly/opencharly#286, so there is no project instruction file to import. #367 records that decision — it is a recorded disposition, not a silent gap.

Files: `opencode.json`, `.pi/extensions/charly-gates.ts`, `scripts/check-harness-config.mjs`, `scripts/check-pi-gates.mjs`. Relates to opencharly/opencharly#359, #367.
