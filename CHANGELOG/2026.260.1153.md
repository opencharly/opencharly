# 2026.260.1153 — feat(agents): harness-neutral rulebook + generated opencode dispatcher

## Summary

Makes the umbrella rulebook harness-neutral, corrects/completes the skill
dispatcher, wires the generated-dispatcher mechanism, fixes opencode skill
addressing, and registers the two missing plugin submodules.

- **AGENTS.md is now harness-neutral.** Removed every agent-specific note: the
  Claude/symlink note, the harness-dir enumerations in rules 4/7/8, the
  per-harness marketplace-loading prose in R0, the pi/model attribution literal,
  and the per-harness hook-wiring list. Rule 8 stays as umbrella policy in
  neutral wording. The stale "389 submodules" count is corrected to ~400 (the
  tree carries 401).
- **Dispatcher corrected + completed.** The R10 row pointed at agent names
  (`check-bed-runner`/`deploy-verifier`) that opencode cannot load; it now points
  at `/charly-check:check`. The table gains the umbrella-relevant skills it was
  missing — 19 distinct refs, all resolving.
- **Charly CLI discipline** (new section + R4 extension): the `charly` CLI / its
  owning skill is the ONLY interface for charly-managed resources — never
  `podman`/`docker`/`systemctl`/raw shell; ALWAYS load the dispatcher skill
  before the first tool call, NEVER skip R0; a missing verb/skill is a product
  defect to RCA and fix upstream, never an ad-hoc workaround.
- **opencode addressing fixed.** opencode's `skill` tool accepts only bare names
  (`^[a-z0-9]+(-[a-z0-9]+)*$` — no `:` or `/`). The namespaced→bare mapping lives
  in `.opencode/instructions.md`, wired via `opencode.json` `instructions[]`,
  plus a `permission.skill` allow-list (exactly the 19 dispatcher skills) and a
  `marketplace` reference.
- **Generated-dispatcher mechanism wired, and its DORMANCY stated.** The
  marketplace generator (opencharly/plugin-marketplace#11, MERGED) emits
  `DISPATCHER.md`. This repo's committed table is **hand-curated umbrella prose
  OUTSIDE any generated markers** — a generated artifact is never hand-edited
  inside its markers. `scripts/sync-dispatcher.sh` splices the generated fragment
  in when BOTH the pinned marketplace carries `DISPATCHER.md` AND AGENTS.md
  carries the markers. **Shipped wiring:** `hooks/pre-commit` runs the live
  `--self-test` (exercises the splice: write / steady-state / stale-fails); the
  **nightly `sync.yml` splice step is the DORMANT call site** (no-op while the
  pin lacks the fragment and AGENTS.md has no markers). The pre-commit gate
  carries NO `--check` call site. The
  named batch that makes the mechanism live is the marketplace regeneration PR
  (opencharly/marketplace#307), which emits `DISPATCHER.md`; a later `task sync`
  that carries that pin can then opt the umbrella into the generated table.
- **Two new submodules:** `plugin-pipeline` and `plugin-review` — the two
  serving-plugin repos for `charly pipeline` / `charly review` that were never
  tracked (every other serving plugin — `plugin-cache`, `plugin-pod`,
  `plugin-agent`, `plugin-cardwire`, `plugin-bpf`, `plugin-feature`, … — is).
  Both pinned at their merged default-branch HEADs.
