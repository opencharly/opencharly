**Finding one — the two path readers read two different path sets.** `head_entry` read a path with a bare pathspec while its sibling `index_entry` read it with `:(literal)`. Git reads a path argument as a PATHSPEC, and the two commands misread it in opposite ways:

- `ls-files` **globs** a pathspec. A path named `a*b` makes `ls-files` return the sibling `a!b` as well, and `a!b` sorts first — so a reader that takes the first record returns a **different path's** record.
- `ls-tree` does **not** glob. But a path whose NAME BEGINS WITH `:` is pathspec MAGIC, and the plain form then matches **nothing** — silently, exit 0, no output, no error.

So a path whose name begins with `:` that the body renders as removed was classified as a carried file, and the row read `  :colonpath    (file)` where it must read `  :colonpath  (removed)`. The validator's stated mechanism — *"for a path containing a glob character"* — is wrong for `ls-tree`, which never globs; the reachable form is the `:`-leading name. The fix lands on the measured one, and **both** readers now take the same `:(literal)` pathspec.

**The reachability, stated honestly: the defect is LATENT in this repository today.** The umbrella's tracked tree carries no path whose name begins with `:` and none that carries a glob character, so no row of the umbrella's own body is misrendered right now — the measurement is pasted in "How tested" below. The readers, though, are generic over any path, and such a path is legal to commit: only `git submodule add` refuses the form, and that refusal is about a submodule's **source** path, not about a plain file. The fix is a correctness fix, and it is blocking under R1 for the reason stated in the compliance section: the asymmetry between the two readers is #738's own, and #738's body claims they are one shared measurement.

**Finding two — the change-class names leaked out of the function.** `CLASS` and `CLASS_DESC` are assigned inside `build_body` but were not declared `local`, so they landed in the caller's scope on every call. They are now declared `local` in the `local` line the function already carries.
