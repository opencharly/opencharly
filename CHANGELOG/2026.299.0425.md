# 2026.299.0425 — fix(gate): read GitHub's whole closing-keyword set, and one fence rule

Closes #702

## Summary

Head `4fab438aac1ef5bb4725acb6de68d0a2c0fb80df` — 1 file changed, 202 insertions(+), 51 deletions(-).

**The umbrella's closing-directive arm read THREE of the NINE closing keywords GitHub accepts, case-sensitively, and its fence reader could not tell a four-backtick fence from a three-backtick one.** Both were raised by the fresh `charly/pr-validator` on this org's own merged pull request #699, so the arm's claim — *"every closing directive names something the directive CAN close"* — was false for six of the nine forms, and for every case GitHub accepts.

GitHub's "Linking a pull request to an issue" names the whole set — `close`, `closes`, `closed`, `fix`, `fixes`, `fixed`, `resolve`, `resolves`, `resolved` — and adds: *"The keywords can be followed by colons or in uppercase."* The arm read `Closes`, `Fixes`, `Resolves`, capitalised. A body whose directive said `closed #7`, `CLOSES #7` or `Closes: #7` was **green**, and GitHub reads all three.

**The fence reader was TWO readers of one thing.** `proseLines` toggled on a backtick fence or a tilde fence; `fencedBlocks` toggled on a backtick fence only; and both ignored CommonMark's fence rules. The naive toggle gets those wrong in both directions, and each error is a real body: it CLOSES a four-backtick fence at the three-backtick line inside it, so a directive pasted inside that fence trips the arm on the body's own quote; it OPENS a fence at a three-backtick line inside a four-backtick one, so a directive **after** that line reads as fenced and escapes the arm entirely; it closes a fence on a run that is followed by text, when CommonMark says only whitespace may follow the closing run; and the two readers disagreed about `~~~`, so a body could paste evidence in a tilde block and the evidence arm never saw it.

**One change, one cutover.** ONE fence scanner now serves both readers, and it implements CommonMark's fence rules — the length rule, and the closing fence's rule that only whitespace may follow the run (an info string belongs to the OPENING fence alone) — so the evidence arm and the directive arm can never disagree about where a fence ends. The keyword grammar reads all nine forms, case-insensitively, with the optional colon, and the finding quotes the directive as it was written.

**The boundary this change does NOT cross is the arm's POSITION** — a directive is read only when the body OPENS a line with it. That boundary is deliberate, and it is now MEASURED rather than asserted: **8** mid-line directives in this repo's 447 merged bodies, of which 3 name a pull request and **2 are legitimate prose** — *"The validator auto-closed #348 after its fifth non-PASS verdict"* and *"the channel bootstrap fix #43's gitlink"*. A full-parity grammar would turn the gate red on ordinary prose (3 reds over 447 bodies, 2 of them legitimate), and a push-time gate that blocks a body for the phrase "the auto-closed #348" is a gate people learn to route around. That measurement, and the cost of crossing the boundary, are filed as opencharly/opencharly#701.

The self-test's fixture table was spelled out in twelve arms and is now one constant, so no arm can spell the table differently from another.
