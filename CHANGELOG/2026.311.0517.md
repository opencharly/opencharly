# 2026.311.0517 — feat(design): a run step may render a document instead of running a command (batch 57)

## Summary

Batch 57 of the DESIGN amendments (tracked in #838). `verb:emit` rendered one document from a schema and a
value map, and **6 of its 7 keys had no field**. The blocker was not a field but a **rule**:

> **D-VERB-5** (before): A `run` step carries its `command` and its `guard` **and no verb**.

A `render` had nowhere legal to live. So the rule moved first, then the schema:

> **D-VERB-5** (now): A `run` step carries its `guard` and **exactly one of its `command` or its `render`
> block**, and no verb.

`#RunFields` gains `render`, and `#Render` is one named struct:

| field | what it carries |
|---|---|
| `schema` | the schema the document is rendered against |
| `config` | the value map the schema shapes — S10's open struct, since the fields are the schema's |
| `var` | the substitutions the render is given, by name |
| `out` | where the rendered document is written |
| `format` | `yaml` or `json` |
| `strict` | fail the step when the document does not satisfy `schema` |
| `report` | the report the render emits — S10, the renderer's own shape |

**`verb:emit` becomes sharp.** **`verb:generate` stays dulled**: its `negate_checks` key inverts a *check's*
verdict, and the design has no such operation — that is a separate decision, not a field.

| file | what changed |
|---|---|
| `DESIGN.cue` | `#Render`; `#RunCommand`/`#RunRender` as the two `run` arms, so the choice is enforced |
| `DESIGN.md` | D-VERB-5's sentence, and a render example beside the sshd guard |
| `design/negative/run-both-arms.yaml` | a run step carrying **both** keys, which the schema now refuses |
| `design/dulling.tsv` | `verb:emit` becomes sharp |
| `design/dulling-disposition.md` | regenerated |
