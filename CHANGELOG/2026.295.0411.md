# 2026.295.0411 — docs(containerd): close the rootless prerequisite gaps and correct four refuted claims

## Summary

The three containerd specs are the reference a provider is being built on. Measured against
the live hosts they carried **three operator prerequisites they never mentioned** and **four
statements the measurements refute** — each of which costs an operator either a host that
will not start, or a capability they already have. This closes both, and adds the image
contract those features require.

**Gaps closed**

| Gap | What was missing | Measured A/B |
|---|---|---|
| `newuidmap`/`newgidmap` | the uidmap helpers that consume `/etc/subuid` + `/etc/subgid`, which the spec named | same `rootlesskit --state-dir=… true`: `rc=0` with the helpers on `$PATH`; `exec: "newuidmap": executable file not found in $PATH` with those two alone removed |
| `/dev/fuse` | the device node the §4.4 fuse-overlayfs fallback opens | same mount: succeeds with the node; `fuse: device /dev/fuse not found. Kernel module not loaded?` with a `tmpfs` over `/dev` in a private namespace |
| who may read a checkpoint | §10 said *where* the store is, never who may read the process memory in it | the `0700` **directory** is the protection: a `0644` image read failed in it and succeeded through a `0755` directory |

`containerd-rootless-setuptool.sh` checks neither of the first two, so a setup that reports
success can still leave a host whose rootless containerd will not start.

**Claims corrected — deleted in place, not annotated**

1. `CONTAINERD.md` called `/run/containerd` *"the rootful runtime root"*. It is the daemon's
   **own configured state path**, which `containerd-rootless.sh` bind-mounts from
   `$XDG_RUNTIME_DIR/containerd` — correct in-namespace, invisible outside. Proven by inode
   identity (namespace `/run/containerd` and host `$XDG_RUNTIME_DIR/containerd` both
   `54:29590456`), identical on containerd 2.4.1 and 2.4.2 with `init.go` byte-identical
   between them. The earlier reading would have filed a false issue against containerd.
2. `CONTAINERD.md` gave the rootless CDI remedy as a link to `/etc/cdi/nvidia.yaml`, which the
   toolkit's `nvidia-cdi-refresh` unit **never updates** — it writes `/var/run/cdi/nvidia.yaml`
   at boot, on module load and when the toolkit changes. A one-shot spec is a snapshot whose
   driver version goes stale on the first upgrade.
3. `K3S.md` said *"the rootless instance cannot checkpoint at all"*. **containerd's own**
   rootless checkpoint is blocked; a rootless **krun** lease checkpoints in the guest (the
   guest kernel's root performs the dump, the host sees only an unprivileged VMM) and a
   rootless crun lease can run CRIU in-container.
4. `LIBKRUN.md` said a krun guest's processes live *"where CRIU cannot reach"*. Host-side CRIU
   **does** attach and fails resolving the container root's fd against the **host** mount
   table (`criu/files-reg.c:1790`, with a crun control at rc=0); in-guest CRIU then works —
   `criu check` → `Looks good`, dump at tick 4, restore into a **fresh** VM continuing **at
   5 → 9** (the counter resumes at 5 and reaches 9), matching `CONTAINERD.md` and `LIBKRUN.md`.

**Also folded in, each measured:** the stop exit code is a function of the stack (`SIGTERM` →
137 on 2.3.5 and 130 on 2.4.2; busybox `poweroff -f` without `CAP_SYS_BOOT` → 1 vs 0); the two
low-port cases (publish needs `ip_unprivileged_port_start`, the container-side bind does not);
the four `nvidia-ctk runtime configure` traps including `--enable-cdi` being wrong on 2.x and
the gate being the **device list**, since `cdi list` exits 0 on an invalid spec; and the
inner-krun library mechanism, where crun's three `dlopen` candidates fail only when **all**
are NULL so the message always blames `libkrun-awsnitro.so.1` (`handlers/krun.c:967-971`).

**New: `CONTAINERD-IMAGES.md`** — the host and lease images (7 host-image subsections §1.1–§1.7,
12 lease-image rows in §2), the cross-cutting rules (state volume on `/var`; a clone carries
`/var` but not `/run`, so a fork is Ready ~8 s before it is workload-usable; `reset-failed`
before restarting the inner engine; a probe never reports its deadline as a duration), and the
acceptance beds. It **cites** `CONTAINERD.md`/`K3S.md`/`LIBKRUN.md` sections rather than
restating the evidence, closing each section with the source index its rows refer to. Building
these images is explicitly out of scope; the two candy gaps it names are filed and cited by
number.

Closes #573
