# 2026.299.0229 — fix(gate): make the self-test's pasted command and its output name the same files

Refs #696

## Summary

Head `02cd7d82fc0367e62268d3e6baa5ee1728a3306b` — 1 file changed, 11 insertions(+), 2 deletions(-).

**The reconciler's self-test fixture pasted a command and an output that did not belong together, and this PR makes them one artifact.** The fresh `charly/pr-validator` raised it as a non-blocking observation on opencharly/opencharly#696: the fixture body pasted `$ grep -n one scripts/two.sh` and, under it, an evidence block naming two OTHER files — `scripts/one.sh` and `scripts/blank.sh`. The command could not have produced that output: run against the fixture's own files it prints NOTHING. So the self-test — the artifact a future reader consults to learn what each arm demonstrates — showed a command and a result that contradict each other.

**The cause is a constraint, not a typo.** The record-path arm (C) requires the body to NAME the file the record names, and its mutation works by REMOVING that name from the body. A command that named ONE file would have to name the record's file too, and the mutation could never fire — so the command was widened to a GLOB over the fixture's `scripts` directory, and the evidence block now carries exactly the three lines that command prints. The glob is sorted, because grep's own file order is not stable across runs (measured: three runs, three different orders) and the sort is what makes the pasted output reproducible.

**The arms are untouched.** This is a change to the FIXTURE, not to the gate: the same nine mutations are caught and the unmutated body is still green. What changes is that the artifact now says what it does.
