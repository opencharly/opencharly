## The `verify-pins.sh` `charly: dirty working tree` FAIL — RCA'd and fixed at source

This was NOT parked. The gate reported:
```
FAIL: charly: dirty working tree
```
**Root cause:** charly's `AGENTS.md` "Hard Cutover by Default" *mandates* every
session work in `.claude/worktrees/<slug>/`, but charly's `.gitignore` omitted
that path (unlike `.check/` and `scratchpad/`, which it does ignore). So a charly
checkout that follows the mandated convention always reads dirty, and the pin
gate fails on it.

**Fix (same cutover, upstream):** opencharly/charly#614 adds
`.claude/worktrees/` to `.gitignore`:
```
$ git -C charly check-ignore -v .claude/worktrees/
.gitignore:82:.claude/worktrees/	.claude/worktrees/
$ git -C charly status --short
(clean)
```
**Fixed in this tree, not parked.** All four upstream fix PRs are MERGED, and this
sync bumps their gitlinks to the merged HEADs — so the `charly: dirty working tree`
FAIL is cured *by this PR's own diff*, not deferred. The same missing-ignore
defect was found in three plugin repos (no `.gitignore` at all) and fixed at
source for them too.

**`verify-pins.sh` PASSES at zero FAIL on a clean worktree of this merged tree:**
```
$ git worktree add --detach /tmp/vc feat/sync-regenerated-corpus   # head 6190be3
$ git -C /tmp/vc submodule update --init --recursive
$ cd /tmp/vc && bash scripts/verify-pins.sh
check-policy-b: OK — 6 distro pins equal charly's gitlinks
verify-pins: OK — 401 submodules, policy B holds
exit=0
```
The `eval-omarchy: dirty working tree` FAIL visible on the author's main
checkout is **local uncommitted working-tree state only** — the submodule's
gitlink equals its `origin/main` HEAD in this diff, and in the clean worktree
`git -C eval-omarchy status --short` is empty. It is not a gitlink problem and
not this PR's diff, and the merged tree is clean.
