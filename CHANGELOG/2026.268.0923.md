# 2026.268.0923 — feat(task): replace the umbrella Taskfile + scripts with the charly task surface

## Summary

Cut the umbrella over to the compiled-in **`charly task`** surface, deleting
`Taskfile.yml` and the human-facing `scripts/*.sh` in the same change (R5).

**Merged with `origin/main` PR #248** (another session's umbrella-root
`check-roster`). Main had already created a root `charly.yml` for the roster and
had already bumped the charly gitlink to `9e62bcbf` (v2026.268.0651, which carries
BOTH the roster support and `plugin-task v0.2026268.534`); this PR takes main's
gitlink as-is (no further bump) and **merges the two `charly.yml` files** rather
than replacing either: the file now carries main's
`repo`/`import: charly: ./charly`/`defaults`/`check-all-beds` **and** this PR's
`charly task` surface.

**The umbrella project manifest `charly.yml`** declares the task surface:
`pins`, `map`, `sync`, `verify`, `policy-b`, `harness`, `skills`, `org-map`,
`omarchy-agents`, `pi-forks`, `hooks`, `self-test`.
- **`pins`** owns the ONE policy-B operation (the former `scripts/lib/policy-b.sh`
  role — a single canonical definition, not copy-pasted three times): the 6-entry
  `distro-*` → `box/*` map appears exactly once, and `policy-b` / `sync` / `verify`
  are thin `verb:task` wrappers selecting the mode. It composes
  **`verb:git-submodules`**.
- `harness` composes **`verb:file-parity`**.
- `skills` runs the restored `scripts/sync-dispatcher.sh` (a no-op when the
  fragment OR the target markers are absent; splice otherwise), preserving that
  script's tested `--self-test` — which `charly task self-test` and `hooks/pre-commit`
  now both run.
- `org-map`, `omarchy-agents`, `pi-forks` are org-specific, ported inline into
  task steps. The three umbrella-specific committed scripts
  (`sync-pin-evidence.sh`, `sync-pr-body.sh`, `sync-dispatcher.sh`) stay and are
  exercised by `charly task self-test`.

**Deleted (R5):** `Taskfile.yml`, and
`scripts/{check-policy-b,check-harness-parity,sync-gitlinks,verify-pins,check-org-map,check-omarchy-eval-agents,sync-pi-forks}.sh`
+ `scripts/lib/policy-b.sh`. (`sync-dispatcher.sh` is RETAINED: its splice +
  `--self-test` is the tested implementation `skills` calls.) (There was no `taskfiles/` directory at `origin/main`
— only the top-level `Taskfile.yml`; `CLAUDE.md` is a **symlink** to `AGENTS.md`,
so the AGENTS.md edits are the CLAUDE.md edits.)

**Rewired:** `hooks/pre-commit` → `charly task policy-b|harness|self-test`;
`.github/workflows/sync.yml` → `charly task sync|skills|policy-b`; docs
(`AGENTS.md` → `CLAUDE.md` symlink; `README.md`, `HARNESS-PARITY.md`,
`DOC-VERIFICATION.md`); harness allow-lists (`opencode.json`, `reasonix.toml`,
`.claude/settings.json`) and the workflow/agent task references
(`.claude/workflows/*`, `.opencode/agent/pr-validator.md`).

**Hook git-var RCA.** The hook now scrubs `GIT_DIR`/`GIT_INDEX_FILE` (and the
other git repo vars) after `rev-parse`: git leaks them into every hook subprocess,
and they corrupt nested `git -C <submodule>` operations (the former scripts
scrubbed them internally at each git call; the task surface runs git through
subprocesses, so the hook scrubs them once at its boundary).


**charly submodule** carries main's own gitlink `9e62bcbf` (v2026.268.0651) — this
PR does NOT move it (PR #248 already did). That charly carries
`plugin-task v0.2026268.534` (the four verbs + the corrected bump order) and the
roster support, so the task surface and the roster coexist.
