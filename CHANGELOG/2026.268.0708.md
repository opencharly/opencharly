# 2026.268.0708 — feat: umbrella-root check-roster config

## Summary

Add the umbrella-root **check-roster** configuration — the single `charly.yml` entity that runs every disposable check bed (namespace-qualified) as one gate.

New file `charly.yml` at the umbrella root:
- `import: [{charly: ./charly}]` (local path) — pulls the `charly` submodule's entities + its own `@github` imports (arch/cachyos/debian/fedora/ubuntu/omarchy) as namespaces.
- `check-all-beds: { check-roster: {...} }` — `select` defaults to `*` (every disposable bed, namespace-qualified); `lanes: 16`; `cpu: 2` / `ram: 2G` enforced on every VM bed; `expected_fail` carries the negative controls (`charly.check-r10-two-vm-fail`, `charly.check-r10-stage-race`); `exclude` drops the `iterate:` bed (`charly.check-preflight-local`); host-local beds are refused by default.
- `defaults` (platform/tag/registry + build-speed tunables).

Gitlink bump: `charly` → `v2026.268.0651` (`9e62bcbf`, charly's merged `main` HEAD).

This is the umbrella-native deliverable of the roster plan; the roster engine itself lands in the `charly` submodule (rule 1 — never edit inside a submodule), where its R10 gate was proven live in opencharly/charly#656.
