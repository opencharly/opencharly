# 2026.311.1926 — docs(design): the host's GPU driver mode is the operator's, not a field (batch 63)

## Summary

Batch 63 of the DESIGN amendments (tracked in #838). `charly vm gpu status|list|mode|plan|recover` reported IOMMU
readiness, listed passthrough GPUs and let an **author set the host's vfio/native driver mode**.

**D-HW-9 already decides the middle of that:** *the solver chooses the GPU and the lease names it* — so the host's
driver mode is the **operator's**, not a document's.

| what | where it belongs |
|---|---|
| what is leasable, and readiness | `charly status` / `charly doctor`, and the `gpu` need |
| the host's vfio/native driver mode | the host, never an authored field |
| a dry run of the host's own state | `charly box inspect` |
| recovering the host's driver state | the host |

A.9 records the trade; the row takes `accept retirement`. The rule text says "dry run" rather than "plan", because
`plan` is a §2 **Not** term and the consistency control refused the first wording.

| file | what changed |
|---|---|
| `DESIGN.md` | A.9's narrowing table gains the host-driver-mode row |
| `design/dulling.tsv` | `vm gpu status\|list\|mode`: `accept retirement`, citing A.9 and D-HW-9 |
| `design/dulling-disposition.md` | regenerated |
