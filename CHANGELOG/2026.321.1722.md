# 2026.321.1722 — fix(design): the untagged FAIL gives the remedy that matches the case, with a tested predicate

## Summary

The `untagged` FAIL line now gives the remedy that matches the case, and **both** of its arms run
under test.

Head `e8be8ff735d7ebe1900c8c39fde975743967ff79`. The change is two files, `scripts/design-module-store.sh` and
`scripts/design-pintag.sh`. Line counts are deliberately not quoted: on this diff they differ by
reader (`--diff-algorithm=myers` gives 52/3 for the second file, `patience` and `histogram` give
51/2), so any single set of numbers would be a claim true only for some readers.

**The defect (opencharly/opencharly#980).** `scripts/design-pintag.sh` answers "is this pin at a
tag" from a **store**, not from the tree. For a path with **no checkout**, `design_module_store`
falls back to the clone's **shared** store (`<git-common-dir>/modules/<path>`), whose tag namespace
can predate the `tag-on-merge` tag the pin sits above. A healthy `changelog-tip` pin — merge plus its
CHANGELOG commit — therefore answers "no tag here", and the control called it untagged, with a FAIL
that named a census row as the remedy. `design/pintag-baseline.tsv` records a pin whose
untagged-ness is **real**; raising a row for a healthy pin turns the census into a rubber stamp.

**The change, in three parts.**

1. **`design-module-store.sh`** gains `design_module_has_checkout <root> <path>`, and
   `design_module_store` itself now branches on it. One place decides whether a path has a
   checkout, so the two cannot drift (R2).
2. **`design-pintag.sh`** moves the branch out of `census` into `untagged_remedy <root> <path>`,
   called from the FAIL `printf`:
   - **with** a checkout — the tag map is the pin's own store, a missing tag is the pin's
     business, and the census is the remedy;
   - **without** one — the tag map is the clone's shared store, a tag created after that store was
     last fetched is invisible, and the remedy is `git submodule update --init <path>` or
     `design-pintag.sh --remote`, with no census row.
3. **Self-test case 20 executes both arms.** It calls `untagged_remedy` twice — once with a path
   carrying a `.git` file, once with a path that has none — and asserts each wording in full.

The gate stays offline: DESIGN.md A.12 keeps step 7 network-free, and this does not touch that.

## How tested

The test that resolves the prior BLOCK is self-test **case 20**, and it runs both arms:

```text
$ bash scripts/design-pintag.sh --self-test
  self-test untagged_remedy                                         : BOTH arms of the untagged remedy run
  self-test an untagged pin with NO checkout names the shared store and the real remedies fails as designed
design-pintag: self-test passed (20 cases; every state, both census directions, the skip, the unreadable pin and bo…)
```

Case 20 is not a label — it fails unless every one of these holds:

```text
hc_own=$(untagged_remedy "$um" hc_yes)      # hc_yes carries a .git FILE
hc_shared=$(untagged_remedy "$um" hc_no)    # hc_no has no .git

design_module_has_checkout "$um" hc_yes        → true
design_module_has_checkout "$um" hc_no         → false
"$hc_own"    contains "own module store"  and "no census row"
"$hc_shared" contains "shared store", "git submodule update --init hc_no", "add no census row"
```

A swapped branch fails it, because each arm's output is asserted by the strings only that arm can
produce. This is what the previous revision lacked: it tested the predicate but never executed the
with-checkout message path, which is why the tier claim did not hold.
