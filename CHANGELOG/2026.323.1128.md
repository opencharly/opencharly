# 2026.323.1128 — fix(pi): retire a watched item on any engine state event, so CONFLICT cannot hot-loop

## Summary

A regression fix for opencharly/opencharly#1160. Head: `f6f0ebf5f16bca009de8cb47463f0e10d3c00886` — 4 files, +109 −25 against `main`, in four commits: `ee926f9b` (the fix), `bb821fca` (round 2), `d5e54e55` (a merge of `origin/main`, which had advanced the `charly` pin) and `f6f0ebf5` (round 3).

**The defect.** #1160 added `conflict` to the events pi's binding watches, but `.pi/extensions/watch.ts` retired an item only on `MERGED`, `CLOSED` and a hand-coded `STALL`. A state event fires from the arm baseline (`runWatch` checks it before anything else), and `--no-arm-wake` does not suppress it. So a watched PR that conflicts with its base re-fired `CONFLICT` on every re-arm — about every 2 s, each one a pi user turn and a GitHub request — for as long as the conflict lasted. The OpenCode binding was not affected: its loop drops an item on any event in the engine's `STATE_EVENTS`.

**The root cause** is the hand-kept list: the binding restated which events are state events, and the restatement went stale the day the engine gained one.

**The fix:**

1. `.pi/extensions/watch.ts` imports `STATE_EVENTS` from `scripts/gh/lib/watch.ts` and keeps ONE `retired` set: an item whose state event fired is not re-armed until a restart. The former `done`/`stalled` split existed only for the status display and named events by hand; it is gone, and the binding compares `ev` with no literal event at all.
2. `scripts/check-pi-watch.mjs` asserts the import, the `STATE_EVENTS.has(…)` rule, and that no comparison of `ev` with a literal event exists, with three new self-test mutations (the import removed; the rule replaced by a hand-coded `STALL`; a terminal event named by hand). It gains a **`LIVE_PI=1` layer**: the real `pi` runtime loads the extension with its shared-lib import, against a local GitHub that always serves a conflicted PR, and one arm must make ONE GraphQL request and deliver ONE wake in 20 s. With `LIVE_PI` unset the layer SKIPS visibly; with `LIVE_PI=1` and no `pi` on PATH it FAILS, because a live run the operator asked for did not happen (R8).
3. `scripts/check-gh-tools.mjs` pins the engine contract the bindings rely on: under `--no-arm-wake`, a conflicted PR still wakes `CONFLICT` at arm.
4. The watch-and-wake reference states the rule for every re-arming binding.
