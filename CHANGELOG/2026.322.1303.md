# 2026.322.1303 — fix(gates): a `||` is a logical operator, not a union — the dpat phantom finding

## Summary

`scripts/design-dpat.sh` counted the first `|` of every `||` as a disjunction: its only `|`
exclusion was half of `_|_`, and the first `|` of `||` is preceded by a space and followed by
`|`, so the D-PAT-3 reader reported a union that does not exist. `spec`'s tip
(`545c73a8`, `schema/candy.cue:56`) introduced exactly that shape — a guard with two `||`
and zero unions — and the phantom blocked the pin wave's push through the pre-push hook.

**The fix:** a `|` is a disjunction only when it stands ALONE — skip it when either neighbour
is also `|`. The `_|_` arm is unchanged; `||` never has a `_` neighbour, so the two exclusions
cannot collide.

**The message, same class as the other three gate-message findings:** a finding is acted on
only if the reader knows WHICH COMMIT was judged. The run now prints
`design-dpat: judged the index pins — spec@<sha>, …` on every run, and each failing module's
pin beside its finding (`the finding(s) in <module> are at <module>@<sha>`). A phantom is then
visible as a phantom: the reader can compare the pin with the tip.

The arms that make the fix provable rather than asserted:

- the CLEAN fixture gains a `#Guarded` block with `if x != _|_ && (y != _|_ || x != _|_)`, so

- a new `pass` arm plants spec 545c73a8's exact guard line and must stay silent
  (`self-test a guard using || and _|_ (spec 545c73a8's shape)  passes as designed`);
- a new `fail` arm puts a genuine `"x" | "y"` BESIDE a `||` on one line and must still report
  the union (`self-test a real union beside a || on one line  fails as designed`).
