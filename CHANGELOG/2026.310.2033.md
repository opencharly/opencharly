# 2026.310.2033 — feat(design): the disposition table states its own counts (batch 52)

## Summary

I reported **"179 sharp / 78 dulled"** for ten rounds running. That does not add up: 179 + 78 + 3 = **260**, not
264. The numbers were computed by hand every time, and a hand-computed total is a claim like any other — with
nothing checking it.

`scripts/design-disposition.sh` now opens the generated table with the counts **it derived from the ledger**:

```
**264 capabilities:** 179 sharp, 82 dulled (57 settled, 25 owed), 3 forbidden, 0 unknown.
```

Because `scripts/design-ledger.sh` regenerates this file and fails on any drift, a quoted total is now the
**artefact's**, not mine.

| file | what changed |
|---|---|
| `scripts/design-disposition.sh` | a counts header, computed in the same pass as the table |
| `design/dulling-disposition.md` | regenerated with the header |

**The subtlety that took two attempts:** *settled* must be counted **within `dulled`**. The three `forbidden`
rows also carry `accept retirement`, so a naive count reports 60 settled and the parts stop summing to the
whole — the same class of error the header exists to prevent.
