# 2026.305.1912 — docs(design): no prose states the size of a set that can grow

## Summary

Closes #821.

DESIGN.md counted sets that grow, such as "charly is eight mechanisms", "six deployment kinds", "the five role words", "four channels", "Eight checks", "the six derivation forms D1–D6", "`M1`–`M8`" and "S1–S11". Every row added to or removed from a table meant a prose rewrite, and nothing caught a missed one. This change makes adding a row a table-only edit:

- **Count-free prose.** Every such phrase now names the set and points at its table: "the mechanisms below", "every deployment kind is a row of the deployment-kind table", "a row of `_role`", "Each channel below", "Each check below", "the derivation forms of D-GEN-8", "the id of a §1.1 mechanism", "the patterns of §10.1". The headings follow: §1.1 is now *The model: mechanisms*, and §14.2 is *One box, every form*.
- **The rule, stated once (A.6).** *Adding a row touches no prose.* A set that can grow is its table, and the prose never states its size or spans its ids. "One" (a single form, D-LAW-1) and "both" (the two sides of a law that admits exactly two, such as D-DEP-6) are not sizes, so they stay.
- **Enforced (A.4 check 5, `scripts/design-consistency.sh`).** A number word before a set noun fails in DESIGN.md and DESIGN.cue. An id range from a set's first row fails there and in TODO.md. The old rule that "a range S1–S<n> ends at the last pattern" is removed, since it only ever forced a rewrite and no such range may now be written.
- **Gate fix.** The parity ledger's mechanism column was accepted only as `M[1-8]`, so adding a mechanism to §1.1 would have turned the design check red. The ids are now derived from the §1.1 table.
- **Stale example.** The §10.1 S3 example showed the retired phases (`_phase: {any: {}, build: {}}`). It now shows the real table, `artifact`/`ready`/`deployment`.
- **References.** TODO.md's two `S1–S11` references now read "the patterns of §10.1". TODO.md's content is unchanged.
