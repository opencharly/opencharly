# 2026.273.0630 — docs(agents)!: one fully-planned task per subagent; the orchestrator plans it as for itself

## Summary

Settles the orchestrator↔subagent workflow contract after the `#717` failures, in ONE coherent
change (the contract had been authored by trial-and-error mid-flight — the RCA of why `#717` took
~3 days: a moving contract plus an ungated push).

**This diff changes four things. All four are described here.**

### A. The ownership contract — the subagent duty set (`## Responsibilities`)

- **`exactly three things — RESEARCH, WRITE CODE, and MERGE CODE` → `exactly FOUR things —
  RESEARCH, WRITE CODE, MERGE CODE, and FIX ITS PR'S VERDICTS`.**
- **Section heading** `### A subagent — RESEARCH, WRITE CODE, MERGE CODE — nothing else` →
  `### A subagent — RESEARCH, WRITE CODE, MERGE CODE, FIX ITS VERDICTS — nothing else`.
- **Worker bullet (replaced):** the old text **forbade** workers from reading verdicts
  (`It NEVER … NEVER reads or dispositions a validator verdict`). That was **wrong** — reading the
  verdicts in full and fixing every finding **IS the worker's job**. The new bullet states it:
  *"Reads `charly/pr-validator`'s results IN FULL and fixes EVERY finding — that IS its job."*
  (The `NEVER creates a PR / pushes / writes a body / decides a merge / coordinates` list is kept.)
- **Brief `Scope boundary` field:** `RESEARCH / WRITE CODE / MERGE CODE only` → `+ READ AND FIX ITS
  PR'S VERDICTS`, with the note that reading/fixing verdicts is the worker's job, not a prohibited act.
- **PR-lifecycle item 3** now names **both** duties: the **worker** reads verdicts to FIX, the
  **orchestrator** reads them to GATE.

### B. One task per subagent, fully planned before dispatch (`## Subagent lifecycle` → *Instruct* / *Use*)

- **New planning preamble:** *"The orchestrator FULLY PLANS every subagent execution — exactly as
  it would plan the task for itself"*: it does the planning itself (exact files, edits, commands,
  evidence, acceptance) **and reads the relevant skills itself, EMBEDDING their content in the
  brief** (naming a skill to load is not enough). *A brief that leaves ANY decision to the worker is
  an orchestrator defect and is NOT dispatched* — the plan is fully fleshed out with **zero
  ambiguities**.
- **New brief field** `The full plan (zero disambiguation)` (the end-to-end execution + embedded
  skill content), added beside the `Task` field.
- **New `Use` rules:** **ONE task per subagent** (a wave of N PRs/items → **N agents, one per
  item**, each with only its findings/file list), and **a task that is not fully planned is NOT
  dispatched**.
- **Reconciled `Skills to load` field:** the skill is loaded for full context, never the only home
  of a rule.

### C. Validate fully BEFORE the push (orchestrator duty)

The orchestrator's *"Fully validating every code change AND every PR body BEFORE the push"* bullet
now spells out the concrete checks — body read end to end; **`Assisted-by:` footer LAST**; every
evidence claim matches the diff; every rule R0–R10 answered; tier matches the proof; **verbatim**
output — and states: **"The validator is NOT a body-linting loop"** — a body/footer/evidence/
rule-answer finding is an **orchestrator validation failure**, fixed in that push, **never re-fired
and iterated**.
