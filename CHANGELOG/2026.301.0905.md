## Summary

Head `af67a1134be4ed2627137f1b3e44f8a2573a606f` — **3 files changed, 74 insertions(+), 4 deletions(-)**.

**The rule now names the rule, not one repo's command.** The org-wide *How tested* bullet told every reader in every repo to run the umbrella's own `./charly/bin/charly task verify` whenever a diff touches a submodule, a gitlink or a pin. A member repo has neither that path nor that task: in opencharly/charly the same command exits 1 with `unknown task "verify"`. The bullet now names the RULE — the gate that owns the change, run in the repo the change lands in, that repo's own `charly.yml` declaring its path and its task name — and marks the umbrella's command as the EXAMPLE it is.

**The umbrella's example is measured, and the measurement refines the issue's premise.** `charly.yml`'s `verify` task composes the pin contract's consistency half (`pins MODE=verify`) AND the currency question (`pins MODE=currency`), so it is a SUPERSET of the currency reading, not the superseded gate the issue's part 1 named. The currency step REPORTS a behind pin rather than failing on it, so the honest currency claim stays that step's own report, never "verify is green". The umbrella's own task table described `verify` as policy B, the checkout audit and the branch audit; the currency step it has run since the pin contract's cutover was missing from that enumeration. The table row now names the step and what it does with a behind pin, so the umbrella describes the gate it recommends the way it runs it.

**The sibling the same sweep found.** The Hooks doctrine still told every repo to "Install the clone-level hook once with `./charly/bin/charly task hooks`". That hook is the umbrella's own — a member repo has no `hooks/` and no such task. The sentence now says so. Leaving it would have made the rulebook contradict itself one paragraph apart, and a cutover that leaves a sibling of the same mechanism behind is not a cutover.

**Both retired wordings are now KEYED** in `scripts/check-retired-claims.mjs`, so the class cannot come back silently. The key is the RULE plus the ABSENCE of a scope word in the claim that carries it — the scope word ("that repo's own", "the umbrella's own") is what separates the rule from its qualified form. A PATH-keyed class would cry wolf: on the umbrella's tree at `e35485a` — the base this change is written against — the prefix `./charly/bin/charly task` occurs in 22 places across 10 tracked files (§5), so the trigger is the rule, not the path.

**Round 1 — the validator's BLOCK, and the RCA behind the fix it asked for.** The `charly/pr-validator` blocked the first push on a self-contradictory measurement: this body said 22 places across 10 tracked files and the NEW CODE COMMENT in the same diff said 15 places across 10 files. The root cause is a measurement with no command attached to it, living on THREE surfaces — the commit message, the code comment and this body — of which the re-derivation that corrected it updated two. The umbrella's own tree grew under the stale figure while it sat there (19 occurrences across 8 files at `22016651`, 21 across 9 at `f7d884b9`, 22 across 10 at `e35485a`), so a figure measured against a moving reference drifts with nobody touching it.
