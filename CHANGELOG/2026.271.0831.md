# 2026.271.0831 — docs(agents): todo-ledger interruption safety + opencode watcher binding

## Summary

Two upstream, harness-neutral rules that make the coordination/watch machinery safe for
**every clone** of the umbrella:

1. **`AGENTS.md` rule 11 — Todo ledger & interruption safety.** `todowrite` is the session's
   durable ledger. On ANY new/interrupting instruction (a user message, an automated watcher
   alert, a delegated report) the agent MUST first reconcile the list (keep every in-flight
   item, add the new one) and THEN act — never start from scratch, never drop an in-flight
   item. This fixes the real failure measured this session: an `opencode run --session` watcher
   push (and any new user message) starts a new turn, and in-flight work was lost.

2. **`.opencode/instructions.md` — "Watching for PR events (opencode)".** Documents the
   generic/harness split and the opencode binding: the watcher is the harness-independent
   `marketplace/scripts/gh_watch.sh` family; opencode has no background-completion notification
   by default (`task` is synchronous, `bash` blocks; `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`
   opts into async) and loads config/plugins/skills once (no hot reload); the one documented
   push channel is `opencode run --session <ses_…> "<alert>"`; the fuller native surface
   (`client.tui.showToast`, `client.session.promptAsync`, the `event` hook) is an optional
   plugin.

Both files are on the **auto-loaded** path (`AGENTS.md` for every harness; `.opencode/instructions.md`
via opencode's `instructions` list), so a fresh clone gets them with no setup.
