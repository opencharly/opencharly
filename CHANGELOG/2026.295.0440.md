# 2026.295.0440 — fix(coord): the closed-set gate's self-test cleans up its fixture dir (opencharly/opencharly#576)

## Summary

The fresh `charly/pr-validator` on `opencharly/opencharly#575` (the umbrella's leg of the
coordination-verb cutover) carried one non-blocking note about this session's own change:

> *the `selfTest` `process.exit` inside the outer `try` skips the `finally` `rmSync`,
> leaking a temp dir per run*

It is a real defect in a change this session made, so it is fixed here, not filed away
(R1). Tracking issue: `opencharly/opencharly#576`.

**The defect.** `scripts/check-coord-verb-set.mjs` — the closed-set gate this cutover
added — ended its self-test with `process.exit()` *inside* the outer `try`:

```js
function selfTest() {
  const dir = mkdtempSync(join(tmpdir(), "check-coord-verb-set-"));
  try {
    ...
    process.exit(bad === 0 ? 0 : 1);   // exits from inside the try
  } finally {
    rmSync(dir, { recursive: true, force: true });   // never reached
  }
}
```

`process.exit()` terminates the process at once, so the `finally` that removes the fixture
directory never runs. Every `--self-test` run — and `charly task verify` runs it on every
umbrella PR — leaves one empty directory in `$TMPDIR`, and leaves it **silently**: the exit
code is 0 either way.

**The fix.** The exit moves OUT of the `try`, exactly as the sibling gates in this tree
already do (`scripts/check-opencode-coord.mjs` and `scripts/check-issue-tracker.mjs` both
exit in their trailing block, after every `try`/`finally` has completed). The self-test
now RETURNS the number of failed arms, and the caller exits:

```js
function selfTest() {
  const dir = mkdtempSync(join(tmpdir(), "check-coord-verb-set-"));
  try {
    ...
    return bad;
  } finally {
    rmSync(dir, { recursive: true, force: true });   // now reached
  }
}
```

**The control.** A fix that nothing observes can come back silently, and the RCA's missed
control was exactly that: *nothing observes `$TMPDIR`*. So the self-test now runs its arms
in a **child process under a controlled `TMPDIR`**, and the parent — a different process,
which is still alive when the child's exit short-circuits the cleanup — looks at that
directory from the outside and fails if anything is left behind:

```
$ node scripts/check-coord-verb-set.mjs --self-test
  ... the arms ...
check-coord-verb-set --self-test: OK
  PASS  the self-test left no fixture directory behind
```

The observer is the reason the coverage is real: an in-process assertion could not catch
the regression, because the process that would make it is the one the early exit kills.
`--self-test-arms` is the internal mode the observer spawns; the public mode is still
`--self-test`, and `charly task verify` runs the unchanged command.

**Nothing else changed.** The gate's contract is the same: same nine labels, same order,
same two jobs, same exit codes, same 17 surfaces, same 11 self-test arms. `charly.yml` is
untouched — the step that runs the gate already runs `--self-test`, and that command now
observes the cleanup as well.
