# 2026.279.1500 — fix(harness): five measured defects in the pi PR-status tool

## Summary

`.pi/extensions/github-pr-status.ts` is the ONLY way a pi session learns a PR's
`charly/pr-validator` verdict — GitHub Actions has no path into a session. It was **broken on
its first live use**, and this fixes the five defects the live use exposed:

1. **State casing.** `gh pr view --json state` returns UPPERCASE (`"OPEN"`), but the poll
   compared lowercase `"open"`. `"OPEN" !== "open"` read as "this PR is no longer open" on
   every poll, so **`watch` returned after a single poll instead of waiting**. Normalised
   once, in `getPR`.
2. **Run lookup.** The run was found with `gh run list --workflow pr-validator.yml`, which
   does NOT resolve the org-required workflow (defined in `opencharly/.github`, it reports
   as `charly/pr-validator`). Measured: it listed unrelated heads while the real run existed
   on the head, so `check` reported "none found" even with a live run. Now queried by **head
   SHA** and matched on the run NAME, newest first.
3. **Failing step.** `gh run view <id> --json jobs` 404s on the org-required workflow — the
   same class the git-workflow skill documents for `gh run rerun`. The failing step is now
   read through the REST jobs API.
4. **INCONCLUSIVE.** A verdict-less `## validator INCONCLUSIVE` comment carries no
   `Verdict:` line, so the comment scan skipped it and reported `no-verdict-yet` (or an OLDER
   PASS/BLOCK). Now classified distinctly, with the "this is not a code finding — escalate"
   guidance in the output.
5. **Watch short-circuit.** `watch` short-circuited on ANY concluded run (including a PASS)
   while its own loop kept polling after a PASS that arrived LATER — the two paths disagreed
   about the same state. It is now terminal only on a FAILED run or a merged/closed PR, so a
   PASS keeps polling until the merge lands (PASS != merged).

Adds `scripts/check-pi-pr-status.mjs` (static assertions over the shipped code + a real
TypeScript parse + a mutation self-test) and wires it into `hooks/pre-commit` and `charly.yml`.

**Review round 1 (R5/B5).** Two shipped comments claimed "Four" defects above five numbered
ones; both now say Five and list defect 5. Comment-only, no behaviour change.
