# 2026.295.1842 — docs(rulebook): a skill lives with the code it describes; a skills-only repo is not a class

### The old text, and the new

**Part II #5 — before.** It said skills "live in the repo that owns them" and never defined
ownership, so every reading was admissible, including the ones that produced carriers:

> A skill's `SKILL.md` and an agent definition's `<name>.md` are **authored content**, the same class
> as `AGENTS.md`: they live in the repo that owns them, under its own `.agents/` trees, and are
> discovered natively from there. The umbrella populates its own `.agents/` because it authors
> skills, never because it vendors the corpus. Where a harness rooted at this umbrella cannot reach
> the corpus natively, the binding that bridges it must be **DERIVED** from the pinned corpus, never
> maintained by hand …

**Part II #5 — after.** Retitled *"Harness config lives only in the umbrella — and a skill lives with
the thing it describes"*, and the classifier is stated as three bullets:

- **A skill belongs with the code, plugin, or config it describes** — the same repo and the same
  lifecycle, so the skill and the thing it documents are edited, reviewed, and tagged together and
  the skill cannot drift from the surface it explains. If the described entity lives somewhere, the
  skill goes there.
- **A general-guidance skill — one with no code, plugin, or config behind it — belongs in this
  umbrella**, because the umbrella is the only repo every consumer shares and guidance with no home
  repo has no other place a consumer can reach it from.
- **A repo whose only content is skills is not a valid class**, and neither is a `*-skills` carrier
  that exists only to own prose. The class rule that retires them is
  [Repo classes and naming](#repo-classes-and-naming).

The lead sentence states the discriminator explicitly: **which repo owns a skill is decided by what
the repo CONTAINS, never by what the skill is about.** The surviving rule from the old text is kept
verbatim — **a hand-maintained corpus binding is forbidden; it must be DERIVED** — as is the
harness-config half and the umbrella-authors-skills-never-vendors-the-corpus sentence, which is now
true rather than aspirational.

**"Repo classes and naming" — new class rule.** The section listed only what the prefixes were, which
is how `layer-*` came to double as a prose home. It now carries a fourth bullet:

> **A repo whose only content is skills is not a class.** No prefix exists for it and none may be
> invented: a `layer-*`, `distro-*`, `plugin-*`, `pod-*` or `vm-*` repo must hold the code, plugin,
> or config its name promises, with its skills beside that content (Part II #5). A `*-skills` carrier
> that exists only to own prose is retired by this rule … A carrier CANDY inside a repo that already
> holds code is a different thing and is unaffected: it is the shape image-owned skills need.

That last sentence is deliberate: `distro-arch`'s `candy/arch-skills` is a real carrier candy with
`copy:` install content inside a repo that holds `box/arch`, and the policy retires **repos**, not
that sanctioned shape.

**R0 — a sibling surface carrying the same false claim, corrected in the same change (R4/R5).** R0
said "Skills live in the opencharly/marketplace repo", which is true of the delivery corpus and false
of authorship — the exact confusion that let a carrier look legitimate. It now reads: skills are
**authored** in the repo that owns them (Part II #5) and **published** as the generated corpus.

**README.md — the placement rule that offered the loophole.** "Candy layers — `layer-<name>`: ONE
candy with its files beside it, **and/or a family's `skill:` entities**" becomes "ONE candy with its
files beside it … **a repo whose only content is skills is not a class**". README's org-map places
each class; it must not advertise a class the rulebook retires.

### Why the rule needs a class rule, measured not assumed

A prior scan for "skills-only repos" returned `distro-arch skills=7 other-content=0`,
`layer-charly-build skills=15 other-content=0` and ~30 similar. That instrument was broken — its
`other-content` grep required an exact `"path": "box/…"` prefix, and `distro-arch` holds `box/arch`.
Re-derived from the 431 initialized checkouts by classifying **what each repo contains**, excluding
VCS/boilerplate (`AGENTS.md`, `README.md`, `CHANGELOG/`, `.github/`, `LICENSE`) and requiring a real
candy field at its structural indentation plus a non-`true` plan command:

**22 of 431 repos are skills-only, carrying 94 of the 422 skills** — 5% of repos, 22% of skills. A
bounded set, not a mass migration, and not zero. Twelve further repos have no non-boilerplate content
and carry no skills at all (a separate defect, not this PR's).

### Round 1 RCA — the missed control

Round 1 returned BLOCK on two findings, both about the BODY rather than the diff, and both mine.

**(1) The `AI_REVIEW_PROMPT` claim.** I pasted the script's PASS line and then wrote a sentence
describing what it proves — "the committed-vs-live `AI_REVIEW_PROMPT` equality" as "part of this
class's emitted-artifact boundary" — without reading the comparison's inputs. I had read the script
earlier and quoted its line-65 comment ("The committed AI_REVIEW_PROMPT block of
`action-review/charly.yml`, dedented"), which names its own scope, and still described a different
one. That is measuring at one scope and describing another: the check never touches `AGENTS.md`.
**Missed control:** the self-audit pasted gates but never asked, for each pasted line, *which files
is this line about?* A pasted PASS is evidence only for the inputs the pasting agent has named.
**Root fix, applied here:** the R7 bullet now names `committedPrompt()` and the exact comparison,
and the "How tested" section attributes each PASS to its inputs.

**(2) Summary/scope contradiction.** The summary said the change "retires a repo class and moves the
skills the org already ships", and the same body later said the moves are NOT in this PR. Both
sentences were written by me in one sitting. **Missed control:** no pass for claims a body makes
about the body's own scope — precisely the `git-workflow` rule that "fixing a claim means finding
every instance of it" and that a body-wide claim is a property of the WHOLE body. **Root fix:**
the summary now states that the diff is prose only and names the follow-up unit explicitly; the
"moves no skills" statement stays, so the two agree instead of one being softened.

**(3) The non-blocking note, fixed rather than rebutted.** The rewrite left one `*Detail:*` pointer
where the paragraph covers two artifact classes. Both pointers are restored in `4ab028f`
(`/charly-internals:skills` for the authored-content contract, `/charly-internals:agents` for what a
harness loads and binds) — a fix, not a rebuttal, because the `agents` half was real guidance that
the rewrite deleted.
