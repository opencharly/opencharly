## Summary

### 1. Command hygiene - a piped exit code is not the command exit code

In `cmd | head` the shell reports *head* status, so an assertion that a command "printed X and returned 0" can be false in **both halves at once**. The section already refuses `grep | head` for output reasons; this adds the *status* reason, with the remedy (capture and report the command own status, or read `${PIPESTATUS[0]}`). *Measured: an `rc=0` presented as proof that a verb dispatched was the pager exit code.*

### 2. Agents, Workflows & Teams - what a monitor must be

A monitor is a **managed background command** the harness can wake on; a detached process cannot wake anyone, so every round becomes a poll. **Arm ONE watch over the whole in-flight list and block on it**, and **re-arming REPLACES the live watch rather than adding to it** - a changed item list is a *different* watch. Its alarm **MUST have a clearing condition** and a window **matched to what it watches**: an alarm nothing can clear is a loop, not an alarm, and where nothing can clear it the state is recorded instead. **The process table, not a job listing, is the authority on what is watching.**

### 3. Charly CLI discipline - a message is owned by the module that built it

A message a program prints is emitted by whichever **module** built that code, not the repo the command ran in; locate it in the module cache before reading the checkout. *Measured: three greps inside the failing repo found nothing; one module-cache grep produced `loaderkit/walk.go:192`.*
