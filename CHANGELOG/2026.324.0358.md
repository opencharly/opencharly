# 2026.324.0358 — feat(setup): one command to a ready session worktree, the DESIGN stores in every clone, and gates that cannot be silently absent

## Summary

The setup cutover of opencharly/opencharly#1155 (with #1142): a fresh clone and a session worktree each come up ready with one command and no other step, and the gates a push depends on cannot be silently absent. Head: `69d06532ff61e9a77ed47ee2072c4fd020ac9a98` — 12 files, +640 −51. Built to the design posted on #1155 (comment 7024039871) and the operator's choice there, "Main clone holds all": every module store lives once, in the main clone's common git dir, and every worktree borrows from it.

1. **ONE command to a ready session worktree.** `CHARLY_WORKTREE_SLUG=<slug> charly task worktree` (`bash scripts/new-worktree.sh <slug>` before a binary exists) fetches `origin/main`, adds `.worktrees/<slug>/opencharly` on `feat/<slug>`, brings the module stores up to the new pins, materializes the working set and builds the worktree's own `charly/bin/charly` (R9). A bare `git worktree add` gave a tree whose pre-push skipped the body linter.
2. **The DESIGN gate's stores, in every clone.** `init-submodules.sh --stores` (`CHARLY_INIT_MODE=stores`), run by `bootstrap.sh`, gives every declared submodule a blobless object store in the common git dir with NO checkout, so the pre-push DESIGN gate reads every pin from any worktree through the existing resolver. Before, such a push from a light tree drew 232 findings (measured on a `TODO.md` push, before #1193 took `TODO.md` out of the gate's inputs).
3. **A linked worktree borrows, never re-downloads.** In a linked worktree, `init` initializes each path with `--reference` to its store, so the clone records a Git alternate; a path that cannot borrow fails the run, named. The git-workflow skill already claimed this; it is now true.
4. **The working set follows a pull.** A working-set (or `--all`) run advances every OTHER checkout a pull left behind its pin when it is clean and a strict ancestor; anything else is a notice. A caller that names its paths still gets exactly those. The closing notice counts the checkouts on disk, not the request.
5. **Quiet fetches.** `bootstrap.sh` sets `fetch.recurseSubmodules=false`.
6. **Gates that cannot be silently absent.**
   - `hooks/pre-push`: when the index pins `marketplace`, every not-materialized state BLOCKS (absent, not a git repository, a linter that cannot run), naming `bash scripts/init-submodules.sh`; a tree with no marketplace gitlink keeps its visible skip. A checkout at the wrong commit already blocked (#1176), so a missing one passing was backwards.
   - `.claude/hooks/pre-commit-gate.sh`: a commit in an umbrella clone whose `core.hooksPath` is not `hooks` is refused, naming `charly task hooks`. The pi, OpenCode and Codex bindings inherit it, because they delegate to this one script.
7. **Two defects found on the way, fixed here because this change edits their files.**
   - `hooks/pre-push` asked `git -C marketplace rev-parse HEAD`, which in a directory that is no repository answers with the SUPERPROJECT's HEAD — so an unmaterialized `marketplace/` read as "a checkout at another commit". It now asks whether the directory is its own top level.
   - `.claude/hooks/pre-commit-gate.sh` reported a golangci-lint built with an older Go than the module targets as "lint reports issues". It is the environment class the gate already treats as a visible NOTE (an unobtainable toolchain, a timeout), and it is now one. The suite's Go fixtures name a Go the installed linter can load: on `main` two cases were red and `lint failure blocked` was green only because the linter could not load the module.

One point of the posted design is amended in the open (#1155 comment 7028829238): the "project cannot load" error belongs to charly core, which cannot name an umbrella script, and the umbrella's own `charly task init` cannot run while the project does not load. It is filed as opencharly/charly#1220; the README names `bash scripts/init-submodules.sh` as the step after a pull that adds an `import:` path.
