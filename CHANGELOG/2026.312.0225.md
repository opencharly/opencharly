### The verdicts

**`kind:task` — accept retirement.** §15.1 makes "a routine with one step list ... a pipeline of one stage", and D-FLOW-1's stage cannot carry the task runner's execution model, so A.9 records the trade (a `dir`, a `vars` map's `${VAR}` substitution, a `depends_on` closure, the staleness model, `silent`/`interactive`, the platform filters). Corrections: the quoted "a bounded choice (`one_of`), never a substitution" clause is §2's `parameter` term, not §8.1's type table (DESIGN.cue says a pipeline's parameter is any text); D-FLOW-1's arms are `step`/`pipeline`/`deployment`/`ask`, not "steps"; and `spec/schema/task.cue:39-100` was out of range — `#Task` is 41-88.

**`check plan` — accept retirement.** §22's checks group names no verb that resolves a box's check plan and prints it without running the checks; the resolve-and-print verb is `box inspect`, which prints the box's own authored `plan:` from the resolved project, not a built artifact's baked plan. Corrections: the old cell said `check step` runs, but plugin-check's command tree has no `step` leaf; and the old target `check box` cannot resolve and print.

**`pooled fan-out (lanes)` — accept retirement.** D-FLOW-1 already states the target verbatim — one run per item of the list a parameter holds (`lane:`), at most `concurrency:` at once — so the trade belongs in A.9, not in an amendment to a requirement that already says it. Corrections: `batch_size`'s bound is `concurrency` (`#StageFields`), while `pause_ms`, `item_var` and `index_var` have no field; §15.1's example reads the item as `$LANE_ITEM` and nothing configures that name; `charly pipeline run --lanes N` no longer exists; the cited ranges move to `pipeline.cue:89-97` and `graph_test.go:63-78`.
