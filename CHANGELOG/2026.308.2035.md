The mutation stales one row's quote (`#StageAsk: {prompt, stale}`) and the run fails with `is quoted as`;
before this batch it would have passed.

Round 2 of review found the control itself was incomplete: the walk that reads a definition's body did
not stop at the next `#Name:` line, so a **brace-less** definition (`#Text: string`) swallowed the braced
one after it, which was then never registered and never checked — a false negative for exactly this
class. The walk now stops at the next definition and resumes there, and a brace-less definition registers
with an empty field set, so a row quoting it fails loudly instead of vanishing. Proved by **counting**, not by one sample — the schema's own count against the parser's:

```console
$ python3 scripts/design-shape-check.py --count DESIGN.cue

declared 318 | registered 318 | missed 0
```

Three numbers, in order: the `^#Name:` lines in `DESIGN.cue`, the definitions the parser registered, and
the definitions it MISSED. The last is `0` on **this** head. `--count` is not a one-off proof: the ledger
control runs it on every gate, and a missed definition is a FAIL, so the coverage can never drift silently. A skipped definition is silently unchecked
(`if name not in defs: continue`), so a green `design-check.sh` cannot prove this on its own. Both ledgers
are checked.
