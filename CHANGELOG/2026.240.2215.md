# 2026.240.2215 — feat(pi): add the gh_pr_status tool — GitHub PR + charly/pr-validator status checking

## Summary

Adds a project pi extension tool `gh_pr_status` to the umbrella's `.pi/` config, closing the gap where the org-wide `charly/pr-validator` verdicts land on GitHub Actions with no path into a pi session.

The tool (`.pi/extensions/github-pr-status.ts`, registered in `.pi/settings.json`):
- **check mode** — one-shot PR status: state, head SHA, mergeable state, the latest `charly/pr-validator` run ON THE CURRENT HEAD (not a stale one), its conclusion, the failing step (`Gate (BLOCK)` vs `wait-for-ci` vs gofmt), and the latest PASS/BLOCK verdict comment.
- **watch mode** — polls until the validator concludes on the current head (or the PR merges/closes, or a timeout) and returns the full matrix. Run inside a background subagent; its completion is the real wake primitive.

It distinguishes a pr-validator BLOCK from a CI-wait timeout from a gofmt failure, because each demands a different agent response. It wraps `gh` read-only only.

## How tested

The exact gh command sequences the tool runs were exercised live against opencharly/charly#414:

```
$ gh pr view 414 --repo opencharly/charly --json state,headRefOid,mergeableState,title
# state=open, head=b3cbc97, mergeable, title=fix(build): ...
$ gh run list --repo opencharly/charly --workflow pr-validator.yml --limit 10 --json databaseId,conclusion,headSha | jq ".[] | select(.headSha == \"<head>\")"
# run 33208492188 concl=success   <- the tool reports this as PASS on the current head
$ gh api "repos/opencharly/charly/issues/414/comments?per_page=5" | grep -oE "Verdict: (PASS|BLOCK)" | tail -1
# Verdict: PASS
```

The settings.json parses; `scripts/check-harness-parity.sh` passes (the `.pi` config is NOT in the parity SHARED list, so this does not affect the mechanical harness twins).

```
## opencharly/plugin-build #3 — PASS
- State: OPEN, Head: 448bd589d4, Mergeable: BEHIND

## opencharly/charly #414 — PASS
- State: OPEN, Head: b3cbc977b3, Mergeable: UNKNOWN
- Verdict: PASS — Validator run 33208492188 @ b3cbc977b3, conclusion: success
```

Both calls succeeded; the tool returned state, head, mergeable, verdict, and the validator run conclusion.

## Two bugs the live testing caught and fixed

1. `latestVerdict` used `gh api --jq ".[].body"`, which emits raw unquoted markdown — not valid JSON — so `JSON.parse` always threw and the verdict was permanently `unknown`. Fixed to fetch the JSON array and scan bodies in JS.
2. `getPR` requested the `mergeableState` field, which gh rejects ("Unknown JSON field"); the valid field is `mergeStateStatus`. Fixed.

Both fixes are in the pushed extension; the fresh-session run above exercises the corrected code paths.
