# 2026.289.0419 — feat(harness): derive the skill bindings from the corpus, and classify authored content as authored (L9, L9.1)

## Summary

Closes the harness half of L9 and its companion L9.1 in one change. Two things land together, because
each is the other's reason:

**1. The rule gains the clause the migration needs (L9.1).** Part II #5 becomes *"Harness config lives
only in the umbrella — and authored content is not harness config"*: a skill's `SKILL.md` and an agent
definition's `<name>.md` are **authored content**, the same class as `AGENTS.md`, they live in the repo
that owns them under its own `.agents/` trees, and the umbrella populates its own `.agents/` because it
*authors skills, never because it vendors the corpus*.

**2. The bindings become DERIVED (L9).** `scripts/sync-skill-bindings.mjs` walks
`marketplace/*/{skills,agents}` and writes the two artifacts that enumerate the corpus, then verifies the
one that merely references it:

| binding | kind | what the generator does |
|---|---|---|
| `.dsh/skills/<name>` (353 flat symlinks) | a **mirror** — an enumeration | derives it: one entry per corpus skill, collision → hard failure |
| `reasonix.toml` → `[skills] paths` (43 entries) | a **reference list** — an enumeration | derives it: one entry per existing `marketplace/<family>/{skills,agents}` dir, in byte order |
| `opencode.json` → `skills.paths` (1 entry) | a **reference** — not an enumeration | verifies it names the corpus root; there is nothing per-family to derive |

That distinction is the whole design. The row called these "three mirrors of one artifact"; measured,
only the farm is a mirror. An *enumeration* drifts the moment the corpus grows, and the two enumerations
are exactly the ones a person was maintaining by hand; a single root entry cannot drift per family at all,
so it is verified rather than rewritten.

`charly task sync` now runs the generator immediately after the pin bump — the pin-advance path, so a
family added upstream is bound in the same pass that advances the gitlink. And `check-harness-config`'s
checks 8 and 13 stop *re-implementing* the derivation (each carried its own `readdirSync` coverage
arithmetic, including a `.well-known` special case) and instead assert the artifacts **ARE** that
derivation — which is the same thing as asking *"was the generator run?"*. Each check keeps the shape
oracles a derivation cannot provide for itself: check 8 keeps "not the bare root, every entry
well-formed", check 13 keeps "every farm entry is a symlink". A generator that emitted a bare-root entry,
or a farm of real directories, would pass its own `--check` and still be wrong.

**The sentence this change is about, and it is tonight's general form applied to harness bindings rather
than corpus artifacts: a HAND-MAINTAINED binding drifts silently because nothing derives it, and a
DERIVED one cannot. Wherever an artifact is regenerated by a chain that cannot see its source — here,
wherever a binding is maintained by hand rather than derived — the drift is silent.** The rule was never
against bindings; it was against hand-maintained copies that drift, which is what *no mirrors, no parity
gate* is aimed at.

### What this change deliberately does NOT do

- **It does not delete the three bindings**, which was the ruling's first form. The measurement above is
  why: at the umbrella root the corpus is reachable only *through a binding*, in all three harnesses, and
  the only way to make deletion coherent would be to change Part II #2 so sessions root in the owning
  repo — contradicting the premise every wave leg is built on. Option 1 was ruled and is what shipped.
- **It does not touch `#492`'s PR** (`feat/umbrella-pin-sync`, another author's). Checked: it carries 7
  gitlinks plus `scripts/sync-pr-body.sh`, so there is **no file overlap** with this change — and the pin
  advance it performs is exactly the path that now runs the generator.
- **It does not absorb `#402`.** That is the `.pi/` signpost drift, assigned and not mine; the one item in
  this row's scope that touched `.pi/` is measured above as already done.
- **It does not edit the `.agents/skills/agents/SKILL.md` skill** (a submodule copy of
  `layer-charly-internals`). Its own text already carves authored content out of harness config — *"A
  rulebook (`AGENTS.md`) is NOT harness config and stays in its own repo"* — so it is consistent with the
  amended rule and needs nothing. Spelling the skills half out there would be a `layer-charly-internals`
  row, not this one.
