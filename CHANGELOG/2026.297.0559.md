# 2026.297.0559 — fix(hooks): the commit gate decides by change class, and each leg runs once (opencharly/opencharly#602, #645, #498)

## Summary

**What this closes.** Three umbrella issues, all about the umbrella's own commit gate:

- opencharly/opencharly#602 — the main-clone binary fallback cannot load the project from a
  linked worktree, so every docs-only worktree commit dies in the hook.
- opencharly/opencharly#645 — the hook runs its charly-backed assertions TWICE per commit.
- opencharly/opencharly#498 — a fresh session worktree cannot commit an umbrella change at
  all.

**The change: the gate is DECIDED, and the decision has ONE owner.** `hooks/pre-commit-gate.sh`
decides by CHANGE CLASS:

- the **self-test** leg — the umbrella's own committed builders' `--self-test`s — is cheap
  (3.4 s measured 2026-10-24), and needs no binary, no project and no submodule, so it runs
  on every commit;
- the **pin check** leg — 29 s measured 2026-10-24 over the umbrella's whole pin set — runs
  only when the staged diff moves a gitlink.

**The change class is EXACT, not a heuristic.** Every value the pin check compares is an
INDEX entry, and a checkout's HEAD can only disagree with the index when the diff moved it
— so a commit that moves no gitlink cannot violate it. The checkout DRIFT the same verb
also sees (a checkout dirty, or at another commit, caused by no commit) stays where the
rulebook puts it: `charly task verify` (AGENTS.md Part II #1).

**Three defects die with the old code.**

1. *The duplication* — the charly-backed pair ran twice per commit, once in the binary
   branch and once under the banner. The gate is called ONCE now, and the fixture asserts
   that count, with a mutation arm that turns the gate red if a second call comes back.
2. *The `needs_charly` flag* — only the NO-BINARY branch consulted it, so the
   binary-present branch ran BOTH legs on a diff that could violate neither; and the
   no-binary branch fell THROUGH to a `run_charly` with an EMPTY binary, so the hook died
   on a command-not-found. The no-binary path now fails LOUD only when the change class
   needs the pin check, and a docs-only commit in a fresh worktree PASSES.
3. *The main-clone binary fallback* — deleted. It was a DIFFERENT source's build, and in a
   linked worktree it cannot load the project at all (R9: the binary equals the source).

**The self-test set has one owner too.** It used to exist only as the TEXT of the
`self-test` task, so the commit gate could reach it only through `charly task self-test` —
which needs the binary and a loadable project, and therefore could not run at all in a
fresh session worktree. It now lives in `scripts/self-test.sh`, and the task and the gate
both call that file, so the set of judged builders is declared once (R2).

**One precision the old hook lacked.** Git sets `GIT_INDEX_FILE` to a TEMPORARY index for a
path-limited commit (`git commit <path>`), and that temporary index — not the repository's
own — is the set of paths the commit carries. The old hook scrubbed `GIT_INDEX_FILE` before
computing the class, so a path-limited commit was judged on a SUPERSET of itself. The new
hook captures the index before the scrub and hands it to the gate, which reads the staged
diff from it.

| file | what it carries |
|---|---|
| `charly.yml` | the `self-test` task calls the script; `verify` runs the script and the new gate, plus the new gate's self-test mode |
| `hooks/pre-commit` | the driver: capture the index the commit carries, scrub the git vars, call the gate ONCE, then the node gates |
| `hooks/pre-commit-gate.sh` | the change-class decision and the two legs — the ONE owner of the charly-backed pair |
| `scripts/check-pre-commit-gate.mjs` | the gate's own assertion — static readings over the shipped text, plus FIRED assertions in a scratch git repository |
| `scripts/self-test.sh` | the self-test SET, in one place, callable without the binary |
