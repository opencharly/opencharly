# 2026.270.0753 — docs(agents): fix the sdk/spec submodule claim + gitlink-pin semantics; add catch-up/cleanup + repo-setup dispatcher row

## Summary

Corrects and clarifies the umbrella rulebook (`AGENTS.md`, symlinked as `CLAUDE.md`).
Docs-only prose (no pin/gitlink/`.gitmodules` change):

1. **R0 strengthened — skills are a MANDATORY, non-optional precondition for ANY code
   change.** A prominent callout now states: the moment a task will edit a file, branch,
   commit, push, open/update a PR, touch a submodule, or run a git/`gh` action, the owning
   skill(s) MUST be loaded FIRST — `/charly-internals:git-workflow` before ANY git/PR
   action. A change made before loading them is an R0 violation and is not landable.
2. **Rule 4 (`sdk`/`spec`).** The text claimed they are “NOT submodules”; they ARE
   `.gitmodules` submodules of the umbrella (evidence below). Reworded: they ARE umbrella
   submodules (so editing them takes a worktree here), but **charly** no longer pins them.
3. **Rule 6 rewritten to remove the self-contradiction** the validator caught
   (“no longer pinned … de-submodule cutover” vs “recorded like every other pin” / “a pin
   IS A GITLINK”). It now states one thing: they are umbrella submodules like every pin;
   what changed is that *charly* resolves them from the Go proxy at pinned `go.mod`
   requires; a pin is a **gitlink**, checked out DETACHED and clean (`task verify`).
4. **New “Catch-up & cleanup” bullet** (umbrella advances via `task sync` + PR; `main`
   ff-only; remove only your own worktree; delete a local branch only if `--merged`).
5. **Rule 9 strengthened — cross-session coordination.** When ANOTHER SESSION'S PR blocks
   you, the ONE channel is a **PR comment on the PR that owns the blocking file** (or a new
   issue naming it), actionable (slug + file/gitlink/pin + what unblocks you + evidence);
   then STOP and ask the operator. Never edit their artifact or work around it.
6. **New rule 10 — mandatory before ANY update push:** ALWAYS read the PR's LATEST comments
   + validation results AND ALWAYS write/update the PR body for the head being published.
7. **Skill Dispatcher** gains the row for the new `/charly-internals:repo-setup` skill.

> **Maintainer sign-off (T4).** This edits the enforced project rulebook; the maintainer
> (operator) is asked to sign off on this change — it adds/strengthens rules only and
> weakens no gate.
