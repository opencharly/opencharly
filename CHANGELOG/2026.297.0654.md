# 2026.297.0654 — fix(hooks): the pin contract's commit-carried inputs have ONE definition (opencharly/opencharly#661)

## Summary

**What this closes.** opencharly/opencharly#661 — the umbrella's own commit gate decides
whether to run the pin check by change class, and the shipped class covered only the
gitlinks. It also carries the disposition of the `charly/pr-validator`'s non-blocking
observation on opencharly/opencharly#660: that observation is **CONFIRMED**, and it is a
defect in the class, not a wording slip. The RCA is posted on #660's thread.

**This is the follow-up to opencharly/opencharly#660** (merged, squash `02177e7`, validator
verdict PASS), which shipped the change class this change corrects. #660's two non-blocking
observations are dispositioned on its thread; the first is the defect fixed here, the second
is a deliberate trade-off that this change does not alter.

**The defect.** `charly task pin-check` composes `verb:git-submodules` in `mode: verify`,
and that verb reads three **commit-carried** inputs:

1. the **index's gitlinks** — the edge's `got` side, and every submodule's recorded
   gitlink (the checkout audit's expectation);
2. the **manifest that declares the pin contract** — `charly.yml`'s `pins:` block, with
   its `pin_map` and `pinned_from`;
3. the **declared path set** — `.gitmodules`, which the checkout audit walks.

The shipped class was "the staged diff moves a gitlink", and the shipped comment called
it EXACT: *"every value it compares is an INDEX entry … so a commit that moves no gitlink
cannot violate it"*. That claim was false. The declaration and the path set are FILES,
and the edge's `want` side is read from the `pinned_from` checkout's HEAD tree — so a
commit that edits the manifest or the declared path set violates the pin check **without
moving a gitlink**, and the gate skipped the check that would have caught it.

**The fix: ONE definition, TWO readers.** The rule now lives once, in
`scripts/pin-contract-inputs.sh`, and the two places that ask the question ask it of that
one definition:

- the **commit gate's change class** (`hooks/pre-commit-gate.sh`) now only MEASURES —
  which staged paths are gitlinks, and which are declaration files. The rule is not
  restated in the gate, so the two cannot drift;
- the **wave body's coverage decision** (`scripts/sync-pin-evidence.sh`) reads the same
  definition, because it asks the same question — *can this diff violate the pin check?*
  Its own copy of that question was **narrower** than the truth: it decided coverage by
  "a `distro-*` pin moved", so a diff that moved charly's own gitlink (which moves the
  edge's `want` side) or edited the manifest was described in a PR body as a diff the pin
  check "cannot fail on". That was false, and it under-claimed what the gate proves.

**The prose surfaces that carried the old model** are corrected in the same change: the
`verify` step's description in `charly.yml`, and the README's row for
`charly task pin-check`, which described the command as asserting the pin contract's edge
alone while the verb runs the edge **and** the checkout audit.

**The class is a deliberate SUPERSET of the violation set.** A `charly.yml` edit that
touches no pin block still fires the check, because the check reads the whole manifest, so
a change to it can change what the check compares — and R3 forbids cleverness in place of
a rule. The checkout drift the same verb also sees (a checkout dirty, or at another
commit, caused by no commit) stays where the rulebook puts it: `charly task verify`
(AGENTS.md Part II #1), which composes the same verb.

**The coverage now has one fired assertion and one mutation arm per input**, so a dropped
leg goes red: 11 arms in the gate's fixture (each mutation turns it red, the unmutated
copy green) and 7 arms in the wave body's self-test, which judge the coverage decision
itself.

| file | what it carries |
|---|---|
| `README.md` | the `charly task pin-check` row: the verb runs the edge **and** the checkout audit |
| `charly.yml` | the `verify` step's description: the change class is the pin contract's commit-carried inputs |
| `hooks/pre-commit` | the driver: the gate is called once, and the gate decides by class |
| `hooks/pre-commit-gate.sh` | the change-class decision — it MEASURES the staged paths and asks the shared rule |
| `scripts/check-pre-commit-gate.mjs` | the gate's own assertion: a fired assertion per input, a mutation arm per input |
| `scripts/pin-contract-inputs.sh` | the ONE definition of the pin contract's commit-carried inputs |
| `scripts/sync-pin-evidence.sh` | the wave body's coverage decision — it reads the same definition |
| `scripts/sync-pr-body.sh` | the generated body's rule-10 line names the same inputs |
