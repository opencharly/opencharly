# 2026.331.0824 — chore(pins): the org-wide pin wave, and pod-whisper joins the umbrella

## Summary

The org-wide pin wave: `charly task sync` advances every umbrella pin to the merged head its repo now
carries — `charly` first, then the `distro-*` edges re-derived from charly's new gitlinks, then every
remaining leaf — so the umbrella is a clean materialization of what the org has actually released.

This wave is the landing point for two things that could not land earlier:

- **`pod-whisper` joins the umbrella.** The repo was created and its first PR merged (`v2026.331.0121`),
  and `distro-cachyos` imports it; the umbrella records the new owner as a gitlink with its pin INTENT
  declared (`branch = main`, a leaf). A `gitlink` with neither an `intent:` entry nor a `branch=` is
  `unpinned`, which fails `charly task verify` structurally — so the branch intent lands in the same
  commit as the gitlink, together with the README org-map row and the pod-class count.
- **The CDI extraction's pins.** Six owner repos merged (each with its beds and their gate), and
  `distro-cachyos` deleted its copies (`#265`) and aligned its remaining in-box pins (`#267`). The wave
  pins `distro-cachyos` at the head that contains all of it.

Why the two above could not be separate commits: the umbrella's pre-commit gate runs `pin-check`, which
refuses any commit while the index pins are behind the checkouts — after this session's merges it
reported 21 failures. The wave is the only sanctioned way to advance them (no hand-pin, no hook bypass).
