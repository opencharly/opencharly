Add the **"referenced root file exists" landing gate** (prevention item 3 of opencharly/opencharly#356) to the umbrella's `charly task verify`.

`opencharly#356` root-caused a HIGH content loss: the four canonical root narratives — `SOUL.md`, `VISION.md`, `GRIEVANCES.md`, `LIBERATION.md` — were relocated from the charly submodule root to the **umbrella** root (where every session is rooted), and the multi-repo cutover landed **delete-first** — charly#791 removed them and the umbrella PR that added them was auto-closed at the validator's block limit. For a window the files existed in **no repository's `main`**, and every agent surface (`AGENTS.md`, `.opencode/instructions.md`, `.pi/extensions/charly-gates.ts`) pointed at `charly/SOUL.md`, a path that no longer resolved. Nothing in `task verify` read those surfaces, so **no gate could see the loss**.

New: `scripts/check-root-refs.mjs`, wired into the `verify` plan with a self-test step. It asserts:

1. the four **canonical root narratives** exist at the umbrella root; and
2. every reference to a **canonical narrative** in an agent surface (`AGENTS.md`, `README.md`, `.opencode/instructions.md`, `.pi/extensions/charly-gates.ts`) **resolves** — a `charly/<Name>.md` reference whose file now lives at the umbrella root is a **STALE-reference FAIL** (the exact `#356` shape). A canonical missing at the root is check 1's failure, so check 2 owns the STALE arm and nothing redundant.

The reference walk is **scoped to the four canonical files on purpose**: matching every `<Uppercase>.md` produced false positives on legitimate different files (`SKILL.md`, `charly/AGENTS.md`), so the gate covers the narrative-relocation class and nothing else. The canonical list is **hardcoded**, so a cutover that also deletes the *reference* (not just the file) still trips the gate.

Two files changed: `scripts/check-root-refs.mjs` (new) and `charly.yml` (two `verify` steps). **Part of opencharly/opencharly#356** — this is the mechanical gate (prevention item 3); the remaining prevention items (the relocation ordering rule — add-before-delete — and the "do not auto-close a multi-repo cutover's middle producer without a successor" rule) land as rulebook/skill edits, so #356 stays open until those land.
