# 2026.278.2352 — feat(harness): gate dispatcher coverage with a ratchet; point AGENTS.md at the full table

## Summary of changes

250 of the 346 skills in the pinned marketplace corpus have **no routing row** in
`marketplace/DISPATCHER.md`, so a session following R0 cannot discover them — the generated
dispatcher carries 96 rows for 346 skills (28% routed).

This adds a gate that pins that number so it cannot silently worsen, and records in `AGENTS.md`
where the full generated table lives.

- `scripts/check-harness-config.mjs` — **new check 12**, two assertions:
  - **(a) invariant** — every `DISPATCHER.md` row resolves to a real
    `marketplace/<family>/skills/<name>/SKILL.md`. A dangling `/charly-<family>:<skill>`
    reference is a hard error in the docs build.
  - **(b) ratchet** — unrouted corpus skills may not exceed `MAX_UNROUTED = 250`.
  - Two `--self-test` mutations added, one per assertion. Two fixture defects fixed, either of
    which would have made the new check silently vacuous: `marketplace/DISPATCHER.md` was absent
    from the staged `surfaces` list, and the staged tree carried no `SKILL.md` files (so the
    ratchet read `0 <= 250` and could never fail).
- `AGENTS.md` — a pointer block after the curated dispatcher table: where the full generated
  table lives, how to browse it by category, and why the curated table is **not** spliced from
  it. The table's intro was reworded to remove duplication with the new block. No heading,
  R-number, or clause name moved.

**Why a ratchet, not a hard assertion.** A hard "every skill has a row" assertion is RED on the
tree it would land on, and `main` is PR-only with required status checks — a permanently-red gate
could never merge and would block every unrelated PR until ~190 owning repos authored `triggers:`.
The ratchet asserts the gap may not GROW; fixing skills passes and lets the ceiling be tightened.
