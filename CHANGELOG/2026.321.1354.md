# 2026.321.1354 — fix(init): derive a BARE repo name a gate reads, not only a slashed path

## Summary

The working-set derivation now sees a **bare** repo name that a gate reads, not only a path with a
slash — which is what makes `design-pintag.sh` runnable on a freshly materialized tree.

Head `43fc1a1632466777910fb2ca9cd7b64ce10d37a2`. Diff, from `git diff --numstat origin/main...HEAD`:

```text
19    1   scripts/init-submodules.sh
1 file changed, 19 insertions(+), 1 deletion(-)
```

**The defect (opencharly/opencharly#1076).** Source 4 of the derivation — "the repos the umbrella's
own gates read" — accepted a quoted string only when it carried a `/`:

```python
head = value.split("/")[0]
if "/" in value and head in declared:
```

`design-dpat.sh` names the contract repo as a **bare** literal when it compares a pin's path
(`$2 != "spec"`), so that read was invisible and the derived set omitted `spec`. `design-pintag.sh`
then reads the `spec` pin's tag from `.git/modules/spec` and, on a fresh tree, died before it could
judge anything.

**Why it is a dead gate, not a missing checkout.** Following the documented bootstrap order on a
fresh worktree at `origin/main`, with the script unpatched:

```text
$ bash scripts/init-submodules.sh
init: OK — 12 of 12 requested path(s) are materialized at their recorded gitlinks

$ bash scripts/design-pintag.sh
design-pintag: spec is pinned at 9b3403a376d53b0c7f6f683aa15da2fc884bcf1c and
               /home/…/.git/modules/spec does not have that commit
design-pintag: FAILED — the pins could not be read (above), so this run proves nothing
exit 1
```

`design-pintag.sh` runs inside the pre-push design gate, so a fresh session could not run the gate
that gates its own pushes.

**The change.** One guard relaxed: a quoted value whose first segment is a declared submodule is a
read of that repo, whether or not it carries a slash. The derived set grows from **12 to 17 paths**,
each of which a gate names; a bare name is no less a read than a slashed one.

## How tested

Same fresh worktree, `origin/main`, after the change:

```text
$ bash scripts/init-submodules.sh
init: OK — 17 of 17 requested path(s) are materialized at their recorded gitlinks

$ bash scripts/design-pintag.sh
design-pintag: tags read from each pin's own module store as GIT resolves it (…)
design-pintag: every pin is at a tag, one CHANGELOG commit above one, or explained
exit 0
```

The control that failed now passes on the documented order.

**The claim can fail.** Self-test claim 1c uses `skipped` — declared, but derived by nothing else, so
it can only arrive through this rule:

```text
  PASS  source 4 sees a BARE repo name — a slash is not required
init-submodules --self-test: OK (every claim is live)
```

With the guard restored, the same self-test reports `init-submodules --self-test: FAIL (1)`, so the
claim is not vacuous.

The full umbrella pre-commit gate ran on this commit and reported `pre-commit: OK`, including the
30-claim `init-submodules.sh` self-test, the pathspec cases, and the nested-level cases.

## Change classification

The working set of a fresh materialization grows from 12 to 17 paths. Nothing downstream changes
meaning: each added path is one a gate names, so the gate now has the data it was already written to
read. A session that materializes the full set (`CHARLY_INIT_MODE=all`) is unaffected. Rollback:
revert this branch; the extra checkouts stay on disk, harmless, and the design gate returns to
failing on a fresh tree.
