## Why the diagnostic matters

The old message named only the winner:

```text

one scope (box=nvidia-cdi); using newest referenced v2026.323.0252
```

A 40-hex commit SHA named beside a release tag in one scope silently loses — `PickCandyVersion` compares `Candidate.GitTag` with `CompareCalVer`, and a SHA carries no recency the CalVer order can read. The new message says that, and says to move the `require:` that names the tag **first** (producer-first), which is the order that actually works.
