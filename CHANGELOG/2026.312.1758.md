## Summary

The audit you asked for found a defect **I introduced** in the previous campaign, and this fixes it.

**DESIGN.md A.9 said:** *"D-SDK-1 limits the shared `sdk` mechanism to repository fetching."* That is **false**.
D-SDK-1 (DESIGN.md:205) reads:

> `sdk` contains `Serve` …, the role interfaces, the typed host client, the protocol conformance harness (§4.7),
> **and the shared mechanisms: executors (shell, ssh, container, adb), the store and its roots (§20), locks,
> readiness waits, matchers, repository fetching, CalVer, check sessions and recording.**

Repository fetching is **one of nine** mechanisms, not the boundary of what `sdk` may hold. A correct row already
existed three lines above it (*"repository fetching is one shared `sdk` mechanism"*); the wrong one was mine, written
in the batch that settled `command:gh` and `verb:gh`, and both of those ledger cells inherited the false premise.

**The corrected reasoning, which still settles both rows — on the true text:** a pull-request write is *not among*
D-SDK-1's nine shared mechanisms, and D-SDK-2 bars domain logic from `sdk`. So the operations have no home there,
and a plugin's own namespaced word (D-PLUG-7) is where one lives. The verdicts are unchanged; the reason is now the
real one.
