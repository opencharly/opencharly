## Summary

Head `47c3adc93106b314cfde4d74f93451ef51234647` — the commit this PR pushes: **2 files changed, 66 insertions(+), 6 deletions(-)**.

**opencharly/opencharly#812 landed with a copy of the very wording it retired.** The change moved this repo's `!`-marker ownership gate's step description to naming every discrimination case its self-test exercises, and in doing so it explained itself by QUOTING the retired two-case ARM 2 phrasing inside the gate script's own explanatory comment — split across two lines, behind a `//` marker. The `charly/pr-validator` raised it on #812 and called it non-blocking for #812's own correctness — but under R1 a finding is blocking when the change introduces it, and this change did, so it is fixed here rather than filed away.

**The R5 sweep pasted in #812's body could not see the copy.** That sweep was a line-based `git grep`, and a retired phrasing that survives a line break is invisible to it — which is exactly where the surviving copy was. The body's claim was true in the sweep's output and false in the tree.

**This PR deletes the copy — and closes the class where this repo already keeps it.** The comment now says **how many** cases the old description named and points at the `CASE` list for what each case is. And the retired two-case enumeration is now a **committed key** in this repo's own retired-claim control, `scripts/check-retired-claims.mjs`: a control that already existed, that holds its key set COMMITTED, and whose scan's unit is a **CLAIM**, which WRAPS. Before this PR that control carried thirteen retired claim classes and not this one; it now carries fourteen, the new one keyed on the retired two-shape enumeration, with the true three-shape wordings as counter-instances so the key cannot cry wolf on a claim that is right.

**The proof is the committed control itself, run on two trees.** The same control is RED on #812's merged tree, naming the copy at `scripts/check-bang-arm-ownership.mjs:99`, and GREEN on this one. A sweep that cannot fail is not a proof — and this one demonstrably can.

**Its predecessor is opencharly/opencharly#812** (squash `f97c01a71b0b0308a9d77e79fbb00cbed0576a36`, merge tag `v2026.302.1924`). #812's merge was the GitHub Actions app's, so it did not close its own issue; this PR is the instance-fix leg of that finding, and the class-level half that remains is filed in opencharly/opencharly#799.

**One fact about that predecessor, because it explains why the copy is still there.** #812's merge landed the ROUND-1 commit — the one that quoted the wording. The round-2 fix, which deleted the quotation, was pushed to the same branch afterwards and **did not land**: `git merge-base --is-ancestor 22eb607ffae7aba139d7bed3c81deb56bcd836d3 origin/main` exits 1. The validator's PASS had already armed auto-merge, and the merge took the round-1 head. So the copy in `origin/main` is the round-1 copy, and this PR is the first landing of the deletion.
