### The candy, and what it is not

`opencharly-guidance` is a **concept candy**: `plan:` is a `true` no-op plus a `true` `check:`, it
composes no box, and it appears in no image — so the three `skill:` nodes add nothing to any
`ai.opencharly.skill` OCI label. Its only job is to own routing metadata:

```yaml
opencharly-guidance:
    candy: { … }
agents-skill:
    skill:
        name: agents
        family: internals
        owner: opencharly-guidance
        triggers: [ … the same five triggers the carrier declared … ]
```

Routing-only: `name`/`family`/`owner` plus the `triggers:` that generate the `DISPATCHER.md` row, and no
inline `description:`/`content:`. The prose is the file, and an inline body that disagrees with its file
is a hard error in the marketplace generator — so nothing is copied back over a node.

The manifest header that said the umbrella *"declares NO candies/boxes of its own"* was true before this
PR and false after it. It is corrected in the same change rather than left to rot (R4/R5).
