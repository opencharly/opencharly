# 2026.299.0317 — fix(gate): refuse a closing directive that names a merged pull request

Closes #698

## Summary

Head `35d2521994f9f3349fb6112dd67aa824f7817615` — 2 files changed, 184 insertions(+), 8 deletions(-).

**The umbrella's push-time gates judged the body's FORM and its FIDELITY TO THE DIFF, and neither asked what KIND of thing a closing directive names.** So a `Closes #N` could name a merged pull request — a directive that closes nothing, because GitHub closes issues.

The instance is this repo's own record, `CHANGELOG/2026.299.0229.md`, written at merge time from the body of #697. It opened with `Closes #696`, and #696 is a pull request; 148 lines further down, the same file's `## Filed issues` section said #696 "is already merged". The fresh `charly/pr-validator` raised the contradiction on #697.

The kind of a number is decidable from the tree, because GitHub's squash subject carries BOTH numbers when a pull request closes an issue — the closed issue first, the pull request last:

```
$ git log --format='%s' origin/main | grep -m1 'make the self-test'
fix(gate): make the self-test's pasted command and its output name the same files (#697)
$ git log --format='%s' origin/main | grep -m1 'docs-pin claim'
docs: correct the docs-pin claim in the 2026.299.0132 entry (#696)
$ git log --format='%s' origin/main | grep -m1 'consumer leg of the charly, plugin-task'
chore(pins): the umbrella's consumer leg of the charly, plugin-task, sdk and distro-cachyos producer work (#684) (#685)
```

The first two lines are this record's own pull request and the pull request it names, and each carries a single parenthesised number: neither closed an issue. The third is a pull request that DID close one, and GitHub wrote both numbers. A directive closes an issue, so the one that record opened was a no-op.

**Two changes, one cutover.** The record is corrected in place — `Closes #696` becomes `Refs #696`, and its `## Filed issues` section names the origin of the finding in prose instead of listing a pull request as though it were a filed issue. And the missed control lands in the same cutover: `scripts/check-pr-body-diff.mjs` gains an arm that asks a closing directive what it names, so a directive naming a number this repo merged as a pull request turns the gate red and is refused.

| file | what it carries |
|---|---|
| `CHANGELOG/2026.299.0229.md` | the correction: the record's closing directive now names the kind of thing it can close, and its Filed issues section no longer presents a merged pull request as a filed issue |
| `scripts/check-pr-body-diff.mjs` | the new arm, and the three self-test cases that prove it: a directive naming a merged pull request turns the gate red, the same line inside a fenced block stays green, and a directive naming an issue stays green |
