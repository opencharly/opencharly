# 2026.267.0953 — fix(opencode): clean up the gate script merged in #243 (phantom option, dead code, flaky assertion)

## Summary

PR #243 (the umbrella's opencode V2 plugin port + regression gate) **auto-merged
at its PASS head `5a66d33`**, which was created *before* three follow-up commits
landed on the branch. Those commits addressed findings raised by the validator on
the companion charly PR (`opencharly/charly#646`), so umbrella `main` currently
carries them unfixed. This PR lands those three fixes.

### What changed

`scripts/check-opencode-plugin.mjs` only:

- **Phantom `--id <id>` option (R5/A1).** The usage header advertised
  `[--id <id>]`, but nothing read it — `discover()` only calls `arg("--plugin")`.
  Removed from the header so it matches the code.
- **Dead `try/catch` (B14(a)/B18).** Layer B wrapped an arrow-function assignment
  in `try { … } catch { /* handled below */ }`; assigning a function cannot throw,
  so the catch was unreachable and its comment pointed at the `existsSync` guard
  that actually handles the missing-script case. Dropped the `try/catch`.
- **Flaky `plugin list` assertion (R1/R4).** The live layer asserted the plugin id
  via `opencode plugin list`. That command has **no directory or `--standalone`
  option**, so it always queries the **shared background service**, and its result
  depends on whichever project bound that service (measured: it reports "No
  plugins found" for a fresh throwaway project while the shared service is bound
  elsewhere). A non-deterministic gate is not a gate. Removed the assertion; the
  behavioural deny/allow assertions already prove the loader deterministically —
  a plugin that failed to load registers no hook, so nothing would deny.

Also dropped the now-unused `relative` import.

The script remains **byte-identical** to charly's copy (verified against
`opencharly/charly#646`'s branch), preserving the shared-not-forked contract.
