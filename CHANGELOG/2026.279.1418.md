# 2026.279.1418 — feat(harness): pi wake binding for the neutral watchers; add the R10 bed watcher

## Summary

A pi session has **no background-completion notification and no subagent**, so a long
wait — a `charly/pr-validator` verdict, a reviewer's BLOCK comment, a 40-minute R10 bed —
was either hand-polled (the R4 band-aid) or silently dropped. The sibling harnesses bind a
watcher (opencode's `pr-watch.ts` + `ctx.session.synthetic`, reasonix's `watch-arm.sh`
SessionStart hook); pi had nothing, and `.pi/APPEND_SYSTEM.md`'s "run `gh_pr_status watch`
in a background subagent" was stale (there is no subagent).

This adds the missing mechanism, **neutral-first**:

- **`scripts/check-bed-watch.sh` (new, HARNESS-NEUTRAL)** — the R10 bed runner/reporter. It
  runs `charly check run` per bed, keeps the full output in a log, and emits one
  `BED <bed> <class> rc=<n> ok=<..> total_seconds=<..> log=<path> summary=<path>` line per
  bed. The process **EXIT CODE** is the honest signal (3 = prereq SKIP, per
  `/charly-check:check`); `summary.yml` alone cannot distinguish a pass from a skip. Any
  harness (bash, Claude Code, Codex, CI) can call it; it contains no pi logic.
- **`.pi/extensions/watch.ts` (new)** — the ONE pi-specific piece: it spawns the neutral
  `marketplace/scripts/gh_watch.sh` (GitHub PRs/issues) and `scripts/check-bed-watch.sh`
  (beds) and turns each emitted line into a user turn via
  `pi.sendUserMessage(..., {deliverAs:"followUp"})`. It contains no watching logic of its
  own (no poll loop) — it delegates, wakes, re-arms the one-shot watcher on exit, treats a
  rate limit (exit 7) as terminal, and kills its children in `session_shutdown`. GitHub
  scopes come from `.pi/watch.items` (comment-only, so INERT by default); a bed is armed
  with the `watch_arm` tool (never auto-launched — running a `disposable: true` bed is a
  deliberate act).
- **`scripts/lib/ts-syntax.mjs` (new) + a PARSE assertion in both pi gates** — closes an
  R1 class found live: an unescaped backtick in `charly-gates.ts`'s injected rules block
  left every regex gate green while pi failed to load the extension.

No marketplace PR, no layer PR, no gitlink bump: the bed watcher lives in this repo's
`scripts/` because its subject is this repo's `.check/` runs. If a non-umbrella consumer
needs it, it promotes to `marketplace/scripts/` (R3, second occurrence).
