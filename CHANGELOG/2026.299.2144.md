# 2026.299.2144 — fix(gate): the nested check must assert the nested POST-CONDITION (#710)

Closes #710

## Summary

Head `373d9b7494c162aab49460183c7c1e75088b6a95` — the commit this PR pushes. This PR's diffstat against `origin/main`: **9 files changed, 1048 insertions(+), 40 deletions(-)**.

`charly task init` makes every materialized path carry its OWN nested level (opencharly/opencharly#647). The umbrella's gate did not follow: its nested step treated an ABSENT nested level as a notice, so a tree whose currency report cannot judge a nested pin passed `charly task verify` in silence — under a step NAMED "charly's own nested submodules are at their gitlinks", on a tree where NONE of the six nested twins had a checkout.

**The decision this issue asks for is the strict one: the notice becomes a FAILURE when `charly` is materialized.** The weighed consequence is stated plainly, because it is the price of the strict reading: a tree whose `charly` was materialized by something other than `charly task init` now turns the umbrella's gate RED, and the failure names the paths and the remedy (`charly task init`). A `charly` that is NOT materialized at all stays a light tree and stays a notice, because its pin is still audited from the index. The cost is deliberate, and the gate must assert the post-condition ITSELF, because the currency report cannot see it.

**The currency report is BLIND to the absent nested level, so the gate has to assert the post-condition on its own.** A twin's CURRENCY is judged from the twin's REMOTE alone: the report consults the twin's CHECKOUT only to CLASSIFY a twin whose remote has moved, and it never asks whether the checkout EXISTS. MEASURED in the reproduced defect state (the whole nested level absent, all six twins), the report's verdict line reads `0 of 411 pin(s) NOT current [411 cur]` and the report EXITS 0 — byte for byte the SAME line the healthy tree produces. Two states, one verdict: the report cannot tell them apart. A checkout is needed only to CLASSIFY a twin whose remote HAS moved, and then the report prints `differs (no checkout of box/cachyos to judge ancestry)`: the twin's CLASS is left UNDETERMINED, though the state's own NAME says the twin is UNJUDGEABLE rather than a named divergence (`ancestryClass`, plugin-task v0.2026297.2108, `candy/plugin-task/verbs.go:916`). What the report sees about the nested level depends on the REMOTES' state, not on the tree's.

**The strict rule has a blast radius, and it is inside this change.** The .pi extension's `charly_worktree_create` materialized `charly` NON-recursively, so a .pi worktree would have gone RED at the new step. Under R1 — this change introduces it, so it is blocking — the .pi path is fixed in the same cutover, not filed: the extension now materializes each materialized module's OWN nested level through the umbrella's own initializer, re-rooted at the module (`--root <module> --all`), and FAILS CLOSED when that pass does not succeed, because `pi.exec` RESOLVES on a non-zero exit and the code has to be read. At a module's root, `--all` IS that module's nested level, so the path lifecycle keeps ONE implementation at every level (R2).

The fixture gate `scripts/check-verify-submodules.mjs` EXTRACTS the shipped step text from `charly.yml` — never a copy, so the two cannot drift — and proves the discriminating cases against FIXTURES: a materialized charly without its nested level FAILS, naming the path and the remedy; an uninitialized charly is a NOTICE and GREEN; a `+`/`U` drift still FAILS; a materialized charly whose nested level IS at its gitlink is GREEN; and one whose nested status CANNOT BE READ FAILS, so an empty check can never claim the nested submodules are at their gitlinks. Three mutations turn it RED: the absent nested level demoted back to a notice (the defect's own shape), the "OK" line printed even when the step examined nothing, and the unreadable status swallowed by `|| true`.

`scripts/check-pi-gates.mjs` gained the matching static assertions — the nested level goes through the umbrella's own initializer, re-rooted at the module, for the module's OWN declared set, and fails CLOSED — and two mutations that turn it RED: the nested level never materialized, and the nested materialization not fail-closed.

**And the .pi path's post-condition is now FIRED, not only asserted as TEXT.** A static assertion reads the call shape; the post-condition is an EFFECT — a materialized nested level inside the worktree — and an effect is not in the text. So the gate LOADS the changed extension and FIRES `charly_worktree_create` against a FIXTURE umbrella: an origin carrying the REAL `scripts/init-submodules.sh`, a `charly` module that DECLARES a nested submodule and a `marketplace` module that declares none. **F6** asserts that a materialized module carries its OWN nested level, at the gitlink its own tree records; **F7** that a nested level which cannot materialize FAILS the tool, never a ready worktree. Two mutations prove the fired coverage is live — the initializer re-rooted at a path that is not the module, and the initializer's non-zero exit swallowed — each keeping EVERY static assertion GREEN and caught ONLY by firing.

`scripts/init-submodules.sh`'s header asserted, twice, that the report's `differs (no checkout of box/cachyos to judge ancestry)` is what an absent nested level produces. The header now says the measured truth — the report judges currency from the twin's REMOTE, and prints that state only once the remote HAS moved — and the .pi cost model that quotes it says the same.
