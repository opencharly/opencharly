# 2026.315.1439 — fix(hooks): derive the DESIGN gate's change class from the commits a push publishes

## Summary

`hooks/pre-push` decided whether to run the DESIGN gate (`bash scripts/design-check.sh`) from
the wrong change set. It built the set as
`git log --format= --name-only $(git rev-list <published> --not --remotes)` — and **`git log
<sha>` walks every ANCESTOR as well**, so the set was the whole HISTORY's path list and
`design_gate_touches_input` matched `design/` on essentially every push. A TODO.md-only commit
read as 1789 paths on 2026-11-11 (block 3 below), which is why a docs push paid the ~12-minute
gate — and why any finding inside it refused a push that could not possibly have caused it.
That is the blast radius opencharly/opencharly#979 reports. Its own diagnosis (three pins with
no release tag) is NOT the cause: the three pins it names are at a tag or one CHANGELOG commit
above one (block 6 below).

**The head is a BASE UPDATE, not a new change.** `strict_required_status_checks_policy: true` on
the org ruleset (23827016, `refs/heads/main`) makes a `BEHIND` head unmergeable, so the branch was
brought up to `main` with `gh pr update-branch` — a MERGE, never a rebase: head
`7259509648fdc9f263b4a70bb3536fd2355b3195`, parents `77427b4…` and `990d5cb7…` (block 8 below). The
merge changes no content of this change: both files hold the SAME blob ids as before it, the diff
against the new `main` has the same stable patch-id and the same 47/5 counts, and the merged tree's
409 gitlinks are identical to `main`'s. Blocks 1–4 were measured on `77427b4`, whose two changed
blobs the merged head carries unchanged (block 8 proves it by blob id); blocks 2, 5, 6, 7 and 8 are
the fresh runs on the merged head.

The fix: the file list and the gitlink list now come from **ONE** pass of
`git diff-tree --no-commit-id --raw -r --root` over the commits this push publishes. The class
is the union of those commits' **own** diffs, the two halves of the class cannot drift apart,
and `--root` keeps a root commit's whole tree in the set, so the class still fails toward
RUNNING the gate (without `--root`, `git diff-tree` prints nothing for a root commit — a false
skip for a repository's first push).

**What this PR does NOT do: it advances no pin, and it raises no census row.** The pins #979
names are healthy at their served tips, so no `design/pintag-baseline.tsv` row is admissible for
them. The residual — the pin-tag control's offline tag map is read from a store that can predate
the tag, so a worktree that never materialized its pins can still report a healthy pin as
untagged — is filed as opencharly/opencharly#980 with the measurement and two candidate
remedies, because the offline-ness of that reading is a stated design decision (DESIGN.md A.12)
and the choice belongs to the operator. The umbrella's one non-current pin (`plugin-kube`) is a
finding of its own: it is `behind` (an advance available now, four merged commits), this change
advances no pin, and the advance is filed as opencharly/opencharly#983 under `## Filed issues`
rather than parked here — the contract reports a `behind` pin and does not fail on it, and a pin
wave has its own R10 (block 7).

Closes #979 — the push it reports as refused is refused no longer, and the three pins it
names are proven healthy below; its residual is opencharly/opencharly#980.

| file | what changed |
|---|---|
| `hooks/pre-push` | the design leg's change set is derived per published commit (`git diff-tree --raw -r --root`, one pass for both the file list and the gitlink list) instead of `git log`, whose walk includes every ancestor; the comment states the measurement |
| `scripts/check-design-gate.mjs` | the failing-first fired case (a docs-only commit above a design-bearing PUBLISHED base must NOT run the gate), two form assertions that pin the derivation (`git diff-tree --root`, never `git log --name-only`), and the measured note |
