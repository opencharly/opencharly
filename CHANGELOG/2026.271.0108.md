## Summary of changes

Extends the existing `AGENTS.md` "Agent identity & comment coordination" section (opencharly/opencharly#279, `v2026.270.1654`) with **field-learned multi-session coordination mechanics**. New material is added and **two existing bullets are REWRITTEN** (the identity-footer order and the takeover window), so this is additive-plus-rewrite prose — not a purely additive diff.

- **Identity footer order is now ONE canonical rule on BOTH surfaces** — `Agent:` FIRST, `Assisted-by:` LAST (a PR body thereby also satisfies the validator's "`Assisted-by` FINAL line" requirement). Rewrites the old surface-dependent wording.
- **The progress signal** — progress is a `charly/pr-validator` run COMPLETING, never session activity; a looping agent never falls quiet and a peer waiting on a running validator is NOT stalled. Stall = no completed verdict within the window while the scope is open+unmerged. Stated ONCE here; every later bullet cross-references it.
- **Window-based takeover, comment-FIRST** (operator Rule A): (1) a coordination comment posted FIRST (ownership board / `BLOCKS` / `STATUS`) — no comment, no takeover, ever; (2) the window (below) elapsing with no owner answer AND no progress (the progress signal above); (3) `TAKING OVER — authority: window-expired` posted BEFORE any push.
- **The window is 60 minutes** (was "~30 min" — the operator rule SUPERSEDES it): a FLOOR, measured from the comment timestamp, extended never shortened without operator sign-off, reset by any owner answer.
- **Auto-close carry-forward** (operator Rule B): all FOUR surfaces mandatory — `RESOLVED — superseded by #<n>` on the closed PR; `Supersedes #<n>` + closure reason on the successor's body with all findings fixed in ONE commit; a `STATUS` on the issue naming the successor; and an ownership transfer (`HANDING OVER`) for a slug that claimed the predecessor but not the successor. Never re-argue on a closed thread; never push at the block limit.
- **Sign-off authority lives in the BODY, delegated form** — `Maintainer sign-off — posted at the operator's direction`, carrying the agent's own footer; delegation ≠ impersonation; the validator rulebook `AI_REVIEW_PROMPT` accepts this form.
- **No R10 class exemption (current project state)** — a plugin-library/schema change runs the full assembled `disposable: true` bed; no library-module waiver; a delegated "bed-exemption" sign-off is not accepted. Points at the R10 change-class matrix.
- **Session-continuation for amendments** — continue the authoring session BY ID; one editor per change.
- **State the dependency chain + unblock order**, and **watch the RIGHT scopes** (a stale watch list produces false stalls).
