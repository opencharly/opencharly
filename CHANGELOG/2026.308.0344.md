# 2026.308.0344 — feat(design): read any cluster resource, and adjudicate the cluster rows (batch 6)

## Summary

Batch 6 of the DESIGN amendments the capability ledger records (tracked in #838). The `kube` check
carried three arms — `node`, `resource`, `pod` — and the ledger called the rest of the cluster
surface lost: 11 of `kube`'s 14 operations and 11 of `kubevirt`'s 13.

**Most of that was a reading error, not a gap.** `resource` takes **any** kind and name, so an
ingress, a storage resource, a service, a `VirtualMachine`, a `DataVolume`, a `Snapshot` and a
`Migration` are all reads of it. D-VERB-4 already makes a wait the `retry` modifier, and D-VERB-1
makes a transition a run step — so `wait-nodes`, `wait-ready` and `start`/`stop`/`restart` were never
check operations. What genuinely had no arm was a **field assertion** and a **raw API read**:

- `resource` gains `value?: #Matcher` — which makes `lb-external-ip` and `guest-info` expressible;
- `raw` is a new arm for an arbitrary API path.

Both cluster rows are `sharp` against that reading, and the `deploy-kubernetes` example now asserts a
pod list, a storage resource, a service with a value matcher and a raw path.

| file | what changed |
|---|---|
| `DESIGN.cue` | the `raw` arm, the `value` matcher on the resource read, and the rule the arms follow |
| `DESIGN.md` | the kubernetes example asserts all four arms |
| `design/dulling.tsv` | `verb:kube` and `verb:kubevirt` become `sharp` against the reading above |
