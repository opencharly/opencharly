# 2026.260.2152 — feat: add the plugin-jetkvm submodule

## Summary of changes

Pins **`opencharly/plugin-jetkvm`** as a submodule of the umbrella, at its default-branch HEAD.

- `.gitmodules`: the `plugin-jetkvm` entry (`branch = main`, plain HTTPS — identical in form to every other plugin entry).
- `plugin-jetkvm`: the gitlink at `2892333a64b442f3e952aad7f8639d6790e172f5` (the repo's `main` HEAD when this PR was opened, verified against `git ls-remote`).
- `README.md`: the plugin-table row (alphabetically between `plugin-interface` and `plugin-k8sgen`), **plus the pre-existing org-map defects the same table had**: three pinned submodules with no row (`plugin-media`, `plugin-pipeline`, `plugin-review`), stale counts (header "400 today" for 401 submodules; Plugins "106 repos" for 105 rows), and two alphabetical inversions (`plugin-cache` after `plugin-candy*`; `plugin-openclaw` before `plugin-omarchy`). Header is now 402, Plugins 109, the three rows added, the two rows moved to their sorted positions.
- `scripts/check-org-map.sh` (NEW): the sweep that checks all of the above is a checked-in script rather than an ad-hoc one — each section's claimed count vs its rows, each section's row ordering, every submodule having a row, and the header count. It takes an optional git ref, so the base and the head are checked by the same code (its base output is the derivation for every number changed here).

**What the pinned repo is:** a charly plugin serving the `jetkvm:` IP-KVM verb. It drives a JetKVM device over the device's own WebRTC control plane — JSON-RPC 2.0 + the binary `hidrpc` channel, with the H.264 video decoded to PNG by ffmpeg — with no browser, served out-of-process over go-plugin gRPC. It is **read-only by default**, with every mutating method (input, power, virtual media, USB, config) behind an explicit `allow_control` gate; `factory-reset` and `update` are refused even then, because the device is a physical appliance rather than a disposable container.

The pinned repo's own history is already landed: genesis plus the read-only method-surface bed (tag `v2026.260.1307`), the `rpc` device-safety gate fix (tag `v2026.260.1317`) and the catalog invariant (tag `v2026.260.1344`).

**Closes / relates to:** follows `opencharly/plugin-jetkvm` (the repo) and `opencharly/layer-charly-check#13` (the `jetkvm` skill entity + dispatcher row).

**Breaking change + rollback:** `none` — an additive submodule plus README rows/order and one check script. The branch carries four commits (the pin, the missing rows, the ordering fix, the script), which the org's squash-merge collapses into ONE landing commit; revert that merge to roll back.

### The org-map sweep

The README's org-map tables are prose no pinning gate reads, so they are swept by a checked-in script: **`scripts/check-org-map.sh`** (added by this PR). It asserts three things — each section's claimed `N repos` equals its own table rows, each section's rows are in ascending path order, and every `.gitmodules` submodule has a row with the header's "(N today)" equal to the submodule count. It takes an optional git ref, so the same script checks the head and the base.
