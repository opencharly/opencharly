# 2026.321.2345 — docs(agents): name DESIGN.md as the MUST's subject

## Summary

**Zero mentions in every one of the four rulebooks.** The rulebook says HOW to work and never says WHAT must be true when the work is done — so an agent can follow it perfectly and still build the wrong thing.

## The change

One paragraph, after the first.

> **And the MUST's SUBJECT is [`DESIGN.md`](DESIGN.md).** This file says how to work; DESIGN.md says what must be true when the work is done — the contract's requirements, its invariants, and the data shapes every repo shares. **Read it before designing anything:** before adding a field, a shape or a mechanism, grep the contract for it and read the row that governs the area. A rule here and a requirement there are two halves of one obligation — **conformance to this file with a violation of DESIGN.md is not a pass.** When the two disagree, the disagreement is a defect in one of them: fix the one that is wrong, in the open, and say so. `spec/schema/*.cue` is the machine-readable projection of DESIGN.md, and `DESIGN.cue` is its schema; where the prose and the CUE differ, the CUE is what the tooling enforces and the difference is a defect to resolve, never a licence to pick whichever is convenient.

**Five claims it makes, each one checkable:**

| claim | why it belongs in the rulebook |
|---|---|
| DESIGN.md is the MUST's subject | the rulebook needs a target; without one "follow the rules" is procedural |
| conformance without it is not a pass | the failure mode this row exists to prevent |
| a disagreement is a defect in one of them | there is no third resolution, and "pick the convenient one" is the usual third |
| the CUE is what the tooling enforces | `spec/schema/*.cue` is generated from DESIGN.md and is what actually validates |
| a prose↔CUE difference is a defect | otherwise two sources of truth silently diverge |
