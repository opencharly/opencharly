### The `design-pintag.sh` failure, filed rather than dismissed

`design-pintag.sh` first failed here on `charly@a5b9da7` with *"untagged — a CHANGELOG commit with no
parent … no census row"*. That is **not** a defect in this change: the `charly` gitlink is
byte-identical here and on `origin/main` (`a5b9da7ed2`), and the control passes there.

The cause is environmental **and worth fixing**: `scripts/init-submodules.sh` materializes with
`git submodule update --init --depth 1`, and **a shallow clone carries no tags**, so the control —
which reads each pin's own module store for tags — saw every pin as untagged. After
`git fetch --tags --unshallow` (826 tags) the identical tree passes.

Filed as **opencharly/opencharly#1071**, because the failure message is indistinguishable from a
genuine untagged-pin finding, and the tempting "fix" — adding a `design/pintag-baseline.tsv` row — is
what the pre-push gate forbids ("lowered, never raised, by the change that fixes it").

Z-Image set), `distro-cachyos#189` (image + bed), `charly#1169` (pac-template fix).
