# 2026.325.2259 — docs(agents): state the skill body location and the owner rule

## Summary

Aligns `AGENTS.md` Part II #5 with the skill-body rule its owning skill now states
(opencharly/sdk#611). Part II #5 said a skill "lives with the code … it describes" — true, but it
does not say **where** in that repo, nor that the owner must be a candy that repo defines. The
collector resolves the body at the repo ROOT of the owner candy's repo
(`sdk/deploykit/skills_collect.go`), so a node naming a candy composed from another repo finds
nothing — measured on opencharly/layer-strata#28 after #25 moved a pod's skill to the pod repo while
the owner candy stayed in the engine repo.

Part II #5 now states both halves:

- the body is authored at the **repo root** of the owning repo, never inside the candy's directory;
- **`owner:` names a candy DEFINED IN THE SAME REPO as the body** — a foreign owner is a load error,
  so a box, pod or VM repo that wants its own skill declares a candy of its own, and one that does
  not carries the node only, with the body in the candy's repo.
