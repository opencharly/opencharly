# 2026.268.1159 — fix(opencode): bound the compaction head and mirror the PR-eval model params

## Summary

The umbrella `opencode.json` used the models.dev generation default plus the stock compaction tail budget. On a long session that combination wedges: `select()` budgets only the retained tail, whose default is `min(15000, 25% of usable)`, so once the newest turn exceeds that budget the summarizer `head` becomes the **entire serialized history** (all reasoning text retained; tool output capped at 2k). The provider rejects the summary request for input length and the session is left unusable.

This change bounds the summarized head and mirrors the org PR-eval engine's model parameters.

Session: `ses_f31022a99ffe1gLJ1RdyDnhlAh` (opencode 1.18.32, provider `ollama-cloud` at `https://ollama.com/v1`, model `deepseek-v4.1-flash`, 1,048,576 context / 393,216 max output).

Changes to `opencode.json`:

| Key | Before | After |
|---|---|---|
| `compaction.preserve_recent_tokens` | (unset → ~15,000) | `500000` |
| `options.max_tokens` | `384000` | `262144` |
| `options.temperature` | (unset) | `1.0` |
| `options.top_p` | (unset) | `0.95` |
| `options.frequency_penalty` | (unset) | `0.5` |
| `options.presence_penalty` | (unset) | `1.0` |

- `preserve_recent_tokens` keeps a large verbatim tail so the summarized head shrinks.
- The model options are exact parity with the org PR-eval engine (`AI_REVIEW_*` defaults / vars) and the vendor-recommended sampling for `deepseek-v4.1-flash`.

## How tested

**1. Root cause measured on the real provider.** The crash was a summarizer prompt of **1,122,556 input tokens** (logged). Reconstructing the head with opencode's exact `serialize()` rules and measuring it through the live provider gives **1,128,448** (0.5% apart; difference = prompt template + prior summary):

```
$ curl -sS https://ollama.com/v1/chat/completions -d @headtext.json | jq -r .error.message   # max_tokens=1
The prompt is too long: 1128448, model maximum context length: 1048576
```

**2. Provider admits on input tokens only** (so `reserved`/`max_tokens` do not size the request):

```
prompt 800,031 + max_tokens 393,216 -> accepted        (usage.prompt_tokens=800031)
prompt 1,050,041 + max_tokens 1     -> rejected        (The prompt is too long: 1050041)
max_tokens 2,000,000                -> rejected        (exceeds maximum output tokens (393216))
```

**3. The committed config's head fits.** With `preserve_recent_tokens: 500000`, the reconstructed head measured through the live provider drops to **634,064** tokens:

```
$ curl -sS https://ollama.com/v1/chat/completions -d @head500k.json | jq .usage.prompt_tokens
634064
```

**4. Wire parity with the PR-eval.** A local echo endpoint captured the request body the committed config actually emits:

```
$ opencode run --model ollama-cloud/deepseek-v4.1-flash hi   # baseURL -> local echo
model=deepseek-v4.1-flash max_tokens=262144 reasoning_effort=high
temperature=1 top_p=0.95 frequency_penalty=0.5 presence_penalty=1
```

matching the org PR-eval engine defaults (`config.go`) and org vars: `AI_REVIEW_MODEL=deepseek-v4.1-flash`, `AI_REVIEW_TEMPERATURE=1.0`, `AI_REVIEW_TOP_P=0.95`, `AI_REVIEW_FREQUENCY_PENALTY=0.5`, `AI_REVIEW_PRESENCE_PENALTY=1.0`, `DefaultMaxTokens=262144`.

**5. Live recovery.** The wedged session was resumed under this config and completed the compaction, then continued executing its PR #57 work:

```
$ OPENCODE_CONFIG_CONTENT='{"compaction":{"auto":true,"prune":true,"reserved":384000,"preserve_recent_tokens":500000}}' \
    opencode run -s ses_f31022a99ffe1gLJ1RdyDnhlAh "continue"
```
(log continued past compaction into `charly box validate` / mutation-test steps; no `ContextOverflowError`)

## Upstream tracking

This is a stopgap; the permanent fix belongs in opencode:

- **anomalyco/opencode#48844** — "Session too large to compact" — the summarization request itself has no size budget (open)
- **anomalyco/opencode#51121** — `fix(session): drop oldest turns when compaction head exceeds model context` (open; links #48844)

I reproduced the failure on opencode 1.18.32 with provider `ollama-cloud` / model `deepseek-v4.1-flash` and documented it on both threads. When #51121 (or an equivalent) lands, `compaction.preserve_recent_tokens` can be dropped; it is a tail cap, so the head still grows as a session does. The model-option parity stands regardless.
