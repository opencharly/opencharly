# 2026.322.0923 — feat(gate): the body-claims gate, its caller, its test, and the source-count arm

## Summary

feat(gate): the body-claims gate ships WITH its caller, which is what it never had

**The gate exists and has never run on a body.** `scripts/check-body-removed-identifiers.mjs` was written on
`#1086`, which auto-closed before it merged — so `origin/main` does not carry it, while `charly.yml:671`
already asserts its `--self-test`. That means `charly task verify` today runs a step naming a script that is
not in the tree. **This PR fixes that and gives the script the caller it lacked.**

## The gap, measured

```console
$ git cat-file -e origin/main:scripts/check-body-removed-identifiers.mjs
fatal: path 'scripts/check-body-removed-identifiers.mjs' exists on disk, but not in 'origin/main'
$ grep -rn 'check-body-removed-identifiers.mjs --repo' hooks/ scripts/
scripts/check-body-removed-identifiers.mjs:27://   node scripts/check-body-removed-identifiers.mjs --repo <path> --body <file> --base <ref> [--head <ref>]
```

**`rc=128`: the path exists on disk and not on `origin/main`.**

**Before this PR there was no caller.** The `grep` above is scoped to `--repo` in `hooks/` and `scripts/`, and
its one match is the script's own usage comment; **this PR is what adds the caller**, in `hooks/pre-push`, as
`node "$CLAIMS" --repo "$ROOT" …`. So its arms were asserted and the gate itself was never invoked on a body
— until this change.

A self-test proves the arms discriminate; it does not judge anything the author wrote.

## What this PR adds

1. **`scripts/check-body-removed-identifiers.mjs`** — the claims gate, with `buildArms()` shared by
   `--self-test` and `--emit-arms` so the table a body carries is emitted from the array the self-test runs.
2. **`hooks/pre-push`** — a fourth body leg, beside the org linter (FORM) and the reconciler (STRUCTURE):
   this one reads the body's CLAIMS against each other and against the tree.

It reads the same `$BODY` the two legs above judge, and it skips visibly when node or the script is absent,
exactly as they do.

## Change classification

Kind: one added script + one hook leg.

**Breaking change + rollback: none — and here is why it breaks nothing.** The hook leg skips visibly when the
script is absent, so a tree without it behaves exactly as today; and `charly.yml:671` already names the
script, so this change makes an existing assertion true rather than adding a new obligation. Reverting
deletes the leg and leaves `charly.yml`'s step failing exactly as it fails now.
