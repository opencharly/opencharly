## Clone hygiene performed (not in the diff)

`task verify` initially FAILED with `docs: dirty working tree`. Root cause: the
Phase-4 candy cutover removed the `charly` submodule from each candy repo
(e.g. docs' own "fix: remove the charly submodule; clone charly recursively at CI
time"), but this clone kept the old working trees on disk, so **207 submodules
carried a stale untracked `charly/` directory** — a review blocker under rule 1.

Before removing anything I confirmed the scope was uniform and the content
disposable:

```
$ git submodule foreach 'st=$(git status --porcelain); [ -n "$st" ] && echo "$name :: $st"'
docs :: ?? charly/
layer-a11y-tools :: ?? charly/
…
dirty submodules: 207
entries that are NOT an untracked charly/: 0

$ # every leftover checked for local work
checked: 207 | dirty or with stashes: 0

$ git submodule foreach 'git clean -ffdn charly'     # dry run
207 lines, all exactly "Would remove charly/"
```

Then `git clean -ffd charly` per submodule. Afterwards zero submodules are dirty
and `verify` passes. This touches only untracked files, so it appears in no diff
and lands in no commit — it is local clone state, recorded here because it is
what moved `verify` from FAIL to PASS.
