# 2026.312.2305 — feat(check): gate what D-PAT-2 and D-PAT-3 can be gated on

## Summary

`DESIGN.md` §25 names "schema patterns on every plugin CUE module (D-PAT-1..3)" as a gate. opencharly/opencharly#947 landed the control for D-PAT-1 and stated plainly that **D-PAT-2 and D-PAT-3 were ungated** — recorded in `TODO.md` 2.16 and in the D-PAT-4 row. This change closes that gap for the half of each rule the pinned CUE text decides, and records the other half as ungated where a reader looks for it, so the gate's name stops implying coverage it does not have.

**What is now gated.** `scripts/design-dpat.sh` — still control 5/5 of `bash scripts/design-check.sh`, one script, one census, one tracked issue — gains two rules:

- **`dup` (D-PAT-2, the one-home half).** A top-level definition is declared in exactly one pinned module, so no module restates a definition another module already owns (D-SCH-1: every shape is defined once; D-SCH-2: a plugin imports a definition and never copies it). A name declared twice inside one module is not a finding — CUE unifies the declarations into the one definition, which is how a pattern constraint and the rows of the same map are written.
- **`union` (D-PAT-3, the form half).** No union is written out alternative by alternative: a `|` disjunction outside an `or(...)` derivation is a violation, except the two-value literal default S3 permits (`*false | bool`, `*120 | (int & >0 & <=1000)`, and a literal default on the right such as `#Scope | *"any"`). A `*` on a definition or a struct is a shape choice, not a default, so it stays a violation. The rule covers both spellings the design names: the shape union (`#A | #B`, `(*#Candy | #Image)`, `#Matcher | [...#Matcher]`) and the inline word list (`"root" | "any"`).

**What is NOT gated, and why — the other half of the deliverable.** D-PAT-2 demands more than one home: the home must be the plugin that OWNS the word, and core must compose the document schema from the registry (§10.3). Neither is decidable from the pinned CUE text: the word-to-owner mapping is built by the loader from each plugin's `describe`, which is Go, and the composed instance exists only at runtime. D-PAT-3 demands that a derivation range over the registry's own definition and that a collection with identities be a map (S5); a gate reading text sees the form of a derivation but not which table it ranges over, nor whether the items of a list carry identity. So those halves are ungated, and this change says so in three places where a reader would otherwise assume coverage: `DESIGN.md` A.11 ("What the gate decides, and what it does not"), the D-PAT-2 and D-PAT-3 rows themselves, and `TODO.md` 2.16 — including what would make the rest decidable: the loader emitting its registry (or the composed schema) as an artifact a control can read and compare against the pinned modules, or each module declaring its own words in CUE.

**The census.** The same `design/dpat-baseline.tsv` now carries all three requirements, and the ratchet is unchanged in kind: green on this tree, red on any new violation, red when an occurrence falls BELOW its row (a fix must lower the row in the same change, so "the census must reach zero" is a mechanic rather than an intention). It records 669 rows and 729 tolerated occurrences:

| rule | requirement | rows | occurrences |
|---|---|---|---|
| `close` | D-PAT-1 | — | 70 |
| `absence` | D-PAT-1 | — | 86 |
| `open` | D-PAT-1 | — | 68 |
| `opaque` | D-PAT-1 | — | 0 |
| `dup` | D-PAT-2 | 26 | 26 |
| `union` | D-PAT-3 | 468 | 479 |

The D-PAT-1 half is untouched: its 175 rows are byte-identical to the committed census, so nothing a previous fix lowered changes meaning here. The `dup` debt is ten definition names with a second home — the LLM, tunnel and deploy-record shapes that `spec` and the self-contained plugin schemas each spell out, across 7 files in 5 pinned modules. The `union` debt is 479 inline disjunctions across 84 files in 51 pinned modules, including the two examples `TODO.md` 2.16 names (`#CandyValue: (*#Candy | #Image)` and its kind-value sibling).

**A defect the new rules depend on, fixed here.** The control's stream puts a `@@FILE` marker before each file's body, and the scanner judges lines until the next marker at the start of a line. Two pinned blobs have **no final newline**, so the next file's marker was glued onto the previous file's last line: the marker was never seen, and every line of the next file was judged under the PREVIOUS file's name — a smaller scan quietly reporting success over a file it never attributed, which is the exact failure A.11's loud-read and blind-run guards exist to prevent. The `dup` rule makes this load-bearing (a name's homes are compared across files), so the reader now guarantees a terminating newline, and the self-test plants the case: a file after a no-newline blob, with a violation that must be reported under its own name.

## Rulebook compliance

- **R0.** Loaded before the first action: `/charly-internals:git-workflow`, `/charly-internals:strict-policy`. Nothing was read from a submodule checkout: every pinned module is read from its own object store at the pinned commit.
- **R1.** Two anomalies surfaced and neither is parked. (1) The reader's glued-marker defect, above: root-caused (a blob without a trailing newline puts the next marker mid-line, so the scanner never resets its file and the next file is judged under the previous name), fixed in this change because the `dup` rule is built on per-file attribution, and proven by removing the fix (the self-test fails on exactly that case). (2) The commit hook's `fatal: not a tree object` on its designed skip — pre-existing, already filed as opencharly/opencharly#946 with #947; re-observed here and left with that issue, which is the record. No warning survives in this change's own gate.

## Change classification

**Non-runtime, specification and gate.** The diff extends one control script, regenerates its census, and corrects the design prose that named the gate as half-built. No schema, pin, product command or user-facing behaviour changes; the one behaviour that changes is the control's own reader attributing a file to itself. The gate for this change is the design check plus the changed paths executed live, both pasted above.

**Compatibility:** nothing for a consumer to change — the check's command, its control order, the census's file and row shape, and the tracked issue are the same, and the D-PAT-1 rows are byte-identical, so the way back is this commit's inverse with no migration.
