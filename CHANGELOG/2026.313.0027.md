# 2026.313.0027 — docs(design): the duplicate rows retire with the composition, not with an edit here

## Summary

`scripts/design-dpat.sh` tolerates 26 duplicate definition sites in `design/dpat-baseline.tsv` —
the D-PAT-2 "one name, one home" debt: ten names across seven CUE files in five pinned repos. The
brief for this branch was to delete the second home of each name and lower its row in the same cut.

That cannot be done from this repository, and this change records why in the section the census
belongs to, so the next session does not rediscover it.

- Every one of those declarations is inside a pinned `spec` or `plugin-*` repo. A deletion lands by
  PR to the owning repo (AGENTS.md Part II #1); this repository records a gitlink and nothing else.
- No copy can be deleted in its owning repo either, yet. A plugin's schema is compiled with nothing
  else in scope — `sdk/schema.go` compiles the schema a plugin serves on its own, refuses it when
  that fails, and the Go generation reads the same unit — and `spec` is the only CUE module among
  the pins. A consumer therefore cannot cite the definition the owner declares; it can only restate
  it.

`DESIGN.md` A.11 now states what retires those rows: the composition §10.3 describes (D-SCH-2,
D-SCH-8), whose first units opencharly/spec#294 carries. It also records the pair that is not a
duplication at all — the egress record schemas restate, in a shape of their own, a persisted record
`spec` types, so its fix is a unification and a decision, never a deletion.

The census is unchanged, and that is the honest state: no declaration was removed, so no row was
lowered.
