### C. The gate has a caller — and the caller is proven to fire

`hooks/pre-push` now runs the gate for a push whose commits change one of the surfaces the six
controls read, and **refuses the push** on a finding. Which pushes those are is defined ONCE, in
`scripts/design-gate-inputs.sh` — the same shape `scripts/pin-contract-inputs.sh` gives the pin
check — and the surfaces are derived from what the controls read:

- `DESIGN.md` and `DESIGN.cue` (the consistency control compares them);
- `design/` (the ledgers, the fixtures, the two censuses);
- `scripts/design-*.sh` (a change to a control changes what is enforced);
- **every pin** — the schema-pattern gate reads each pinned module's CUE, and the pin-tag control
  reads every pin of the index.

Three properties beyond "it runs":

- **It cannot be skipped by a body condition.** The leg runs before every body leg, because the
  hook's body legs legitimately stand down (no body file yet, no linter, no `python3`) and a tree
  assertion that stood down with them would report a pass it never earned.
- **It refuses to judge a tree that is not the one being pushed.** The controls read the working
  tree (design files) and the INDEX (pins), so the leg compares each half the way that half is
  read — worktree for the files, `--cached` for the gitlinks — and BLOCKS, naming the remedy, when
  the checkout is not the published commit. This is the false-PASS/false-BLOCK pair #744 taught
  this hook to fear. Comparing gitlinks through the worktree would have been worse than useless:
  an unmaterialized submodule reads as a deleted path, and every light tree would block.
- **The guard's surface list is DERIVED from that one definition**, never restated (round 2's
  finding), so a surface added to the change set cannot leave the guard behind.

`charly task design-check` is the same command through the umbrella's own verb surface (one owner:
it delegates to `scripts/design-check.sh`), and `scripts/check-design-gate.mjs` asserts the caller
in the commit gate — statically, by **firing the shipped hook** on each input, and with a mutation
arm that deletes the leg's call and requires the fired case to go red.

**A defect the wiring exposed, fixed here.** `design-dpat.sh` and `design-pintag.sh` read a pinned
module's store at `<git-common-dir>/modules/<path>`, but a LINKED WORKTREE — the shape AGENTS.md
Part II #2 mandates for every session — keeps its submodule repositories under
`<git-common-dir>/worktrees/<name>/modules/<path>`. Measured on the merged tree: `dotgithub` pinned
at `3f1ad6cab2`, absent from `.git/modules/dotgithub`, present in the worktree-scoped store, and
`design-pintag.sh` refused with "does not have that commit — the control cannot read the pin it
judges". The refusal is the right shape; the location was the defect. The resolution now lives in
one place, `scripts/design-module-store.sh`, which asks GIT for the repository it uses and falls
back to the plain clone's store when no checkout exists.

### Why the push and not the commit

Measured, not asserted: the gate is **11m57s** on this tree (109 committed negative cases, each
spawning a `cue export`), and **25 of the last 60 commits on `main`** touch the design surface.
A commit-time leg would add ~5 minutes to the average commit — a wall contributors learn to work
around, which is how a gate stops being one. The push fires once, `charly task hooks` installs it
for every contributor, and the change set keeps an ordinary diff at zero cost. A measured "this
placement is too slow, here is what fires instead" — not an unwired gate.
