# 2026.271.1650 — fix(opencode): dual plugin contract (server + setup) — gates were silently unenforced on 1.18.x

## Summary

**R1 fix: opencode plugins must load under BOTH plugin generations.** opencode selects the plugin shape by the default export:

- **opencode ≥ 2.0** — `{ id, setup(ctx) }` (register via `ctx.tool.hook`; shell tool `shell`).
- **opencode 1.x** — `{ id, server(input) }` returning a hooks object keyed `"tool.execute.before"` (shell tool `bash`). A definition WITHOUT `server` is **rejected**: `must default export an object with server()`.

Both repo plugins shipped **only `setup`**. On the then-installed **1.18.33** every startup logged `failed to load plugin … must default export an object with server()`, so the pre-commit/pre-push gates were **silently unenforced** — while `check-opencode-plugin.mjs` "passed" them (Layer A only checked `id`+`setup`). The host has since been upgraded to **v2.0.18** (which loads `setup`), but the dual export is the portable form and the gate hole needed closing regardless.

### Changes
- `.opencode/plugins/umbrella-gates.ts` + `pr-watch.ts` — export BOTH `setup(ctx)` and `server(input)`, sharing one implementation (`gate()` / `watch()`).
- `.opencode/instructions.md` — corrects the false "only `{id,setup}`" note; documents both shapes; reconciles the installed-generation claim (1.18.33 was the earlier measurement; the host is now v2.0.18).
- `scripts/check-opencode-plugin.mjs` — **Layer A now REQUIRES BOTH `setup` AND `server`**, closing the hole: a one-generation plugin (the exact regression) now FAILS the gate. The `--standalone` rationale is corrected in place.
