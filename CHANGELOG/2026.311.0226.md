# 2026.311.0226 — feat(design): an agent run can be told what to read, call and return (batch 56)

## Summary

Batch 56 of the DESIGN amendments (tracked in #838). `verb:agent` carried **10 authored keys and 8 of them had
no field**. Six go on `#HarnessStepFields`, which already held the harness ref, the evidence, the failure
outcomes and the redo policy:

| key | field |
|---|---|
| `skill` | `skill` — the skills this run is given |
| `tools` | `tool` — what it may call |
| `outputs` | `output` — its reply contract, per name |
| `max_turns` | `turn` — its ceiling |
| `cache` | `cache` (`#AgentCache`) — what it reuses between runs |
| `repo` | `checkout` — the repositories placed before it |

Two deliberate placements:

- **`skills` (the corpus root) is a *harness-node* field, `skill_dir`**, not a step field — it is where the node
  reads from, not what one run is given.
- **`output` is a per-name map whose shape is the caller's** (S10), so the design does not invent a reply
  vocabulary it would then have to keep.

`llm` was added by batch 55 and is shared here unchanged (R2), and `redo`/`fail_on` already existed.

| file | what changed |
|---|---|
| `DESIGN.cue` | six fields on `#HarnessStepFields`, `skill_dir` on `#Harness`, and the named `#AgentCache` |
| `DESIGN.md` | the release pipeline's review stage runs a `harness_run` exercising all six |
| `design/dulling.tsv` | `verb:agent` becomes sharp |
| `design/dulling-disposition.md` | regenerated |
