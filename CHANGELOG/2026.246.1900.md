# 2026.246.1900 — feat(prompt): plan discipline requires explicit approval before execution

## Summary

The pi harness system-prompt append (`.pi/APPEND_SYSTEM.md`) mandated saving a plan to `plan/` before execution but did **not** gate execution on user approval — so a request like "make a plan" was read as authorization to plan-and-execute in one flow (observed live: a "make a plan to run all check beds" request launched 10 concurrent bed runs in the same turn, before the plan was reviewed).

This change makes the plan the deliverable: save it to `plan/`, present it for review, and **STOP for explicit approval before any execution**. Execution in the same flow is allowed only when the request unambiguously authorizes it ("plan and execute", "then do it", "run it"); ambiguous plan+execute requests default to plan-only and ask.
