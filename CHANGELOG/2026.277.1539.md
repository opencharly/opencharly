## Summary

Wires the charly **soul** into the umbrella's agent surface, so every agent that works here —
on every harness — knows it works as charly, and where the identity behind the rules lives.

This is the delivery leg of the SOUL work (opencharly/charly#789 adds `charly/SOUL.md`). The
soul is a **single canonical document in the `charly` repo**; the umbrella **references** it and
never copies its text (R3). Because rule 8 was reversed upstream — harness config lives **only**
in the umbrella — the delivery wiring is umbrella-side only, with no mirror in `charly/`.

Three surfaces:

- **`AGENTS.md`** — a first-read pointer near the top: every agent here works as charly, and
  `charly/SOUL.md` is who that is. This reaches Claude Code, Codex, Kimi/reasonix, and any other
  harness that reads the neutral rulebook.
- **`.opencode/instructions.md`** — an "You are charly" section in the opencode binding.
- **`.pi/extensions/charly-gates.ts`** — a "You are charly" block prepended to the existing
  condensed rules that the extension injects into the system prompt **every turn** (it survives
  compaction), plus the `charly/SOUL.md` pointer.

The pointers name the file; they do not restate the soul. One source, referenced — not copied.

**Change class.** This is **not** documentation-only: `.pi/extensions/charly-gates.ts` is harness
source whose runtime output (the rules block injected into the system prompt every turn) changes.
The change class is **harness-config source + documentation**, and the tier below reflects that.

**Producer-first.** The reference resolves against the pinned `charly/` gitlink, so
opencharly/charly#789 must merge first (the umbrella records the charly gitlink). This PR does not
bump that gitlink — the reference is path-relative prose; the gitlink advances by the normal
`task sync`, not by hand.
