# 2026.289.1341 — fix(scripts): the corpus guard tests materialisation, not existence, in all three arms — a session worktree's `task sync` no longer deletes the farm

Closes opencharly/opencharly#508

## Summary

**A guard that tests `existsSync` is not a guard on a system that creates empty mount points.** `git worktree add` creates the submodule MOUNT POINT, so every session worktree — the layout `AGENTS.md` Part II rule 2 prescribes for every lane — has `marketplace/` **present and empty**. The old guard accepted that as a corpus, so `charly task sync` derived **zero** skills and published the result as a state: it deleted all **353** `.dsh/skills` entries and rewrote `reasonix.toml`'s `[skills] paths` to zero entries, reporting `exit=0 done` — while the harness-config gate, on the same tree, turned **RED** with the same derivation's false STALE verdict.

**One predicate, one module, per derivation INPUT.** `scripts/lib/corpus.mjs` owns it; the flat farm enumerates skill **files** and needs `corpusHasSkills`, while `reasonix.toml` enumerates family **directories** and needs `corpusHasFamilies`. A tree can hold one input without the other — the gate's own staged tree does, and this worktree does — so a guard that stopped the whole run on the first unmet need would silently drop the half that could still derive. **Each half reports its own visible SKIP and the other continues**, and the writer writes **nothing** for a skipped half rather than publishing a zero-entry result.

**All three arms now agree on the same tree** — the writer, `--check`, and the gate's two skip tests — which is what the defect was: *one predicate with three implementations and only one honest*. The two gate skip tests and the writer's notice import the same module and print the same reason, so they cannot paraphrase their way apart again.
