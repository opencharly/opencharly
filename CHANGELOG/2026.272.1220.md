# 2026.272.1220 — docs(agents)!: align the merge language with native auto-merge (no agent merges)

## Summary

`#311` (merged `v2026.272.0828`) introduced a claim that **contradicts the actual org
workflow**: the main session was said to own the *"merge decision (merge only on a validator
PASS)"* and a subagent *"does not merge"*. In this org **no agent merges at all**.

**The real mechanics (verified against the live repo + the authoritative skills):**
- Every opencharly repo has `allow_auto_merge: true` (`allow_merge_commit: false`,
  squash-only, `delete_branch_on_merge: true`).
- The `charly/pr-validator` gate **arms GitHub native auto-merge (squash) inline on its own
  PASS** — its file header: *"On PASS, enables GitHub native auto-merge (squash)."* There is
  **no separate auto-merge workflow**.
- `bypass_actors` is the `charly-auto-merge` App only; `gh pr merge --admin` is forbidden.
- A `BEHIND` branch is recovered with `gh pr update-branch` (never a force-push), then merged
  on the new head.
- The org-wide `tag-on-merge` workflow fires on `charly/pr-validator` completion, writes
  `CHANGELOG/<CalVer>.md` from the merged PR body, and tags the merged HEAD.

**This PR corrects `AGENTS.md` to say that:**
1. Main session: **no "merge decision"** — it drives the PR to a **PASS on the final head**;
   **no agent runs `gh pr merge`**, `--admin` is forbidden, never push at the block limit.
2. Subagent: **never merges or arms a merge**.
3. On a BLOCK, the subagent **does not push again until the parent confirms every block is
   addressed** (the push gate).
4. The PR-lifecycle block gains **item 5 — "Who merges: no agent"**.
5. The development-model landing line now names **native-auto-merge squash**.
