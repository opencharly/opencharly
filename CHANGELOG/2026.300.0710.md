# 2026.300.0710 — refactor(gate): the harness spells the mutation target and the spawn result once

## Summary

**R2: the harness spells the mutation target once, and reads a spawn result once.** The `charly/pr-validator` noted, on #729, that the two mutation entries which break the same line spell the same target twice. Re-reading the file for that note turned up a second duplication in the same file: the spawn result is read three times, and the null-status rule is stated three times, none of them named.

Head `9a929b78feb161e3ca36d4382a2cb6c5f31acabd` — the commit this PR pushes: **1 file changed, 33 insertions(+), 9 deletions(-)**.

**What the duplication was.** The mutation table holds two entries that break the **same** line in **different** ways — one swallows the reconcile's exit status (assertion B), one turns a PASSING reconcile red (assertion A) — and the target was written out **twice**, byte-identically. Edit one and the other silently stops matching: the harness would report *"mutation ... targets text that occurs 0 time(s)"* only at the moment someone ran it. That is the failure mode #727 was about, one layer down. Separately, the spawn result was read in three places, and the rule a signal-killed child encodes — `status` is null, and null is a FAILURE — was stated three times, unnamed.

**What this change does.** Three changes, one rule (R2 — one canonical implementation per behavior):

- the shared target becomes a **named constant** (`STATUS_TARGET`) the two entries use, so the two cannot drift apart;
- the spawn result is read in **one place** (`spawnResult`), which states the null-status rule once and joins stdout+stderr once;
- the `failures.length === 1` conjunct is spelled out in a comment: it is evaluated first, so `failures[0]` is the **only** failure the nested run reported, never the first of several (the validator's second note, rebutted with evidence on #729's thread).

**The helper stays inside this file on purpose.** The harness copies **itself** into a fixture checkout and runs the copy there, so the copy must be self-contained — a shared `scripts/lib/…` import would not resolve inside the fixture, and the self-test would die on the import rather than on the assertion. The repo-wide twin of this duplication — the same reading spelled per script across five more gate scripts — is filed as opencharly/opencharly#731, with the constraint that shaped it measured.

| file | what it changes |
|---|---|
| `scripts/check-governance-reconcile.mjs` | the mutation target the two entries share becomes one named constant, the spawn result is read in one place, and the nested verdict's order-independence is stated in the code |

Closes #730
