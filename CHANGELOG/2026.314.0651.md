# 2026.314.0651 — feat(design): gate pinned-module citations at the pin and re-anchor four rows

## Summary

`design/dulling.tsv` cites the pinned source it reasons about by `path:line` — a claim about
somebody else's commit — and nothing in this tree resolved one. `scripts/design-ledger.sh` checks a
citation into `DESIGN.md`/`DESIGN.cue` and deliberately refuses a LINE there (`a line drifts on
every edit of this document`), but a citation into a pinned submodule was accepted in the line form
and **never opened**. So the one citation form that rots on a schedule this repository does not
control was the one form no gate read: a pin advance that moved a construct out from under a row
left `bash scripts/design-check.sh` green.

That is opencharly/opencharly#963, and it is not hypothetical. opencharly/opencharly#962 advanced
`plugin-jetkvm` and falsified two rows of the ledger — `jetkvm.cue:437-473` ends two lines short of
`#JetkvmDeviceInput` (doc comment :470, body :475) and `481-578` spans `_method` (:516-605) instead
of the enum `#JetkvmMethod` (:614) — and both stayed green through every gate run.
opencharly/opencharly#964 fixed the two `cua` citations its own advance broke, which is the proof
that the same failure recurs on every advance.

**The control.** `scripts/design-cite.sh` is the seventh control, wired into
`bash scripts/design-check.sh` as step 5/7 (and so into `hooks/pre-push`, which runs that command by
change class). It reads the tree's pin set from its **index** (`git ls-files --stage`) and each
module **from its own object store at the pinned commit** — through `scripts/design-module-store.sh`,
the ONE resolver `design-dpat.sh` and `design-pintag.sh` already use, so a linked worktree's
`<git-common-dir>/worktrees/<name>/modules/<path>` is handled and no second copy of that knowledge
exists here. A working checkout is never read for a judgement.

**What "contains what the row claims" means here — the judgement the whole control turns on.** The
ledger carries no machine-readable statement of a line range's subject: a row names a definition of
`DESIGN.cue`, never a construct of a pinned module. So "the range contains what the row claims" is
**not decidable from the ledger's own data**, and this control does not assert it. It judges the
three forms on what each one's text can decide:

| form | what is claimed | what is judged |
|---|---|---|
| `<module>/<path>` | this is the artifact that shows today | the path exists in the pinned tree (file or directory) — a failure, never a skip |
| `<path>:<definition name>` | this file declares this construct | the pinned file declares that name at the pin. **A pin advance cannot falsify this form**, which is why it is the form the two repaired `jetkvm` rows use |
| `<path>:<a>` / `<path>:<a>-<b>` | these lines are the artifact | (1) `1 <= a <= b <= <lines>`; (2) the construct the range sat inside when the row was affirmed still encloses it; (3) the bytes at those lines are still the bytes the row was affirmed against |

Facts (2) and (3) are what `design/cite-baseline.tsv` records — the construct and a digest per line
citation — and they turn the silent failure (a pin advance re-pointing a citation at a different
construct) into a loud one, naming the row, the pin, the construct the range now sits in and the one
it was affirmed against. The baseline is **not an exemption**: the check fails in both directions, so
a line citation absent from it is a claim nobody affirmed, and a row whose citation the ledger no
longer carries overstates the record and is lowered in the change that re-anchored the row. The file
can therefore only shrink toward the rows that cite a name. DESIGN.md A.13 states the same split for
the design, as A.11 states it for the schema-pattern gate.

A citation of a repository this tree does not pin (`opencharly/<repo>@<commit>` beside a
repository-relative path) is reported as **unchecked** — a commit id is immutable, so it cannot
drift, and this tree does not carry the repository to read it — never as a finding and never
silently. A citation into this repository's own files is checked for existence and range only: it
cannot drift under a third party's commit.
