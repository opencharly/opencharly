# 2026.308.0020 — feat(design): adjudicate the artifact-phase rows by measurement (batch 3)

## Summary

Batch 3 of the DESIGN amendments the capability ledger records (tracked in #838). Batches 1 (#843)
and 2 (#845) landed the restored fields and the plural address list; this closes the artifact-phase
gap that six ledger rows recorded.

**The gap.** §16.5 said the artifact phase's instance "starts no init and no service", so `service`,
`process`, `port`, `kernel_param`, `dns` and `interface` were pinned to `#DeploymentPhase` — while
today a build-context check runs inside the builder container and observes exactly that running
state. Three of the six rows carried `amend D-VERB-3`; three carried `amend D-VERB-7`.

**The amendment.** The artifact's instance is now a **disposable container that starts the init and
services the content declares**, binds no capability, publishes no port and reaches no other node,
and is destroyed afterwards. The artifact itself is still untouched — that is what the isolation
guarantee protects — and the observation exists again. `D-VERB-7` now says every fact verb observes
an artifact and a deployment, and only a **protocol** verb is deployment-only, its endpoint existing
nowhere before realize.

Seven arms move in `DESIGN.cue`: the six rows this batch settles, plus `mount`. `verb:mount` already had a `sharp` verdict because its fields survive (`source`, `fstype`, `opt`), and it now also records the phase it observes — before this change it was deployment-only like the other six, and the row did not say so. The six rows become `sharp` against the requirement each now satisfies. The negative case that
encoded the old rule — a `port:` check in the artifact phase — is retargeted at `http:`, which stays
deployment-only and still fails. The fact-verbs example asserts a service check in the artifact
phase, so removing the restored arm fails validation.

**Measured context, scoped honestly.** Across candy manifests only:

```console
$ cat measure.py
import glob, re
files = [f for f in glob.glob("**/candy/*/charly.yml", recursive=True)
         if ".worktrees" not in f and ".build" not in f]
plans, hits = 0, []
for f in files:
    lines = open(f, errors="ignore").read().splitlines()
    if not any("plan:" in l for l in lines):
        continue
    plans += 1
    block = []
    for l in lines:
        if re.match(r'\s*-\s*(check|run):', l):
            if block:
                body = [b for b in block if not b.lstrip().startswith("#")]
                verbs = any(re.match(r'\s+(service|port|process|dns|interface|mount|kernel[-_]param):', b) for b in body)
                build = any(re.match(r'\s+-\s+build\s*$', b) or ('context' in b and 'build' in b) for b in body)
                if verbs and build:
                    hits.append(f)
            block = [l]
        else:
            block.append(l)
print("candy manifests with a plan:", plans, "| build-context runtime-verb checks:", len(hits))
$ python3 measure.py
candy manifests with a plan: 324 | build-context runtime-verb checks: 0
```

No candy plan observes running state while building today, so the restored capability costs nothing
in practice. This is context for the amendment, not its justification: the amendment is the fix, and
a measurement alone would have left the gap open.
