### RDD — the host hook bridge was probed and REFUTED (recorded in the ledger, not claimed)

The ledger's first draft assumed a profile-root `dsh-hooks-claude-code` mount would run the git
gates. That was probed on isolated `$DSH_HOME` copies and **does not work**: the row composes and
the module imports, but no hook ever fires and no config is read (a deliberately malformed
`configPath` warns nothing; the decompressed session log has zero hook/matcher events). Three
probes bound the cause: a `main` push ran UNBLOCKED and four matcher spellings plus a
`SessionStart` hook were silent (so it is not a matcher); a documented `insert` DID apply — the
`dsh-base` README's own `dsh-tool-str-replace-editor` row appeared in a headless session's tool
list — so the patch layer is fine; and activation failures DO warn loudly (a spike produced
`dsh: warning: 3 entries did not activate`), so the bridge's silence means "never applied", not
"failed". The cause is an activation condition the package's docs do not expose; correcting this
change's own earlier claim, an absent `shell` service is NOT it (`@deepseek-ai/dsh-shell` is the
seam and `dsh-bash-sandbox` provides `shell` at the profile root). The ledger and `.dsh/README.md`
record the probe and mark the `pod-dsh` wiring BLOCKED pending operator direction. Nothing in this
PR claims the host gates work.
