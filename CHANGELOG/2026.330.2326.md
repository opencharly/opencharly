# 2026.330.2326 — fix(pi): parse the dispatcher table at any heading level and fire the loader

## Summary

R0 was un-dischargeable in pi, and nothing could see it. `charly_load_skills` is the only way a pi
session loads the skills the rulebook's dispatcher selects; it located that table with a literal
`### Skill Dispatcher` heading regex, while `AGENTS.md` now carries the section as a top-level
`## Skill Dispatcher`. The fallback returned an empty array, so **every** call answered
`Could not parse the skill dispatcher table from AGENTS.md` and loaded nothing — from the moment the
heading was promoted. This branch fixes the parse, fixes two more defects in the same function that
the same firing exposed, and adds the gate that would have caught all three.

**The three defects, all in `parseDispatcherTable` and its matcher:**

- **The heading level was an assumption about a document the extension does not own.** Matching is
  now `^#{1,6}\s+Skill Dispatcher$` — any level.
- **The matcher let a FRAGMENT stand in for a whole trigger.** Cells were split on `/` and `,` and
  matched bidirectionally by substring, so a chunk could be a word taken out of a path: the
  `local:`/`vm` row's cell contains `~/.config/charly/`, which yields the chunk `charly`, and that
  is in nearly every rulebook keyword. MEASURED, with the heading fixed so the table parsed:
  `charly box build` loaded 5 refs instead of its own 3 — `charly-local:local-deploy` and
  `charly-vm:vm` came along — and a two-letter chunk matched `maintenance` (`nc`). Matching is now
  token-wise: every token of the caller's phrase must be a prefix of a token in the cell.
- **`realpathSync` was called and never imported.** It is not a Node global, so `real()` threw on
  every call and its `try/catch` returned the path unchanged — a fallback branch hiding a defect
  (R3), which the syntax-only parse check cannot see.

`##`, the parse returned zero rows and `charly_load_skills` could not serve R0.
