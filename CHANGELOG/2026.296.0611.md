**The clone is BLOBLESS** (`--filter=blob:none`): every commit and tree are present, so

### The measurement measured the machine, not the tree

**The mechanism.** `scripts/measure-clone.sh` cloned the tree under test from this checkout
with the **local transport**, and a local clone **copies the source's entire object store**:
every commit on every branch, including other sessions' pushed branches and their loose
objects. The reading was therefore a property of the workstation, not of the tree. Measured
on this branch: the source and the clone it produced were byte-identical in their stores
(`.git/objects` 11 M in both), and with the tree, the `charly` pin (`9fd74793`) and the built
version stamp
(`2026.295.1709`) unchanged, the light clone read 75 M, then 76 M, then 77 M over six hours
and the bootstrapped light tree 126, 127, 128 and 129 M. The band the README committed
rotted with the readings.

**Ruled out.** Upstream submodule growth (the pins were 0–4 commits ahead, the store 10 M);
the local `charly` store's growth (the clone's store is fresh from the remote: 13,195 objects
against the local 42,150); the script's own version. Two back-to-back clones both read 129 M
with identical breakdowns — the drift was a property of the environment, not of the tree.

**The missed control.** The band was committed from one day's readings; the samples half of
the comparison is **manual** (`--samples <log>`), and the pre-commit hook runs the comparison
*without* samples — so nothing re-derived the band when a run outgrew it. It never asked
**what the measurement measured**.

**The blast radius.** The README's clone-shape table and every band it carries — the light
clone, the bootstrapped light tree, the `--all` shape and the `openclaw` store — and every
sentence quoting them.

**The root fix.** The measurement clones the superproject **over the transport**
(`--no-local`), on the **one branch that holds the tree under test** (`--single-branch
--branch <the branch>`), so the clone carries the *tree's* history and a reading is a
property of the tree. The branch is found from the tree itself: the checkout's own branch
when it holds the tree, else the first that does, else the whole history — the only way to
reach a commit on no branch. The missed control is in the diff too:
`scripts/check-readme-measurements.mjs` now **fails on a measurement that clones the tree
with the local transport**, and its self-test mutates the measurement's own clone invocation
to prove the assertion can fail.

### The measurement could die on a ref that moved, and said nothing about why

**The mechanism.** The measurement resolves the tree under test **once**, at the start, and
clones it **minutes later** — the light phase alone is three fresh clones, the full shape
another six minutes after that. The clone carries the branch **as it was at clone time**, so a
branch **rewritten** in between no longer holds the tree the run resolved: the clone succeeds
and the checkout of the tree fails. The pre-change clone path sent git's own error to
`/dev/null` and returned a bare *"the clone at … failed"*, so the run died naming neither the
cause nor the tree.

**Measured.** A run of this branch's own measurement died exactly there — at the **full**
shape, after the light phase had completed three clones and the bootstrap — with
`measure-clone: the clone at /tmp/charly-measure.9PwJnh/full failed.` and nothing else. The
cause was in git's output, which the script threw away: the source branch had been
**rewritten** (the commit reworded with `git commit-tree`, the tree unchanged) between the
run's resolution of the SHA and the clone, so the branch the clone carried no longer
contained it. Ruled out: the network, the disk, the permissions, the script's own version.

**The missed control.** The script never asked **whether the clone carries the tree it
resolved**, and it discarded the only evidence that could have said so. A measurement whose
failure is silent can die for a dozen reasons and name none — and the run it kills is the
run that re-derives the bands.

**The root fix.** Two changes in the clone path: the tree under test is **fetched by its
SHA** when the clone does not carry it (`git fetch --no-tags <source> <sha>` — measured to
work for an unadvertised SHA), so a branch that moved and a tree on **no branch** are both
measurable; and **git's error is never silenced** — a clone, a fetch and a checkout that fail
each print git's own output under a line saying what was attempted.

**The control.** `scripts/measure-clone.sh --self-test` builds a source repo, a tree a
branch holds and a tree **no** branch holds, and asserts three things — a tree a branch holds
is cloned with the tree; a tree no branch holds is fetched by its SHA; a failure **names
git's own error**. It runs in `charly task self-test`, and so in the pre-commit gate. §2f
carries the **differential**: the pre-change clone path, extracted from the pre-change commit
and run against the **same fixture and the same assertions**, fails the last two.

### The band was narrower than the runs produce

**The mechanism.** The `--all` shape's wall clock is a **network** sample, not a CPU one: the
shape clones every declared path in parallel and then checks them out one at a time, and its
time is dominated by the vendored upstream mirrors (`openclaw` alone holds 7.6 GB of
history). Its run-to-run spread is therefore tens of seconds, not seconds — and the band the
README committed was derived from the runs available when it was written, so its lower bound
sat **2 s above** readings this machine has actually produced. Every `--all` sample taken on
this machine, across 24 runs of this branch:

```
355 357 359 359 360 361 361 362 362 362 362 363 363 363 363 364 367 367 370 371 375 375 380 385 403
```

The committed band covered 359–403: it excluded the two lowest samples in that list, both of
them real readings of the same shape, on the same machine, over the same transport.

**What the gate said.** The final tree's own run measured **357 s**, the band said
**359–403 s**, and the comparison refused the sample by name: *"the band is narrower than the
runs produced"*.`

**The missed control.** The band was derived **once, by hand**, and nothing re-derived it
when a later run landed below its lower bound. The control that DID work is the one that
caught it: the **samples arm**, which sees a band only when a live run's reading is handed
to it. That arm fired here, on the final tree, before the push.

**The blast radius.** The README's clone-shape table and the prose that restates it — the
two sites the comparison's prose arm holds in agreement — and every body that quotes the
band.

**The root fix.** The band is widened to the range the runs produce — **5 m 55 s – 6 m 43 s**
— in the table and in the prose, and the measurement is re-run **on the widened tree**, so
the band the tree carries is the band that tree's own run falls inside. That re-run measured
**359 s** — inside the widened band, where the refused reading was 357 s. The initializer's
behaviour is untouched: the sizes the same run measured (71 M light, 1.9 G for
`--all`, 123 M bootstrapped, 500 M for the `openclaw` store) are unchanged and
still inside their bands.

### The audit's own band excluded a sample it had taken

**The mechanism.** The branch-audit step's band — the sentence that says what the
parallelization buys — was carried as a **remembered figure** ("192 s to 212 s serial,
13 s to 15 s at `-P 16`"), drawn from the samples available when it was written. The gate
that times the shipped step on every head keeps taking samples, and this head's own sample,
**194 s** serial and **13 s** at `-P 16`, is **below** the
band's lower bound. A band that excludes a sample of its own step is narrower than the step
it describes — the same class as the `--all` band above.

**The missed control.** Nothing derived the band from the samples: the band was a figure in
the prose, and the gate that produces the samples (§7) never read the prose back. The two
earliest rounds' logs are gone, and those samples survive only in the earlier bodies' prose —
so a band rebuilt from the logs alone would be **narrower** than the samples it claims to
cover.

**The blast radius.** The body's own claim about what the parallelization buys, and every
body that quotes the band after it.

**The root fix.** The band is **derived, not remembered**. The samples live in a **ledger**
(`audit-samples.tsv`), which holds the dated samples whose logs are gone with their
provenance, and the body's band is the **union** of that ledger and every §7 sample this
branch's gates took. The union is **190 s to 212 s** serial and
**13 s to 15 s** at `-P 16`: this head's own reading is inside it, and no sample
the step ever produced is outside it.

### The body's count of the diff's new files was stale

**The mechanism.** The classification section counted the diff's new scripts as **three**;
the diff adds six. Compressing that paragraph for the 65 536-character limit had replaced a
true enumeration of three names with a **bare count** — the one form nothing can check, since
the names it replaced were things the diff could be asked about. The file table listed all
six as new throughout; the sentence above it said three.

**The missed control.** `scripts/check-pr-body-diff.mjs` asserted the file **table** against
the diff and the pasted head against the head, and stopped there — it deliberately did not
read the prose (*"a row that says the README carries a change the README does not carry is a
judgement, and judgement is the validator's job"*). Right for prose, wrong for a **count**:
a count is the diff's own arithmetic, so the diff can decide it. Nothing in the pre-push path
asked the arithmetic, so the stale number survived the gate and cost a review round.

**The blast radius.** Every count the prose states about the diff's file set, in this body and
in every body this repository's reconciler guards.

**The root fix.** The reconciler gained a third rule, **N**: every count the prose states
about the diff's **new** files equals the diff's. It is derived **mechanically** — a number,
"new"/"added", a noun naming files or scripts — so *"the four new gates"* is not read as a
claim about the file set, and a scope the prose names narrows the comparison. Its self-test
arm proves it can fail, and §2e-bis runs it against the very body the validator BLOCKed.
