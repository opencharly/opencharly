### The `dev/worktree build` `WARNING:` — root-caused and resolved (R1)

An earlier revision of this body pasted the gate output with a leading
`WARNING: charly is a dev/worktree build …` line and only *explained* it. That is an
environmental disposition, not a fix — so here is the warning-free run plus the mechanism.

The notice is charly's plugin-provenance guard. `plugin_loader.go` emits it from
`warnSkippedFHSPlugins` (`:452-465`) only when **both** hold: the running binary is not
FHS-installed (`packagedInstallDirs = {"/usr/bin", "/usr/local/bin"}`, `:427`) **and**
`bakedPluginDir = "/usr/lib/charly/plugins"` (`:398`) exists with a `.providers` manifest. This
host satisfies both — a root-owned *packaged* charly at `/usr/bin/charly` owns 10 `.providers`
files there, and it is a **different release** that cannot run the umbrella at all:

```
$ ls /usr/lib/charly/plugins/*.providers | wc -l
10
$ /usr/bin/charly version
2026.256.1316
$ cd <worktree> && /usr/bin/charly task org-map
charly: error: unexpected argument task
```

The canonical environment for the umbrella gate — rule 4 + R9 + `bootstrap-charly.sh` ("build
once per clone"; "never install it as a shared binary") — has **no** packaged charly, so
`/usr/lib/charly/plugins` does not exist and the guard cannot fire. charly's documented mode that
reproduces exactly that environment is `CHARLY_PLUGIN_ONLY=1` (`plugin_loader.go:472-477` —
*"the supported way to resolve AS-IF-UNPACKAGED"*; `:487-489` returns **before**
`warnSkippedFHSPlugins()`). On a dev/worktree build it is **behavior-neutral**: the dev path
already drops the FHS dir (`:490-493`), so the plugin search path is unchanged. Measured:

```
$ ./charly/bin/charly version
2026.277.2125

$ ./charly/bin/charly task list  > A.out 2> A.err
exit=0  stderr=1247 bytes  stdout=1149 bytes
  A.err line 1: WARNING: charly is a dev/worktree build …

$ CHARLY_PLUGIN_ONLY=1 ./charly/bin/charly task list  > B.out 2> B.err
exit=0  stderr=969 bytes  stdout=1149 bytes
  B.err line 1: plugin github.com/opencharly/plugin-example-kind/candy/plugi…

$ grep -c "WARNING" A.err ; grep -c "WARNING" B.err
1
0
$ diff -q A.out B.out && echo "stdout IDENTICAL"
stdout IDENTICAL
```

That is: the `WARNING` count goes `1 → 0`, the exit code stays `0`, and stdout is byte-identical
(`1149` bytes both). Only the not-applicable notice disappears; nothing else changes. The four
gate pastes above are therefore the same gate, run in charly's documented as-if-unpackaged mode:
**warning-free**, with nothing filtered. stderr still carries charly's `plugin …: served from …`
provenance **info** lines (they are present in *both* modes — `969` bytes of them remain in the
`CHARLY_PLUGIN_ONLY=1` run above), so what the pastes show is the unedited gate stderr + stdout.

The finding's other suggested route — install the freshly built binary at `/usr/local/bin` (the
path its own predicate tests) — is refused: **R9 says "never install it as a shared binary"**, and
doing so would shadow the host's `/usr/bin/charly` for every other session on this machine —
precisely the cross-version hazard the notice exists to warn about. The documented
as-if-unpackaged mode gives the same warning-free result without mutating the host.
