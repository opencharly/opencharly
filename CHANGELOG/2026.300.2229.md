# 2026.300.2229 — fix(guidance): a path argument is a PATHSPEC — the guidance says so, and a gate asserts it

## Summary

Head `cb5deb1b8eef3935ed18f8f474d195fbd2005bca` — the commit this PR pushes: **7 files changed, 677 insertions(+), 20 deletions(-)**.

**Git reads a path argument as a PATHSPEC, not as a path.** `*`, `?` and `[` make it match SEVERAL paths, and a leading `:` is pathspec MAGIC that matches NOTHING. Where the reader does not validate its pathspec, the misread is SILENT — the command exits 0 having answered about the WRONG record, or about nothing at all. Measured on 2026-10-27 (git 2.56.0) on a fixture whose declared paths are `a*b`, its sibling `a!b` (at the older twin) and a third `:colonpath`:

```

$ git ls-files -s -- ':colonpath'; echo "exit=$?"
```

The bare form asked for ONE submodule and received TWO checkouts — the sibling at the older twin included. The colon form asked for a path that exists and received an ERROR, because a leading `:` is magic and `:colonpath` matches nothing. Only the literal form reads the path the author named.

**The umbrella's guidance taught the bare form.** This PR states the rule ONCE, in the git-workflow skill's non-negotiable invariants, rewrites every site the bare form survived in, and ships the CONTROL that keeps it that way.

**The rule, stated once.** A path argument whose content is not yet fixed — a PLACEHOLDER (`<…>`) or a VARIABLE (`$…`) — is written in the literal pathspec form, after a `--` separator: `git ls-tree HEAD -- ':(literal)<sub>'`, `git ls-files -s -- ':(literal)<path>'`, `git submodule update -- ':(literal)<path>'`, `git add -- ':(literal)<path>'`. A name the author has already fixed is written as it is — a repository path (`charly`), an example's `old`/`new`, a REV (`HEAD`, `origin/main`) — and a DIRECTORY argument (`git -C <dir>`) is not a pathspec, so it must not carry the magic.

**The sites: 19 path arguments at 18 sites over 5 files**, measured by the control below against the pre-change tree. The issue's own enumeration of group A named seven — every one of them a `ls-tree` reader — and the leg's scan finds the writers too (`git add`, `git rm`), the index read (`git ls-files -s`), the `git grep` path restriction, and a `git submodule update` placeholder the enumeration missed (`umbrella-mechanics.md:298`).
