# 2026.307.1803 — feat(design): the capability ledger and its A.8 check

## Summary

Adds the capability ledger and the check that keeps it honest — deliverable 1 of
opencharly/opencharly#838.

`design/parity.tsv` (DESIGN.md A.7) proves *where* a capability lands. It cannot say whether it
lands *whole*: a `merged` disposition names the row that absorbs a word, never that the row keeps
every operation, guarantee and freedom the word has today. This PR adds the second question as a
normative, gate-checked artifact.

- `design/dulling.tsv` — one row per `design/parity.tsv` capability, in parity order (264 rows).
  Each row records today's surface, the governing requirement, the target form, a verdict
  (`sharp|dulled|forbidden|unknown`), the one clause that blunts it, the evidence for both halves
  and the action that follows. The file stores only what `parity.tsv` does not have — no class,
  repository, disposition or target column is copied — so the two cannot drift; the check
  enforces the one-row-per-capability join instead (R2).
- `design/dulling-admission.tsv` — the new-capability half: 30 ways a future capability can enter
  the system, and whether each can be taken without amending DESIGN.md.
- `scripts/design-ledger.sh` — the control: exact coverage of `design/parity.tsv` (no missing, no
  duplicate, no extra, same order), the verdict and action enums, every cited `DESIGN.md`/
  `DESIGN.cue` line resolving, and the rule that a row naming a requirement cites a line that
  carries it. `--self-test` mutates all eight invariants and fails unless every mutation is
  reported.
- `scripts/design-check.sh` runs it as control 4/4; `scripts/design-consistency.sh` now validates
  the ledgers' requirement IDs and `§` references.
- `DESIGN.md` — A.1 file registration, A.2 (fourth control), A.4 check 4, and the new A.8.

Findings recorded at this head: 264 capabilities — 121 `dulled`, 3 `forbidden`, 134 `sharp`,
6 unproven; 30 admission paths — 16 `dulled`, 3 `forbidden`; 114 rows name an amendment across
38 targets. Resolving those is the remainder of #838 and does not ride this PR.

**Round 2 (after the validator's BLOCK at `165f23e`).** The review found two assignments in the
self-test that no line read (the `expect` helper restores with `cp`, not from those backups) —
dead code in a file this PR adds (R5). Both are deleted; nothing else was raised. The gate was
re-run on the new head, and the class behind it is filed as #841 (no shell static analysis in the
pre-commit gate).

**Round 3 (after the validator's BLOCK at `c2ffe69`).** The same class recurred one function below:
the self-test copied `DESIGN.md`, `DESIGN.cue` and `parity.tsv` into its work dir, but `check_all`
read those three from the repository's globals, so the copies were never opened. `check_all` now
takes the root it judges, the self-test passes its own tree, and a ninth mutation truncates that
copy and requires the check to fail — so a self-test that silently read the repository would now be
caught by its own suite. That is the control #841 asks for, applied here rather than only filed.
