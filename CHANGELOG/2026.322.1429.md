# 2026.322.1429 — feat(harness): derive Claude's plugin set from the corpus, gate it, and bootstrap every harness in one script

Agent: claude-binding

## Summary

Closes #1100. A Claude Code session rooted at the umbrella loaded **none** of the `/charly-*` skills the AGENTS.md dispatcher routes to, so R0 could not be met natively. The RCA (in #1100) found two independent signatures:

- **The Claude binding was hand-maintained.** `.claude/settings.json` `enabledPlugins` named 26 of the corpus catalog's 44 plugins, while the other three harness bindings (the DSH farm, `reasonix.toml`, `opencode.json`) are derived from the whole corpus. Its only control was check 3's `plugins.length >= 20`, a floor that can never see drift.
- **Enablement is not installation.** Nothing in a clone writes the per-user install records that make an enabled plugin load. The plugin registry here held 0 records.

**The fix:**

- **The plugin set is derived.** `scripts/sync-skill-bindings.mjs` gains a `claude` binding: `enabledPlugins`' `@charly-plugins` keys are derived from `marketplace/.claude-plugin/marketplace.json`, in byte order, with a byte-range rewrite of that object only. Keys of other marketplaces are preserved. It runs in the pin wave's existing re-derive step, so a corpus advance re-derives it like the other bindings.
- **The gate asserts the derivation.** Check 3 of `scripts/check-harness-config.mjs` now checks the derivation instead of the floor, and asserts that no `gh pr merge` auto-allow exists. Both arms are in the self-test.
- **One bootstrap entrypoint**, `scripts/bootstrap.sh`, composes the existing steps without re-implementing any:
  - `init-submodules.sh`, the charly build and `charly task hooks`;
  - a `--check` of the derived bindings;
  - per-harness install records. For Claude it registers the marketplaces `extraKnownMarketplaces` names, then **installs and updates** every enabled plugin at project scope (`install` alone leaves an existing record on the old commit). For Codex it registers the marketplace.
  - It **fails if a harness rewrites a tracked file**. The committed `.claude/settings.json` is kept in the form Claude Code writes, so the install is a fixed point.
  - It **warns about every missing dependency and installs none**: `git`, `python3`, `go`, `node`, `gh`, `golangci-lint`, and `gopls` while `gopls-lsp` is enabled.

**The same Claude-config audit also found:**

- `permissions.allow` auto-approved `Bash(gh pr merge:*)`, which AGENTS.md forbids ("No agent merges"). It is removed and asserted absent.
- `.claude/workflows/triage-check-failure.js` registers as `triage-verify-failure`. The file is renamed to its registered name, and `agent-roster.md` is corrected: it described a bed-triage `/triage-check-failure` and a `charly status` `/verify-status`, while the shipped workflows are pinning-gate tools.
- `agent-roster.md` said agent teams are enabled by an `env` block in the committed settings. No such block ever existed (`git log -S CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS -- .claude/settings.json` is empty), so the prose now says so. Its heading, "Agent teams (experimental — enabled in committed settings)", now reads "opt-in per session". It was left behind in round 1 and the validator found it. The retracted claim is also a committed key of `scripts/check-retired-claims.mjs` (run by `charly task verify`), so it cannot come back.

**Pod MCP servers** (operator direction: public servers only). The four localhost pod servers reported `failed` in every session. That was fixed at the source in opencharly/plugin-marketplace#62 (merged), opencharly/spec#377 (merged) and opencharly/marketplace#623 (merged). This PR carries none of it: the umbrella's own harness configs already list only the public `deepwiki`.
