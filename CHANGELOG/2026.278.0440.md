## Summary

Harness config lives **only** at the umbrella root (rule 8, #317). Three of those surfaces are injected into *every* session, and they restated policy that `AGENTS.md` and the skills already own — a second implementation, which drifts silently (R3). This PR removes the restatements and keeps the harness mechanics.

**Measured drift (why this is a defect, not tidiness):**

- `.opencode/agent/pr-validator.md` told the validator to run `./charly/bin/charly task verify` **on every PR head** — docs-only diffs included — plus its own copy of the body checklist and the attribution rule. The canonical validator rulebook carries no such mandate, so the copy kept firing on its own schedule.
- `.pi/APPEND_SYSTEM.md` told the agent to arm auto-merge with `gh pr merge --auto --squash`. `AGENTS.md` says the opposite: the `charly/pr-validator` gate arms native auto-merge inline on its own PASS, and "No agent runs `gh pr merge`".
