## Summary

Head `1a63ccd83162dfff731f5d094df84cc55cb45ec3` — the commit this PR pushes: **2 files changed, 97 insertions(+), 14 deletions(-)**.

**This is the successor of #724, and it carries the finding the validator raised there.** #724 has already merged, and a finding raised on my own PR is fixed rather than filed away (R1) — so the fix travels in its own PR, on a fresh branch off fresh `origin/main`, and the predecessor is named here and in the commit message.

**What the finding was.** #724 added `scripts/check-governance-reconcile.mjs` — the umbrella's own gate wrapper around the pinned governance reconcile — and the `verify` task gained two steps that run it. The script carries a self-test that proves each of its four assertions can fail, each paired with a mutation that breaks exactly that one. The validator's review of #724 raised one observation, about assertion **D** ("the strong form is invoked with `--root <the checkout>`"):

> the D assertion compared the stub's echoed `--root` against the `mkdtempSync` path the caller held, as SPELLINGS.

The two spellings differ whenever the path a module resolves for ITSELF differs from the path the caller holds — and that is not an exotic shape. Node resolves a module's own location to its real path, so on a platform whose temp root is a symlink (macOS: `/var` → `/private/var`) the module sees the real spelling while the caller holds the linked one. The two strings then differ, D fails, and the self-test exits 1: loudly, never silently — but on every run, on that platform. On a platform whose temp root is not a symlink, the defect is invisible, because the shipped fixture never produced the asymmetry in the first place: the assertion could not be wrong about a shape it never saw.

**The fix, and the two changes that carry it.** The fixture is now addressed **through a symlink**, so the checkout's path has two spellings on every platform, and the assertion compares the **real** paths — it judges the directory, not the spelling of its path. The proof that the fix is load-bearing is in the shipped coverage rather than in prose: the asymmetry is now real everywhere, so the pre-fix comparison is measurably RED here as well.

Two further changes come with it, both from the same review:

- **The mutation harness gains a second mechanism**, and it is the mechanism this fix needs. The first mechanism proves a mutation of the **gate's** executed path: the fixture copy runs the mutated gate, and the parent judges the copy's behaviour. A mutation of the **harness's own** assertion logic is invisible to it — the fixture copy runs as a gate and never executes the parent's assertion code — so such a mutation changed nothing the parent observed, and the assertion would have looked live while it was not: a coverage that cannot fail. The second mechanism runs the mutated source **as a self-test** and requires that nested self-test to FAIL on the assertion under test. The nested run does not recurse, and says so.
- **`runGate`'s unused `skipped` field is gone** — dead code (R5).

The self-test now proves **five** mutations against **four** assertions, and the fifth is this fix: reverting the comparison to the spelling makes the mutated self-test fail on D.

| file | what it changes |
|---|---|
| `scripts/check-governance-reconcile.mjs` | the D assertion compares the REAL paths; the fixture is addressed through a symlink, so the asymmetry is real on every platform; the mutation harness gains the second mechanism; `runGate`'s dead `skipped` field is removed |
| `charly.yml` | the self-test step's description states what the step now also proves — that the strong form is invoked with `--root <the checkout>` |
