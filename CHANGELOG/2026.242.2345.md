### `gst-wayland-display` tracks `stable`, not `main`

`main` does not exist in that fork. Every entry's `branch =` is read from the repo's **real**
default via the GitHub API rather than assumed — which is what the README already requires:
*"nothing ever assumes `main` — defaults are resolved via `git ls-remote --symref`, so a future
default-branch rename keeps working."* A blanket `-b main` would have created a dangling pin that
`verify` only catches later.

### Why only 2 README rows for 7 repos

The org map is a **selective index, not an inventory** — it lists infrastructure and notable
standalone repos, and contains **no** `pod-*` entries at all among the ~330 candy repos already
submoduled. The two added match that granularity:

- **`gst-wayland-display`** — a patched upstream fork, exactly the `pixelflux` precedent already in
  the table (which likewise notes its non-`main` default branch).
- **`charly-streamer`** — the product code.

The pods, layers and the plugin are ordinary candy repos and are no more listed than their ~330
siblings. **No pinning-policy edit is needed**: rule 3 already covers *"everything else → its own
default-branch HEAD"*, so the new entries fall under the existing rule rather than needing a new
clause.
