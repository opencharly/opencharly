# 2026.295.1707 — docs(design)!: restate the target as eight unified mechanisms with full capability parity

Closes #593

## Summary

This PR restates the normative target (DESIGN.md + DESIGN.cue) **top-down**. charly is eight mechanisms, and every capability is an instance of exactly one of them: a row of that mechanism's table, never a kind, verb, command group or plugin of its own (new law **D-LAW-8**, new §1.1).

| # | Mechanism | Table in DESIGN.cue |
|---|---|---|
| M1 | content → IR | the candy body, `#ActionAlt` |
| M2 | artifact (one builder, BuildKit) | `#ArtifactRef`, `build` |
| M3 | deployment = kind × driver | the kind table, `#Driver` |
| M4 | need → grant | `#Need` |
| M5 | lifecycle and state | `#MethodIO` (`capture` with a scope, `restore`) |
| M6 | venue | `#VenueOutputAlt`, `_venueOperationWord` |
| M7 | observation | `#FactVerb`, `#ProtocolVerb` |
| M8 | store | the store host methods |

How the upstream changes since 2026-10-14 land as rows rather than new concepts:
- **containerd, krun, Firecracker.** `containerd` (spec#266) is a container-engine driver row. `libvirt`, `qemu`, `krun` and `firecracker` (spec#227/#229) are hypervisor driver rows. Drivers are chosen by the new user-configuration schema (`#UserConfig`, `#Driver`; **D-DRV-1..3**, §12.6) and never named in an authored document. The form a `vm` consumes follows its driver: a disk, a root drive plus the `os` `boot` kernel, or an image for `krun` (**D-FORM-3**).
- **New needs.** The runtime facts of CONTAINERD.md, K3S.md, LIBKRUN.md and CONTAINERD-IMAGES.md (read in full) become needs: `isolation: microvm` (the runtime handler or RuntimeClass), `privilege: rootful`, and `nesting: userns` (the narrow seccomp profile, never unconfined). They have new grant-matrix rows in §16.1 and **D-HW-7**.
- **Capture and restore.** `capture` gains `scope: filesystem | process` (CRIU), and the new kind method and command `restore` (**D-CAPTURE-4/5**) absorb `vm snapshot revert`, `check run --anchor` and the k3s datadir backup.
- **Venues.** Every interaction is a venue operation, and a venue declares the operations it serves (a microVM venue serves no `exec`; **D-VENUE-1/2**, §12.7).
- **Verbs.** A verb is a fact verb or a protocol verb (**D-VERB-6**). New typed fact verbs: `user`, `group`, `mount`, `kernel-param`, `dns`, `interface`. Application and internal-operation verbs become namespaced (**D-PLUG-7**) or `api` methods.
- **One workflow kind.** `pipeline` absorbs `task`, and its stages carry `lane:` (the spec#264 fan-out) (**D-FLOW-1/2**, §10.1). This is a design call, flagged here for review.
- **Store.** It is served read-only as an image registry (**D-STORE-10**, charly-registry).
- **Volumes.** A volume can be `encrypted`, absorbing plugin-enc.
- **Every first-party kind and verb is now typed.** This replaces the opaque `_otherKind`/`_otherVerb`/`#OtherBody` (**D-KIND-5**). `#Opaque` remains only on S10 lines, and a new consistency control enforces that.
- **Parity is proved, not designed.** `design/parity.tsv` (Appendix A.8) maps:
  - every provider word of the 110 product plugins on `origin/main` (plus charly-registry);
  - 33 subcommand groups whose disposition differs from their group;
  - 20 runtime capabilities.

  Each row names its mechanism and DESIGN home. Design-check check 4 now resolves every D-ID and `home`-column § in it.

The check machinery changed with the design, as Appendix A.7 requires:
- `scripts/design-consistency.sh` adds three controls: the S10 control, the verb-table disjointness control, and ledger IDs/§ in check 4.
- `scripts/design-examples.sh` adds a `user-config` example mode validated against `#UserConfig`.
- `design/example/rules.cue` adds reference clauses for roster beds, pipeline stages and builder boxes.
- There are 9 new negative cases and 4 new self-test rows; one row is re-anchored.

Section numbers are stable, because TODO.md cites them; new material lives in §1.1, §10.1, §12.6, §12.7 and A.8.
