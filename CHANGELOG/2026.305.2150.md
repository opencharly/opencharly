# 2026.305.2150 — fix(task): declare the prune step's 30m ceiling so the 90s floor cannot kill a reap

## Summary

The umbrella's `prune` task step now declares `timeout: 30m`. It declared none before, so the
runner's per-attempt never-hang floor (90s) was the step's only ceiling — and this verb's cost
scales with the session debt it reaps: it scans the project root plus **every** initialized
submodule and asks GitHub for each repo's PR list.

MEASURED 2026-11-01 on this checkout: the pre-declaration dry run was killed by that bound, in the
runner's own words —

```
killed by the per-attempt never-hang bound of 1m30s — the step ran longer than that, it did not crash.
```

— and the step's output shows it had already rendered its whole plan (pasted below) before the kill
landed. So **90s is the ceiling the step met, not a measurement of the work it needed**: on this
tree the debt was large enough that the dry run was cut short mid-scan. For `MODE=prune` that same
kill lands **mid-reap** — the worst state for a verb whose entire purpose is a provable cleanup.

The sibling `git-submodules` step already carries exactly this declaration, with its reason
("A step the floor cuts short is KILLED mid-run, so the ceiling is declared here" — `charly.yml`
line 286 on `main`, same `30m`). `prune` was added later and never received it. This change gives
`prune` the same ceiling and the same kind of reason, and nothing else: one comment block and one
key.
