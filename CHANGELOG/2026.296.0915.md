**The control.** `charly task verify` judged CONSISTENCY — every checkout equals the
gitlink the index records — and said nothing about CURRENCY — every pin at the ref its
intent names. A tree can be perfectly consistent while every pin is behind what its repo
serves, which is exactly the state this wave found and exactly the state the gate could
not see. So `verify` now also asks the currency question and **reports** it: the verb
answers `StatusPass` with a message that names every pin that is not current and the
producer-first legs that would make it current. A pin that is behind is an advance
available now, in its producer's own repo, not a broken edge — so the gate names it and
stays green; only a pin the workflow cannot judge, or two sides that disagree, fails it.
