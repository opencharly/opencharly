# 2026.329.1028 — docs(fork-gate)!: conform DESIGN A.12 and the repo-setup skill to gated forks

## Summary

The contract and the guidance for the gated-fork cutover, landing **before** any fork mints a
tag (R11).

- **DESIGN A.12** (`D-PLUG-3`): a first-party fork now carries the tag-on-merge caller, so it is
  tagged like any other landing repo. `not-applicable` describes a repository with **no caller** —
  an un-onboarded fork, a vendored mirror, an archived repo, or a captured-output branch — and it
  no longer describes forks in general. The amendment records the classification a fork pin takes:
  `pre-release-process` at the caller-install commit, then `changelog-tip` / `tagged`.
- **`scripts/design-pintag.sh`** comment brought in step with A.12 (a fork is not a no-caller
  example).
- **`.agents/skills/repo-setup`**: the org model is **two org rulesets from one payload builder**
  (A: non-fork `main`; B: forks on `~DEFAULT_BRANCH`, the SAME `workflows` rule + required
  `validate / validate`), so **no per-fork `pr-validator.yml` is copied**; the only per-fork file
  is the tag-on-merge caller; mirror sync uses the App-token `sync-forks.yml`; a new
  **Onboarding a fork** checklist; forks leave the exclusion list.
- **`README.md`** org map: the vendored forks are gated and tagged at merge; sync via
  `sync-forks.yml`.

The mechanism landed in opencharly/.github#322 (tag `v2026.329.0923`). This PR is the contract and
the guidance; the live rollout is opencharly/.github#320.

**R1 — a gate anomaly found and fixed at its control.** The first design-check run failed with
50 false `untagged` findings on a fresh session worktree. The pins at issue have no checkout, so
the offline tag map comes from the shared module store, and `scripts/init-submodules.sh` fetches
`--tags` **only when a store LACKS its pin** (`:908-919`) — an existing store is never refreshed.
`git -C <store> fetch --tags` for the 50 stores (no failures), then the same design check passed;
**no census row was added** (the pins are tagged; the stores were stale). Filed as
opencharly/opencharly#1279 (non-blocking; the durable control fix is separable).
