### The CalVer, read from the workflow rather than assumed

The org reusable workflow `opencharly/.github/.github/workflows/tag-on-merge.yml`, at the `8e0bf3c3d8` this repo pinned in #590, computes the tag like this:

```js
const { data: commit } = await github.rest.git.getCommit({ ...repo, commit_sha: pr.merge_commit_sha });
const d = new Date(commit.committer.date);
const y = d.getUTCFullYear();
const doy = String(Math.floor((d - new Date(y, 0, 0)) / 86400000)).padStart(3, '0');
const hh = String(d.getUTCHours()).padStart(2, '0');
const mm = String(d.getUTCMinutes()).padStart(2, '0');
const tag = isGoModuleRepo
  ? `v0.${y}${doy}.${parseInt(hh + mm)}`
  : `v${y}.${doy}.${hh}${mm}`;
const calver = tag.replace(/^v/, '');
```

Five things are settled by that text, none of them by inference: the basis is the **merge commit's committer date**, not the PR's `merged_at`; `doy` is the day-of-year zero-padded to three digits; `hh`/`mm` are **UTC**; this repo is not one of the three proxy-consumed root modules (`['sdk', 'spec', 'plugin-gh']`), so the plain form applies; and the tag is created by `git.createRef({ ref: 'refs/tags/<tag>', sha: merge_commit_sha })` — a **lightweight** tag, not an annotated one.
