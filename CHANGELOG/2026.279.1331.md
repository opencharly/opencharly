# 2026.279.1331 — fix(sync): emit rule 7's Agent: line from the body builder

## Summary

`scripts/sync-pr-body.sh` is the ONE builder for a pin-sync PR's body. It emitted the
`Assisted-by:` trailer and **no `Agent:` line**, so every body it rendered violated
`AGENTS.md` rule 7's canonical order (`Agent:` FIRST, `Assisted-by:` LAST, ADJACENT) and the
run that opened the sync PR had to insert the line by hand — a workaround for a missing
builder behaviour (R4), invisible to everyone who trusts the builder's output.

Measured on `origin/main`, this branch's merge-base `58840b9`:

```
$ git show origin/main:scripts/sync-pr-body.sh | grep -c -i "agent:"
0
exit=1

$ git show origin/main:scripts/sync-pr-body.sh | grep -c "Assisted-by:"
2
exit=0

$ git show origin/main:scripts/sync-pr-body.sh | grep -n "Assisted-by:"
214:    echo "*Assisted-by: ${SYNC_ASSISTED_BY}*"
372:  tail -n 1 "$tmp/body" | grep -qE '^\*Assisted-by: .+ \(fully tested and validated\)\*$' \
exit=0
```

The missing half was already specified; only the producer was absent. The org's own body
linter requires the `Agent:` line to be the line DIRECTLY above the trailer
(`marketplace/scripts/pr_body_lint.py:102-103`), and the builder's own self-test asserts the
trailer is the FINAL line. Both hold after this change.

**The change** — one file, `scripts/sync-pr-body.sh` (62 insertions, 8 deletions):

1. a **fail-loud guard** on `SYNC_AGENT`, parallel to the existing `SYNC_ASSISTED_BY` tier
   guard, before anything is written: an unset value returns non-zero and the caller gets no
   body at all, so a manual run cannot ship an anonymous one;
2. the emitter prints `*Agent: ${SYNC_AGENT}*` immediately **above** the trailer;
3. the `Assisted-by:` trailer stays the FINAL line — the existing assertion is untouched;
4. the self-test gains four arms: the **adjacency**, an **unset** `SYNC_AGENT`, a **second
   identity** the line must track, and a **count**.

Both identity lines stay caller-supplied; no identity is canned into the script.

**A defect this change found in its own first cut, and fixed here (R1/R2).** The first cut
reworded the emitted `## Attribution` prose to name the trailer with a literal
`` `Assisted-by:` ``. That gave the rendered body TWO occurrences, where the constructor the
owning skill names as canonical — `marketplace/scripts/squash_body.py` — accepts exactly one:
its `render_body` fails loud on prose containing an `Assisted-by:` trailer. RCA: the builder
held no invariant on the occurrence count in its own output, so nothing in the suite could
notice a second one. The emission was reworded to carry none, and arm 4 is the control that
would have caught it — proven by mutation in **How tested** below.

Head `1b7c6fb1d91ff21f5b2a827badc619ff4ba2e915`.
