# 2026.271.1841 — feat(opencode): coordination custom tools (V2) + pr-watch V2 delivery fix

## Summary

Makes the OpenCharly GitHub workflow + issue/PR-coordination surface **fully
automatic and properly typed for opencode V2**, and fixes a measured defect in the
existing PR-watch binding.

### 1. Coordination as first-class opencode tools (new)

`.opencode/plugins/coord.ts` — a proper V2 `{ id, setup }` plugin registering two
custom tools that bind the GENERIC shell scripts (the grammar is **not**
reimplemented — R3):

- **`coord_comment`** → `marketplace/scripts/coord.sh`: post ONE verb-labelled
  coordination comment (`CLAIM`/`OWNING`/`HANDING OVER`/`TAKING OVER`/`BLOCKS`/
  `UNBLOCKS`/`STATUS`/`RESOLVED`) carrying the canonical two-line footer
  (`Agent:` FIRST, `Assisted-by:` LAST), with `assign` for a CLAIM.
- **`coord_watch`** → `marketplace/scripts/gh_watch.sh`: a bounded, session-invoked
  one-shot wait returning the wake line. The continuous background watch stays
  `pr-watch.ts`'s job.

Identity (`agent`/`harness`/`model`/`confidence`) resolves **tool arg > `COORD_*` env
> `.opencode/coord.conf`**; the **session is always the live `toolCtx.sessionID`**, so
a stale config can never mislabel who is speaking. The scripts resolve via
`COORD_SH`/`GH_WATCH_SH`, then `<dir>/marketplace/scripts/…`, then
`<dir>/../marketplace/scripts/…` — so a repo without a marketplace submodule (e.g.
`opencharly/.github` at `.worktrees/<slug>/dotgithub`) finds the sibling worktree's
scripts instead of forking them.

### 2. `pr-watch.ts` V2 delivery — R1 fix

The V2 `setup(ctx)` context has **NO `client`** (only 1.x's `server(input)` does).
MEASURED 2026-09-28 against the REAL **v2.0.18** binary: `client` is `undefined` and
`session.list` does not exist, so the V2 delivery path silently no-opped and warned
`SDK client unavailable`. The V2 "inject context without starting a turn" primitive
is `ctx.session.synthetic({ sessionID, text })`; the session id is captured from
`ctx.tool.hook("execute.before", e => e.sessionID)` (or the first prompt). The V1
SDK-client path is retained.

### 3. Type pin + config

- `.opencode/package.json` (new): declares `@opencode-ai/plugin` **1.18.33** and
  `"type": "module"`. V2 plugins type against the `./v2/promise` export. **Both
  1.18.32 and 1.18.33 ship it** (verified against their published packages); the pin
  tracks 1.18.33, the newest release (there is no 2.x npm release). Type-only imports
  erase at runtime, so NO `node_modules` is needed to load.
- `.opencode/.gitignore` (new): ignore `node_modules`/`bun.lock`; **track**
  `package.json`.
- `.opencode/coord.conf.example` (new): the identity defaults template.
- `.opencode/lib/wake-line.ts` (new, R3): the ONE shared wake-line helper used by both
  `coord.ts` and `pr-watch.ts` (`lib/`, not `plugins/`, so discovery never treats it as
  a plugin).
- `.opencode/instructions.md`: document the MEASURED V2 custom-tool contract
  (`{ content }` result required; JSON-Schema `input`) and the corrected pr-watch V2
  delivery.

### 4. Tests (A/B/B2/C, live-or-skip)

- `scripts/check-opencode-coord.mjs` (new): **A** V2 shape + the declared
  `@opencode-ai/plugin` version/type; **B** the pure helpers; **B2** drives the actual
  `coord_comment`/`coord_watch` **execute** paths against stub scripts (this layer fails
  on the double-`bash` regression); **C** `LIVE_OPENCODE=1` drives the REAL binary to
  register AND call `coord_comment` through the REAL `coord.sh`.
- `scripts/check-pr-watch.mjs`: now asserts BOTH the V2 (`ctx.session.synthetic`,
  `ctx.tool.hook`) and V1 (`client.tui`, `noReply: true`) delivery primitives are
  present as CODE (comments stripped).
- The scripts themselves are covered by `marketplace/scripts/coord_test.sh`
  (companion PR) and the unchanged `watch_family_test.sh`.

### 5. Review-round fixes

- **coord_watch double-`bash`**: `watchArgv()` returned `["bash", script, …]` while the
  caller did `spawnSync("bash", …)`, so the watcher never ran. `watchArgv` now returns
  the script + args (no leading `bash`); Layer B2 tests the execute paths.
- **R3 duplicated helper**: `wakeLine`/`lastWakeLine` now live once in
  `.opencode/lib/wake-line.ts`.
- **False comment**: `check-opencode-coord.mjs` now ACTUALLY asserts the declared
  version + `type: module` (and the installed `./v2/promise` export when present).
- **`coord.conf` git-ignored**: `.opencode/.gitignore` now ignores it (the example
  says so).
- **Live C layer staged the plugin's siblings**: it now stages `.opencode/lib/` (the
  plugin imports `../lib/wake-line.ts`) and captures the REAL `coord.sh` stdout
  deterministically, retrying a model no-call ONCE (bounded). A Node footgun was fixed:
  `process.env.X = undefined` sets the STRING `"undefined"` (it had poisoned `COORD_SH`
  for the live layer) — the restore now DELETES.
- **Version claim corrected**: both 1.18.32 and 1.18.33 ship `./v2/promise`; the pin
  tracks 1.18.33.
